# コミュニケーション計画

## 1. 方針と適用範囲

当事者、技術協力者、継続参加者が、社会課題と試行成果、費用・負荷、次の判断を同じ証跡で確認できるようにする。非同期の公開記録を基本とし、会議は当事者確認または意思決定が必要な場合だけ行う。関係者の一覧、期待、懸念は [[prj-0001:prj-stakeholder-register|ステークホルダー登録簿]] を正とする。

## 2. コミュニケーション機会

| 対象・機会                   | 伝える・確認する内容                                   | タイミング                 | 手段                           | 責任 | 証跡                     |
| ---------------------------- | ------------------------------------------------------ | -------------------------- | ------------------------------ | ---- | ------------------------ |
| `PO` の判断                  | 価値、範囲、優先順位、費用・時間上限、公開可否         | 判断ゲート前、重大変更時   | Issue、Pull Request、決定記録  | `PM` | 判断理由と結果           |
| 代表利用者・協働組織との試行 | 課題、期待価値、試行成果、現金支出、作業負荷、継続条件 | 試行設計時、試行終了時     | 相談・試行記録、Issue          | `BA` | 合意と評価結果           |
| AI Agent の作業              | 入力正本、制約、出力、完了条件、人間の判断者           | 各タスク開始時とレビュー時 | exec plan、差分、レビュー結果  | `BA` | 入力と生成結果の対応     |
| チームの進捗                 | 完了、次の作業、ブロック、必要な判断                   | 節目または状態変化時       | Schedule、登録簿、Pull Request | `PM` | 状態と次の行動           |
| 将来の利用者・貢献者への公開 | 利用方法、適用範囲、費用・負荷の考え方、改善提案方法   | 初期公開時、主要変更時     | 公開文書、Issue                | `BA` | 公開内容、提案、採否理由 |

定例会議や定期報告は設けない。確認すべき事実または判断が生じた時点で、上表の機会を使う。

## 3. エスカレーション

| 条件                                       | 一次対応                            | 最終判断 | 証跡                   |
| ------------------------------------------ | ----------------------------------- | -------- | ---------------------- |
| 当事者の課題と仕様・試行成果が一致しない   | `BA` が不一致と代替案を整理する     | `PO`     | 確認記録、決定記録     |
| 費用・参加時間が上限を超える見込み         | `PM` が縮小・延期・中止案を整理する | `PO`     | 課題、決定記録         |
| 品質、権利、個人情報、公開適性に重大な懸念 | `QE` が対象を隔離し影響を整理する   | `PO`     | レビュー、決定記録     |
| 依存未解決や遅延が初期公開へ影響           | `PM` が再計画案を整理する           | `PO`     | 課題、再計画、決定記録 |

緊急度だけで重要判断を口頭完結させない。暫定対応後、理由と結果を正本へ記録する。

## 4. 情報管理と公開

- 判断、課題、リスク、変更、次の作業は、後から根拠を追える正本へ記録する。
- 公開記録には個人名、連絡先、非公開組織情報、認証情報、秘密情報を記載しない。
- 当事者の発言や試行データは、同意した用途・範囲で匿名化して扱う。
- AI Agent へ渡す情報は作業に必要な最小範囲とし、出力は人間が確認する。
- 生成ビューや Schedule を直接修正せず、生成元の正本を更新する。

## 5. 見直し条件と未決事項

代表利用者・協働組織の参加、公開範囲、試行方法、主な連絡手段、AI Agent の利用条件が変わった場合に見直す。具体的な代表利用者、協働開始時の連絡手段、定期確認の要否は、各試行の開始前に `BA` と `PM` が整理し `PO` が決定する。
