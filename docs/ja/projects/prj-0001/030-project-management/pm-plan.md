# プロジェクト管理計画

## 1. 管理目的と適用方針

SpecDojo の初期公開と代表試行を、[[prj-0001:prj-overview|プロジェクト概要]] の三つの価値仮説に沿って管理する。小規模な CivicTech プロジェクト向けの軽量運用とし、本書は横断的な上限・判断ゲート・正本だけを定める。品質、コミュニケーション、責任分担の詳細は各計画へ委譲する。

AI Agent は整理、作成、実装、検証を支援できるが、社会課題、期待価値、費用・時間上限、主要変更、公開可否は人間の `PO` が判断する。

## 2. 統合管理方針

| 管理対象           | 基準・上限                                                                                                      | 確認契機                                                                         | 逸脱時対応                                                              | 責任 |
| ------------------ | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---- |
| スコープ           | [[prj-0001:prj-scope\|プロジェクトスコープ]] の最小成果物、CLI、代表試行、公開導線                              | 追加提案時                                                                       | 対応する価値仮説と SC-ID、同時に削る項目を示す                          | `PM` |
| スケジュール       | 全体マイルストーンと、トラック別の `sch-strategy-<track>.yaml` および生成される `sch-track-<track>.yaml` で管理 | トラック追加・移行時、トラック間依存・マイルストーン変更時、後続へ影響する遅延時 | 対象 Strategy と全体マイルストーンを見直し、Track Schedule を再生成する | `PM` |
| 現金支出           | SpecDojo の利用・ライセンス費は0円。代表試行の追加支出は事前承認上限内                                          | 有償依存の追加前、代表試行終了時                                                 | OSS・既存資産への代替、範囲縮小、中止を比較する                         | `PO` |
| 参加者の時間       | 代表試行前に参加者区分ごとの上限を承認し、継続負担も分けて記録                                                  | 計画時、上限接近時、引き継ぎ時                                                   | 成果物、手順、確認回数を減らす                                          | `PM` |
| 品質               | SC-01〜SC-03 と AC-01〜AC-04 を初期公開ゲートとする                                                             | 代表試行前、初期公開前                                                           | 是正、期限付き例外、Not GO を判断する                                   | `QE` |
| 課題・リスク・変更 | 判断者、期限、次の行動、価値・費用・負荷への影響を記録                                                          | 発生・顕在化・状態変更時                                                         | プロジェクト登録簿へ分離して追跡する                                    | `PM` |

現金支出と人の時間は別の制約として扱い、無償労働を低コストの根拠にしない。

## 3. 判断ゲートとエスカレーション

| ゲート       | 判断条件                                                           | 判断材料                                     | 起案・整理 | 最終判断 | 証跡               |
| ------------ | ------------------------------------------------------------------ | -------------------------------------------- | ---------- | -------- | ------------------ |
| 代表試行開始 | 代表課題、当事者、期待価値、試行成果、費用・時間上限が決まっている | 試行計画、上限、未決事項                     | `BA`, `PM` | `PO`     | 決定記録           |
| 初期公開     | SC-01〜SC-03 と AC-01〜AC-04 を満たす                              | 試行結果、支出・作業記録、検証結果、未達一覧 | `PM`, `QE` | `PO`     | 判定・是正記録     |
| 重大変更     | 目的、初期範囲、費用・時間上限、公開時期へ影響する                 | 価値、影響、代替案、同時に削る項目           | `PM`       | `PO`     | 変更要求、決定記録 |
| 公開後の継続 | SC-04〜SC-06 の観測結果から改善継続が妥当                          | 活用事例、利用者評価、費用・負荷、運用状況   | `BA`, `PM` | `PO`     | 振り返り、決定記録 |

次の場合は担当ロールが作業を止め、`PM` が `PO` の判断材料を整理する。

- 当事者価値と試行成果に重大な不一致がある。
- 現金支出または参加者の時間が承認上限を超える見込みである。
- 個人情報、権利、セキュリティ、公開適性に重大な懸念がある。
- 初期公開の対象または時期へ重大な影響がある。

## 4. 正本・報告・見直し

| 情報                       | 正本                                       | 更新・報告契機          | 主な確認者 |
| -------------------------- | ------------------------------------------ | ----------------------- | ---------- |
| 目的・価値・範囲・成功条件 | プロジェクト定義成果物                     | 基準変更時、各ゲート前  | `PO`, `BA` |
| 作業順序・owner・進捗      | Schedule                                   | 節目、遅延、依存変更時  | `PM`       |
| 課題・リスク・変更・決定   | [[prj-0001:pjr-index\|プロジェクト登録簿]] | 発生・状態変更時        | `PM`, `PO` |
| Role code・実行主体・責任  | ロール、メンバー、RACI                     | 体制または owner 変更時 | `PM`, `PO` |
| 品質・代表試行             | 品質計画、検証・試行記録                   | 各品質ゲート前          | `QE`, `PO` |
| 現金支出・参加時間         | 代表試行の費用・作業記録                   | 上限接近時、試行終了時  | `PM`, `PO` |

進捗と判断依頼の伝え方は [[prj-0001:pm-communication-plan|コミュニケーション計画]]、品質ゲートは [[prj-0001:pm-quality-management-plan|品質管理計画]]、責任分担は [[prj-0001:pm-raci|RACI]] を正とする。本計画は、価値仮説、初期範囲、成功基準、費用・時間上限、体制のいずれかが変わったときに見直す。

## 5. 未決事項

代表課題、試行成果、追加現金支出上限、参加者別作業時間上限、公開範囲は、[[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] の未解決事項を正本とし、本書へ重複記載しない。
