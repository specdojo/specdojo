# Edit Result

## 1. 実施内容

個票 [[prj-0001:pjr-0156-dct-merge-same-name-group|PJR-0156 dctカタログmergeの同名group結合対応]] の完了条件に沿って、同一 domain の複数 DCT ファイルにある同名 group を1章へ結合する処理を実装した。

- `mergeDomainCatalogs` の入力を関数内でもファイル名昇順に正規化し、OS の列挙順や呼び出し元の配列順に依存しないようにした。
- 同一階層の `name` 完全一致を結合キーとし、最初の group の章位置・`base_path`・`note`・`min_size` を保持する。後続 group の `deliverables` はファイル名昇順、各ファイル内の定義順で追記し、子 `groups` は同じ規則で再帰結合する。
- 名前が異なる group と無名 group は個別に保持する。単一ファイル内の同名 group は結合対象にせず、既存構造を維持する。
- マージ前の各ファイルを走査する既存の `local_id` 重複検出を維持し、同名 group 結合後も重複をエラーとして検出する。
- [[specdojo:dct-rulebook|成果物カタログ（ドメイン別）作成ルール]] のファイル命名・ID例を成果物種別分割へ更新し、同名 group の結合キー、順序、入れ子、属性継承、無名 group の規則を追記した。
- data-model テンプレートを `bdd` / `cdsd` / `sld` / `stsd` / `cld` / `ccd` / `cstd` の7ファイルへ再分割した。既存の成果物定義と group 名を維持し、実テンプレートを scaffold/build するテストで `業務データ辞書` 5ファイルと `概念モデル` 2ファイルがそれぞれ1章になることを確認した。
