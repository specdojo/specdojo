### 1.1. 現状調査（確認済みの事実）

  - フロー: `resolveRegisterRunTarget` → `requireRunnableRegisterItem` → `resolveRegisterCommand` → `generateRegisterPlan` → `scaffoldResult` → `register start` → `spawnAgentInPlace` → 成功時 `register review` / 失敗時 `register wait`（`--conclusion`）。
  - 状態遷移は `spawnRegisterTransition()`（`register` サブコマンドを spawn）で一元化されている。
- CLI 定義は `registerRunCommand()`。`--register <pjrId>` は単一値オプション。バリデーションは `rcmd.action` 内で行われ、`--parallel`（`isManual && parseParallel(opts.parallel) !== 1`）と `--worktree`（`opts.worktree && !hasTask`）は既に理由付きで拒否される（register は manual かつ task なしのため両方に該当する）。
- ID正規化は `src/exec-register.ts` の `normalizePjrId()`（`PJR-XXXX` 形式検証・大文字化）。
