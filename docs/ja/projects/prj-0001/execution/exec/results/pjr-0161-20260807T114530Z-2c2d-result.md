# Edit Result

## 1. 実施内容

PJR-0161「登録簿承認 type の承認フローと PR/commit 使い分けの規約化」に対応した。個票 `pjr-0161-register-approval-workflow-policy.md` の完了条件を作業基準とし、関連文書へ承認運用を反映した。

- 承認の2区分（成果物レビュー / 内容承認）と、承認を要する type ごとの承認フロー（register 状態遷移 `review` → `close` / `reject` / `defer` / `wait`）、承認者ロール（RACI の A）を [[specdojo:register-operation-guide]] に新設した `承認フローと承認者`（2.5 節）へ定義した。
- 承認方式の使い分け（既定 commit ＋ 限定 PR）と PR を強制する3ケース（`develop → main` 昇格 / `change-request` 承認 / 不可逆・高リスク・framework schema 破壊的変更）を [[specdojo:git-branching-standard]] に新設した `承認ゲートと PR 強制条件`（8 節）へ明文化し、禁止事項へ自動統合への PR ゲート付与と自己承認の禁止を追記した。
- `main` / `develop` の branch protection と `CODEOWNERS` による承認者強制方針を [[specdojo:git-branching-standard]] の `同期・履歴・保護`（5 節）へ追加した。
- 承認方式の運用手順（commit ベース承認と PR 承認の作成〜書き戻し）を [[specdojo:branch-workflow-guide]] に新設した `承認方式を使い分ける`（7 節）へ追加した。
- `decision` / `question` テンプレートへ承認節（決定者・決定日 / 回答者・回答日・承認方式・証跡）を追加し、[[specdojo:pjr-rulebook]] の type 別標準構成へ両 type の承認節を必須内容として反映した。
- 個票の作業内容表（作業 No.1〜6）を `done` に更新し、対応結果へ反映先を記録した。

既存の [[specdojo:register-operation-guide]] `PO 留保事項の PR 承認運用`（4.2 節）と矛盾しないよう、既定 commit ＋ 限定 PR の原則で整合させ、詳細手順は既存節を正本として相互参照した。

## 3. 申し送り

- `CODEOWNERS` ファイル自体はリポジトリに未整備（`承認者強制方針` を規約として定義した段階）。実際の branch protection 設定と `CODEOWNERS` の owner 割り当ては platform 側の運用作業として別途必要。
- git-branching-standard の frontmatter `status` は `draft` のまま。`ready` 昇格は人間の判断による。
- 承認者ロール（RACI の A）の具体的な人物・役割割り当ては pm-raci との突き合わせで確定させる余地がある。本タスクではロール名（PO/CCB・意思決定者・回答権限者など）レベルで定義した。

## 4. 実践の型の活用

`rulebook-maintenance` 系のドキュメント整備タスクとして進めた。個票（`pjr-0161-register-approval-workflow-policy.md`）の完了条件・設計方針（3.2 type 別承認方式表、3.3 PR 強制3ケース）を一次基準とし、これを standard（規範）/ guide（手順）/ rulebook（構成規範）/ template（実体）の各層へ責務分担して反映した。

- 規範（PR 強制条件・branch protection・CODEOWNERS）は `git-branching-standard` を正本に置いた。
- 運用（承認2区分・type 別フロー・承認者ロール）は `register-operation-guide` を正本に置いた。
- 手順（commit / PR の使い分け操作）は `branch-workflow-guide` に置いた。
- 個票の type 別必須構成は `pjr-rulebook` §4.3 に、実体は decision/question テンプレートに反映し、rulebook とテンプレートの整合を保った。

既存の `register-operation-guide` 4.2 節（PO 留保事項の PR 承認運用）と本タスクの新規記述が重複しうるため、既存節を PR 承認の詳細手順の正本として温存し、新設節からは相互参照に留めて二重管理を避けた。章参照は markdown ルールに従い章タイトルで記載した。
