- 手入れ plan の出どころは `source=grade` / `source=condense` とした。同じ節で出どころを区別できるためである。condense は成果物ごとの最新の完了済み result を選び、宣言された対象 Kata と原因の種類が一致する記録だけを展開する。修正済みの原因を戻す記録なので、grade と異なり成果物のハッシュ一致は要求しない。
- 統合後、オーケストレーターが既存成果物 1 件で register の `--approach condense` から実行し、対象だけの編集、result のリストと表、Kata の手入れ plan への展開を確認する。runner に関わる変更を含むため、運用メモに従い PJR-JSEY の統合後確認にも含める。

PJR-1BRQ の指示に基づき、成果物の「磨き込み（condense approach）」を実現するための基盤を構築しました。具体的には、`result` 内で「修正すべき箇所とその原因」を構造的に記録するための `specdojo.condense_records` スキーマを定義しました。これにより、`grade` による指摘事項を、次回の `condense` 実行時に自動的に手入れの計画（plan）として取り込むことが可能になります。また、手入れの出どころを `source=condense` として明示的に扱うことで、整理されたワークフローを実現しています。
