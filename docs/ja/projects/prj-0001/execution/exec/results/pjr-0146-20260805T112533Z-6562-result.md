適用 1: ルール SSOT への反映。`.github/instructions/markdown.instructions.md` の既存 `## 10. 禁止事項` の直前に次の節を挿入し、既存 `## 10. 禁止事項` を `## 11. 禁止事項` に採番し直す。

```markdown
## 10. 履歴蓄積ファイルのリンク記法

plan / result / 個票（`pjr-<NNNN>-<topic>`）など、履歴として蓄積される Markdown 成果物では、リンク先ファイル名の変更に追従する修正が発生する Markdown リンク（`[表示名](パス)`・参照リンク `[表示名][ラベル]`）を書かない。参照は次の記法に統一する。

- 対象は次の履歴蓄積ファイル。登録簿本体（`pjr-index.md`）は個票セルの参照に Markdown リンクを用いるため対象外とする。
  - `docs/ja/projects/**/exec/plans/` 配下の plan。
  - `docs/ja/projects/**/exec/results/` 配下の result。
  - `docs/ja/projects/**/controls/project-register/pjr-*.md` の個票。
- `docs/` 配下の文書を参照する場合は、`id` を正とする wikilink（`[[id]]` または `[[id|表示名]]`）を使う。ファイルをリネームしても `id` は変えない運用のため、参照側の修正が不要になる。
- `docs/` 外のファイル（`.github/instructions/` など）を参照する場合は、リポジトリルートからの相対パスをインラインコードまたはプレーンテキストで書く。
- 外部URLは Markdown リンクにせず、URL そのまま（bare URL または autolink）で書く。
- 既存の履歴ファイルは、Markdown リンクを含むものが見つかった時点で上記記法へ置き換える。一括の遡及移行は必須としない。
- 違反検知は `npx tsx tools/docs/src/validate-history-links.ts` で行う。検出時は exit 1 で失敗する。
```

あわせて `## 11. 禁止事項` の表へ次の行を追加する。

```text
| 履歴蓄積ファイル（plan / result / 個票）で Markdown リンク `[]()` を使う | リンク先のリネームで追従修正が発生するため（`[[id]]`／パス表記に統一する） |
```
