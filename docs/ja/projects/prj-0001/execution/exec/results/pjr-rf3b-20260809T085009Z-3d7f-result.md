## 3. 申し送り

- 新スキーマは `.remarkrc.yaml` の `schemaRules` へ未登録である。既存個票は登録項目のフィールドを持たないため、先に登録すると必須項目の欠落で全件が検証エラーになり commit がブロックされる。適用の切り替えは既存項目の一括移行（[[prj-0001:pjr-9p5q-migrate-existing-register-items]]）と検証経路の更新（[[prj-0001:pjr-vc94-update-validation-and-tests]]）で、移行と同一の変更として行う。登録位置は `docs/ja/projects/**/*.md` の汎用ルールより前（先勝ちのため）。
- `deliverable-frontmatter.schema.yaml` に追加した登録項目フィールドは移行期間用の任意項目である。個票へ厳密スキーマを適用した後は不要になるため、[[prj-0001:pjr-vc94-update-validation-and-tests]] で削除可否を判断する。
- 日付は YAML の引用符付き文字列で書く必要がある（引用符なしは timestamp 値として読み込まれ `type: string` に違反する）。個票 frontmatter を書き込む CLI（[[prj-0001:pjr-tt4j-register-cli-write-to-tickets]]）は引用符付きで出力する必要がある。
- 一覧の「タイトル」「説明」列の生成方法は本タスクでは決めていない。タイトルは H1 から表示 ID 部分（`PJR-XXXX` と後続の空白）を除いた文字列で確定できるが、説明は個票本文のどこを要約するかが未決である（_UNDECIDED_）。frontmatter へ `summary` を追加すると本文との重複が生じるため追加していない。一覧生成を担当する [[prj-0001:pjr-rzr3-pjr-index-as-generated-view]] で、本文先頭段落からの導出か `summary` 追加かを決める。
- `register defer` は完了日を記録しないため、`deferred` は `completed_on` 必須の対象から外した。運用上 `deferred` にも日付を残す方針へ変えるなら、`$defs/ClosedItemStatus` と `register defer` の双方を同時に変更する必要がある。
- [[specdojo:pjr-rulebook]] の `推奨 Frontmatter 項目` と `index と個別登録項目の同期` は本タスクでは更新していない。rulebook・運用ガイド・テンプレートの更新は [[prj-0001:pjr-rdnc-update-docs-for-ticket-ssot]] の担当範囲のため、そちらで新スキーマの項目定義に合わせる。
