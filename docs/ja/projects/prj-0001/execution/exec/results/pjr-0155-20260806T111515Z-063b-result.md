## 1. 実施内容

PJR-0155「dctカタログの1 domain複数ファイル分割（物理分割）対応」を、個票 [[prj-0001:pjr-0155-dct-domain-multifile]] の完了条件に沿って実装した。

- 設計方針: 分割ファイルは `dct-<domain>-<part>.yaml` とし、各ファイルの `domain` キーは分割前と同一に保つ。論理ドメインは `domain` キーで判定し、ファイル名には依存しない。マージ順序はファイル名の昇順で決定的に定め、ファイル列挙順（OS 依存）に依存しない。
- `src/catalog-build.ts` に、同一 `domain` の複数ファイルを 1 つのドメインカタログへ束ねる仕組みを追加した。
  - `loadCatalogDocs`: `dct-*.yaml` をファイル名昇順で読み込む共通ヘルパー。
  - `mergeDomainCatalogs`: `domain` でグルーピングし、先頭（昇順先頭）ファイルのメタ情報に全パートの `groups` を連結したマージ済みカタログを返す。`project_id` / `base_path` の不一致、パート間の `local_id` 重複を per-domain エラーとして返す。
  - `validateCatalogDomains`: 「domain 重複を一律 ERROR」から「マージ可能性の検証」へ変更（`mergeDomainCatalogs` へ委譲）。
  - `buildCatalog`: 各ファイルを個別に構造検証したうえで `domain` 単位にマージし、`generated/dct-<domain>.md` を 1 つ出力する方式へ改修。構造不正なパートを含む domain は出力をスキップする。
- schema `docs/specdojo/schemas/v1/dct.schema.yaml` の `domain` 説明に、物理分割と同一 domain マージ・整合制約を明記した。
- rulebook `specdojo:dct-rulebook` の「ファイル命名・ID規則」に分割命名を追記し、「記述ガイド」へ `物理分割（1 ドメイン複数ファイル）` を新設した。
- `catalog generate` は各ファイルの `deliverables` を個別に実体化する処理で、domain マージ生成物（`dct-<domain>.md`）を作らないため改修不要と判断した（_ASSUMPTION_ ではなく、生成対象が deliverable 本体である事実に基づく）。判断根拠は個票の対応結果にも記録した。
