# Edit Result

## 1. 実施内容

PJR-TT4J（[[prj-0001:pjr-es57-register-file-ssot-migration]] の分割2）として、register CLI の読み書き先を `pjr-index.md` の表から個票 frontmatter へ切り替えた。完了条件は個票の記載を基準にした。

- 個票 frontmatter を正本として扱う共通モジュール `src/register-item.ts` を新設した。責務は次の3つ。
  - 導出: 表示 ID は個票ファイル名（`pjr-XXXX-<topic>.md`）、タイトルは H1（表示 ID の接頭辞を除いた部分）、説明は最初の `##` 章の段落から導出する。処理状態・分類・優先度・担当・登録日・期限・完了日・結論は frontmatter の登録項目フィールド（[[prj-0001:pjr-rf3b-register-item-frontmatter-schema]] で定義した `item_status` などのキー）から読む。省略キーは一覧表示時に `-` / `_TODO_` へ補う。
  - 走査: 登録簿ディレクトリ直下の個票を ID 昇順で読み、`pjr-index.md` や命名規約外のファイルは除外する。
  - 書き込み: `specdojo:` 名前空間を YAML として読み書きし、値なしはキー削除、キー順は登録項目の並びへ正規化する。日付は引用符付き文字列で出力され、prettier 整形後の表記と一致することを確認した。
- `register add` を個票生成へ変更した。表への行追記を廃止し、全項目が個票を持つ前提になったため `--ticket` を撤去した。タイトルは H1、`--description` は概要段落、その他の項目値は frontmatter へ書き込む。ID 衝突は個票ファイル名と未移行の一覧行の双方から検出する。統合ブランチへの予約経路（`reservePjrIdOnIntegration`）も、登録行ではなく個票1ファイルを作成して commit する形へ変更した（`planReservationRow` を `planReservation` へ置き換え、ID 収集に `collectRegisterItemIds` を追加）。
- 状態遷移（`start` / `wait` / `review` / `close` / `reject` / `defer` / `reopen`）と `update` を個票 frontmatter の更新へ変更した。終端状態ガードなどの遷移検証は既存ロジックを流用し、`reopen` は `completed_on` のキーを削除する。`close` / `reject` に伴う文書成熟度 `status` の昇格・廃止は従来どおり。
- 一覧の読み取りが必要な処理を個票走査へ切り替えた。`register build` の派生ビュー生成、`exec run --register` の対象解決（`resolveRegisterRunTarget`）、`routine` の対象抽出がいずれも `loadRegisterItems` を入力にする。`pjr-index.md` は列見出しの供給元としてのみ読む。
- 移行期の互換として、個票 frontmatter に登録項目フィールドを持たない項目は `pjr-index.md` の行を値として読み、遷移・更新時に行の値ごと個票 frontmatter へ書き出して移行する（オンデマンド移行）。個票ファイル自体が無い項目は書き込み先が無いため、個票作成を促すエラーで中断する。
- `exec run --register` の commit 対象（`registerRunnerManagedPaths` / `registerStatePaths`）に対象個票を追加し、状態遷移の書き込みが commit から漏れないようにした。
- `--dry-run` は、個票のパスと書き込み予定のフィールド（`add` は生成予定の個票内容、予約は作成予定の個票パス）を表示し、ファイルを書き換えない。
