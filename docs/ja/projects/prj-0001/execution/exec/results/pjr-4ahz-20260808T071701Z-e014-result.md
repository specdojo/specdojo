# Edit Result

## 1. 実施内容

PJR-4AHZ「routineでexec resumeからautoを順次実行可能にする」を実装した。個票の完了条件を作業基準とした。

- 設計判断（作業1）: 汎用 `sequence` action ではなく、専用 action kind `exec-cycle` と専用コマンド `exec cycle` を採用した。単一プロセス・単一ロックで固定順序を保証でき、各 step が自身でロックを取り直さないため後続 step の自己 busy skip を避けられる。汎用 sequence は各 step がロックを再取得し、順序設定を再導入するため不採用とした。
- 順次実行制御（作業2）: `exec cycle` は `withProjectExecRunLock`（`commandLabel` に `"cycle"` を追加）で project 実行ロックを run 全体で保持し、その内側で `runResumeMode({ due: true })` → `exec validate` / `exec refresh`（`spawnValidate` / `spawnRefresh`）→ `runBatchMode({ auto: true })` を固定順で実行する。resume / refresh / auto の各 step は自前でロックを取得しないため、一連の処理全体が単一ロックで保護され、step 間に手動実行・別 routine・CI が割り込まない。
- 結果集約と失敗方針（作業3）: `process.exitCode` を step ごとに退避・リセットして step 結果を分離する `takeStepFailure` を実装。resume 失敗（再延期含む）は中断せず継続、validate/refresh 失敗は auto step を中止、auto 失敗は記録のみ。`[cycle] summary: ...` に step 結果を出力し、いずれか失敗で終了コード 1。routine 側はこの終了コードから `last_result` に `failure` を記録し、開始時 busy（`ROUTINE_BUSY_SKIP_EXIT_CODE`）は `skipped` として記録する。再開対象 0 件でも状態再計算と auto 実行へ進む。
- schema / CLI 検証 / dry-run / 互換性（作業4）: `routine.schema.yaml` の `action.oneOf` に `exec-cycle` を追加。`routine.ts` に `RoutineActionKind` の `exec-cycle`、`parseRoutineDoc` の kind 検証と strategy/parallel/loop/max_rounds 検証（exec-auto と共通化）、`buildExecCycleArgs`、`executeRoutine` の dry-run/実行分岐を追加した。既存 `exec-auto` / `exec-resume` / `job` と単独の `exec run` / `exec resume` は変更なしで動作する。`exec cycle --dry-run` は refresh を実行しないため、auto step は `runBatchMode` を呼ばず planned な `exec run --auto ...` を表示する（ready.json 未生成による誤 failure を回避）。
