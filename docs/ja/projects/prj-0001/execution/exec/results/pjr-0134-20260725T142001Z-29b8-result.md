# Edit Result

## 1. 実施内容

PJR-0134「exec run --autoを連続worker pool化」に対応した。

個票の完了条件を基準に、`exec run --auto --loop --parallel <n>` の制御を固定バッチ方式から completion-driven worker pool 方式へ変更した。`--loop` 指定時は、agent が1件完了するたびに root 側の統合処理と `exec build` を直列に実行し、空いた `--parallel` 枠へ次の Ready task を投入する。`--loop` なし、または dry-run は従来どおり開始時に選択した最大 `n` 件だけを実行する経路として残した。

provider capacity は現在実行中の provider 数として管理するようにし、task 起動時に枠を予約、agent 終了後に枠を解放するよう変更した。critical task が rate limit または failure になった場合は新規投入を止め、既に起動済みの task は終了処理まで drain する。

関連文書として [[specdojo-exec-operation-guide|SpecDojo exec運用ガイド]]、[[specdojo-command-reference-guide|SpecDojoコマンドリファレンス]]、[[specdojo-exec-config-guide|実行設定ガイド]]、[[sysd-agent-settings|エージェント共通設定]] を更新した。

exec plan の `freeform` 相当の進め方に従い、登録簿と個票の完了条件を正として作業した。背景は [[prj-0001:pjr-0122|launch trackの振り返り]] の「長時間 agent に引っ張られて次が実行できない」課題、設計根拠は [[sysd-agent-settings|エージェント共通設定]] の責務分担、運用仕様は [[specdojo-exec-operation-guide|SpecDojo exec運用ガイド]] と [[specdojo-exec-config-guide|実行設定ガイド]] を参照した。
