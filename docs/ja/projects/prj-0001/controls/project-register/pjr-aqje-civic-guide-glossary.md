# PJR-AQJE シビックテック入門ガイドに用語の説明とリンクを足す

## 1. 概要

入門ガイドで説明なしに出る epic・todo・起票・完了条件・close・PJR の ID などを、冒頭の用語の表と詳しい文書へのリンクで説明する

## 2. 入力

- 利用者の指摘（2026-11-28）: epic や PJR-CD34 など、いきなり分からない単語が出てくるので説明かリンクが要る
- 対象の読者はプログラムを書かない人を含む小さなシビックテックのチーム
- BXYM（作り方の流れの見直し）とは目的が違うため別の todo にした

## 3. 完了条件

- シビックテック入門ガイドの冒頭（「次に読む文書」の後）に、「この文書で使う言葉」の表を置く。1 語 1 行で、プログラムを書かない人が読んで分かる言葉で説明する。
- 表に入れる語は次のとおり。ガイドに出てくるのに説明のない語がほかにあれば足し、足した語と理由を個票の対応結果に書く。
  - 登録簿の種類: epic、todo、decision、question
  - 作業の進め方: 起票、完了条件、review、close
  - 道具と文書: `exec run`、`ready`、rulebook、agent、オーケストレーター
  - 登録簿の項目の ID（`PJR-` で始まる番号）
- 表の各行から、詳しい説明のある文書（登録簿運用ガイド、実践の型活用ガイド、オーケストレーター運用ガイドなど）へ wikilink を張る。リンク先のない語は、表の説明だけで足りるようにする。
- 2 つの対話の例で、`PJR-AB12` などが登録簿の項目の番号の例だと分かる一文を添える。
- 英語版（`docs/en/`）は変えない。
- `npm run -s lint:md` を通す。
- `CHANGELOG.md` は変えない。個票の対応結果に「CHANGELOG に書く事項」の小節を作り、区分と行の文案を書く。影響がなければ「なし」と書く。
- 迷った点は executor が決め、決めた内容と理由を個票の対応結果と報告の `handoff` に書く。
