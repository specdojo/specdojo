# PJR-KV58 全体概要の Orchestrator の図を直接のデータストアだけに絞る

## 1. 概要

cdfd-overview の Orchestrator の調整の図で、直接読み書きするデータストアを稼働構成・登録簿・実行記録の 3 つに絞り、6 区分の位置をほかの図にそろえ、CLI 経由のデータストアは 5.1・5.2 の区分からの線で表す

## 2. 入力

- PJR-5Q7R では、runner の内部の関数が読み書きするものまで Orchestrator の直接と数え、13 のデータストアに線が引かれた。図は 4558×2004px で、6 区分の位置もほかの図とそろっていない（2026-11-02）
- 利用者の判断: Orchestrator が直接読み書きするのは、稼働構成（参照・記録）、登録簿（参照・記録）、実行記録（参照）。進捗報告は CLI 経由（schedule 系の P-09）。CLI 経由のものは、区分からデータストアへの線で表す（2026-11-03）
- 利用者は、CLI 経由の線を Orchestrator の図に重ねず、5.1・5.2 の図の区分からの線で表す案 A を選んだ（2026-11-03）

## 3. 完了条件

- [[prj-0001:cdfd-overview]] の「Orchestrator の調整」の図で、Orchestrator が直接読み書きするデータストアが、稼働構成（参照・記録）、登録簿（参照・記録）、実行記録（参照）の 3 つだけになっている。6 区分（3.1〜3.6）への指示の線は残す
- 「Orchestrator の調整」の図の 6 区分の位置が、「トランザクションデータの流れ」と「マスタ・構成データの流れ」の図とそろっている。Orchestrator は一番上に置く
- PJR-5Q7R で Orchestrator の直接とされ、今回外したデータストア（Kata、成果物カタログ、スケジュール戦略、定期実行定義、ジョブ定義、実行計画、成果物、評価結果、進捗報告、派生ビュー・索引）について、それを CLI で扱う区分から、そのデータストアへの線が「トランザクションデータの流れ」または「マスタ・構成データの流れ」の図にあることを確かめている。足りない線は足す。データストアごとの区分と、確かめた図・足した線を個票の対応結果に表で記録する
- 個票の対応結果に、Orchestrator が直接読み書きするデータストアの判断の表を、上の範囲に合わせて書いている
- 図の説明は 1 文までとする
- 3 つの図を `d2 --layout elk` で SVG に出力し、並びと大きさを個票の対応結果に記録する
- 「プロセス領域」と「データストア」の表、「詳細 CDFD 一覧」、「凡例（本プロダクト共通）」は変えない。status は変えない（draft のまま）。詳細の CDFD の文書は変えない
- `npm run lint:md`・`npm run lint:d2` と親の検証が通る
