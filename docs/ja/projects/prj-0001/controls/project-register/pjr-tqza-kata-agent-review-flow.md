# PJR-TQZA kata のレビューの流れを agent で人の流れに合わせる

## 1. 背景

kata（rulebook・sample・recipe・template）の人のレビューの前に、agent のレビューで人の流れ（目的の過不足 → 構成 → 読みやすさ → 正しさ → ほかの文書との整合）をできるだけ済ませ、人は案を確かめて採否を決めるだけにしたい（利用者の依頼、2026-11-24）。今の agent のレビューは次の理由でこの流れに届いていない。

- grade は 24 の役割の観点を 1 回でまとめて採点し、観点の多くはプロジェクトの成果物向けで kata に合わない（例: sample に `vp-pm-plan-feasibility`）。
- 採点が甘い。`opr-sample` は 24 観点のうち 20 が満点で 94 点だった。書き手と grade が同じ claude の系統だった（`graded_by: sonnet-review-executor`）。
- review の段（090）の plan は「review は成果物を再評価しない」とし、grade の結果で完了の可否を判断するだけである。
- plan は「確認に用いてよい文書は、宣言された文書だけ」とし、正しさの正本（schema・src・コマンドリファレンス）や同じ系列の文書を読ませず、コマンドで確かめる指示もない。
- 読みやすさ（`vp-ux-readability`）に、利用者の基準の具体的なチェック項目がない。

## 2. 入力

- 利用者のレビューの流れ（2026-11-24）: 文書の目的に沿った過不足ない内容か → 文章の構成が分かりやすいか → 文章が読みやすいか → 内容の正しさ → ほかの文書との整合
- v0.10.0 に入れる（利用者の指定、2026-11-24）

## 3. 検討した選択肢

| 選択肢 | 内容                                                                                                                                                                                                                                        | 利点                                               | 懸念                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------- |
| A      | 人の流れに合わせた 5 段（R1 目的の過不足・R2 構成・R3 読みやすさ・R4 正しさ・R5 整合）を、書き手と別のモデルが段ごとに行い、kata 専用の観点に絞り、人へは段の順の報告と直した案（差分）を渡す。最初に 2〜3 の型で人のレビューと目合わせする | 人の流れと同じ順で、人は案の採否を決めるだけになる | 段が増える分、1 つの型の時間と利用枠が増える |
| B      | 今の grade の観点を kata 向けに絞り、採点の基準を厳しくするだけにする                                                                                                                                                                       | 手間が小さい                                       | 正しさと整合は確かめられないまま残る         |
| C      | 今のまま人が全部をレビューする                                                                                                                                                                                                              | 追加の作業がない                                   | 62 の型の人の確定に時間がかかる              |

## 4. 決定内容

- 案 A を採る。kata の agent のレビューを、人の流れに合わせた 5 段（R1 目的の過不足・R2 構成・R3 読みやすさ・R4 正しさ・R5 整合）にし、書き手と別のモデルが段ごとに行う。
- 観点は kata 専用の組に絞る。R4 は正本（schema・src・コマンドリファレンス）と突き合わせ、R5 は同じ系列の文書・参照先・用語集を読む範囲に入れる。
- 人へは段の順の指摘と直した案（差分）を渡し、agent が迷った点に印を付ける。人は案を確かめて採否を決める。
- 最初に prj-overview・opr・stsd の sample の 3 つで、利用者のレビューと agent の指摘を比べて目合わせする。
- この流れを sample の横串の確認（段 2）のやり方として使う。

## 5. 採択理由

- 利用者のレビューの流れと同じ順にすると、人は探す作業ではなく確かめる作業だけになる。
- 書き手と別のモデルにすると、書き手と同じ見方による見落としを減らせる。
- 正しさと整合は、正本と関連文書を読ませないと確かめられない。
