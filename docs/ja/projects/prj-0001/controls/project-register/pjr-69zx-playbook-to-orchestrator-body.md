# PJR-69ZX 運用メモの一般の知見をオーケストレーターの本文へ移す

## 1. 概要

prj-0001 の運用メモ（`pm-orchestrator-playbook`）には、prj-0001 に限らず、どの利用者のオーケストレーターにも効く知見が溜まっている。配布するオーケストレーターの本文（`.agents/specdojo-orchestrator.agent.md`）へ移し、運用メモには prj-0001 に固有の事柄だけを残す。

## 2. 入力

- 利用者の要望（2026-11-25）: playbook に書いてあることで、orchestrator に反映したほうがよいものを確認して起票する
- オーケストレーターが運用メモと本文を照らした（2026-11-25）。本文にない一般の知見が 10 件ほどある
- 担当と期限は利用者の確認待ち

## 3. 完了条件

- 運用メモの次の知見を、配布するオーケストレーターの本文の該当する章へ、prj-0001 に固有の名前（PJR の ID・agent の名前・パス）を外した一般の形で移す案を作る。

### 5.4. 決めたことと理由

- 移す先の章: 別の project への起票と MD034 は「登録簿（register）の使い方」、再開の 4 件は「止まったときの対処」の表の後の箇条書き、close の前の 2 件は「close の前の確かめ方」、完了条件の 3 件は「完了条件の書き方」とした。表へ行を足すと既存の列の幅が変わり差分が大きくなるため、再開の 4 件は表に入れず箇条書きにした。
- `register_sync` の書き方: 本文に設定の細部を写すと設定リファレンスと二重になるため、専用ブランチへ commit・push されることと、登録簿運用ガイド・設定リファレンスを確かめることだけを書いた。
- 第 4 章の qwen の制限（検査・削除を伴わない文書だけ）と terra の用途: オーケストレーターの長く効くメモ（利用者の決定の記録）に基づいた。運用メモへ書いた根拠の個票は見つからなかったため、反映の前に利用者が確かめる。
- reporter の既定: routing（gemma26、代わりは sonnet-reporter）のままとし、PJR-Q723（done）で代わりの reporter への自動のやり直しが入ったため、列の例から固定の指定を外した。

### 5.5. CHANGELOG に書く事項

- 区分: 変更
- 行の文案: オーケストレーターの指示に、別の project への起票、再開の前の追加の指示（`--resume-note`）と止まったときの直し方、close の前の確かめ方、完了条件の書き方（CHANGELOG の推奨の方式・読むだけの文書を名前で書くことなど）を足した。
- 備考: 本文の変更案の反映が入った版に載せる。反映しない場合は『なし』とする。
