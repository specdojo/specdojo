# PJR-05QS 全体概要の図から Orchestrator を外して表にし、線をまとめる

## 1. 概要

cdfd-overview の 2 つの図から Orchestrator のノードと線を外して調整の表にまとめ、同じ区分とデータストアの間の線を 1 本にまとめてラベルを短くし、章の参照をタイトルにする

## 2. 入力

- PJR-PZ6H で 7 区分と一対一のノードの 2 つの図にしたが、今までの受け渡しをまとめずに移したため線が多く、図は 5028×3238px と 6004×2374px で文書の幅ではラベルが読めない。Orchestrator からの要求と応答の線が図の上半分を占めている（2026-11-02）
- 利用者は、Orchestrator を図から外して表にするのが妥当と判断した（2026-11-02）
- 説明の文で「第 3 章」「第 7 章」と番号で章を参照していて、Markdown の規則に反している

## 3. 完了条件

- [[prj-0001:cdfd-overview]] の「トランザクションデータの流れ」と「マスタ・構成データの流れ」の図から、Orchestrator（`P-14`）のノードと、Orchestrator につながる線をすべて外している。図のプロセスのノードは 3.1〜3.6 の 6 区分になる
- 「概念データフロー（概要）」に「Orchestrator の調整」の表がある。図から外した Orchestrator の要求と応答（相手の区分、渡す・受け取るもの）と、Orchestrator が読み書きするデータストア（実行記録、定期実行定義、ジョブ定義、成果物カタログ、スケジュール戦略、稼働構成など）を、行にまとめる。表は端的にし、同じ相手への要求と応答は 1 行にまとめる
- 同じ区分と同じデータストアの間で同じ向きの線が複数ある場合は、1 本にまとめている。ラベルは代表的な名詞の 1〜2 語にする（例: 「実行状態・実行結果・完了記録（Job を含む）」は「実行記録」）
- 外した線とまとめた線を除き、区分とデータストアの間の受け渡しは残す。今の図の線との対応（残した、まとめた、表へ移した）を個票の対応結果に表で記録する
- 2 つの図とも、6 区分のノードの位置をそろえ、上から 3.1、3.2〜3.4、3.5、3.6 の順に並べている。`d2 --layout elk` で SVG に出力し、並びと図の大きさ（幅×高さ）を個票の対応結果に記録する。図の大きさは今（5028×3238px、6004×2374px）より小さくする
- 本文で章や節を番号だけで参照している箇所（「第 3 章」「第 7 章」など）を、章・節のタイトルで参照する形に直している
- 「プロセス領域」の章の表（3.7 Orchestrator を含む）、「データストア」の表、「詳細 CDFD 一覧」、「凡例（本プロダクト共通）」は変えない。status は変えない（draft のまま）。詳細の CDFD の文書は変えない
- `npm run lint:md`・`npm run lint:d2` と親の検証が通る
