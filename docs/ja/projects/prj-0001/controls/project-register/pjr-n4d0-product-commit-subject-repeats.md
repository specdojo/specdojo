# PJR-N4D0 同じ項目を何回か流すと、プロダクトの commit のタイトルがすべて同じになる

## 1. 課題内容

`exec run --register --worktree` がプロダクトリポジトリに作る commit の 1 行目は、項目のタイトルから作られる（`commit_subject_template` の `{title}`）。同じ項目を `--force-restart` や `--resume` で流し直すと、回ごとに中身の違う commit がすべて同じタイトルになる。

利用側の例では、1 つの項目を 4 回流して、次のように同じタイトルの commit が 4 つ並んだ。

```text
4ae1587 feat: テストのレポートの Markdown をサマリーと集計だけにし、詳細を CSV に分ける
1cd3cb7 feat: テストのレポートの Markdown をサマリーと集計だけにし、詳細を CSV に分ける
f330c8f feat: テストのレポートの Markdown をサマリーと集計だけにし、詳細を CSV に分ける
b583aa6 feat: テストのレポートの Markdown をサマリーと集計だけにし、詳細を CSV に分ける
```

実際の中身は、「集計を冒頭に置き、CSV の行を決まった順にする」「unit の結果を、状態機械の遷移を記録する設定で取る」「各節を結論の文から始め、注記に分ける」のように回ごとに違った。プロダクトの履歴は上流へ pull request として出すため、利用者が push の前に `git rebase -i` の `reword` で 6 つのタイトルを書き直した。

## 2. 入力

<!-- 対話で得た前提・制約・委任範囲を記録する。完了・回答の判定条件とは分ける。 -->

- 利用側（OpenFisca-Japan の作業の project。`repos` でプロダクトリポジトリを宣言している）で、specdojo 0.9.2 を使って見つけた。
- プロダクトの `commit_subject_template` は `{type}({scope}): {title}`（scope は空）を使っている。
- 2 回目からの run は、前の回の review の指摘や追加の要求を受けて、`--force-restart` で新しい run として流している。

| スケジュール | _TODO_                                                                                                                                                 |

| 関係者       | プロダクトリポジトリの履歴を上流へ出す利用者、上流のレビュアー                                                                                         |

## 4. 対応方針

| 項目     | 内容                                                                                                                                                                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原因     | 1 行目が、回ごとに変わらない項目のタイトルだけから作られる                                                                                                                                                                                                                                                                          |
| 対応策   | _UNDECIDED_: 回ごとに違う 1 行目にする方法を決め、理由を対応結果に書く。案: (a) 2 回目からは、executor の報告の要約（その回に何をしたか）を 1 行目に使う。(b) `commit_subject_template` に、その回の要約を表す置き換え（例: `{summary}`）を足し、利用者が選べるようにする。(c) 2 回目からは、タイトルのあとに回を区別する語を付ける |
| 依存事項 | なし                                                                                                                                                                                                                                                                                                                                |
| 完了条件 | 下の箇条書きのすべてを満たす                                                                                                                                                                                                                                                                                                        |

- 同じ項目を 2 回流したとき、プロダクトの commit の 1 行目が回ごとに区別できる（テストで確かめる）。
- 1 回だけの run の 1 行目は、今のまま項目のタイトルから作られる（テストで確かめる）。
- 設定リファレンスの `commit_subject_template` の節に、流し直したときの 1 行目を書く。
- 末尾の `Refs:` の行は今までどおり付く。
- `CHANGELOG.md` は未公開の版の節に書き、公開済みの版の節を変えない。
