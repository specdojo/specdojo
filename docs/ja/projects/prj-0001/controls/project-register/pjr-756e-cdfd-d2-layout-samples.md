# PJR-756E CDFD の D2 の記法と 3 つの sample を、囲み・担当のレーン・時系列で描き直す

## 1. 概要

PJR-DM1N の決定に沿って cdfd-d2-rulebook に図の種類ごとの描き方を足し、cdfd-overview-sample・cdfd-sample・cdfd-uc-sample の図を描き直す

## 2. 入力

- PJR-DM1N で、全体概要は業務のまとまりの囲み、プロセスグループ別は担当ごとのレーンと受け渡しの番号、ユースケース別は `sequence_diagram` で描くと決めた（indie、2026-11-28）
- まず型の sample から直す。製品の CDFD は sample の形が決まってから PJR-T1D1 でそろえる（indie、2026-11-28）
- 担当 BA・期限 2026-12-31 は indie の指示（2026-11-28）

## 3. 完了条件

- PJR-DM1N の決定に沿って、`cdfd-d2-rulebook` に図の種類ごとの描き方を足す。
  - 全体概要: 業務のまとまりごとにコンテナで代表ノードを囲む。全体概要でグループを囲むことの禁止は、まとまりの囲みに限って外す（グループ自体をコンテナで表すことは引き続き禁じる）。
  - プロセスグループ別: 担当（人・システム・外部主体）ごとに一番外のコンテナでレーンを作り、プロセスを担当のレーンに置く。受け渡しのラベルの先頭に手順の番号（「1.」「2.」）を付ける。
  - ユースケース別: D2 の `shape: sequence_diagram` で、参加する単位を縦の線に、受け渡しを上から順の矢印で描く。開始と終了の出来事の表し方を決めて書く。
  - 決まりに合わせ、レーンの順・番号の付け方・凡例の書き方と、禁止事項の表を直す。
- 主の CDFD の rulebook（`cdfd-overview-rulebook`・`cdfd-rulebook`・`cdfd-uc-rulebook`）で、図の描き方に触れる記述があれば、`cdfd-d2-rulebook` と食い違わないように直す。
- 3 つの sample（`cdfd-overview-sample`・`cdfd-sample`・`cdfd-uc-sample`）の D2 の図を、上の描き方で描き直す。業務の中身（駄菓子屋の文脈、プロセス・イベント・データストア・受け渡しの ID と表）は変えず、図だけを直す。表と図の対応は保つ。
- `npm run lint:d2` と `npm run -s lint:md` を通し、親の検証を通す。
- 文書サイトで 3 つの図を見て、indie が読みやすさを確かめてから close する。直す点が出たら、この todo の完了条件に回目として足す。
- `cdfd-mermaid-rulebook` と製品の CDFD は変えない（製品は PJR-T1D1 でそろえる）。
- `CHANGELOG.md` は変えない。個票の対応結果に「CHANGELOG に書く事項」の小節を作り、区分と行の文案を書く。
- 迷った点は executor が決め、決めた内容と理由を個票の対応結果と報告の `handoff` に書く。

## 5. 対応結果

### 5.1. 実施内容

- `cdfd-d2-rulebook` に「図の種類ごとの描き方」を足した。全体概要は業務のまとまりのコンテナ（`area`）、プロセスグループ別は担当のレーン（`lane`）・記録・保管（`store_area`）・受け渡しの手順番号、ユースケース別は `shape: sequence_diagram` で描く。あわせて、全体方針の概念表・本文構成の表・エッジ・凡例と可読性・最小限スタイル・禁止事項（理由付きの表）を直した。
- `cdfd-overview-rulebook` は、グループ・区分をコンテナで表す禁止を残したまま、D2 で二つ以上の代表ノードを業務のまとまりで囲むことを認め、禁止事項の表も同じ例外にした。`cdfd-rulebook` にはレーンと手順番号への参照を、`cdfd-uc-rulebook` には `sequence_diagram` での描き方を足し、D2 の `direction: down` と `a <- b` の記述を置き換えた。
- 3 つの sample の図を描き直した。業務の中身（ノード、受け渡しのラベル、ID、表）は変えていない。
  - `cdfd-overview-sample`: 仕入・販売・在庫を「商品の流れ」、顧客・締めを「つけと締め」で囲んだ。章冒頭にまとまりを書き、凡例に囲み・レーン・記録・保管・番号の読み方を足した。
  - `cdfd-sample`: P-01・P-02 の図を担当のレーンに分け、全受け渡しに手順番号を付けた。P-02 の図直後の注記には、受入品の経路（14〜19）と返品の経路（20〜26）を書いた。
  - `cdfd-uc-sample`: 通常の図と例外時の戻りの図を `sequence_diagram` にした。
- `cdfd-mermaid-rulebook`・製品の CDFD・`CHANGELOG.md` は変えていない。

### 5.2. 決めた点と理由

- レーンは D2 の `grid-rows` で横の帯にせず、`direction: down` の ELK 配置で、担当の囲みを見えない線の順に上から並べた。`grid-rows`・`grid-columns` の帯を `d2` v0.9.0 で試したところ、セルをまたぐ線が直線で引かれ、ほかのノードやレーンを横切った。ELK なら線が直角に曲がって引かれる。帯の形が要るかどうかは、indie が文書サイトで確かめて決める。
- データストアと物理保管は担当ではないため、レーンに入れず、一番下の「記録・保管」（破線の枠）にまとめた。外部主体と他グループ（在庫グループ・販売グループ）は、その主体のレーンに置いた。
- イベントは出来事を起こした担当のレーンに置き、条件の成立のように起こした担当を決められない出来事は、起動するプロセスのレーンに置いた。例: 「仕入記録確定後に返品対象がある」は店主代表のレーンに置いた。
- 手順の番号は一本の線に一つ振り、データストアの参照・更新と起動条件も数えた。分岐した後は経路ごとにまとめて続きの番号を振り、範囲を注記に書いた。
- 「家族利用者代表（管理責任: 店主代表）」のプロセスは、作業する側の家族利用者代表のレーンに置いた。担当はレーンで表すため、プロセスの表示ラベルに `（担当: …）` を付ける決まりを外した。
- ユースケース別の開始・終了の出来事は、一番左・一番右の六角形の縦の線にした。D2 の sequence diagram のノートは六角形にならない（試した結果）ため、ノートは使わない。縦の線の並びは、開始・参加単位・データストアと物理保管・終了の順にした。sequence diagram では上からの並びが順序を表すため、手順の番号は付けない。
- 全体概要のまとまりの名前（「商品の流れ」「つけと締め」）は、図の描き方として新たに付けた。一つのグループだけを囲むまとまりは作らない決まりにした。

### 5.3. 残課題

- template（`cdfd-overview-template`・`cdfd-template`・`cdfd-uc-template`）と recipe は、この todo の範囲外として変えていない。`cdfd-uc-template` の D2 の骨組みは `direction: down` のままで、rulebook の `sequence_diagram` と食い違う。`cdfd-template` にもレーンと番号の骨組みがない。別の todo でそろえる。
- 作業内容 4（親の検証）と 5（indie が文書サイトで確かめる）は未了。

### 5.4. CHANGELOG に書く事項

- 区分: 型と文書
- 行の文案: CDFD の D2 記法ルールに図の種類ごとの描き方を足しました。全体概要は業務のまとまりで囲み、プロセスグループ別は担当のレーンと受け渡しの手順番号で、ユースケース別は `sequence_diagram` で描きます。全体概要・プロセスグループ別・ユースケース別の rulebook と 3 つの sample をこの描き方に合わせました（PJR-DM1N、PJR-756E）。
