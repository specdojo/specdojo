# PJR-Y5RD kata による理解の負債の解消で、シビックテックを持続可能にする位置づけとする

## 1. 背景

SpecDojo は OSS として広め、シビックテックを持続可能にすることを目指す（[[prj-0001:prj-overview|プロジェクト概要]] の CH-01・BV-03）。2026-11-23 の位置づけの見直し（PJR-36QG の `3.16.`）では、価値の中心を「kata による成果物の標準化」と「プロダクトから分けた環境での記録と継続」に寄せた。BMAD・Spec Kit・Kiro などの競合は主に「AI で速く作る」を解いており、シビックテックで先に詰まる「作った後に理解が失われ、引き継げなくなる」問題（理解の負債）を正面から扱うものは少ない。AI がコードを速く書くほど、この負債は速くたまる。

## 2. 入力

- 利用者の意図（2026-11-23）: SpecDojo を OSS で広めたい。prj-overview のとおり、シビックテックを持続可能にするために、kata による理解の負債の解消を目指す。kata が整備できれば、理解の負債がある人や agent でも仕様や要件を復元して中身が分かるようになる

## 3. 検討した選択肢

| 選択肢 | 内容                                                                            | 利点                                                            | 欠点                                                                      |
| ------ | ------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| A      | 仕様駆動開発のツールとして、競合と同じ土俵で機能を比べて広める                  | 説明が分かりやすい                                              | BMAD・Spec Kit・Kiro などの後ろ盾のある競合と、速さや機能の量で比べられる |
| B      | kata による理解の負債の解消で、シビックテックを持続可能にすることを中核に据える | 競合と別の場所に立てる。prj-overview の CH-01・BV-03 と一致する | 「理解の負債が減った」ことを示す測り方と実証が要る                        |

B を採る（利用者の決定、2026-11-23）。

## 4. 決定内容

SpecDojo の位置づけを「kata による理解の負債の解消で、シビックテックを持続可能にする」とする。

- 理解の負債を抱えた人や agent でも、kata（rulebook・sample・recipe）に沿って、既存のコードや断片的な記録から仕様と要件を決まった形で復元できるようにする。
- コードから戻せるのは主に「何をしているか」で、当事者の困りごと・設計の理由・対象外の判断などの「なぜ」は戻らない。agent がもっともらしく埋めると、分かったつもりの仕様ができて負債が見えにくくなる。そこで、次の流れ全体を中核にする。

| 段       | 内容                                                               |
| -------- | ------------------------------------------------------------------ |
| 復元     | kata に沿って、既存のコードや記録から仕様と要件を起こす            |
| 確認状態 | 起こした内容のうち、根拠で確かめられた部分と推測の部分を分けて示す |
| 人の確定 | 推測の部分を、当事者や経験者が確かめて確定させる                   |
| 記録     | 以後の「なぜ」を登録簿に残し、最初から失わない                     |

- 最初の実証の場は OpenFisca-Japan（project-inclusive、既存の OSS の改修で外部の PR とレビューを伴う）とする。
- 後続の項目: シビックテック向けの入門の型の組と導入ガイド、理解の負債の測り方（引き継ぎのテスト）と OpenFisca-Japan での試行、v0.10.0 の後の普及の計画、確認状態を成果物に持たせる方法の検討。

## 5. 採択理由

- 「仕様駆動開発のツール」より、「シビックテックの理解の負債をなくす」のほうが、競合と別の場所に立てる。
- 少人数で入れ替わりのある活動では「前の人に聞く」ができないことが多く、型が聞く代わりになる（BV-03 無理のない継続）。
- 復元だけでは推測が正本に紛れるため、確認状態と人の確定を組にすることで、復元した仕様を信頼できる共同資産にできる。これは、既存実装から仕様を復元して根拠と確認状態を記録する、という Continuous Specification Engineering の検証の条件とも重なる。
- OpenFisca-Japan は、それ自体がシビックテックの既存の OSS で、実際の利用がすでにある。
