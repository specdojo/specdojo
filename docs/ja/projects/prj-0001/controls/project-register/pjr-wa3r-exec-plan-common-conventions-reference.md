# PJR-WA3R exec の plan の共通の規約を本文への差し込みから参照へ改める

## 1. 背景

exec の plan は、共通の規約（記法・成果物規約）を `docs/ja/specdojo/templates/` の断片から作るたびに本文へ差し込む（`injectCommonConventions`）。差し込みにしたのは、agent に plan の本文が標準入力で渡されるだけで、`.github/instructions/` は Claude・Copilot にしか届かないため、どの agent にも確実に届くのが plan の本文だけだったからである。

2026-10-17 時点で、register の plan（例: PJR-Y79W の plan、99 行）のうち「共通: 記法・成果物規約」が 38 行と約 4 割を占める。plan は履歴として残り、`docs/ja/projects/prj-0001/execution/exec/plans/` は 808 ファイル・12 MB ある。利用者から、異常終了の条件や共通の規約を別ファイルにして参照する提案があった（2026-10-17）。

## 2. 検討した選択肢

| 選択肢 | 内容                                                                           | 利点                                  | 欠点                                                         |
| ------ | ------------------------------------------------------------------------------ | ------------------------------------- | ------------------------------------------------------------ |
| A      | 今のまま差し込む                                                               | どの agent にも確実に届く             | plan の約 4 割が毎回同じ内容で、履歴が膨らみ、本文が埋もれる |
| B      | すべてを参照にし、plan にはパスだけを書く                                      | plan が短くなり、規約の版が明確になる | agent が読まずに進めるおそれがある                           |
| C      | 守らないと失敗に直結する要点と異常終了の条件だけを本文に残し、詳細を参照にする | B の欠点を抑えつつ plan を短くできる  | 要点と詳細を二重に管理する                                   |

## 3. 決定内容

選択肢 C を採る（2026-10-17、利用者が承認）。

1. plan の本文には、異常終了の条件（タスクごとの終わり方の約束）と、共通の規約のうち守らないと失敗に直結する要点（成果物のリンクの書き方など、数行）を残す。
2. 共通の規約の詳細は、plan から参照する別ファイルにする。plan には、作業を始める前にそのファイルを読むことと、パスを書く。
3. 参照するファイルは、agent が worktree の中から読める場所に置く。利用者のリポジトリでは原本が `node_modules/specdojo/` の中にあるため、worktree から読めるかを確かめ、読めない場合は runner が worktree に置く。
4. 要点と詳細の原本は 1 か所にし、要点は詳細から機械的に取り出すか、要点の断片を別に持つ。どちらにするかは実装で決めて記録する。
5. 既存の plan（履歴）は書き換えない。

## 4. 採択理由

- どの agent もファイルを読めるため、パスを指定すれば、以前の差し込みの理由（ツールによって届かない）は解消できる。
- 失敗に直結する数行を本文に残すことで、agent が参照を読まなかった場合の影響を抑えられる。
- plan が短くなり、タスク固有の内容が読みやすくなる。
