# PJR-K4PM 入力情報と出力情報に直した clis の型を確定する

## 1. 背景

PJR-025M で、clis の入出力をファイルに限らず入力情報と出力情報に分けて書く形に直すと決めた。PJR-1K77 で直した clis の型を人が確かめて確定する。確定した型で、カタログの付け替え（PJR-8J47）と clis の代表の作成を進める。

## 2. 入力

- 型の確定は人が行う（PJR-025M と同じ扱い）。

## 3. 検討した選択肢

| 選択肢       | 内容                                                                                                | 利点                                                                               | 懸念                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 確定         | 入力情報と出力情報に直した clis の型を確定する                                                      | 手戻りがない                                                                       | 自システムの API と、CLI が起動する外部コマンドの参照先がない。図が個々の仕様を並べ、ifx-cmd との違いが分かりにくい |
| 直す（採用） | 図は入力情報の仕様・出力情報の仕様への線だけにし、参照先の表に自システムの API と外部コマンドを足す | clis と ifx-cmd の違いが図で崩れない。CLI が呼ぶもの・起動するものの正本が漏れない | clis の型をもう一度確定する手間がかかる                                                                             |

## 4. 決定内容

「直す」を採る。

- 位置づけの図は、sf → clis、clis → コマンドリファレンス（構文・引数の正本参照）、clis → 入力情報の仕様・出力情報の仕様（中身の正本参照）だけにする。ifx-cmd・ファイル・ifx-api の個別の箱は図から外す。
- clis と ifx-cmd の違いは、全体方針と役割分担の文で示す（clis は利用者がシステムを操作する側、ifx-cmd はシステムが外部を呼ぶ側）。
- 入力と出力の要点の規則で、参照する正本を種類ごとに書く。ファイルはその rulebook か schema、外部システムの API は ifx-api、自システムの API はシステム設計の索引（sysd-index）が案内する内部 API の定義（まだない段階では名前と用途だけ）、CLI が起動する外部コマンドは ifx-cmd（渡すものは出力情報、受け取る結果は入力情報）。
- sample に、外部コマンドを起動する例を足す。

## 5. 採択理由

- ifx-api は外部システムとの連携の型で、自システムの API は対象外である。
- CLI が外部コマンドを起動すること（SpecDojo の exec run が AI provider CLI を起動するなど）があり、その中身の正本は ifx-cmd である。
- 図に ifx-cmd を参照先として線で結ぶと、clis と ifx-cmd が別物であることがかえって分かりにくくなる（indie の指摘、2026-11-08）。
