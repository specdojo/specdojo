# PJR-ANKZ 移行テスト計画（ntp）とリハーサル計画（mtp）の型を 1 つにまとめるか決める

## 1. 背景

ntp-rulebook（移行テスト計画（リハーサル計画））と、カタログの mtp-index が使う mtp-rulebook（リハーサル計画）は題材が同じで、型が二重になっている疑いがある。

orchestrator の比較（2026-11-18）: ntp-rulebook の全体方針は「移行リハーサルの実施計画を定義し、切替前に妥当性を検証する（テスト範囲・シナリオ・環境・判定基準・是正計画）」。mtp-rulebook は同じ移行リハーサルの計画と評価基準を、回数・環境とデータの準備・検証観点・合否基準・差異の扱い・GO/NO-GO の判断まで定めている。

## 2. 入力

- orchestrator の調べ（2026-11-18）: ntp-rulebook の題は「移行テスト計画（リハーサル計画）作成ルール」。カタログの dct-migration-planning の mtp-index は mtp-rulebook を使い、概要は「切替前に成果物カタログ・Schedule・登録簿が実運用に耐えるかを検証するリハーサル計画」。ntp は決まるまで kata-slim-2 の対象外

## 3. 検討した選択肢

| 選択肢    | 内容                                                                 | 利点                                                                                                                                                                                                                      | 懸念                                                                             |
| --------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| A（推奨） | ntp の型（rulebook・sample）を非推奨にし、後継を mtp-rulebook にする | mtp-rulebook（354 行）は移行リハーサルの回数・環境・検証観点・合否基準・差異の扱い・GO/NO-GO まで定め、カタログの mtp-index も使っている。ntp-rulebook（62 行）は章の見出しと一般的な指示だけで、mtp にない判断を持たない | ntp を使っている利用者がいれば移行の案内が要る（prj-0001 には ntp の文書がない） |
| B         | ntp を mtp の個別文書（`mtp-<term>`）の型として残し、役割を分ける    | 型の名前を変えずに済む                                                                                                                                                                                                    | mtp-rulebook がすでに `mtp-<term>` の作り方を定めており、二重になる              |
| C         | 2 つとも残し、kata-slim-2 で別々に簡潔にする                         | 今の構成を変えない                                                                                                                                                                                                        | 同じ題材を 2 つの型で磨く手間が二重になり、利用者がどちらを使うか迷う            |

## 4. 決定内容

A を採る。移行テスト計画（ntp）の型（rulebook・sample）を非推奨にし、後継を mtp-rulebook（リハーサル計画）とする。新しい `ntp-<term>` は作らない。

## 5. 採択理由

- mtp-rulebook は移行リハーサルの回数・環境・検証観点・合否基準・差異の扱い・GO/NO-GO まで定め、カタログの mtp-index も使っている。
- ntp-rulebook は章の見出しと一般的な指示だけで、mtp にない判断を持たない。
- prj-0001 に ntp の文書はなく、移行の対象がない。
