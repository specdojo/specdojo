# PJR-C11R register の run の変更範囲が docs 全体と読まれて並べられない

## 1. 課題内容

個票の本文の docs/ などの語から project:docs と読まれ、ほかの docs を変える run とすべてぶつかる

## 2. 入力

- 利用者の決定（2026-11-23）: オーケストレーターの推奨どおり起票する
- v0.10.0 に入れる（利用者の指定、2026-11-24）

## 3. 影響範囲

| 観点         | 影響                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| スコープ     | register / schedule 共通の変更範囲推定、単体テスト、設計・運用文書                         |
| スケジュール | v0.10.0。統合後の動作確認を close 前に実施する                                             |
| コスト       | 外部サービス・追加依存なし。動作確認の agent 実行は統合後に行う                            |
| 品質         | 本文の上位ディレクトリによる不要な待機を防ぎ、明示対象・glob・同一ファイルの排他を維持する |
| 関係者       | DEV が実装、runner が親検証、orchestrator が統合後の smoke と close 判断を行う             |

## 4. 対応方針

| 項目     | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 原因     | 個票の本文の上位のディレクトリだけの語（docs/ など）から、変更範囲を docs 全体と読む |
| 対応策   | 上位のディレクトリだけの語を範囲にせず、範囲が広すぎるときは警告する                 |
| 依存事項 | なし                                                                                 |
| 完了条件 | 下の箇条書きのすべてを満たす                                                         |

- `exec run --register` の変更範囲の予約が、個票の本文の `docs/` などの語から `project:docs`（docs 全体）と読まれ、ほかの docs を変える run とすべてぶつかって並べられない。2026-11-23 の PJR-E73Z は、ほかの run の予約とぶつかって 3 回始まらず、PJR-EF4Z も E73Z の統合を待った。
- 個票の本文から範囲を読むときに、`docs/`・`src/` のような上位のディレクトリだけの語を範囲にしない（または、より狭い語があればそちらを使う）。範囲が広すぎるときは、予約の前に警告を出す。読み方を変えたときに、今まで防げていた衝突を見逃さないことを確かめる。
- 単体テストを足す（上位のディレクトリだけの語、狭い語との組み合わせ）。
- 関連する設計・ガイド・CLI リファレンスを直す。
- runner の動きを変える場合は、統合の後に orchestrator が `exec smoke` を流して確かめてから close する。
- `npm run typecheck`・`npm run lint:ts`・`npm run test:unit` を通し、親の検証を通す。
- `CHANGELOG.md` は変えない。個票の対応結果に「CHANGELOG に書く事項」の小節を作り、区分と行の文案を書く。影響がなければ「なし」と書く。
- 迷った点は executor が決め、決めた内容と理由を個票の対応結果と報告の `handoff` に書く。
- 保護された設定（`.specdojo/`・`.agents/`・`.claude/`・`.codex/`・`.opencode/`・`package.json` など）は変えない。変更が要る場合は、変更案を個票の対応結果と報告の `handoff` に書く。

## 5. 対応結果

### 5.1. 作業内容と確認

| 作業内容                           | 状態 | 実績・確認                                                                                                                                                                             |
| ---------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 範囲推定と予約前の警告             | done | 本文の上位ディレクトリ・repo ルートだけの語を除外。明示対象と glob の広い予約は維持し、除外・維持の両方を標準エラーへ警告する                                                          |
| 衝突検知の回帰テスト追加           | done | 上位語だけ・狭い語との併記、repo 修飾・正規化、同一ファイル待機、明示対象・glob・下位ディレクトリの重複、不明範囲の直列化を追加。単体テスト・型検査・lint は親 runner の検証で実行する |
| 設計・ガイド・CLI リファレンス更新 | done | 除外する本文表現、全体を予約する指定方法、警告と不明範囲の扱いを記載した                                                                                                               |
| 統合後の `exec smoke`              | open | 統合後の build と実 agent の起動が必要なため executor では実行しない。orchestrator が PJR-C11R を対象に smoke を実施し、成功を確認してから close する                                  |

### 5.2. 判断と申し送り

- 本文の候補を正規化した後、repo ルートまたは上位ディレクトリ 1 要素だけの表現を除外する。ディレクトリ構文または実在するディレクトリであることを確認し、拡張子のないルートファイルも維持する。`docs/` と個別パスが併記されていても、狭いパスだけを残す。`targets` / `target_path` と glob は変更意図の明示と判断し、全体の予約を維持する。下位ディレクトリやファイルの排他規則は変えない。
- 上位語だけで範囲が空なら既存の不明範囲とする。狭いパスが残ればそれを予約する。全体の変更が必要なら明示対象か glob を指定し、不明範囲も待機させる運用では `--unknown-scope serialize` を使う。既定の `parallel` は維持した。
- 警告は推定時に候補ごとに重複を除いて出し、範囲予約より前に確認できるようにした。保持済みの未統合予約は従来どおり残すため、旧 runner の広い予約が残っている場合は先行項目を再開・統合する。
- 保護された設定の変更は不要。result の記入と親検証は reporter / runner に引き継ぐ。
- executor の確認では Prettier、登録簿の生成、カタログ検証、履歴リンク検証、差分の空白検査が成功した。カタログ検証は既存の re-export 参照・未作成文書などに警告を出すが、エラーはない。
- 統合後は build し直し、orchestrator が `exec smoke --project prj-0001 --register PJR-JSEY --targets PJR-C11R --executor-by <executor> --reporter-by <reporter>` を新しいプロセスで実行してから close する。

### 5.3. CHANGELOG に書く事項

- 区分: 不具合修正
- 文案: register / schedule の変更範囲推定で、本文の `docs/`・`src/` などをディレクトリ全体の予約と誤認して並列実行を妨げる問題を修正。広すぎる本文の候補と、明示対象・glob による広い予約を予約前に警告する。
