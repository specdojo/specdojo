# PJR-T2X5 v0.10.0 の後も機能改善を続け、v1.0 まで破壊的な変更をしない

## 1. 背景

- PJR-6XYD の入力と完了条件で、v0.10.0 の後は機能追加をいったん止める期間にすると決めていた（利用者の承認、2026-11-24）。PJR-BHJM は英語版をその例外として扱っていた。
- 利用者の判断（2026-11-25）: 機能改善はまだ必要なため、止める方針は撤回する。利用者には新しい版へ順次上げてもらい、その代わりに破壊的な変更をしない約束を置く。
- v0.10.0 で、agy の対応の削除と、0.9.2 で非推奨にした 9 コマンドの削除という大きな破壊的変更は済んでいる。

## 2. 入力

- 利用者の判断（2026-11-25）: 機能改善はまだ必要なため、止める方針を撤回し、利用者には逐次 update してもらう
- 利用者の判断（2026-11-25）: 期限は v1.0 まで。ルールはオーケストレーターの推奨どおり

## 3. 検討した選択肢

| 案        | 内容                                                    | 利点                                         | 欠点                                     |
| --------- | ------------------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| A         | v0.10.0 の後は機能追加を止める（PJR-6XYD の当初の方針） | 利用者の環境が変わらない                     | 試しで見つかった改善も出せない           |
| B（採用） | 機能改善は続け、v1.0 まで破壊的な変更をしない           | 改善を順次届けられる。上げる側の負担が小さい | 変える前に非推奨の期間を置く手間が増える |
| C         | 機能改善を続け、破壊的な変更も minor の版で許す         | 変えやすい                                   | 利用者が上げるたびに移行の手間を負う     |

## 4. 決定内容

- v0.10.0 の後も機能改善を続ける。利用者には `npx specdojo update` で新しい版へ順次上げてもらう。PJR-6XYD の「機能追加をいったん止める期間」の方針は撤回する。
- v1.0 まで、次の 5 つを利用者との約束として破壊的な変更をしない。
  - CLI: コマンドとオプションの削除・改名、終了コードの意味
  - 設定: `specdojo.config.json`・`exec-defaults.yaml`・`agent-members.yaml` のキー
  - 記録の形: 個票・イベント・strategy・track・frontmatter の schema と置き場所
  - 型: kata の id と、rulebook が求める必須の章（利用者の文書が grade や検査で落ちる変更）
  - 生成物: 利用者がリンクする生成ページの場所
- 足すこと（新しいコマンド・任意のキー・任意の欄）は自由とする。消す・変えるときは先に非推奨にし、警告を出して動く期間を少なくとも 1 つの minor の版のあいだ置く。
- どうしても壊す必要があるときは、版を決めて予告し、`CHANGELOG.md` の「移行の注意」と `update` で移行の道を用意する。

## 5. 採択理由

- オンボーディング（PJR-F636）や実際のプロジェクトでの試し（PJR-Q5YP）で見つかる改善を、止めずに届けられる。
- 大きな破壊的変更は v0.10.0 で済んでおり、約束を置くのに良い時期である。
- 期限を日付でなく v1.0 で区切ると、守る側と利用者の双方に分かりやすい（利用者の判断）。
