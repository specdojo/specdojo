# PJR-52EE 実行を見張り、失敗の種類に応じて再開するか止めるかを決める仕組みを用意する

## 1. 概要

負荷の時間切れや上限は自動で再開し、判断が要る失敗だけを止めて知らせる（orchestrator の夜間の見張りの置き換え）

## 2. 入力

- 2026-11-12〜13 の型の整備と夜間の実行で、orchestrator が手作業やシェルスクリプトで補った

## 3. 完了条件

- 実行中・延期・中断のタスクと register 項目を定期的に見て、止まったものを見つける。見る間隔は routine の設定で決める。
- 止まった理由を種類で分け、種類ごとの対応を設定（exec-defaults など）で決められる。少なくとも次を扱う。
  - 使用量の上限: 解除の時刻まで待つか、代わりの agent で流し直す。指名した agent が長い上限（例: 数日）のときは、claim を取り消して別の agent で流し直せる。
  - 親の検証の失敗のうち、負荷による時間切れと分かるもの: 同じ検査を流し直してから再開する。
  - 統合先の新しい commit が要る失敗: worktree を統合先に同期してから再開する（PJR-50CF と合わせる）。ぶつかったら止めて知らせる。
  - 判断が要るもの（型の決まりを変えないと直らない指摘、保護された設定の変更、commit の対象外の変更（PJR-1Y1M）など）: 止めたまま、理由と次にすべきことを残す。
- 自動で手を打った回数に上限を設け、同じタスクで繰り返し失敗したら止める。
- 手を打ったことと止めたものを、朝の報告（夜間の routine の朝報告と同じ置き場所）と登録簿にまとめて残す。人やオーケストレーターが、朝に読むだけで続きを判断できる。
- **agent の種類に頼らない**：Claude Code の「後ろの処理が終わったら会話を再開する」機能に頼らず、cron と routine だけで動く。オーケストレーターが Claude Code・Codex・Antigravity のどれでも、同じ設定で同じに動く。
- **立ち上げたままのオーケストレーターと共存する**：オーケストレーター（Claude Code・Codex・Antigravity のどれでも）を立ち上げたまま運用していても、見張りとぶつからない。
  - オーケストレーターや人が手で始めた run・再開・直しの途中にある worktree には触らない。見分けは、実行中のプロセスと lock、claim の actor、手で付ける「見張りの対象外」の印で行う。
  - オーケストレーターや人が、見張りをいつでも止めたり再開したりできる（全体、またはタスク単位）。
  - 別の run が lock を持っている間は何もせず、次の回に回す（PJR-KVWH と合わせる）。
  - claim の取り消し・再開・延期などの手を打ったら、見張りを actor にした event として必ず残し、オーケストレーターが登録簿と状態を読むだけで分かるようにする。
  - worktree や branch を消す操作は既定ではしない。する場合も、作業の変更が残っていないことを確かめてからにする。
  - オーケストレーターが手で run を流しているときに見張りが動いても、ぶつからないことを統合テストで確かめる。
- **オーケストレーターを立ち上げたままにしなくても動く**：判断が要るものは止めて理由と次にすべきことを朝の報告と登録簿に残し、オーケストレーターは朝や区切りに新しく立ち上げて読めば続きを判断できる。夜に判断させたい場合は、判断が要るものを見つけたときだけ短い指示でオーケストレーターを一度起動する形（`orchestrator night` と同じ考え方）を選べる。
- 2026-11-13〜14 の夜の実例（上限・型のメニューの足し忘れ・commit の対象外・branch の食い違い・負荷の時間切れ）を、回帰テストの場面として再現している。
- 関連する設計・ガイド・CLI リファレンスを直している。
- 迷った点は executor が決め、決めた内容と理由を個票の対応結果に書いている。pipeline では報告の `handoff` にも書く。
- CHANGELOG.md は変えず、利用者に影響する変更を個票の対応結果の「CHANGELOG に書く事項」の節に書いている（PJR-EPQ3）。
- `npm run typecheck`・`npm run lint:ts`・`npm run test:unit`・`npm run lint:md` と親の検証が通っている。
