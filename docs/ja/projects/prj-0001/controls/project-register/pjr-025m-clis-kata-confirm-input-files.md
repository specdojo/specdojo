# PJR-025M 入力ファイルの規則を足した clis の型を確定する

## 1. 背景

PJR-PJYJ で、clis の型に入力ファイルの規則を足して直すと決めた。PJR-6AQF で直した clis の型を人が確かめて確定する。確定した型で、カタログの付け替え（PJR-8J47）と clis の代表の作成を進める。

## 2. 入力

- 型の確定は人が行う（PJR-PJYJ と同じ扱い）。

## 3. 検討した選択肢

| 選択肢       | 内容                                                                                                                             | 利点                                             | 懸念                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------- |
| 確定         | 入力ファイルの規則を足した clis の型を確定する                                                                                   | 手戻りがない                                     | API の呼び出し・環境変数・標準入力など、ファイル以外の入出力が抜ける |
| 直す（採用） | 5 章を「入力と出力の要点」にし、入力情報と出力情報に分けて種類（ファイル・標準入力・環境変数・対話の入力・API など）の列で並べる | CLI が受け取るもの・外へ出すものを漏れなく書ける | clis の型をもう一度確定する手間がかかる                              |

## 4. 決定内容

「直す」を採る。

- 5 章を「入力と出力の要点」にし、5.1 入力情報と 5.2 出力情報（標準出力もここにまとめる）に分ける。
- 入力情報の種類はファイル・標準入力・環境変数・対話での入力・API の応答、出力情報の種類は標準出力・標準エラー・作る・変えるファイル・API への送信（相手の状態を変えるもの）とする。
- 中身は書かず正本を参照する。ファイルはその rulebook か schema、API は外部 I/F の仕様（`ifx-api`）を参照し、clis にはどのコマンドがどの API をなぜ呼ぶかと失敗時の扱いだけを書く。
- 入力情報ごとに、ない・壊れている・届かない（API ではつながらない・時間切れ・拒否）ときの扱いを書き、終了コードとエラーの章の表につなげる。
- 認証情報は名前と用途だけを書き、値は書かない。取得と更新の両方を行う API の呼び出しは、入力情報と出力情報の両方に挙げる。

## 5. 採択理由

- CLI の中から API を呼び出すこともあり、ファイルに絞った章立てでは入出力が抜ける（indie の指摘、2026-11-08）。
- API の契約は外部 I/F の仕様が正本で、clis に繰り返すと重複になる。
