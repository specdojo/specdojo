# PJR-3VJM 決定記録（dec）の型を非推奨にするか決める

## 1. 背景

prj-0001 の決定は登録簿の decision で管理しており dec 文書がない。登録簿の decision と役割が重なる dec の型を非推奨にするかを決める。

orchestrator の比較（2026-11-18）: dec-rulebook の必須章（背景・検討した選択肢・決定内容・採択理由・影響範囲）は、登録簿の decision の個票の章（背景・入力・検討した選択肢・決定内容・採択理由・承認・影響範囲とフォローアップ）にすべて含まれる。

## 2. 入力

- orchestrator の調べ（2026-11-18）: dec-rulebook と dec-sample はあるが、リポジトリに `dec-<NNNN>` の文書はない。決定は pjr の decision と pm-decision-log（生成）で管理している

## 3. 検討した選択肢

| 選択肢    | 内容                                                                                            | 利点                                                                                                                                                                                   | 懸念                                                                                              |
| --------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| A（推奨） | dec の型（rulebook・sample・template）を非推奨にし、後継を登録簿の decision（pjr の個票）にする | 決定の記録が登録簿の 1 か所にまとまる。個票の decision は背景・選択肢・決定内容・採択理由・承認・影響範囲の章を持ち、dec の必須章をすべて含む。決定の一覧は pm-decision-log が生成する | dec を使っている利用者がいれば移行の案内が要る（prj-0001 には dec の文書がない）                  |
| B         | dec の型を残し、kata-slim-2 の子の項目（PJR-0VPB）で簡潔にする                                  | 登録簿を使わない利用者も決定を文書で残せる                                                                                                                                             | 登録簿の decision と同じ判断を 2 つの型で書くことになり、どちらを正とするかが利用者に分かりにくい |
| C         | dec の型を残し、登録簿の decision から生成する文書（派生ビュー）に変える                        | 文書として読みたい利用者の要望に応えられる                                                                                                                                             | 生成の仕組みを作る手間が要り、pm-decision-log と役割が重なる                                      |

## 4. 決定内容

A を採る。決定記録（dec）の型（rulebook・sample）を非推奨にし、後継を登録簿の decision（pjr の個票）とする。新しい `dec-<NNNN>` は作らない。

## 5. 採択理由

- 登録簿の decision の個票は、dec-rulebook の必須章（背景・検討した選択肢・決定内容・採択理由・影響範囲）をすべて含み、承認の章も持つ。
- 決定の一覧は pm-decision-log が登録簿から生成するため、dec を残すと同じ判断を 2 つの型で書くことになる。
- prj-0001 に dec の文書はなく、移行の対象がない。
