# PJR-9JN6 完了条件の保護された設定の一覧が変更範囲と読まれ、関係のない項目が順番待ちになる

## 1. 課題内容

保護された設定を「変えない」と書いた完了条件の文から .agents などが変更範囲として推定され、触る範囲の違う項目どうしが重なると判定される

## 2. 入力

- 2026-11-17 に PJR-8NB8 と PJR-C07H を並べて流すと、C07H が「[scope] waiting: PJR-C07H — PJR-8NB8: project:.agents <> project:.agents」で 8NB8 の統合まで待った。8NB8 は JSEY の手順のコマンド化、C07H は親の検証の計測で、どちらも .agents を変える予定はない
- どちらの完了条件にも「保護された設定（lefthook.yml・.agents/・.claude/・.codex/・package.json・.specdojo/ など）は変えない」という文があり、ほかの多くの項目の完了条件にも同じ文がある。PJR-MJ8V の 2 回目で plan の共通の手順は推定から外したが、項目ごとの完了条件の中の「変えない」と書いた一覧は推定に残っている
- 2026-11-17 の 2 回目では、PJR-9JN6 自身が「[scope] PJR-9JN6 blocked by unintegrated PJR-8NB8: project:CHANGELOG.md <> project:CHANGELOG.md」で止まった。どちらの完了条件にも「`CHANGELOG.md` は変えず、個票の対応結果に文案を書く」（PJR-EPQ3）という文がある。先行の項目の親の検証が失敗すると、誤って重なった後続の項目は待つのではなく止まる（8NB8 の失敗で C07H・8S4T・9JN6 の 3 件が止まった）
- 止まりはしないが、この文を持つ項目は並べても順番に流れ、並べる効果がなくなる

## 3. 影響範囲

| 観点         | 影響                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| スコープ     | `src/exec/run/change-scope.ts` の変更範囲の推定と、その回帰テスト                       |
| スケジュール | 保護された設定の一覧を持つ項目どうしは並べても順番に流れ、並べて流す run の完了が遅れる |
| コスト       | agent の利用枠は増えない。待つ時間だけ run が長くなる                                   |
| 品質         | 重なりの判定が実際の変更範囲を表さず、待機の記録が誤った理由を示す                      |
| 関係者       | exec run を並べて流す orchestrator と利用者                                             |

## 4. 対応方針

| 項目     | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原因     | 変更範囲の推定が、完了条件の中の「変えない」「変更しない」と書いた文と、保護された設定の一覧に出てくるパスまで拾う                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 対応策   | 完了条件の否定の文（「変えない」「変更しない」など）と保護された設定の一覧に出てくるパスを推定から外す。項目が実際に変える対象のパスは推定に残す                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 依存事項 | PJR-MJ8V で入れた変更範囲の推定と順番待ちの仕組み                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 完了条件 | 保護された設定の文と `CHANGELOG.md` を変えない文（PJR-EPQ3）を共有するだけの 2 件が重ならない回帰テストがある。同じ関数を変える 2 件が重なると判定される既存のテスト（ED0K・1GCD の形）が通る。保護された設定は変えず、変更が要る場合は変更案を個票の対応結果と報告の `handoff` に書く。迷った点は executor が決めて理由を個票の対応結果に書く。`CHANGELOG.md` は変えず、個票の対応結果の「CHANGELOG に書く事項」に文案を書く（PJR-EPQ3）。`npm run typecheck`・`npm run lint:ts`・`npm run test:unit`・`npm run lint:md` と親の検証が通る。2 回目の実行（2026-11-18）: schedule の型のタスク（track kata-slim、approach rulebook-maintenance）が、互いに「project:docs/ja/specdojo/rulebooks <> project:docs/ja/specdojo/rulebooks」で重なると判定され、1 件が統合で止まると残りの rulebook のタスクがすべて止まった。`change-scope.ts` が `targetReferenceDirsForApproach` の返す参照用の型のディレクトリ（読むだけの場所）を変更範囲に足しているためである。参照用のディレクトリは推定から外し、変更範囲は対象の型のファイル（`authoredKataPath` など）に限る。別々の型の rulebook を直す 2 件が重ならず、同じ型のファイルを直す 2 件は重なる回帰テストを足す |

## 5. 対応結果

### 5.1. 実施内容と判断

- `src/exec/run/change-scope.ts` で、項目固有の本文から「変えない」「変更しない」「変えず」などで終わる節を除いてパスを推定する。句点・改行・表のセルで区切り、読点では述語の後だけ区切ることで、設定の列挙と同じ文の変更対象を区別した。
- ファイル名による一律除外はしない。同じパスを別の条件で変更すると書いた場合や、明示した `targets` / `target_path` は範囲に残す。候補がなくなった場合は既存の不明範囲の扱いを使う。保護された設定の変更案はない。
- `tests/src/exec/run/change-scope.test.ts` に、保護設定と CHANGELOG の禁止文を共有する独立項目の並行実行・先行失敗後の起動、否定表現の違い、同じ文の肯定対象、明示対象の保持、同じ関数を変更する項目の統合待ちの回帰テストを追加した。既存の ED0K・1GCD 型のテストは維持した。
- [[specdojo:exec-operation-guide|exec運用ガイド]] に、否定された本文の節を除外する規則と、明示対象を残す規則を追記した。
- 2 回目の追加完了条件に対応し、`targetReferenceDirsForApproach` が返す変更許可用ディレクトリを推定範囲へ自動追加する処理を除いた。この関数は commit の許可範囲を表すため、実際に変える範囲とは区別する。変更範囲は索引・カタログで解決した対象や `authoredKataPath` の出力ファイルから求め、明示的に指定したディレクトリは従来どおり残す。
- 回帰テストでは rulebook・recipe・sample・template の maintenance ごとに、異なるファイルの並行予約と先行失敗後の独立項目の起動、同じファイルの統合待ちを確認する。authoring の異なる出力、bootstrap 系の個別対象、解決できない対象の不明範囲の扱いも検査対象にした。運用ガイドの既定範囲の説明を実装に合わせて修正した。

### 5.2. 検証と申し送り

- 初回・2 回目とも executor の Prettier 整形、履歴リンク検査、カタログ検査、登録簿の生成検査が成功した。カタログ検査では未変更のカタログに re-export 参照・未作成文書の警告が出たが、終了コードは 0 だった。型検査・TypeScript/Markdown 等の lint・schema 検査・ユニット／統合テストは指定された親 runner の検証に委ね、今回も重複実行していない。
- 統合後は [[prj-0001:pm-orchestrator-playbook|オーケストレーター運用メモ]] に従い、PJR-JSEY の実 agent CLI による動作確認の対象に PJR-9JN6 を含める。実 agent の利用枠を消費するため executor では起動せず、人の確認へ申し送る。

### 5.3. CHANGELOG に書く事項

- 不具合修正: 並列の exec run で、完了条件の「保護された設定は変えない」「CHANGELOG.md は変えず」という文を変更範囲に含め、無関係な項目を順番待ちや未統合エラーにする誤判定を修正。
- 不具合修正: kata を扱う exec run の変更範囲に変更許可ディレクトリ全体を自動追加せず、個別の対象ファイルで判定することで、別々の kata のタスクが互いの統合待ちや未統合エラーで止まる誤判定を修正。

### 5.4. 統合の後の確認（orchestrator）

- 2026-11-19 に `exec smoke --register PJR-JSEY --targets PJR-8NB8,PJR-9JN6,PJR-C07H,PJR-ZK3T --executor-by sonnet-executor --reporter-by gemma26-reporter` を流し、PJR-JSEY が sonnet-executor で start から review まで通り、start と review の event の actor に実体名が記録された（fa59c521e）。
- 2026-11-19 に PJR-DM9B・PJR-YGZF・PJR-A5FY を `--parallel 3` で並べて流した。3 件とも完了条件に「保護された設定は変えない」と「`CHANGELOG.md` は変えず」の文を持つが、範囲の順番待ちにならず並んで流れ、それぞれ統合された。
