# PJR-VNT1 業務仕様の冒頭は頭書きと目的・適用範囲の章にそろえる

## 1. 背景

業務仕様の文書の冒頭を、H1 直下の 1〜2 行の頭書きと「目的」「適用範囲」の章に分ける形にそろえる。stsd は 3APD の中で直し、ほかの種類は各 epic の Kata の手入れで適用する

## 2. 入力

- 利用者の指摘: stsd の「概要」は記述が多すぎる。H1 の下に 2 行程度の頭書きを置き、目的・適用範囲に分けたほうが分かりやすい。cdfd はそうなっている（2026-11-05）
- 現状: cdfd（全体概要・プロセス領域別・ユースケース別）は頭書き + 目的 + 適用範囲（PJR-PRYZ）。stsd・bps・opr・br・cdsd・cld は「概要」の章にまとめて書く。framework の standard は「目的・適用範囲」
- 利用者は案 A（stsd を試行の中で直し、ほかは各 epic の Kata の手入れで適用する）を選んだ（2026-11-05）

## 3. 検討した選択肢

| 選択肢 | 内容                                                                              | 利点                                                                              | 懸念                                                               |
| ------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| A      | stsd を試行の中で直し、ほかの種類は各 epic の Kata の手入れの段で同じ形にそろえる | 試行の中で確かめてから広げられる。各 epic の流れ（手入れ → retrofit）の中で直せる | 全部がそろうまでに時間がかかる                                     |
| B      | stsd だけ直す                                                                     | 早い                                                                              | 種類によって冒頭の形が違うまま残る                                 |
| C      | 業務仕様の Kata をすべて今まとめて直す                                            | 一度にそろう                                                                      | 実物のない種類の Kata まで先に変えることになり、試行の意味が薄れる |

## 4. 決定内容

A を採る。業務仕様の文書の冒頭は、H1 直下の 1〜2 行の頭書き、「目的」、「適用範囲」の章に分ける（cdfd の形）。stsd は 3APD の中で直し（PJR-F1FD・PJR-NEPD・PJR-YSST・PJR-SWRE・PJR-P9SW と 5 件の文書）、bps・br・cdsd・cld・opr などは、それぞれの epic の Kata の手入れの段で同じ形にそろえる。あわせて、stsd の状態遷移図の表示名は、値がある場合は`状態名<br>値`とする。

## 5. 採択理由

- stsd の「概要」は、対象・スコープ・目的・利用者・正本の管理場所・状態変更を起こす業務範囲・終了点を置かない理由が箇条書きで並び、10 行を超えていた。
- cdfd は PJR-PRYZ で頭書き + 目的 + 適用範囲に直し、読み手が目的と範囲を分けて読める。framework の standard も「目的・適用範囲」を冒頭に置く。
- 実物のない種類の Kata を先に変えず、各 epic の流れで直すほうが、試行で確かめた手順に沿う。
