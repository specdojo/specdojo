# PJR-76N9 成果物と sample の本文に、文書の役割の割り当てと承認の進み具合を書かない

## 1. 背景

成果物と sample の本文には、文書を作る・確かめる・承認する役割の割り当てや承認の進み具合を書かず、承認と留保は登録簿で追う。rulebook の「誰が判断するか」は「どの利用場面で何を判断するための文書か」に直す

## 2. 入力

- 利用者の指摘（2026-11-21、cnd-specdojo の確定の前）: 概要に PO・ARC・BA・DEV などの役割を書く必要があるか。3 章・4 章が長い
- orchestrator の調べ（2026-11-21）: 役割の割り当ての文は製品の成果物と sample に約 28 件（cnd-specdojo・cpd-specdojo-cli・bes-index・cdsd-execution・`sysd-*`・cnd-sample など）、「誰が……判断するか」と書く rulebook は 19 件（cnd・cxd・atc・pjr など）。cnd-rulebook の 6.1 は「誰がどの利用場面で配置・結合の何を判断するかを示します」としつつ、1 章では役割の割り当てをメンバー定義に委ね、Person を確認者一覧と区別している
- cnd-specdojo の 4.2 の後半は承認の範囲・留保・差し戻しの記録で、設計の中身ではない。品質管理計画（pm-quality-management-plan）の本文も多くが役割の手順で、CLI・runner・hook は読んでおらず、ゲートの判定の記録も無い
- 利用者の承認（2026-11-21）: decision を起票して決まりを決め、流している波の strategy に伝え、cnd-specdojo は手直しの todo（Q9DF）を開き直し、ほかの成果物はまとめて直す todo、rulebook は第 3〜6 波と kata-slim-3 で直す

## 3. 検討した選択肢

| 選択肢 | 内容                                                                                            | 利点                                                                            | 懸念                                                               |
| ------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| A      | 本文に役割の割り当てと承認の進み具合を書かず、登録簿で追う。rulebook の「誰が判断するか」を直す | 文書が設計や計画の中身だけになり短くなる。承認の記録が登録簿の 1 か所にまとまる | 約 28 件の成果物と 19 件の rulebook を直す手間がかかる             |
| B      | 今のまま、本文に書いてよいとする                                                                | 直す手間が要らない                                                              | 文書の運用の記述が設計の中身と混ざり、長くなる。登録簿と二重になる |

## 4. 決定内容

案 A を採る。

- 成果物と sample の本文には、文書を作る・確かめる・承認する役割の割り当て（例:「ARC が構成案を担当し、BA は……を確認する」）や、承認の範囲・留保・差し戻しなどの進み具合を書かない。承認と留保は登録簿の個票で追う。
- 文書の中身として役割が要る場合（RACI、体制、利用者の接点、業務の担当など、その文書が扱う対象そのもの）は、この決まりの対象外とする。
- rulebook の「誰がどの利用場面で何を判断するか」は、「どの利用場面で何を判断するための文書か」に直す。
- sample の作成標準と rulebook の作成標準に、この決まりを足す。
- 直す順番: cnd-specdojo は手直しの todo（PJR-Q9DF）を開き直して直す。ほかの成果物はまとめて直す todo を起票する。rulebook と sample は第 3〜6 波と kata-slim-3 の中で直し、流している波の strategy にも伝える。

## 5. 採択理由

- 役割の割り当てはメンバー定義・RACI・登録簿が正本で、本文に書くと二重になる。
- 設計や計画の文書が、文書の運用の記述で長くなっている（cnd-specdojo の 3・4 章、品質管理計画）。
- kata-slim で rulebook から外した「文書の運用の記述」と同じ種類で、成果物と sample にも同じ方針をそろえる。
