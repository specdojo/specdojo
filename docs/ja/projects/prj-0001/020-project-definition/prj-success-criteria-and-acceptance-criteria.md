# 成功基準と受入条件

## 1. 判定対象と適用範囲

初期公開では、代表的なシビックテックプロジェクトについて、口頭説明なしに次の一連の利用が成立するかを判定する。

1. 初めての参加者が Why、主要判断、現在の状態を理解する。
2. 人と AI Agent が同じ正本を参照して変更する。
3. 後任者が未決事項と次の作業を理解して継続する。

| 業務価値 ID | 業務価値                                                         |
| ----------- | ---------------------------------------------------------------- |
| BV-01       | 技術・非技術の参加者が、目的と判断根拠を共有して作業に参加できる |
| BV-02       | 人と AI Agent が、同じ正本と変更影響を確認して更新できる         |
| BV-03       | 担当者が交代しても、口頭説明なしに作業を継続できる               |
| BV-04       | 活動が継続し、参加機会と判断の透明性を保てる                     |

初期公開の GO / Not GO は SC-01〜SC-03 と AC-01〜AC-04 のすべてで判定する。SC-04〜SC-06 は公開後の価値検証であり、初期公開の合否には含めない。社会課題への寄与は SpecDojo 単独の成果とはみなさない。

## 3. 受入条件

| ----- | --------- | ------------ | ------------------------ | ------------------------------------------------------------------------------ | -------------------------------- | ----------- | ------ |
| AC-01 | BV-01〜03 | 利用者視点   | 最小セットを利用できる   | SC-01〜SC-03 に必要な成果物、選択案内、作成支援資料があり、代表試行に合格する  | 対象成果物一覧と代表試行の記録   | `BA`, `QE`  | `PO`   |
| AC-02 | BV-02〜03 | 技術的受入   | 正本と関係を検証できる   | ID、メタデータ、参照関係、生成物が検証に合格し、利用を妨げる重大な不整合がない | 検証コマンド、対象、結果、確認日 | `ARC`, `QE` | `PO`   |
| AC-03 | BV-01〜04 | 公開適性     | OSS として試用できる     | 利用方法、ライセンス、改善提案の入口があり、個人情報・機密情報を含まない       | 公開前レビュー記録               | `BA`, `QE`  | `PO`   |
| AC-04 | BV-01〜04 | 是正・再判定 | 未達を是正・再判定できる | 未達 ID、利用者影響、是正内容、担当、期限、再判定結果を記録できる              | 是正・例外承認・再判定の記録     | `QE`        | `PO`   |

## 4. 判定手順と証跡

1. `BA` と `QE` が代表利用者、前提説明、必須情報、重大な行き詰まりを事前に定める。
2. 代表利用者が、保守担当者の説明を受けずに SC-01〜SC-03 を実施する。
3. `BA` が利用者の理解、`ARC` が人と Agent の参照・変更結果、`QE` が証跡と技術的受入を確認する。
4. 未達時は是正または期限付き例外を記録し、`PO` が GO / Not GO を判断する。
5. 公開後は `BA` が SC-04〜SC-06 を確認し、`PO` が改善方針を決める。
