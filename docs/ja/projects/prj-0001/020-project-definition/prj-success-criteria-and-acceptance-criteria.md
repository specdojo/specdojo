# 成功基準と受入条件

## 1. 判定対象と適用範囲

本書は、[[prj-0001:prj-scope|プロジェクトスコープ]]で定めたシビックテックの初期対象について、次の三段階を判定する。以下の「プロジェクト」はシビックテックプロジェクトを指す。

1. 初期公開時に、代表利用者が主要な利用場面を完遂できるか。
2. 公開後に、実際のプロジェクトで利用・継続・再利用され、利用者価値が生じたか。
3. 中長期に、利用プロジェクトが活動を継続し、参加機会と透明性を保てているか。

初期公開の GO / Not GO は、公開前に判定する SC-01〜SC-04 と AC-01〜AC-06 のすべてを必須条件とする。単純な合格項目数の割合では判定せず、いずれかが未達の場合は是正または例外承認を行う。SC-05〜SC-07 は公開後の短期、SC-08〜SC-11 は中長期の成功検証に用い、初期公開の合否には含めない。

個別システムの品質や、社会課題が SpecDojo だけで解消されたかは判定しない。中長期の効果は、活用実績と利用者の確認から寄与を評価する。文書構造、lint、公開適性は業務価値ではなく受入条件として扱う。

`PO` は利用者価値と最終的な GO / Not GO を承認する。`BA` は代表利用者による試行と公開後の価値検証、`ARC` は人と AI Agent の共通参照および技術的境界、`QE` は測定方法と証跡の再現性を確認する。

| 業務価値 ID | 業務価値                                                                                       | 主な判定場面                           |
| ----------- | ---------------------------------------------------------------------------------------------- | -------------------------------------- |
| BV-01       | 初めて参加する人が、必要な成果物を選び、次に行う作業を特定できる                               | 初期公開前の着手シナリオ               |
| BV-02       | 技術・非技術の参加者が共通の型を用いて成果物を完成させ、目的、公共的価値、判断根拠を説明できる | 初期公開前の作成・レビューシナリオ     |
| BV-03       | 人と AI Agent が同じ仕様と判断根拠を参照し、変更対象について共通の理解を形成できる             | 初期公開前の変更シナリオ               |
| BV-04       | 担当者が交代しても、後任者が目的、判断経緯、未決事項を理解し、更新を継続できる                 | 初期公開前の引き継ぎシナリオ           |
| BV-05       | 利用者が SpecDojo を実際のプロジェクトへ適用し、成果物を継続的に利用・再利用・改善できる       | 公開後の利用事例と利用者フィードバック |
| BV-06       | 利用プロジェクトが社会課題への取り組みを継続し、多様な参加者と判断根拠を共有できる             | 中長期の活用事例と運用実績             |

## 4. 判定手順と証跡

1. `BA` と `QE` は、着手、作成・レビュー、変更、引き継ぎの各シナリオについて、参加者属性、前提説明、必須タスク、重大な行き詰まりの定義を事前に固定する。
2. 代表利用者は、保守担当者による手順説明を受けずにシナリオを実施する。安全確保または環境障害への支援は許容するが、支援内容を記録する。
3. `BA` はタスク完了と利用者の理解を、`ARC` は人と AI Agent の参照先・判断理由・影響対象を、`QE` は測定方法と証跡の再現性を確認する。
4. `ARC` と `QE` は、Frontmatter、ID、参照関係、lint、生成物、公開範囲を確認し、技術的受入の結果を利用者試行と分けて記録する。
5. 未達の SC / AC がある場合は、利用者への影響、是正内容、担当、再確認する ID、再判定時期を記録する。例外を認める場合は、`PO` が理由、期限、代替策を承認する。
6. `PO` は SC-01〜SC-04 と AC-01〜AC-06 の結果および例外を確認し、初期公開の GO / Not GO を判断する。
7. 公開後は `BA` が利用事例、運用状況、利用者フィードバックを収集し、SC-05〜SC-11 を所定の時期に判定する。`PO` は未達時の改善方針を決定する。
