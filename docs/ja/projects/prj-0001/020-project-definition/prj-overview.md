# プロジェクト概要: SpecDojo

SpecDojo は、社会課題の当事者と、それに取り組む市民、地域団体、行政、専門家、開発者の知識をテクノロジーへつなぎ、人と AI Agent によるシビックテックの実現と継続を支援するオープンなドキュメントフレームワークである。

## 1. 背景

本プロジェクトの直接の対象者は、資金と専門人材が限られる中で社会課題に取り組むシビックテックの参加者である。当事者、市民、地域団体、行政・公共領域の担当者は解くべき課題と期待価値を判断し、専門家、開発者、AI Agent 活用担当、将来の貢献者はそれを実現・改善するために協働する。

この協働には、相互に切り離せない三つの課題がある。

1. **課題と技術の断絶**: 課題を知る人と技術を持つ人の間に用語と知識の隔たりがあり、当事者が求める変化と異なるソリューションが作られ得る。
2. **実現費用の不足**: 資金と専門人材が限られ、必要性があっても構築・改善・提供に進めない、または試作後に停止し得る。
3. **善意への依存**: 判断、知識、作業が少数の参加者の余暇、経験、記憶に集中し、負荷の増加や離脱によって活動とソリューションを継承できなくなり得る。

AI Agent と OSS は費用と専門作業を減らせる可能性を持つが、それだけでは三つの課題を同時に解けない。社会課題、対象者、期待価値、制約が共通の正本に言語化されていなければ、技術や AI が現場と異なる解を効率よく作るだけになり、再利用が人の負荷を別の場所へ移すことにもなり得る。

## 2. 必要性

個別の文書、ツール、属人的な調整をその都度追加する方法では、課題と技術の対応、費用、作業負荷の判断が分散し、次の参加者が同じ前提から改善を続けられない。AI Agent と OSS の利用が広がる時点で、手段を選ぶ前に Why を共有し、実現から継承まで同じ判断軸を使える正本が必要である。

中心仮説を次のとおり定める。

> **CH-01 — 仕様でつなぐ協働**: 社会課題に関する当事者の知識と技術者・AI Agent の能力を言語化された仕様でつなぎ、オープンに再利用できる共同資産にすれば、限られた資金と人員でも当事者に有用なソリューションを実現し、特定個人の無理に依存せず継続・継承できる。

CH-01 は、次の三つの初期価値仮説が同時に成立したときに支持され、その先に中長期価値仮説がある。

| ID      | 短縮名           | 価値仮説                                                                                                      | 位置づけ |
| ------- | ---------------- | ------------------------------------------------------------------------------------------------------------- | -------- |
| `BV-01` | 課題と技術の接続 | 当事者の社会課題と期待価値を保ったまま、技術者と AI Agent が実行可能な仕様へつなげられる。                    | 初期成立 |
| `BV-02` | 低コストな実現   | OSS、再利用、AI 支援により、低い現金支出と許容可能な参加負荷で試行成果を実現できる。                          | 初期成立 |
| `BV-03` | 無理のない継続   | 判断、知識、作業を共有すれば、特定個人の無理な善意に依存せず分担・継承できる。                                | 初期成立 |
| `BV-04` | 社会活動への寄与 | BV-01〜BV-03 が実利用で続けば、ソリューションと社会課題への取り組みが継続し、多様な参加者が改善へ関与できる。 | 中長期   |

BV-01 を欠けば現場と異なる解を作り、BV-02 を欠けば実現できず、BV-03 を欠けば継続できない。このため、いずれか一つの達成で CH-01 を支持したとは判断しない。BV-04 は三つの初期価値の成立後に、SpecDojo 単独の成果ではなく社会活動への寄与として確認する。

## 3. 基本的な考え方

| 判断原則                          | 守る価値                  | 判断軸                                                                                         |
| --------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------- |
| **Why before What**               | `BV-01`                   | 対象者、課題、期待する変化を手段より先に確認し、当事者価値と一致しない案は安価でも採用しない。 |
| **Specification-Driven**          | `BV-01`, `BV-03`          | 当事者の言葉から判断・検証結果までを、人と AI Agent が参照・更新できる正本でつなぐ。           |
| **Start Anywhere, Evolve Always** | `BV-01`, `BV-03`          | 必要な箇所から始め、当事者評価と検証結果に応じて Why と成果物を更新する。                      |
| **Open and Reusable**             | `BV-02`, `BV-04`          | 公開可能な成果物と知見を共同資産として再利用し、追加支出と重複作業を減らす。                   |
| **Sustainable Participation**     | `BV-02`, `BV-03`, `BV-04` | 現金支出だけでなく作業時間と継続負担も費用として扱い、必要な成果物を選んで役割を分担する。     |

判断が競合する場合は、当事者価値との一致、現金支出と作業時間を合わせた総費用、参加負荷、継続可能性の順に確認する。ただし、後順位の価値を無制限に犠牲にしてよいことを意味せず、事前に定めた上限や人間の判断責任を越える案は採用しない。

AI Agent は記録、提案、実行、検証を支援する。社会課題の定義、期待価値、主要判断、公開可否は人間が責任を持つ。

## 4. 実現したいこと

本章は CH-01 と価値仮説を検証するための What の方向だけを示し、成果物の詳細と対象外は [[prj-0001:prj-scope|プロジェクトスコープ]]、解決アプローチは [[prj-0001:prj-issues-and-approach|プロジェクト課題と解決アプローチ]]、判定基準は [[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] を正とする。特定の機能、工程、開発手法、技術、AI 製品は本書では固定しない。

- 社会課題、対象者、期待価値から、要求、仕様、検証までを結ぶ文書体系。
- 必要な成果物を選び、技術・非技術参加者が共同で作成するための作成支援資料。
- OSS と AI Agent を利用し、現金支出と作業負荷を記録しながらソリューションを具体化する手順。
- 判断、未決事項、次の作業を共有し、無理なく役割を交代・分担する仕組み。
- 誰もが利用、改善、再利用できる OSS としての公開導線。

初期はシビックテックで検証し、得た知見をほかの公益活動やプロジェクトへ展開する。

## 5. 期待効果

### 5.1. 初期公開指標

| 価値仮説                 | 初期検証で確認すること                                               |
| ------------------------ | -------------------------------------------------------------------- |
| `BV-01` 課題と技術の接続 | 当事者が示した課題と期待価値を保ったまま、実行可能な仕様へ変換できる |
| `BV-02` 低コストな実現   | 追加支出と参加者負荷を記録し、事前に定めた上限内で試行成果を作れる   |
| `BV-03` 無理のない継続   | 作業が一人に集中せず、別の参加者が判断と作業を引き継いで改善できる   |

具体的な基準は [[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] を正とする。「低コスト」は人の無償労働を意味しないため、現金支出と作業時間を分けて測定する。

### 5.2. 短期指標

公開後9か月までは、実際のシビックテックでの利用件数、課題と仕様の対応に対する当事者評価、現金支出と作業負荷、継続利用の状況を確認する。

### 5.3. 中長期指標

中長期には、`BV-04` として、SpecDojo を利用した活動が社会課題への取り組みを継続し、ソリューションを利用可能な状態に保ち、多様な参加者が無理なく改善に関与できているかを確認する。成果を SpecDojo 単独に帰属させず、活用事例、費用・作業記録、運用状況、利用者評価から寄与を判断する。

| 観点             | 確認する変化                                           |
| ---------------- | ------------------------------------------------------ |
| 社会課題への寄与 | 当事者が必要とするソリューションが提供・改善されている |
| 利用可能性       | 費用や専門人材の不足を理由に利用・運用が中断していない |
| 継続可能性       | 負荷が特定個人に集中せず、参加者が交代・分担できている |

## 6. 前提条件

- 代表利用者と技術協力者が、課題、期待価値、試行結果を確認できる。
- 現金支出だけでなく、人の作業時間と継続負担も費用として扱う。
- 人と AI Agent が同じ正本を参照できる形式を用いる。
- 特定の開発手法、技術、生成 AI 製品に過度に依存しない。
- 公開可能な知見を OSS として共有し、実利用から継続的に改善する。
