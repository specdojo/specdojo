# プロジェクト概要: SpecDojo

SpecDojo は、人と AI Agent が共有できる仕様体系を通じて、プロジェクトの立ち上げ、改善、運用を支援するオープンなドキュメントフレームワークである。汎用基盤を目指し、初期はシビックテックで有効性を検証する。

## 1. 背景

シビックテックでは、市民、地域団体、行政、専門家、開発者が、所属や専門性の違いを越えて社会課題に取り組む。一方、限られたリソース、担い手の交代、知識の属人化により、活動の継続と引き継ぎが難しい。

AI Agent は少人数の活動を支援できるが、目的、判断、仕様が共有されていなければ、誤った前提のまま作業を進める。人にも Agent にも解釈でき、変更に合わせて更新される共通の記録が必要である。

## 2. 必要性

中心課題は、プロジェクトの Why、主要判断、現在状態、次の作業が個人の記憶や複数の場所に分散し、参加者の交代時に活動を継続できないことである。

- 目的と当事者への価値が共有されず、実装やツール選定が先行する。
- 仕様、判断経緯、未決事項の所在が分からず、変更と引き継ぎが止まる。
- 人と AI Agent が異なる情報を参照し、結果と確認負荷がばらつく。

初期検証では、「共通の型で目的、判断、次の作業を残せば、口頭説明なしに人と AI Agent が変更と引き継ぎを継続できる」という仮説を検証する。

## 3. 基本的な考え方

1. **Why before What**: 何を作るかより先に、対象者、解く課題、期待価値、判断理由を明らかにする。
2. **Specification-Driven**: 仕様を納品物ではなく、人と AI Agent が参照・更新する正本として扱う。
3. **Start Anywhere, Evolve Always**: 必要な成果物から始め、学びと変更に合わせて育てる。

成果物、責任分担、変更管理、品質管理、トレーサビリティは既存標準を参考にするが、工程順序や全文書の作成は強制しない。AI Agent は記録、実行、検証を支援し、主要判断と責任は人間が担う。

## 4. 実現したいこと

- Why、主要判断、仕様、未決事項、次の作業を関連付ける文書体系。
- 必要な成果物を選び、作成・レビューするための rulebook、recipe、sample、template。
- 人と AI Agent が正本と変更影響を確認するための ID、メタデータ、検証手段。
- OSS として利用、改善、再利用するための公開導線。

初期公開では、シビックテックの変更・引き継ぎシナリオに必要な最小セットを優先する。得た知見は、ほかの領域とライフサイクルへ段階的に展開する。

## 5. 期待効果

### 5.1. 初期公開指標

| 観点       | 確認する効果                                                 |
| ---------- | ------------------------------------------------------------ |
| 理解・着手 | 初見の参加者が Why、主要判断、現在状態、次の作業を説明できる |
| 変更       | 人と AI Agent が同じ正本と影響対象を確認して更新できる       |
| 引き継ぎ   | 後任者が口頭説明なしに未決事項を理解し、作業を継続できる     |

具体的な合格基準は [[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] を正とする。文書数、参照整合、lint、公開適性は利用者価値ではなく受入条件として扱う。

### 5.2. 短期指標

公開後9か月までは、実プロジェクトで使われたか、更新が継続したか、知識共有または引き継ぎが改善したかを確認する。初期目標は利用3件、導入3か月後の更新継続率70%以上、改善を実感した回答70%以上とする。

### 5.3. 中長期指標

中長期には、SpecDojo を利用したシビックテックプロジェクトが社会課題への取り組みを継続し、参加機会、判断の透明性、引き継ぎ可能性を保てているかを確認する。SpecDojo 単独に成果を帰属させず、活用事例、運用状況、利用者の評価から寄与を判断する。

| 観点         | 確認する変化                                                 |
| ------------ | ------------------------------------------------------------ |
| 活動の継続   | 社会課題に取り組むサービスや活動が運用・改善を続けている     |
| 参加機会     | 非エンジニアや市民が判断、成果物更新、改善提案に関与している |
| 透明性・継承 | 判断根拠と変更履歴を共有し、担当交代後も活動を継続できる     |

## 6. 前提条件

- 目的、主要判断、公開可否は人間が承認する。
- 人と AI Agent が同じ正本を参照できる形式を用いる。
- 成果物は目的、規模、リスクに応じて選択する。
- 特定の開発手法、技術、生成 AI 製品に過度に依存しない。
- OSS として公開し、実利用の知見から継続的に改善する。
