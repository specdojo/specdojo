# プロジェクト概要: SpecDojo

SpecDojo は、人と AI Agent が共有できる仕様体系を通じて、プロジェクトの立ち上げ、改善、運用を支援するオープンなドキュメントフレームワークである。

## 1. 背景

社会課題の解消や地域・公共活動の継続には、多様な主体が協力してプロジェクトを立ち上げ、改善し続ける仕組みが必要である。しかし、その担い手となる市民、専門家、行政、開発者のリソースは限られており、知識の属人化・断絶・引き継ぎ困難という壁が繰り返し生じている。

こうした状況において、生成AIおよびAI Agentの発展は、限られた体制でも多くのことを実現できる可能性を広げている。企画から要件定義、設計、実装、テスト、運用・保守まで、AIが支援・実行できる領域が拡大しているからである。

## 2. 必要性

しかし、この可能性を活かすには、プロジェクトの知識や判断を継続的に共有・更新できる形にする必要がある。その中心的な課題が、言語化の難しさである。言語化は、担当者の経験や力量に依存しやすく、標準化・再利用・継続的更新が進みにくい。

その結果、多くのプロジェクトでは以下の問題が生じている。

- 目的や解決すべき課題が曖昧なまま、実装やツール選定が先行する
- 要件や設計意図の伝達不足による認識齟齬・手戻り
- 仕様や判断経緯の不足による属人化・ブラックボックス化
- 担当者交代や長期運用時の保守・改修困難化
- 変更時に、どの要件・設計・実装・運用ルールへ影響するか追跡できない
- 個人の善意や熱量に依存し、継続的な運用や引き継ぎが難しくなる

加えて、AIの力を引き出すためには、人間同士の理解や合意形成を目的とした言語化のあり方を変える必要がある。今後は、人間に加えてAI Agentも実行主体となるため、人が理解しやすいことに加え、AI Agentが解釈し、参照し、タスク実行に活用できることが求められる。

## 3. 基本的な考え方

こうした課題に対して、SpecDojo は、言語化の結果であるドキュメントを、単なる納品物や記録ではなく、人とAI Agentが協働するための共有知識基盤として位置付け、再構築する。

1. **Specification-Driven（仕様駆動）**: 要求、要件、仕様、設計を分断せず、人間とAI Agentが共有できる仕様体系として整理し、それを中心にプロジェクトを構築・改修・運用する。
2. **Why before What（Whatの前にWhy）**: 何を作るかを決める前に、なぜ作るのか、誰のために作るのか、どの成果を目指すのかを明らかにする。
3. **Start Anywhere, Evolve Always（どこからでも、育て続ける）**: どこから始めてもよい。ただし、Why は最初から固定せず、学びに応じて継続的に更新する。

SpecDojo は、Waterfall や PMBOK で重視されてきた成果物、責任分担、変更管理、品質管理、トレーサビリティを参考にする。ただし、Waterfall のように工程順序を固定するものではない。要件定義から始めても、プロトタイプ開発から始めても、運用課題から始めてもよい。

## 4. 実現したいこと

- AI Agent時代の仕様駆動プロジェクト運営を支える、オープンなドキュメントフレームワーク **SpecDojo** を整備する。

- サービスやシステムの構築・改修・運用・保守に必要となり得る文書群を体系化するとともに、規約、テンプレート、サンプル、各種ツール等を通じて、ライフサイクル全体を一貫して支援する。ただし、すべての文書作成を強制せず、プロジェクトの目的、規模、リスク、公共性、運用責任に応じて、必要な成果物を選択できるようにする。

- 特に、シビックテック、地域活動、教育、福祉、行政、NPO、OSSなど、公共性や継続性が重要なプロジェクトにおいて、市民、専門家、行政、開発者、AI Agentが協働しやすい共通の型を提供する。

- SpecDojo をオープンソースとして公開し、誰もが自由に利用・改善・再利用できる共通基盤として育てる。

## 5. 期待効果

SpecDojo の価値は、利用者がプロジェクトに必要な成果物を選び、目的と判断根拠を共有し、作成・レビュー・引き継ぎ・改善を継続できることにある。AI Agent はこの利用者価値を支援する実行主体であり、人間の理解や判断責任を置き換えない。

初期公開前は実利用件数を測れないため、代表利用者が実施するシナリオによって、見つけやすさ、着手しやすさ、理解しやすさ、作業完遂、引き継ぎ可能性を確認する。文書一式の存在、参照整合、lint、公開適性は、利用者価値そのものではなく、価値提供を開始するための受入条件として扱う。

公開後の短期には、実際に使われたか、継続利用されたか、別のプロジェクトで再利用・改善されたかを追跡する。中長期には、SpecDojo を利用したプロジェクトが社会課題への取り組みを継続し、多様な参加者が判断根拠と変更履歴を共有できているかを確認する。下記の目標値は初期仮説であり、具体的な判定条件、証跡、確認者は [[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] を正とする。

### 5.1. 初期公開指標

初期公開前には、代表利用者が SpecDojo を用いて主要な利用場面を完遂できるかを確認する。

| 観点             | 指標                                                   | 初期目標                                     | 測定方法                                                                     |
| ---------------- | ------------------------------------------------------ | -------------------------------------------- | ---------------------------------------------------------------------------- |
| 着手しやすさ     | プロジェクトに必要な成果物を選び、次の作業を特定できる | 代表シナリオの必須タスク完了率80%以上        | 初見の代表利用者が案内と成果物カタログを用いて行った結果を観察・記録する     |
| 作業完遂         | 成果物を作成・レビューし、判断根拠を説明できる         | 必須タスク完了率80%以上、重大な行き詰まり0件 | rulebook、recipe、sample、template を用いた一連の作業結果と発話を記録する    |
| 人とAIの共通理解 | 人と AI Agent が同じ仕様と判断根拠を参照できる         | 重要な参照先・判断理由の不一致0件            | 同じ変更シナリオに対する参照先、判断理由、影響対象を比較する                 |
| 引き継ぎ可能性   | 後任者が目的と判断経緯を理解し、更新を継続できる       | 必須確認項目の説明・更新完了率100%           | 引き継ぎ役が既存文書から目的、決定、影響対象、次の作業を特定できるか確認する |

### 5.2. 短期指標

公開後の短期には、利用、継続、再利用と、それによって直接の利用者課題が軽減されたかを確認する。公開直後は母数が小さいため、まず累積件数と具体的な利用事例を確認し、母数が増えた後に割合指標を再評価する。

| 観点       | 指標                                                             | 初期目標        | 測定方法                                                               |
| ---------- | ---------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------- |
| 利用       | SpecDojo を用いて成果物を作成・改善した外部プロジェクト数        | 累積3件以上     | 公開成果物、導入報告、利用者への確認から、具体的な利用場面を確認する   |
| 継続       | 導入後も仕様または判断記録を更新しているプロジェクトの割合       | 70%以上         | 導入確認から一定期間後の文書更新、変更記録、利用者フィードバックを確認 |
| 再利用     | テンプレートやサンプルを別案件へ適用し、成果物を完成できた件数   | 累積3件以上     | 再利用された成果物と、適用時に必要だった変更・支援内容を確認する       |
| 利用者評価 | 知識共有、合意形成、引き継ぎ、変更影響確認の改善を実感した利用者 | 回答者の70%以上 | 利用前の困りごとと利用後の変化を、事例ヒアリングまたはアンケートで確認 |

### 5.3. 中長期指標

中長期的には、SpecDojo の利用件数そのものではなく、利用したプロジェクトが社会課題への取り組みを継続し、参加機会、透明性、引き継ぎ可能性を保てているかを確認する。SpecDojo だけに成果を帰属させず、活用事例、運用状況、利用者フィードバックから寄与を確認する。

| 観点             | 指標                                                                       | 初期目標     | 測定方法                                                         |
| ---------------- | -------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------- |
| 社会課題への寄与 | 社会課題の解消・軽減につながるサービスや活動の継続運用件数                 | 累積3件以上  | 活用事例、導入報告、運用状況、利用者フィードバックから確認する   |
| 継続性           | SpecDojo を利用したプロジェクトが一定期間後も運用・改善されている割合      | 70%以上      | 一定期間後のリリース、課題対応、保守、文書更新状況を確認する     |
| 参加機会         | 非エンジニア・市民参加者が成果物更新や改善提案に関与した件数               | 累積10件以上 | 課題定義、要件、運用ルール、判断記録、改善提案への関与を集計する |
| 公共性・透明性   | 判断根拠、仕様、変更履歴を関係者または一般に公開しているプロジェクトの割合 | 70%以上      | 公開リポジトリ、共有文書、事例記事、導入報告から確認する         |

## 6. 前提条件

SpecDojo の策定および活用にあたっては、以下を前提とする。

- SpecDojo は、人間の判断や責任を代替するものではなく、人とAI Agentが協働するための基盤であること
- AI Agentは、上流工程の意思決定者ではなく、課題、目的、選択肢、判断根拠を整理し、人間の意思決定を支援する存在であること
- ドキュメントは、人間にとっての理解容易性と、AI Agentにとっての解釈容易性を両立すること
- SpecDojo は、特定の開発手法、言語、基盤、生成AI製品に過度に依存しないこと
- 各プロジェクトは、目的、規模、リスク、公共性、運用責任に応じて、SpecDojo の成果物体系を取捨選択して適用すること
- SpecDojo は、オープンソースとして公開し、実際の活用事例や各現場の知見を取り込みながら継続的に改善すること
