# プロジェクト概要: SpecDojo

SpecDojo は、社会課題に関する知識とテクノロジーを言語化された仕様でつなぎ、人と AI Agent によるシビックテックの実現と継続を支援するオープンなドキュメントフレームワークである。

## 1. 背景

シビックテックでは、市民、地域団体、行政、専門家、開発者が協働して社会課題に取り組む。しかし、課題を知る人と技術を持つ人の間には、用語、知識、参加可能時間の隔たりがある。資金と専門人材も限られ、活動は一部の人の善意や熱量に依存しやすい。

AI Agent と OSS は、構築・改善の費用と専門作業を減らせる可能性を持つ。一方、社会課題、当事者への価値、制約が言語化されていなければ、技術や AI が現場と異なる解を効率よく作るだけになり得る。

## 2. 必要性

シビックテックを継続可能にするには、次の三つを同時に成立させる必要がある。

1. 当事者の課題と期待価値を、技術者と AI Agent が実行可能な仕様として理解できること。
2. OSS、再利用、AI 支援によって、追加の現金支出と参加者の作業負荷を抑えてソリューションを実現できること。
3. 知識と判断を共同資産として残し、特定個人の無理な負担に依存せず改善を継続できること。

中心仮説は、次のとおりである。

> 社会課題に関する当事者の知識と技術者・AI の能力を言語化された仕様でつなぎ、オープンに再利用できる形にすれば、限られた資金と人員でも有用なソリューションを低コストで生み出し、特定個人の善意や無理に依存せず継続・継承できる。

## 3. 基本的な考え方

1. **Why before What**: 対象者、課題、期待する変化を、手段より先に確認する。
2. **Specification-Driven**: 当事者の言葉から検証結果までを、人と AI Agent が更新できる正本でつなぐ。
3. **Start Anywhere, Evolve Always**: どこからでも始め、学びに応じて Why と成果物を更新する。
4. **Open and Reusable**: 成果物と知見を公開・再利用し、費用と作業を減らす。
5. **Sustainable Participation**: 必要な成果物を選び、役割を分担して負荷を見える化する。

AI Agent は記録、提案、実行、検証を支援する。社会課題の定義、期待価値、主要判断、公開可否は人間が責任を持つ。

## 4. 実現したいこと

- 社会課題、対象者、期待価値から、要求、仕様、検証までを結ぶ文書体系。
- 必要な成果物を選び、技術・非技術参加者が共同で作成するための作成支援資料。
- OSS と AI Agent を利用し、現金支出と作業負荷を記録しながらソリューションを具体化する手順。
- 判断、未決事項、次の作業を共有し、無理なく役割を交代・分担する仕組み。
- 誰もが利用、改善、再利用できる OSS としての公開導線。

初期はシビックテックで検証し、得た知見をほかの公益活動やプロジェクトへ展開する。

## 5. 期待効果

### 5.1. 初期公開指標

| 価値仮説         | 初期検証で確認すること                                               |
| ---------------- | -------------------------------------------------------------------- |
| 課題と技術の接続 | 当事者が示した課題と期待価値を保ったまま、実行可能な仕様へ変換できる |
| 低コストな実現   | 追加支出と参加者負荷を記録し、事前に定めた上限内で試行成果を作れる   |
| 無理のない継続   | 作業が一人に集中せず、別の参加者が判断と作業を引き継いで改善できる   |

具体的な基準は [[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] を正とする。「低コスト」は人の無償労働を意味しないため、現金支出と作業時間を分けて測定する。

### 5.2. 短期指標

公開後9か月までは、実際のシビックテックでの利用件数、課題と仕様の対応に対する当事者評価、現金支出と作業負荷、継続利用の状況を確認する。

### 5.3. 中長期指標

中長期には、SpecDojo を利用した活動が社会課題への取り組みを継続し、ソリューションを利用可能な状態に保ち、多様な参加者が無理なく改善に関与できているかを確認する。成果を SpecDojo 単独に帰属させず、活用事例、費用・作業記録、運用状況、利用者評価から寄与を判断する。

| 観点             | 確認する変化                                           |
| ---------------- | ------------------------------------------------------ |
| 社会課題への寄与 | 当事者が必要とするソリューションが提供・改善されている |
| 利用可能性       | 費用や専門人材の不足を理由に利用・運用が中断していない |
| 継続可能性       | 負荷が特定個人に集中せず、参加者が交代・分担できている |

## 6. 前提条件

- 代表利用者と技術協力者が、課題、期待価値、試行結果を確認できる。
- 現金支出だけでなく、人の作業時間と継続負担も費用として扱う。
- 人と AI Agent が同じ正本を参照できる形式を用いる。
- 特定の開発手法、技術、生成 AI 製品に過度に依存しない。
- 公開可能な知見を OSS として共有し、実利用から継続的に改善する。
