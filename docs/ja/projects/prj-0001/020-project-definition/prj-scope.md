# プロジェクトスコープ: SpecDojo

本書は、SpecDojo の初期公開で作るものと、代表利用者が検証する範囲を定める。

## 1. 対象業務

対象は、少人数で運営され、技術・非技術の参加者が入れ替わるシビックテックプロジェクトである。初期検証では、参加者が口頭説明に頼らず、目的、主要判断、現在の仕様、未決事項、次の作業を理解して変更と引き継ぎを行えることを確認する。

| 利用者                   | 初期利用場面                               | 期待する結果                         |
| ------------------------ | ------------------------------------------ | ------------------------------------ |
| 市民・地域・行政の参加者 | 目的、公共的価値、主要判断を確認・更新する | 技術知識に依存せず、判断に参加できる |
| 開発者・技術協力者       | 仕様と変更影響を確認して成果物を更新する   | Why と判断を失わずに変更できる       |
| 後任者・AI Agent         | 正本、未決事項、次の作業をたどる           | 口頭説明なしに作業を再開できる       |

### 初期公開に含めるもの

1. Why、スコープ、成功基準、主要判断を記録するプロジェクト定義の最小セット。
2. 仕様、判断、未決事項、次の作業を関連付ける ID、メタデータ、参照ルール。
3. 最小セットを作成・レビューするための rulebook、recipe、sample、template。
4. 変更・引き継ぎシナリオと、参照整合・形式を確認する検証手段。
5. README、ライセンス、改善提案の入口など、OSS として試用できる公開導線。

## 2. 対象システム

| 対象               | 内容                                                   | 境界                                       |
| ------------------ | ------------------------------------------------------ | ------------------------------------------ |
| 文書フレームワーク | 成果物、作成支援資料、ID、メタデータ、参照関係         | 個別プロジェクトの業務システムは含めない   |
| 検証・管理手段     | 参照整合、形式確認、成果物カタログ、実行状態の最小管理 | 外部 SaaS との同期・認証連携は含めない     |
| 公開導線           | 利用方法、ライセンス、改善提案、公開可能なサンプル     | 有償サービスや個別団体の内部運用は含めない |

## 3. 対象期間

- 初期公開: 最小セット、作成支援資料、検証手段、公開導線を整え、代表シナリオに合格するまで。
- 公開後: 実利用3件を目安に、利用継続と課題改善を確認するまで。

## 4. スコープ外

| 対象（Out）                            | 理由                                           |
| -------------------------------------- | ---------------------------------------------- |
| 全ライフサイクル・全文書種別の完成     | 初期仮説の検証に必要な最小セットを優先する     |
| 特定業務システムの開発・運用           | SpecDojo は文書フレームワークである            |
| 特定手法、技術、AI 製品への最適化      | 利用プロジェクトが選択できる共通の型を保つ     |
| 外部サービス・個別団体システムとの連携 | 初期検証に不要で、運用と情報管理の範囲が広がる |
| 人間の意思決定責任の代替               | AI Agent は記録、実行、検証の支援者として扱う  |

## 5. 境界の判断基準

追加候補は、次の順で判断する。

1. SC-01〜SC-03 の変更・引き継ぎシナリオに必要か。
2. P-01〜P-03 のいずれかを直接改善するか。
3. 既存の成果物や手段で代替できないか。

いずれも満たさないものは初期公開後に送る。

## 6. スコープ変更方針

変更提案には、対応する P-ID / SC-ID、利用者影響、追加・削除する成果物、初期公開時期への影響を記録する。`BA` と `ARC` が影響を確認し、`PO` が承認する。初期公開前に項目を追加する場合は、同時に削除または延期する項目を示す。
