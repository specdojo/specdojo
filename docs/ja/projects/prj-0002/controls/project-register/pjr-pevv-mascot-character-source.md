# PJR-PEVV 道着を着たカワウソのキャラクターの設定と原本を作る

## 1. 概要

マスコット（道着を着たカワウソ）の性格・配色・ポーズの種類などの設定を決め、画像生成 AI を中心に人の手も加えて原本を specdojo-assets に作る。作り方とライセンスを asset.yaml に記録する

### 1.1. 作業の流れ（2026-10-12）

利用者と合意した流れ。人が決めて AI が量を出し、仕上げと権利の確認は人が持つ。

| 段階                  | AI の役割                                                                                     | 人の役割                                       | 残すもの                                          |
| --------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------- |
| 1. 設定を決める       | claude が名前・性格・世界観・配色の案を出す                                                   | 選んで決める。避けること（NG）も決める         | `profile.md`                                      |
| 2. 方向を探る         | agy（Nano Banana）と codex（gpt-image）の両方で、同じ設定から絵柄・頭身・配色を変えた案を出す | 比べて方向とツールを 1 つに絞る                | 採用しない案は `drafts/`、プロンプトは `prompts/` |
| 3. 基準の絵を固める   | 選んだツールで、三面図・表情集・基本のポーズをまとめたキャラクターシートを作る                | 細部（模様・帯の色・尻尾の形など）を確定させる | `source/` に基準のシート                          |
| 4. 必要な絵を量産する | 基準のシートを参照画像として渡し、LP で使うポーズを作る                                       | 基準から外れたものを捨てる                     | `source/` に原本、`prompts/` に設定               |
| 5. 仕上げる           | 背景の除去、高解像度化。claude が画像を読んで崩れを確かめる                                   | 崩れを直し、色をパレットに合わせる             | 仕上げた原本                                      |
| 6. 権利を確かめる     | 似た既存のキャラクターの調査を補助する                                                        | ツールの規約と類似を確かめ、ライセンスを決める | `asset.yaml`                                      |

- 画像の生成は、人が選ぶ段階が中心のため、exec ではなく会話の中で行う。
- ComfyUI は最初は使わない。段階 4 で参照画像を渡してもキャラクターがずれる場合に検討する。この devcontainer（arm64）には GPU がないため、使う場合は Mac のホスト側で動かす。
- 根拠: agy は Nano Banana（Pro は Gemini 3 Pro Image）を呼び出せる（<https://antigravity.google/blog/nano-banana-pro>）。codex の画像生成は第三者の解説で確認した（<https://codex.danielvaughan.com/2026/04/27/codex-cli-image-generation-gpt-image-2-visual-development-workflows/>）。claude は画像を生成できない。

## 2. 完了条件

- 段階 1: 設定が `specdojo-assets/assets/characters/<character-id>/profile.md` に書かれている。`<character-id>` は名前とあわせて決める（例: `dojo-otter`）。少なくとも次を含む。
  - 性格と、使う場面での振る舞い
  - 配色（LP のテーマとの関係）
  - ポーズや表情の種類（当面 LP で使うものを含む）
  - 避けること（NG）
- 段階 1 の名前と設定の採用、段階 3 の基準のデザインの採用は、それぞれ decision として起票して決める。人の創作的な寄与の証跡として残す。
- 段階 2: agy と codex で同じ設定から出した案を比べ、方向と使うツールを決めた理由が残っている（note として起票するか、本個票の対応結果に書く）。
- 段階 3〜4: 基準のキャラクターシートと、LP で使う原本が `source/` に、`<id>-<variant>.<ext>` の名前である。生成のプロンプト・ツール・モデルの版・参照画像を `prompts/` に、原本と同じ `<variant>` の名前で残している。
- 段階 5: 仕上げで次を確かめている。
  - 道着の合わせが右前（着る人から見て左の身頃が上）である。左前は死装束のため誤り。
  - 前足の指の数、帯の結び目、文字（刺繍など）が崩れていない。
  - 色がパレットに合っている。
- 段階 6: `asset.yaml` に、原本ごとの作り方（AI での生成か手描きか、人が手を入れた内容）・使ったツールとその利用規約の確認結果（商用利用の可否、生成物の権利の扱い）・ライセンスが書かれている。既存のキャラクターとの類似を確かめた方法と結果も書く。特定の作品名や作家名をプロンプトに入れていない。
- LP で使う原本が `exports.yaml` に載っている。
- 前提: PJR-F34R で `specdojo-assets` の骨組みができている。
