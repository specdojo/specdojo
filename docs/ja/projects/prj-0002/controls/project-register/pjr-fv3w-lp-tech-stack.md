# PJR-FV3W ランディングページの技術スタックを決める

## 1. 背景

Cloudflare で静的サイトとして公開するランディングページのフレームワークを、Tailwind CSS を前提に比較して決める

## 2. 検討した選択肢

| 選択肢 | 内容                                  | 利点                                                              | 懸念                                                                                |
| ------ | ------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| A      | Next.js（静的書き出し）+ Tailwind CSS | 経験を生かせる。利用者が最も多い。                                | 静的なページにも React の実行時コードが載る。ドキュメントのサイトと技術が分かれる。 |
| B      | Astro + Tailwind CSS                  | 静的サイト向けで出力が最も軽い。必要な箇所で Vue の部品も使える。 | 新しく覚えることがある。                                                            |
| C      | Nuxt（静的書き出し）+ Tailwind CSS    | ドキュメントのサイトと同じ Vue にそろえられる。                   | Vue と Nuxt を覚える必要がある。静的なページにも Vue の実行時コードが載る。         |

利点と懸念は比較前の見立てであり、比較の中で確かめて更新する。

比較の観点は次のとおり。

- 標準的であること（利用者の多さ、公式の案内の有無）
- Cloudflare への配置のしやすさ
- マテリアルデザインの指針を Tailwind CSS で表現しやすいか
- 学ぶ手間
- 表示の速さ
- 保守の続けやすさ

完了条件は、候補ごとに上記の観点の評価を表にまとめ、「決定内容」「採択理由」「承認」を埋めることとする。

## 3. 決定内容

B（Astro + Tailwind CSS）を採用する。ランディングページは Astro の静的出力として作り、Cloudflare 上の静的サイトとして公開する。マテリアルデザインの指針は Material 3 の色の役割・文字の段階・角丸・影の段階を Tailwind CSS のテーマとして定義して表現する。

## 4. 採択理由

- 判断材料は PJR-G4QN の比較評価である。6 観点のうち、Cloudflare への配置のしやすさ・表示の速さ・保守の続けやすさで B が最も優れる。
- ランディングページは動きの少ない静的なページであり、既定で画面側の実行時コードを出力しない Astro が適している。
- Astro は Cloudflare の公式手順で静的サイトのまま配置でき、開発元が Cloudflare に属している。
- 学ぶ手間は A（Next.js）に劣るが、部品の書き方が JSX に近く、Next.js の経験を一部生かせる。
- マテリアルデザインの表現は Tailwind CSS のテーマで行う方式となり、候補による差はない。
