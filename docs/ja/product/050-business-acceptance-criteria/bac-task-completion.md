# 業務受入条件（タスクの評価と完了）

## 1. 概要

成果物の editor から独立した品質評価を完了判断に利用し、PO・PM が今回のタスクの成果を承認でき、PM が決定と完了を記録できることを確認する。判断根拠と未充足事項を残すことで、別の参加者が判断と改善作業を引き継げるようにする。

- 利用場面・対象範囲: 成果物または評価コンテキストの変化による評価要求から、grade・finding の確定、review gate での完了条件との照合、完了記録または再計画要求の引き渡しまで。
- 対象外: タスクの選択・準備・編集・検証の詳細、再計画後の実作業、物理コマンドと保存形式、初期公開の GO / Not GO 判定。
- 根拠: [[bps-deliverable-evaluation|成果物評価]]、[[bps-task-completion|タスク完了]]、[[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] の AC-01・AC-02・AC-04。代表試行に必要な判断・検証の記録と、未達時の是正・再判定への入力を本受入対象で確認する。これだけでプロジェクト全体の受入を満たすとは扱わない。

| 役割   | 確認・合意する内容                                                              |
| ------ | ------------------------------------------------------------------------------- |
| BA     | 利用場面、根拠 BPS と業務受入条件の対応、参加者が判断を引き継げる粒度を確認する |
| QE     | 評価対象・独立性・評価結果の鮮度と、各シナリオの証跡・期待結果を確認する        |
| PO・PM | 最新の品質評価と今回の完了条件を分けて照合し、タスクの完了可否を判断する        |
| PM     | 決定と完了した実行が対応する記録、未完了時の再計画への引き渡しを確認する        |
| PO     | 本書の業務的妥当性、対象範囲、停止・再開条件を承認する                          |

## 2. 受入条件

共通前提として、評価対象と対象タスクを識別でき、成果物カタログの完了条件・根拠参照、Kata の評価観点・rubric を取得できる。評価は editor から独立した runner が行い、完了判断の PO・PM と完了記録を残す PM の権限を確認できる。

`content_hash` は評価対象の内容の一致確認に用いる。鮮度の条件は内容の一致だけでなく、依存先・Kata を含む評価コンテキストの変化が反映済みであることとする。評価単位・観点の正本は成果物評価 BPS とし、grade の段階値や finding の保存構造は本書で定めない。

### 2.1. BAC-01 独立した評価結果を確定する

根拠: [[bps-deliverable-evaluation|成果物評価]] の「処理」「出力」。

#### 2.1.1. 前提

- 成果物の内容が変わり、現在の内容と評価コンテキストに対応する確定済み評価結果がない。
- 評価開始から確定まで対象の内容は変わらない。

#### 2.1.2. 操作

- Orchestrator の評価要求を受け、QE が評価単位を固定し、runner が評価し、QE が鮮度と記録の完全性を確認する。

#### 2.1.3. 期待結果

- 現在の `content_hash`、28 観点すべての判定根拠、grade、finding、評価主体を確認できる評価結果が一件確定する。
- 品質基準への非適合は grade・finding に表れ、評価不能と区別される。QE の確定確認では判定内容を再評価しない。
- 評価結果がタスク完了判断へ渡される。この時点でタスクの完了は確定しない。

#### 2.1.4. 判定方法

- QE が評価確定時に成果物、評価要求、評価結果、担当記録を照合し、対象の一致、全観点の根拠、editor と runner の独立性、確定件数を確認する。PM は評価の確定だけで完了記録が作られていないことを確認する。

### 2.2. BAC-02 既存結果の再利用とコンテキスト変更を区別する

根拠: [[bps-deliverable-evaluation|成果物評価]] の「トリガー」「処理」。

#### 2.2.1. 前提

- 現在の `content_hash` と一致する確定済み評価結果がある。
- 各ケースは独立して確認する。

#### 2.2.2. 操作

- QE が評価要求の対象と既存評価結果、評価コンテキストを照合し、再利用または評価の実行へ引き渡す。

#### 2.2.3. 期待結果

| ケース ID | 条件・入力                                           | 期待結果（観測点）                                                                 |
| --------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------- |
| C-01      | 依存先と Kata を含む評価コンテキストに変化がない     | 再評価せず、同じ確定済み grade・finding を最新の事実として引き渡す                 |
| C-02      | 依存先または Kata が変化し、既存結果には未反映である | 内容の一致だけで再利用せず、現在のコンテキストによる評価を経て一件の結果を確定する |

#### 2.2.4. 判定方法

- QE が引き渡し時に既存・今回の評価結果と評価要求を照合する。C-01 は新しい評価を起動していないこと、C-02 は変化後のコンテキストで評価されたことを確認する。

### 2.3. BAC-03 評価できない理由を残し、完了判断を保留する

根拠: [[bps-deliverable-evaluation|成果物評価]] の E-01、[[bps-task-completion|タスク完了]] の E-02。

#### 2.3.1. 前提

- 共通前提と異なり、評価に必須の基準・根拠・実行記録のいずれかを取得できず、grade・finding が未確定である。

#### 2.3.2. 操作

- QE が評価不能を記録し、PO・PM がその評価不能記録に対応する完了要求を確認する。

#### 2.3.3. 期待結果

- grade を推測で補わず、不足情報、停止範囲、補完担当、再開条件が評価不能記録に残る。
- 完了要求と評価不能の理由が対応付き、完了判断と完了記録が保留される。品質の非適合や完了不可の verdict と取り違えない。
- 不足情報を補完し、grade・finding が確定してから完了判断へ進める。補完不能なら完了保留記録を代替成果として残す。

#### 2.3.4. 判定方法

- QE が停止時に評価不能記録、PM が完了要求と保留記録を照合する。再開時には QE が補完と評価確定を、PO・PM が最新結果を確認してから判断を始めたことを確認する。

### 2.4. BAC-04 評価中の対象変更では古い案を確定しない

根拠: [[bps-deliverable-evaluation|成果物評価]] の E-02。

#### 2.4.1. 前提

- 評価を開始した後に成果物が変わり、開始時と現在の `content_hash` が一致しない。

#### 2.4.2. 操作

- runner と QE が確定前の内容の不一致を確認し、変更後の対象を新しい評価単位として扱う。

#### 2.4.3. 期待結果

- 変更前の grade 案・finding 案は確定結果として使われず、確定評価の件数にも数えない。
- 変更後の成果物と `content_hash` を特定して評価を開始し、その内容に対応する結果だけが完了判断へ渡る。

#### 2.4.4. 判定方法

- QE が評価の引き渡し時に変更前後の成果物、評価要求、評価結果を照合し、古い案の未確定と変更後の対象の一致を確認する。

### 2.5. BAC-05 完了条件との照合を経て決定と完了を記録する

根拠: [[bps-task-completion|タスク完了]] の「処理」「出力」「検証・受入観点」。

#### 2.5.1. 前提

- review gate 時点で最新の grade・finding があり、変更内容、plan、実行記録、完了条件、該当する進捗報告の判断事項を対応付けられる。
- 今回の範囲と完了条件を満たし、完了を妨げる未充足事項がない。

#### 2.5.2. 操作

- PO・PM が評価の鮮度を確認して入力を固定し、今回の変更と要求された成果を照合する。PM が完了可能の決定に従って記録する。

#### 2.5.3. 期待結果

| ケース ID | 条件・入力                           | 期待結果（観測点）                                                                          |
| --------- | ------------------------------------ | ------------------------------------------------------------------------------------------- |
| C-03      | finding がなく完了条件を満たす       | 完了可能の verdict と判断根拠が確定する                                                     |
| C-04      | finding は残るが今回の完了を妨げない | finding を消去・再評価せず、妨げない理由と必要な改善指示を伴う完了可能の verdict が確定する |

- 両ケースで、登録簿に完了・決定の記録、実行記録に完了記録が一件ずつ残る。対象タスク、verdict、判断者、判断根拠、判断時点と完了した実行を対応付けられる。
- review は品質を再評価せず、確定済みの grade・finding を事実として利用する。grade・finding に疑義がある場合も品質判定を置き換えず、成果物評価へ評価要求を戻す。

#### 2.5.4. 判定方法

- QE が完了記録後に評価結果と判断記録を照合し、品質評価が置き換わっていないことを確認する。PM は登録簿と実行記録の対象・判断・時点・件数を照合し、PO が完了根拠を確認する。

### 2.6. BAC-06 grade が良好でも未充足なら完了にしない

根拠: [[bps-task-completion|タスク完了]] の E-03、[[prj-0001:prj-success-criteria-and-acceptance-criteria|成功基準と受入条件]] の AC-04。

#### 2.6.1. 前提

- 最新の評価結果を利用でき、grade は良好である。
- 共通前提と異なり、plan・実行記録・完了条件の不足、または照合による未充足事項がある。

#### 2.6.2. 操作

- PO・PM が完了要求を照合し、未充足事項を特定して Plan へ引き渡す。

#### 2.6.3. 期待結果

- 完了不可の verdict と根拠、未充足事項、改善指示を含む再計画要求が残り、完了記録は作成されない。
- grade・finding を書き換えて不足を埋めた扱いにしない。再計画後の対応と評価が完了し、最新の評価結果と完了要求がそろってから再開する。
- プロジェクト受入の未達を伴う場合は AC-04 の未達 ID、利用者影響、費用・負荷への影響、是正内容、担当、期限、再判定結果へつなげられる。不明な期限・上限や例外承認を本書で決めない。

#### 2.6.4. 判定方法

- PO・PM が引き渡し時に plan、完了条件、実行記録、再計画要求を照合し、未充足の対応先と完了記録の未作成を確認する。QE は後続の再判定が変更後の評価を利用していることを確認する。

### 2.7. BAC-07 鮮度不足または review 中の変更で判断を止める

根拠: [[bps-task-completion|タスク完了]] の E-01 と「検証・受入観点」。

#### 2.7.1. 前提

- 次のケースのいずれかに該当し、現在の成果物と評価コンテキストに対応した結果を判断に使えない。

#### 2.7.2. 操作

- PO・PM が判断の開始前、または確定前に評価の鮮度を照合し、Orchestrator から成果物評価への要求へ戻す。

#### 2.7.3. 期待結果

| ケース ID | 条件・入力                                     | 期待結果（観測点）                                     |
| --------- | ---------------------------------------------- | ------------------------------------------------------ |
| C-05      | 評価結果が存在しない                           | 完了判断を開始せず、現在の内容に対する評価要求を渡す   |
| C-06      | 評価結果と現在の `content_hash` が不一致       | 古い結果で verdict を推測せず、現在の内容の評価を待つ  |
| C-07      | 内容は一致するが評価コンテキストの変化が未反映 | 既存結果で完了判断を始めず、変化を反映した評価を待つ   |
| C-08      | review の入力固定後に成果物が変わった          | verdict と完了記録を確定せず、変更後の内容の評価へ戻る |

- いずれも review 自身は再評価せず、独立した runner による最新の grade・finding が確定してから、鮮度確認を起点に完了判断を再開する。

#### 2.7.4. 判定方法

- QE と PM が停止時と再開時に評価要求、変更前後の内容と評価結果、review の記録を照合し、停止中の verdict・完了記録の未確定と、再開に用いた結果の鮮度を確認する。

### 2.8. BAC-08 評価者が editor と同一なら評価を開始しない

根拠: [[bps-deliverable-evaluation|成果物評価]] の「前提条件」「検証・受入観点」。

#### 2.8.1. 前提

- 共通前提と異なり、指定 runner が editor と同一である。

#### 2.8.2. 操作

- QE が評価開始前に担当の独立性を確認する。

#### 2.8.3. 期待結果

- 評価を開始せず、独立した runner への差戻しと再開条件を確認できる。
- 独立した runner と必要な情報がそろった後に評価単位を固定し直し、評価を開始できる。

#### 2.8.4. 判定方法

- QE が差戻し時に評価要求・担当記録・差戻し記録を照合し、評価の未開始を確認する。再開時には editor と runner が別の主体であることを確認する。

### 2.9. BAC-09 判断・記録の権限を確認できなければ完了処理を開始しない

根拠: [[bps-task-completion|タスク完了]] の「前提条件」。

#### 2.9.1. 前提

- 共通前提と異なり、完了判断の PO・PM、または完了記録を残す PM の権限を確認できない。

#### 2.9.2. 操作

- PO・PM が完了処理の開始前に判断者と記録者の権限を確認する。

#### 2.9.3. 期待結果

- 権限を確認できるまで完了処理を開始せず、完了判断・記録を行わない。未定義の代理承認で進めない。

#### 2.9.4. 判定方法

- PM が開始前に判断者・記録者の権限確認と完了処理の記録を照合し、権限未確認のまま判断・記録が行われていないことを確認する。
