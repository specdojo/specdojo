# 分類一覧（登録項目の種別）

## 1. 概要

- 業務目的: 担当が交代しても、起票者が選んだ分類から追跡の目的・終了の仕方・承認者を読み取れるようにし、判断や作業を特定個人の記憶に依存させない。
- 対象エンティティ: 登録項目（`register_entry`）。属性の定義は [[prj-0001:bdd-register-entry|業務データ辞書（登録項目個票）]] を正とする。
- 主担当ロール: BA（分類の業務的意味と使い分けの定義）、人間の PO（区分けの方針・公開可否の最終承認と説明責任）。`ready` への昇格は人間が判断する。本書は公開用の分類定義と参照先を扱い、実個票の個人情報・非公開情報を含めない。
- 利用者: DEV（schema enum・CLI の許容値との対応確認）、QE（分類別の終端・承認条件の検証）、登録項目を起票・更新する PM と各 owner
- 適用範囲: 個票 Frontmatter の `item_type` と起票時に選ぶ分類。本書では分類の選び方に必要な条件だけを示し、状態遷移・終了承認の詳細は第4章の状態定義に委ねる。

## 2. 分類定義

| 定義項目         | 内容                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象エンティティ | 登録項目（`register_entry`）                                                                                                                       |
| 分類定義名       | 分類（`item_type`）                                                                                                                                |
| 種別             | 業務分類                                                                                                                                           |
| 正本参照（SSOT） | `schema_ref: docs/specdojo/schemas/v1/register-item-frontmatter.schema.yaml#/$defs/ItemType`。CLI の対応確認先: `src/register/item.ts#VALID_TYPES` |
| 説明             | 何を追跡し、どの結果をもって通常の追跡を終えるかを分ける区分。終端（完了か決定済みか）、終了を承認する人、派生ビューへの振り分けを決める           |

## 3. 値の業務的意味と使い分け

| 値               | 分類名   | 業務上の意味と使い分け                                                                                                                                                                      |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `note`           | 記録     | 共有・備忘のために継続更新する記録。審査や終了承認の対象にせず、起票済みのまま更新を続ける。対応・回答・判断が必要になったら、その内容に合う分類で別の項目を起票する                        |
| `question`       | 問い     | 回答や確認が必要な事項。回答が確定したら決定済みで終える。回答によって選択肢から方針を選ぶ必要が出たら `decision`、作業が発生したら `todo` を起票する                                       |
| `decision`       | 判断     | 既存合意の変更要求を除く、記録・追跡する意思決定。複数の選択肢から当該領域の意思決定者が決め、決定済みで終える。決定後に必要な作業は `todo` として起票する                                  |
| `issue`          | 課題     | すでに起きている問題。未発生の懸念は `risk` に分ける。対応を確認して完了で終える                                                                                                            |
| `risk`           | リスク   | まだ起きていない懸念。起きた時点で `issue` として起票する。対応完了か受容の判断により完了で終える                                                                                           |
| `change-request` | 変更要求 | 承認済みの成果物・仕様・計画を変える要望。選択肢の比較を伴っても、既存合意の変更を求める場合はこちらを使う。採択した変更の反映と必要な確認を終えて完了とする                                |
| `epic`           | エピック | 一つの `track` 全体の計画と、着手・完了の判断を担う項目。作業そのものは `derived_from` でつないだ子 `todo` で行う。子の状態からは自動で完了せず、子項目と Schedule を見て人が完了を判断する |
| `todo`           | 作業     | 実施することが決まっている具体的な作業。やるかどうか自体が未定なら `question` か `decision`、仕様・計画の変更要望なら `change-request` を使う。対応を確認して完了で終える                   |

## 4. 関連仕様との関係

- 業務データ辞書: 第1章の辞書の `item_type` に対応し、分類名と意味を同辞書の論理名・ラベルに合わせる。
- 状態定義: 分類別の終端・終了承認者・継続記録は [[prj-0001:stsd-register-entry|ステータス定義（登録項目個票）]] を参照する。
- 派生ビュー: 分類は登録簿の一覧・派生ビューの振り分けに使われる。生成処理は `src/register/register.ts` が参照する実装を正とする。
- 変更影響: 値・意味・振り分けを変更するときは、BA・PO が区分方針、ARC・DEV が辞書・状態定義・スキーマ・CLI・派生ビューの更新要否と既存個票への影響、QE が選定境界を確認する。不整合は実行結果へ残す。
- 照合: 正本のファイル・定義位置が解決でき、各正本値に業務説明が過不足なく対応し、CLI の許容値が同じ集合であることを確認する。確認結果と承認前に残る照合は [[prj-0001:pjr-7zzr-cdt-register-type-refine-confirmed-kata|PJR-7ZZR の対応結果]] を参照する。
