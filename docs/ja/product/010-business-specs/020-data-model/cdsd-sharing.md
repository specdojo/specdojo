# 概念データストア定義（活用と共有）

## 1. 概要

活用と共有で扱う概念データストアのうち、正本から再生成する派生情報、監査履歴、人が確定する報告記録について、業務上の役割、内容、粒度、更新責務を一覧で定義する。BA は報告に使う情報の位置づけの確認に、ARC は直接編集してよいデータストアと再生成するデータストアの区別を設計の基礎に、QE は陳腐化・未転記の確認対象の識別に利用する。

- 本書は進捗監視・報告・ログ管理の CDFD に記載していた情報の正本・参照情報・更新責務の詳細を移設したものである。
- 派生情報は正本から再生成するものであり、本書のデータストアから正本へ逆に書き戻さない。正本は [[prj-0001:cdsd-planning|概念データストア定義（プロジェクトの立上と計画）]] と [[prj-0001:cdsd-execution|概念データストア定義（プロジェクト実行）]] を参照する。
- _TODO_: 成果物本体と成果物索引のデータストアは、対応する業務データ辞書の作成時に追加する。

## 3. 正本区分と更新責務

| データストア名     | 位置づけ                                        | 主な生成・再構成                       | 利用時の扱い                                             | 更新責務                                             |
| ------------------ | ----------------------------------------------- | -------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------- |
| 計画派生情報       | Schedule・実行 event から再生成する計画情報     | 計画展開、派生生成                     | 同じ更新時点の集合として参照し、一部だけを手修正しない   | PM・運用担当が再生成する                             |
| 登録簿管理ビュー   | 登録項目個票から再生成する管理ビュー            | 派生生成                               | 横断監視と報告材料に使い、直接編集しない                 | BA・運用担当が再生成する                             |
| 登録項目の監査履歴 | 個票内の追記型 event から都度再構成する参照結果 | 登録簿ライフサイクル                   | 期間内の変化と報告の対応確認に使い、履歴自体は変更しない | PM・監査担当が再構成し、元の個票・event は変更しない |
| 費用・作業記録     | 費用と参加負荷への影響を判断するための記録      | 人間の記録・確認                       | 進捗報告の判断材料として参照し、報告から正本を更新しない | PM・BA が記録の所有者へ更新を委譲する                |
| 監視結果           | 監視で作る基準時点・検知・対応の作業記録        | 報告（監視入力確認〜対応整理）         | 報告記録の材料として保持し、正本の代替にしない           | PM・BA・QE が監視のたびに更新する                    |
| 進捗報告・議事録   | 人間が確定する報告記録                          | 報告（進捗報告作成、会議・議事録作成） | 状況、判断、決定、次の行動、根拠参照を記録する           | PM・BA、会議の確認者が更新・確認する                 |

監視結果と報告記録の保管先・保持期間・公開範囲は未決であり、[[prj-0001:cdfd-reporting|概念データフロー図（進捗監視・報告・ログ管理）]] の未決事項で扱う。
