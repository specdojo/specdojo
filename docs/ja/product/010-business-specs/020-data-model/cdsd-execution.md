# 概念データストア定義（プロジェクト実行）

## 1. 概要

プロジェクト実行で扱う概念データストアのうち、実行 event と定期処理・Job に関わるデータストアについて、業務上の役割、内容、粒度、更新責務を一覧で定義する。BA は実行記録の管理単位の確認に、ARC は正本と派生物の区別を設計の基礎に、QE はデータ検証・整合性確認の対象の識別に利用する。

- 本書は定期処理、進捗監視・報告の各 CDFD に記載していたデータ正本の詳細を移設したものである。
- 定期処理の実行状態の意味と due 判定・結果記録・次回判定の規則は [[prj-0001:stsd-routine-run|ステータス定義（定期処理の実行結果）]] を正本とし、本書では再定義しない。

## 2. 概念データストア一覧

| データストア名   | 対応プロセス               | 主な内容                                                                                | 更新タイミング                         | 粒度                | 主な用途                                           |
| ---------------- | -------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------- | ------------------- | -------------------------------------------------- |
| 実行 event       | タスク実行、定期処理、報告 | task の claim・complete・block・release・reopen 等の状態遷移、actor、理由、日時         | イベント（状態変更時）                 | 状態遷移毎          | task 状態の再構成、進捗・滞留の監視根拠            |
| 定期処理定義     | 定期処理                   | routine ID、enabled、interval または cron・timezone、missed run・overlap policy、action | 変更時                                 | routine 毎          | 実行機会の選択条件、委譲する action の定義         |
| routine 実行状態 | 定期処理                   | `last_run`、`last_result`、`last_scheduled_for`、配列 action の `last_action_results`   | イベント（実行試行時・結果反映時）     | routine 毎          | 次回 due 判定、実行結果の運用確認                  |
| Job Definition   | 定期処理                   | 入力定義、task、idempotency 規則、checkpoint 規則、precondition                         | 変更時                                 | Job 毎              | Job Run の生成条件と冪等性の判定                   |
| Job Run 履歴     | 定期処理、タスク実行       | Job Run ID、idempotency key、attempt、Run の状態、解決済み入力、checkpoint              | イベント（Run 生成時・attempt 終了時） | Job Run・attempt 毎 | 重複実行の防止、反復位置の引き継ぎ、実行結果の監査 |

## 3. 正本区分と更新責務

| データストア名   | 位置づけ                              | 主な生成・更新       | 利用時の扱い                                                                              | 更新責務           |
| ---------------- | ------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------- | ------------------ |
| 実行 event       | task 状態遷移の正本                   | タスク実行           | 報告・監視では参照のみ行い、状態訂正はタスク実行へ委譲する                                | task owner、PM     |
| 定期処理定義     | 定期処理の選択条件の正本              | 人間による定義変更   | 不正定義は実行対象にせず、実行状態から推測で補正しない                                    | PM、運用担当       |
| routine 実行状態 | 定期処理の実行結果の正本              | 定期処理             | 委譲前に試行を記録し、結果反映で直前結果を記録する。委譲先の記録と照合して確認する        | 運用担当           |
| Job Definition   | 反復実行単位の定義の正本              | 人間による定義変更   | Run 生成前の検証に合格した定義だけを使う                                                  | Job owner          |
| Job Run 履歴     | Job Run・attempt と checkpoint の正本 | 定期処理、タスク実行 | 完了済みの同一 Run は変更しない。checkpoint は成功した attempt の許可された範囲だけ進める | 運用担当、実行担当 |

Schedule・マイルストーンは [[prj-0001:cdsd-planning|概念データストア定義（プロジェクトの立上と計画）]]、実行 event から再生成する state・Ready・CPM・timeline は [[prj-0001:cdsd-sharing|概念データストア定義（活用と共有）]] で扱う。
