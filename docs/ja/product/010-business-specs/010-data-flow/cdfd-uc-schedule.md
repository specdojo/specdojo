# 概念データフロー図（スケジュール計画から完了まで）

[[cdfd-overview|概念データフロー図（全体概要）]] のケース `C-02`「schedule 系（成果物の作成から完了まで）」について、成果物カタログ定義から計画展開、実行、評価、完了記録と進捗・閲覧提供までの領域間の引き渡しを定める。

## 1. 目的

BA・PM と各タスクの担当者が、成果物の期待価値・完了条件から担当と実行根拠までを同じ正本で引き継ぎ、限られた参加者でも作業を分担・継承できるようにする。ARC は領域とデータストアの読み書きを設計入力に、QE は受入条件と戻り先を検証入力に使い、PO は人間が担う完了・マイルストーン・ゲートの判断境界を承認する。

## 2. 適用範囲

- **対象**: `C-02` の固有領域 P-03・P-04・P-09・P-10、共用領域 P-07・P-08・P-11・P-14 を対象に、「何を成果物として管理するかの判断が確定した」ことを入口として、計画・実行・評価を経た人間の完了判断と完了記録の確認、および要求された進捗報告・派生ビューの提供までを扱う。
- **対象外**: register・routine 系、構成管理・文書廃棄の内部、個別プロセス、操作手順、実装詳細、状態定義・遷移は扱わず、共通の責任分担・領域の区分は [[cdfd-overview|概念データフロー図（全体概要）]]、状態の定義・遷移は今後整備する `stsd-deliverable`・`stsd-task-execution`・`stsd-job-run` へ委ねる。

## 3. プロセス領域

区分・領域 ID・名称・起点イベントは全体概要の「プロセス領域」（7 区分）を正本とし、`C-02` に参加する八領域だけを示す。正常系の主経路は P-03 → P-04 → P-07 → P-08 → P-11、P-09・P-10 は各要求で起動する提供経路、P-14 は全体の調整であり、実行サイクルと Orchestrator は 3 系統が共用する同一領域として内部を展開しない。

| 全体調整 | Orchestrator     | P-14 オーケストレーター | PM が調整を担い、対話型運転は全参加者、自動運転は runner が支援する。計画・実行・評価・完了・報告・生成要求を、正本の実行状態と人間の判断に基づいて発行する。 | [[cdfd-overview\|全体概要・プロセス領域]] |

## 4. データストア

引き渡す情報と判定の根拠となる正本を全体概要と同じ名称・区分で示し、読み書きの主体を領域 ID で識別する。

### 4.1. マスタ・構成データ

| データストア             | 関連引き渡し           | 横断上の利用                                                                                                                                                            |
| ------------------------ | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 稼働構成                 | H-02                   | P-04・P-07・P-14 がメンバー・ロール、agent 定義・権限、実行既定値を参照する。                                                                                           |
| Kata / kata              | H-01〜H-04             | P-03 が定義の型、P-04 が Kata grade・作成要件、P-07 が作成・レビュー・検証の型、P-08 が rubric・評価観点を参照する。                                                    |
| 成果物カタログ / catalog | H-01〜H-04、H-06・H-07 | P-03 が成果物 ID・依存・`done_criteria`・`evidence_refs` を更新し、P-04・P-07・P-08・P-11・P-14 が対象・条件・根拠を、P-09・P-10 が提供対象を参照する。担当は持たない。 |
| スケジュール戦略         | H-02、H-05・H-06       | P-04 が既定値・phase の作業要件・`owner_rules`・ゲート・マイルストーン定義を参照・更新し、P-14 が要求の発行条件、P-09・P-11 が判断基準として参照する。                  |

### 4.2. トランザクションデータ

| データストア         | 関連引き渡し           | 横断上の利用                                                                                                                                                    |
| -------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登録簿 / register    | H-01・H-02、H-05〜H-07 | P-03・P-04 が決定記録と epic・track の対応を参照する。P-11 が完了・再計画の決定を記録し、P-09・P-10 が対応状況・生成元として参照する。                          |
| Schedule（track）    | H-02、H-05〜H-07       | P-04 がタスク・担当・期間・依存とマイルストーンを更新し、P-07・P-14 が対象タスクを、P-09・P-10・P-11 が計画を参照する。タスク状態は保持しない。                 |
| 実行計画 / plan      | H-02〜H-04             | P-04 が対象・手順・完了条件を生成し、P-07・P-08・P-11・P-14 が作業と根拠の対応を参照する。                                                                      |
| 実行記録             | H-02〜H-07             | P-07 が result・evidence・検証結果と実行状態、P-11 が完了記録、P-14 がサイクルの実行記録を更新する。P-08・P-09・P-10 と P-14 が記録済みの状態・結果を参照する。 |
| 成果物 / deliverable | H-03〜H-05、H-07       | P-07 が作成・更新し、P-08 が評価、P-11 が完了照合、P-10 が生成元として参照する。完成確定に伴う `status` の `ready` への更新は人間が行う。                       |
| 評価結果             | H-04〜H-06             | P-08 が grade・finding または評価不能理由を更新し、P-09・P-11・P-14 が最新の評価を参照する。Kata の評価情報は Kata / kata の参照に含める。                      |
| 進捗報告             | H-05・H-06             | P-09 が確認済みの進捗と判断事項を更新し、P-11・P-14 と人間が完了・再計画、マイルストーン・ゲート判断の入力として参照する。                                      |
| 派生ビュー・索引     | H-07                   | P-10 が正本との整合を確認して更新し、関係者へ閲覧提供する。進捗報告に属する生成ビューは含めない。                                                               |
