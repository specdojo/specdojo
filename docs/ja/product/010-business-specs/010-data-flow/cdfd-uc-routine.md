# 概念データフロー図（定期処理・自動運転）

[[cdfd-overview|概念データフロー図（全体概要）]] のケース `C-03`「routine 系（定期実行と Job）」について、Orchestrator のサイクル到来から定期実行判定、Job Run によるタスク生成・委譲、共用実行サイクルと次回判定の記録までの引き渡しを定める。

## 1. 目的

PM・OPS と各 Job の担当者が、反復作業の条件・手順・結果を共有し、限られた参加者でも定期確認を継続・継承できるようにする。ARC は領域と正本の読み書きを設計入力に、QE は重複・取りこぼしと再開条件を検証入力に使い、PO は自動運転の許容範囲と人間の介入境界を承認する。

## 2. 適用範囲

- **対象**: `C-03` の固有領域 P-05・P-06 と共用領域 P-14・P-07・P-08・P-11 を対象に、定義の整備、および「PDCA の各サイクルが到来した」を入口とする実行機会の選択から Job Run の生成、register・schedule 系への要求、自動実行・評価・完了と、結果・次回判定情報の記録確認までを扱う。
- **対象外**: register・schedule 系の内部、個別プロセス、コマンド・保存形式・待機時間などの実装詳細と状態定義・遷移は扱わず、共通の責任分担・7 区分は [[cdfd-overview|全体概要]]、状態は [[stsd-routine-run|定期処理の実行結果のステータス定義]] および今後整備する `stsd-job-run`・`stsd-task-execution` へ委ねる。

## 3. プロセス領域

区分・領域 ID・名称・起点イベントは全体概要の「プロセス領域」を正本とし、`C-03` に参加する六領域を示す。定義整備は P-06 → P-05 → P-14、運転は P-14 → P-07 → P-08 → P-11 → P-14 を基本とし、評価・完了要求がある場合に共用サイクルを通る（単なる時期未到来・スキップは実行結果の記録で今回の判定を終える）；P-07・P-08・P-11 と P-14 は 3 系統が共用する同一領域とし、内部を複製しない。

## 4. データストア

全体概要と同じ名称・区分の部分集合を示す。Job Run・試行履歴・前回成功情報（checkpoint）・routine の実行状態は「実行記録」に含め、独立したデータストアを追加しない。

### 4.1. マスタ・構成データ

| データストア             | 関連引き渡し     | 横断上の利用                                                                                                                                |
| ------------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 稼働構成                 | H-01〜H-04       | P-06 が実行主体・権限、P-14・P-07 が実行既定値・agent 定義と権限を参照する。運転中の自動変更は行わない。                                    |
| Kata / kata              | H-01・H-05・H-06 | P-06 が定義の型、P-07 が作成・検証の型、P-08 が評価基準を参照する。                                                                         |
| 定期実行定義 / routine   | H-02・H-03・H-07 | P-05 が周期・条件・対象 Job と次回判定の規則を更新し、P-14 が有効性・時期・取りこぼしの方針を参照する。試行に伴う状態更新は実行記録へ残す。 |
| ジョブ定義 / job         | H-01〜H-03・H-05 | P-06 が入力・手順・実行主体・成功条件を更新し、P-05 が対象 Job を、P-14・P-07 が委譲先・事前条件・同一実行の識別規則を参照する。            |
| 成果物カタログ / catalog | H-05・H-06       | 成果物を評価・完了する場合に P-08・P-11 が対象の `done_criteria`・`evidence_refs` を参照する。                                              |

### 4.2. トランザクションデータ

| データストア         | 関連引き渡し | 横断上の利用                                                                                                                                                                                                         |
| -------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登録簿 / register    | H-04・H-06   | register 系が対象・判断・対応記録を管理し、P-07 が要求対象と必要な承認を参照する。P-11 が登録項目の完了を扱う場合も同じ正本を使う。                                                                                  |
| Schedule（track）    | H-04         | schedule 系が管理するタスク・担当・依存を P-07 が参照して委譲する。タスク状態は実行記録を正本とする。                                                                                                                |
| 実行計画 / plan      | H-03〜H-06   | P-07 の受入で Job Run の解決済みタスクを計画へ具体化し、既存の登録項目・Schedule タスクの計画は各系統のものを参照する。P-08・P-11 が対象・基準を照合する。                                                           |
| 実行記録             | H-02〜H-07   | P-14 が試行開始・予定時刻・集約結果・理由・次回判定情報、P-07 が Job Run・attempt・result・evidence・成功時の checkpoint、P-11 が完了記録を更新する。P-14・P-07 は既存 Run と履歴、P-08・P-11 は判断根拠を参照する。 |
| 成果物 / deliverable | H-05・H-06   | 作成・更新を行う Job では P-07 が対象を更新し、P-08 が評価、P-11 が完了照合のため参照する。                                                                                                                          |
| 評価結果             | H-06・H-07   | P-08 が grade・finding・評価不能理由を更新し、P-11・P-14 が最新の結果を参照する。                                                                                                                                    |

## 6. 引き渡し

P-14 は定義された周期・条件・Job・権限の範囲で要求を発行し、P-07 は決定論的手順を runner、判断を agent へ割り当てる（[[sysd-job-execution|Job 実行設計]]）。H-04 の register・schedule 系への委譲は [[cdfd-uc-register|register 系 CDFD]]・[[cdfd-uc-schedule|schedule 系 CDFD]] へ接続し、Job の完了と委譲先タスクの完了を別々に追跡する。
