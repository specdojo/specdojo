# 概念データフロー図（登録簿起票から完了まで）

ケース `C-01`「register 系（登録簿起票から完了まで）」について、未整理事項の発見または意思決定から、登録項目の起票、対応、評価、人間による完了判断と完了記録までの領域間の引き渡しを定める。

## 1. 目的

BA と各領域の担当者が、担当交代時にも登録項目と判断根拠を同じ正本で引き継ぎ、起票から完了までの欠落を防ぐために、通過順と開始条件を確認できるようにする。ARC は読み書きと引き渡しを設計入力に、QE は差し戻し・保留・却下と再開条件を検証入力に使い、PO は人間による承認と完了確定の境界を承認する。

## 2. 適用範囲

- **対象**: `C-01` の P-02 → P-07 → P-08 → P-11 と、その起動・再開を調整する P-14、未整理事項の発見・意思決定から完了記録の確認まで、および epic・track による schedule 系との引き渡しを扱う。
- **対象外**: 他系統・構成管理・文書廃棄の内部、各領域の個別プロセス、補助操作、実装詳細、状態定義・遷移は扱わず、共通の責任分担は [[cdfd-overview|概念データフロー図（全体概要）]]、領域内部は [[cdfd-plan|Plan]]・[[cdfd-do|Do]]・[[cdfd-check|Check]]・[[cdfd-action|Action]]、登録項目・実行記録の状態は `stsd-register-entry`・`stsd-job-run` を正本とする。

## 3. プロセス領域

区分・領域 ID・名称・起点イベントは [[cdfd-overview|概念データフロー図（全体概要）]] の「プロセス領域」を正本とし、`C-01` に参加する次の五領域だけを示す。正常系は P-02 → P-07 → P-08 → P-11、P-14 は全体の調整役であり、実行サイクルと Orchestrator は 3 系統が共用する同じ領域として扱い、内部を複製しない。

## 4. データストア

引き渡す情報または条件判定に使う正本だけを、[[cdfd-overview|概念データフロー図（全体概要）]] と同じ名称・区分で示す。

| データストア             | 関連引き渡し | 横断上の利用                                                                                |
| ------------------------ | ------------ | ------------------------------------------------------------------------------------------- |
| Kata / kata              | H-01、H-02   | P-07 が実行・検証基準、P-08 が rubric・評価観点を参照する。                                 |
| 稼働構成                 | H-01         | P-07 がメンバー・ロール、agent 定義・権限を参照し、実行主体の権限と承認者の権限を確認する。 |
| 成果物カタログ / catalog | H-02、H-03   | P-08 が `done_criteria`・`evidence_refs`、P-11 が完了条件を参照する。                       |

### 4.2. トランザクションデータ

| データストア      | 関連引き渡し | 横断上の利用                                                                                                                                          |
| ----------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登録簿 / register | H-01〜H-04   | P-02 が登録項目・決定記録、P-07 が対応内容、P-11 が完了・決定の記録を更新し、対象と判断を対応付ける。P-08 は対応結果、schedule 系は epic を参照する。 |
| Schedule（track） | H-05         | schedule 系が生成した track 計画と epic の対応を P-02・P-14 が参照する。タスク状態は実行記録を正本とする。                                            |
| 実行計画 / plan   | H-01、H-05   | schedule 系で生成された対象・手順・完了条件を P-14 と P-07 が参照する。P-02 に計画生成の責務を置かない。                                              |
| 実行記録          | H-02、H-03   | P-07 が result・evidence・実行状態、P-11 が人間の判断後の完了記録を更新し、P-14・P-08 が参照する。                                                    |

| 進捗報告          | H-03         | schedule 系の P-09 が生成した判断事項がある場合に P-11 が参照する。register 系では生成しない。                                                        |

## 6. 引き渡し

実行・評価・完了要求は P-14 が発行し、各受け側は要求と以下の情報・条件がそろった場合だけ開始する。登録項目の承認判断は人間が担い、保留・却下は H-01 の成立とみなさず、完了確定は P-11 の PO・PM に委ねる。

| 引き渡し ID | 送り元領域                | 受け側領域                               | 引き渡す情報                                                             | 引き渡し条件                                                                                                                                                                                                                                                                                                                                                                           | 戻す条件                                                                                                                           |
| ----------- | ------------------------- | ---------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| H-01        | P-02 登録簿定義           | P-07 タスク実行                          | 対象登録項目、登録項目・決定記録、実行計画、承認結果                     | PM が対象を一意に特定でき、P-07 が計画の対象・手順・完了条件、Kata、実行主体と稼働構成の権限を確認でき、人間が対応対象を承認している。保護設定以外の保護対象の変更・統合を含む場合は、稼働構成のメンバー・ロール・権限を参照して承認者がその対象を承認できる人間であると確認でき、登録簿の決定記録で承認者・承認対象・承認結果を確認し、その対象が実行計画の変更・統合対象と一致する。 | 対象・計画・基準・実行主体・権限の不足、承認判断の保留・却下、または必要な承認者の権限・決定記録・計画との対象一致を確認できない。 |
| H-02        | P-07 タスク実行           | P-08 成果物評価                          | 対応済み登録項目、対応内容、検証結果、result、evidence、実行状態         | 対応が完了し、対象と対応内容が登録簿で対応付き、`done_criteria` ごとの評価に使う `evidence_refs`、result・evidence・実行状態と Kata の評価基準を P-08 が特定できる。                                                                                                                                                                                                                   | 評価対象が対応後に変更された、対応内容と記録を対応付けられない、必要な根拠・評価基準を取得できない、または対応完了を確認できない。 |
| H-03        | P-08 成果物評価           | P-11 タスク完了                          | 確定した評価結果、評価不能・再評価の条件、進捗報告の判断事項（ある場合） | QE が grade・finding または評価不能の範囲を確定し、対象が評価後に変更されておらず、PO と PM がカタログの完了条件と報告の判断事項を照合できる。評価不能の範囲がある場合は完了確定不可として扱い、確定した非適合の評価結果とは区別する。                                                                                                                                                 | 評価結果が未確定、対象との対応喪失、完了条件・判断事項の不足、完了を妨げる評価不能、または完了条件の未充足がある。                 |
| H-04        | P-02 登録簿定義           | schedule 系（P-03・P-04、境界）          | epic、登録項目・決定記録                                                 | PM が対象 epic と決定を登録簿で一意に特定でき、schedule 系が管理対象と計画展開の判断に参照できる。                                                                                                                                                                                                                                                                                     | epic または決定を特定できず、どの作業のまとまりを計画へ渡すか判断できない。                                                        |
| H-05        | schedule 系（P-04、境界） | P-02 登録簿定義・P-14 オーケストレーター | track 計画（epic 対応）、タスク・担当・依存、実行計画                    | P-02・P-14 が対象 epic と track の対応を確認でき、P-14 が track 上のタスクと対象・手順・完了条件を持つ実行計画を特定できる。                                                                                                                                                                                                                                                           | epic と track の対応、実行対象タスク、または実行計画を特定できない。                                                               |

agent による保護設定の変更は人間の承認があっても P-07 内で適用せず、人間または対話型 Orchestrator による実行外適用へ委ねる（[[cdfd-do|概念データフロー図（Do）]]）。

## 7. 例外時の戻り先

| 対象引き渡し | 条件不成立                                                                                     | 戻り先領域                                                    | 戻す情報                                             | 再開条件                                                                                                                                                            |
| ------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
