# 概念データフロー図（登録簿起票から完了まで）

ケース `C-01`「register 系（登録簿起票から完了まで）」について、未整理事項の発見または意思決定から、登録項目の起票、対応、評価、人間による完了判断と完了記録までの流れを定める。

## 1. 目的

未整理事項や決定事項を登録簿に残し、承認された対応から評価、完了記録までを判断根拠と対応付けることで、担当者が交代しても対応の漏れを防ぎ、判断と作業を引き継げるようにする。

## 2. 適用範囲

- **対象**: `C-01` の P-02 → P-07 → P-08 → P-11 を、未整理事項の発見・意思決定から完了記録の確認まで扱い、epic・track の対応と計画・判断材料の補完に関わる schedule 系との受け渡しを含む。
- **対象外**: 共用する実行サイクルの内部、他系統の内部、構成管理、文書廃棄、各領域の個別プロセス、補助操作、実装詳細、状態定義・遷移は扱わず、登録項目・実行記録の状態は `stsd-register-entry`・`stsd-job-run`、共通の責任分担と要求の調整は [[cdfd-overview|概念データフロー図（全体概要）]] の「適用範囲」と「Orchestrator による PDCA の調整」を正本とする。

## 3. プロセス領域

区分・領域 ID・名称・起点イベントは [[cdfd-overview|概念データフロー図（全体概要）]] の「プロセス領域」を正本とする。`C-01` の正常系は P-02 → P-07 → P-08 → P-11 とし、epic を計画へ展開する場合は P-04 と連携する。schedule 系は受け渡しに関係する領域だけを示し、実行サイクルは 3 系統が共用する一つの参加単位として扱い、内部の正本は全体概要とする。

### 3.1. register 系（P-02）

| 順序 | プロセスグループ・区分 | プロセス領域    | 横断上の役割                                                                                                                                                                                                       | 参照先                                            |
| ---- | ---------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| 1    | register 系            | P-02 登録簿定義 | 全参加者が起票でき、PM が対象と決定を一意に記録する。人間が承認した対応対象を実行へ、epic と決定記録を計画へ渡す。保留は不足情報の補完と人間の承認を待ち、却下は理由を記録して実行せず、再提案には再承認を要する。 | [[cdfd-overview\|概念データフロー図（全体概要）]] |

### 3.2. schedule 系（P-03〜P-04・P-09〜P-10）

| 順序                      | プロセスグループ・区分 | プロセス領域              | 横断上の役割                                                                                                                                    | 参照先                                            |
| ------------------------- | ---------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 補完時                    | schedule 系            | P-03 成果物カタログ定義   | 評価・完了判断に必要なカタログの完了条件・根拠参照の不足を補う。                                                                                | [[cdfd-overview\|概念データフロー図（全体概要）]] |

| 判断事項がある場合        | schedule 系            | P-09 進捗可視化報告       | 完了判断に用いる進捗報告の判断事項を渡し、対象範囲・時点の不足を補う。                                                                          | [[cdfd-overview\|概念データフロー図（全体概要）]] |

### 3.3. 実行サイクル（実行・評価・完了）（P-07〜P-08・P-11）

| 順序 | プロセスグループ・区分           | 含む領域                                          | 横断上の役割                                                                                                                                                                                                                                                                                                                                                                                                                                                          | 参照先                                                                                           |
| ---- | -------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 2〜4 | 実行サイクル（実行・評価・完了） | P-07 タスク実行・P-08 成果物評価・P-11 タスク完了 | PM が対象・計画・実行主体と権限、必要な人間の承認を確認し、owner ロールが対応・検証する。editor から独立した runner の照合と QE の評価結果を受け、PO と PM が最新の grade・finding、完了条件と判断事項を照合し、人間が review から close へ進める完了可否を確定する。対応・完了記録を返し、対象・計画・判断材料の不足や未充足は補完元へ戻す。評価不能は非適合と区別して完了確定を止める。内部の読み書き・再評価・再試行と保護設定の実行外適用の調整は参照先へ委ねる。 | [[cdfd-overview\|概念データフロー図（全体概要）]] の「プロセス領域」「概念データフロー（概要）」 |

## 4. データストア

このケースで系統と実行サイクルの間を受け渡す正本だけを、[[cdfd-overview|概念データフロー図（全体概要）]] と同じ名称・区分で示す。実行サイクル内部で使う Kata・稼働構成、実行記録・評価結果の読み書きは全体概要へ委ねる。

### 4.1. マスタ・構成データ

| データストア             | 関連する参加単位                       | 横断上の利用                                                                            |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------------------------- |
| 成果物カタログ / catalog | P-03・実行サイクル（P-07〜P-08・P-11） | P-03 が不足する完了条件・根拠参照を補い、実行サイクルへ評価・完了判断の材料として渡す。 |

### 4.2. トランザクションデータ

| データストア      | 関連する参加単位                             | 横断上の利用                                                                                                                                                                               |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 登録簿 / register | P-02・P-04・実行サイクル（P-07〜P-08・P-11） | P-02 が登録項目・承認判断・決定記録と保留・却下の理由を残し、承認済み対象を実行サイクルへ、epic と決定を P-04 へ渡す。実行サイクルから対応内容と人間が確定した完了・決定の記録を受け取る。 |
| Schedule（track） | P-02・P-04・実行サイクル（P-07〜P-08・P-11） | P-04 が生成した track 計画と epic の対応を P-02 と実行サイクルへ渡す。タスク状態は実行記録を正本とする。                                                                                   |
| 実行計画 / plan   | P-04・実行サイクル（P-07〜P-08・P-11）       | P-04 が対象・手順・完了条件を生成・補完し、実行サイクルへ渡す。P-02 に計画生成の責務を置かない。                                                                                           |
| 進捗報告          | P-09・実行サイクル（P-07〜P-08・P-11）       | P-09 が生成・補完した判断事項がある場合に実行サイクルへ渡す。register 系では生成しない。                                                                                                   |
