# システム化機能一覧（全体構成）

本書は、SpecDojo が CLI と runner で実現するシステム化機能の全体構成と一覧を定義する。各機能を業務プロセス領域と CLI コマンド群へ対応付け、機能分割・コンポーネント設計、テスト対象の網羅確認、個別機能仕様（`sf-<term>`）への入口として使う。

## 1. 目的と対象範囲

業務プロセス領域ごとにシステムが担う責務を確定し、業務仕様からの漏れと機能間の責務の重なりを一覧で判断できるようにする。これは [[prj-0001:prj-overview|プロジェクト概要]] の、課題を実行可能な仕様へつなぐこと（`BV-01`）と、作業と判断を分担・継承できること（`BV-03`）に対応する。

| 区分   | 範囲                                                                                                                                                                                |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象   | SpecDojo CLI のコマンド群と、runner が自動で行う処理（agent 起動、検証、記録、統合、派生生成）。業務プロセス領域 `P-01`〜`P-14` のうち、システムが記録・検証・生成・起動を担う部分  |
| 対象外 | 人間が行う判断（スコープ・受入の承認、`ready` への昇格、構成変更の承認、非推奨化の判断）、外部 agent 製品と Git・エディタなど外部ツールの内部処理、個別機能の入出力・振る舞いの詳細 |

- 読者: 機能分割とコンポーネント設計を行う ARC、実装範囲を確認する DEV、テスト対象を洗い出す QE、業務仕様との対応を確認する BA。
- 承認: 人間の PO（indie）がシステム化のスコープを承認する。本書の確定は `status` の昇格と同じく人間の判断とする。

## 2. 機能構成

業務プロセス領域の ID は [[prj-0001:dct-business-model-bps|成果物カタログ（業務モデル／業務プロセス仕様）]] の区分に従う。機能領域は関連する業務プロセス領域をまとめて分け、計画（`P-03`・`P-04`）と可視化（`P-09`・`P-10`）のように責務の異なる処理は別の領域にする。領域の略号は機能 ID の `<AREA>` に使う。

| 機能領域         | 略号    | 業務プロセス領域       | システムの責務                                                                         | 人間に残す判断                     |
| ---------------- | ------- | ---------------------- | -------------------------------------------------------------------------------------- | ---------------------------------- |
| プロジェクト構成 | `SETUP` | `P-01`・`P-12`         | 導入時の構成・Kata・開発環境を配置し、承認済みの構成変更を反映して利用可能性を検査する | 導入条件と構成変更の承認           |
| 登録簿           | `REG`   | `P-02`                 | 登録項目・決定記録の起票、状態遷移、履歴を記録する                                     | 起票内容と対応方針                 |
| 計画             | `PLAN`  | `P-03`・`P-04`         | 成果物カタログを検証・表示し、カタログと戦略から Schedule と実行計画を展開する         | 成果物として管理する対象と完了条件 |
| 定期実行         | `ROUT`  | `P-05`・`P-06`         | 定期実行の期日を判定し、ジョブ（決定論的コマンドまたは agent 委譲）を実行・記録する    | 周期・条件・委譲の要否             |
| 実行サイクル     | `EXEC`  | `P-07`・`P-08`・`P-11` | タスクの実行受入から agent 実行、検証、統合、結果記録、評価、完了記録までを行う        | 業務上の完了承認、評価結果の受入   |
| 可視化・派生生成 | `VIEW`  | `P-09`・`P-10`         | 進捗の集計表示と、文書索引・表示ページなどの派生成果物を生成し閲覧に供する             | 進捗報告の確定                     |
| 文書の廃棄       | `DEPR`  | `P-13`                 | 非推奨化した文書を現行文書と区別できる場所へ移す                                       | 非推奨化の判断                     |
| 運転調整         | `ORCH`  | `P-14`                 | 対話型オーケストレーターを、宣言済みリポジトリだけを許可して起動する                   | PDCA の運転判断                    |

業務プロセス領域 `P-01`〜`P-14` はすべていずれかの機能領域に属し、システム化しない業務プロセス領域はない。各領域の人間の判断はシステム化の対象外とし、システムは判断の入力と結果の記録までを担う。

## 3. システム化機能一覧

CLI 列はトップレベルのコマンド名を示す。サブコマンド・引数・出力の詳細は CLI 仕様（`clis-index` 配下）と command-reference を正本とし、本書へ転記しない。

| 機能 ID       | 機能名             | 概要                                                                                              | 業務プロセス仕様                                          | CLI                                     | 個別仕様                                   |
| ------------- | ------------------ | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------- | ------------------------------------------ |
| `SF-SETUP-01` | 初期セットアップ   | 導入条件を確定し、Kata の配置と稼働構成・開発コンテナ構成を初期化する                             | `bps-init-required`                                       | `init`・`kata`・`devcontainer`          | 一覧行で要約                               |
| `SF-SETUP-02` | 稼働構成管理       | 構成変更の影響を評価し、承認済みの変更をプロジェクト設定へ反映して検査する                        | `bps-config-change-evaluation`                            | `config`・`project`                     | 一覧行で要約                               |
| `SF-REG-01`   | 登録簿管理         | 判明事項・判断・計画要求を登録項目または決定記録として起票し、状態と対応結果を追跡する            | `bps-register-required`                                   | `register`                              | 一覧行で要約                               |
| `SF-PLAN-01`  | 成果物カタログ管理 | 成果物 ID・依存・完了条件・根拠参照を検証して表示を生成し、カタログが指す成果物ファイルを用意する | `bps-planning-catalog-strategy-update`                    | `catalog`・`deliverable`                | 一覧行で要約                               |
| `SF-PLAN-02`  | スケジュール展開   | カタログ・スケジュール戦略・Kata grade から成果物ごとのタスクを Schedule に展開する               | `bps-planning-schedule-event-update`                      | `schedule`                              | 一覧行で要約                               |
| `SF-ROUT-01`  | 定期実行           | 定期実行定義の期日と条件を判定し、対象の要求やジョブを起動して記録する                            | `bps-routine-required`                                    | `routine`                               | 一覧行で要約                               |
| `SF-ROUT-02`  | ジョブ実行         | 定義済みのジョブを runner が直接実行するか agent へ委譲し、成功条件に照らして結果を記録する       | `bps-routine-job-run`                                     | `job`                                   | 一覧行で要約                               |
| `SF-EXEC-01`  | タスク実行         | タスクを選んで着手を記録し、agent 実行・検証・worktree の隔離と統合・結果と完了の記録を行う       | `bps-task-selection-preparation`・`bps-parallel-required` | `exec`・`agent`                         | [[prj-0001:sf-task-execution\|タスク実行]] |
| `SF-EXEC-02`  | 成果物評価         | editor から独立した runner が成果物と Kata を評価し、grade と finding を記録する                  | [[prj-0001:bps-deliverable-evaluation\|成果物評価]]       | `grade`                                 | 一覧行で要約                               |
| `SF-VIEW-01`  | 進捗可視化         | 報告時点の計画・実行・評価の情報から、ダッシュボードとガントチャートを生成する                    | `bps-reporting-monitoring-detection`                      | `dashboard`・`timeline`                 | 一覧行で要約                               |
| `SF-VIEW-02`  | 派生生成           | 文書索引、YAML 表示ページ、文書サイトを生成し、変更を監視して再生成する                           | `bps-derived-project-scoped`                              | `index`・`yaml-pages`・`build`・`watch` | 一覧行で要約                               |
| `SF-DEPR-01`  | 非推奨化・保管     | 非推奨化した成果物ファイルを現行の配置から外し、保管場所へ移す                                    | `bps-deprecation-process`                                 | `deliverable`                           | 一覧行で要約                               |
| `SF-ORCH-01`  | 運転調整           | 対話型オーケストレーターを provider CLI で起動し、プロジェクトが宣言したリポジトリだけを許可する  | `bps-routine-register-schedule-cycle`                     | `orchestrator`                          | 一覧行で要約                               |

- `SF-EXEC-01` はタスク完了（`P-11`）の完了記録を含む。完了可否の判断に使う評価は `SF-EXEC-02` が担い、業務上の完了承認は人間に残す。
- `deliverable` は成果物ファイルの用意（`SF-PLAN-01`）と保管への移動（`SF-DEPR-01`）の 2 機能にまたがる。コマンド群の分割は CLI 仕様で判断し、本書では機能ごとに行を分ける。
- 個別仕様は代表 1 件（`sf-task-execution`）だけを作成する方針（PJR-2GD6）とし、その他の機能は一覧行の要約を正とする。詳細化が必要になった機能は、成果物カタログへ `sf-<term>` を追加してから作成する。
