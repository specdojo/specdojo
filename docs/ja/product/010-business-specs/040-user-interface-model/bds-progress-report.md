# 帳票仕様（週次進捗報告）

## 1. 概要

週次進捗報告は、プロジェクトの 1 ISO 週分の作業の完了・進行・課題・翌週予定を、記録からまとめた報告である。読み手は前週からの変化と残る課題を同じ形式で確かめ、翌週の優先度と担当を判断する。作業と判断を特定の参加者の記憶に頼らず共有する手段として、[[prj-0001:prj-overview|プロジェクト概要]] の `BV-03`（無理のない継続）に対応する。

## 2. 読み手と利用目的

| 読み手                       | 利用目的                                           | 帳票から判断すること                                   |
| ---------------------------- | -------------------------------------------------- | ------------------------------------------------------ |
| PM                           | 週ごとの進み具合と停滞を同じ観点で定点観測する     | 停滞・遅延している作業、翌週に割り当て直す担当と期日   |
| PO                           | 成果物の完成状況と課題を確認する                   | 翌週に優先する成果物、範囲や順序の見直しが要る課題     |
| 各ロールの担当・将来の貢献者 | 自分が関わる作業の状態と、前週に決まったことを知る | 引き継ぐ作業、着手できる作業、確認を求められている事項 |

- 作成責任は PM とする。報告は AI Agent が Job から作成し、PM が内容を確認する。報告の本文で業務判断を確定しない。
- 個人の作業量の評価や、外部への公開報告には使わない。公開可否は人が判断する。

## 3. 出力の時期と契機

- 契機: routine `rtn-weekly-report` が毎週金曜 17 時（`Asia/Tokyo`）に Job `job-weekly-report` を起動する。契機と入力の定義は `rtn-weekly-report.yaml`・`job-weekly-report.yaml`、扱いの正本は [[specdojo:routine-operation-guide|routine運用ガイド]] と [[prj-0001:sysd-job-execution|Job実行設計]] の「週報作成」とする。
- 対象期間: 起動予定時刻が属する ISO 週（例: `2026-W32`）を 1 期間とする。週の計算は routine のタイムゾーンを基準にし、実行端末のローカル時刻に依存しない。
- 取りこぼし: 端末や外部スケジューラの停止中に過ぎた週も、再開後に 1 週ずつ作る。各週の報告を欠かさないためである。
- 再出力: 同じ週の再実行は同じ Job Run の再試行として扱い、別の報告を増やさない。手動では `exec run --job job-weekly-report` に期間を渡して作成できる。
- 重複起動: 同じ project の実行が動作中なら起動を見送り、次の起動機会に委ねる。

_ASSUMPTION_: 現在 `rtn-weekly-report` は `enabled: false` のサンプル定義であり、定期起動では報告が作られない。本書は有効化後の動作を記述する。

_UNDECIDED_: 金曜 17 時の起動時点では ISO 週の土日と金曜夜が未経過である。期間の終点を起動時点とするか、週末までとして翌週に補うかは未決である。

## 4. 出力形式と提供方法

- 形式: Markdown 文書。本文の章立て・ID・ファイル名の規則は [[specdojo:pr-rulebook|進捗報告 作成ルール]] を正本とする。
- 保存先: project の `base_path` を起点とする `reporting/progress-reports/`。保存先ディレクトリは、報告を作る AI Agent が初回の保存時に作る。
- 単位: 1 ISO 週につき 1 件。期間で一意な文書として保存する。
- 提供方法: プロジェクトのリポジトリ内の文書として読み手が参照する。メール送付や外部への配信は行わない。

## 5. 対象範囲と元にする記録

対象は 1 project の、対象期間内の記録とする。他の project の記録、対象期間外に完了した作業は含めない。

| 記録                      | 用途                                     | 正本                                                                 | 欠けるときの扱い                                   |
| ------------------------- | ---------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------- |
| Schedule・exec の完了実績 | 完了事項と進行中事項を特定する           | exec の状態記録（[[specdojo:exec-operation-guide\|exec運用ガイド]]） | 読めない場合は報告を作らずに停止し、推測で補わない |
| 登録簿の状態変化          | 課題・依頼の起票・完了・保留を特定する   | 登録簿の個票と状態変化の記録                                         | 同上                                               |
| Schedule の未完了タスク   | 翌週予定を特定する                       | Schedule の定義と exec の状態記録                                    | 同上                                               |
| 前回の週次進捗報告        | 前週との差分と、持ち越した課題を確かめる | `reporting/progress-reports/` の前回分                               | 初回など前回分がない場合は差分を「前回なし」と記す |

- routine の実行履歴は端末側だけに保存され、Git で共有されないため、報告の元にする記録に使わない。
- _ASSUMPTION_: 「欠けるときの扱い」の停止は、記録を推測で補わないという本書の方針による。Job の実装上の失敗の扱いは確認していない。

## 6. 表示項目

下表は各項目の意味と出所を定める。

| No  | 区分   | 項目名           | 意味・定義                                               | 元にする記録                         | 記録からの確かめ方                                                     |
| --- | ------ | ---------------- | -------------------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------- |
| 1   | 見出し | 報告期間         | 対象の ISO 週と、その開始日・終了日                      | Job Run の入力（期間）               | Job Run の期間と一致し、開始日が月曜・終了日が日曜であることを照合する |
| 2   | 見出し | 対象プロジェクト | 報告対象の project ID                                    | Job Run の対象 project               | Job Run の対象と一致することを照合する                                 |
| 3   | 明細   | 完了事項         | 期間内に完了したタスク・成果物と、その ID                | Schedule・exec の完了実績            | 期間内に完了へ遷移したタスクの集合と、過不足なく一致することを照合する |
| 4   | 明細   | 進行中事項       | 期間末時点で着手済み・未完了のタスクと、止まっている理由 | Schedule・exec の完了実績            | 期間末時点で実行中・停止中のタスクの集合と一致することを照合する       |
| 5   | 明細   | 登録簿の状態変化 | 期間内に起票・完了・保留となった登録簿項目               | 登録簿の状態変化                     | 期間内の状態変化の記録と一致することを照合する                         |
| 6   | 明細   | リスク・課題     | 影響度と対応方針を付けた未解決のリスク・課題             | 登録簿の状態変化、前回の週次進捗報告 | 未完了の登録簿項目と前回の持ち越し課題に対応することを照合する         |
| 7   | 明細   | 次期予定         | 翌週に着手・完了を予定する作業、担当、期日               | Schedule の未完了タスク              | 未完了タスクの ID・担当ロールと一致することを照合する                  |

_UNDECIDED_: 「登録簿の状態変化」を進捗報告のどの章に置くかは、進捗報告の rulebook で定めていない。

## 7. 集計・算出ルール

- 期間への割り当て: 記録の日時を `Asia/Tokyo` に換算し、対象 ISO 週に含まれるものを数える。
- 完了の数え方: 期間内に完了へ遷移したタスクを 1 件と数える。期間内に差し戻して再び完了したタスクも 1 件とする。
- 前週との差分: 前回の報告のリスク・課題のうち、今回も未解決のものを持ち越しとして示す。
- 進捗率: 割合は表示しない。進捗報告の rulebook が根拠のない進捗率を禁じており、本帳票では分母を定義しないためである。
- 端数処理: 件数のみを扱うため該当しない。

## 8. 例外と注意事項

| 状況                               | 報告の扱い                                                           | 対応する役割と次の手                                      |
| ---------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------- |
| 期間内に完了・状態変化がない       | 報告を作り、該当する項目に「該当なし」と書く                         | PM が停滞の理由を確認し、リスク・課題に記す               |
| 停止中に複数の週が過ぎた           | 過ぎた週ごとに 1 件ずつ作る                                          | PM が各週の報告で期間の取り違えがないことを確認する       |
| 同じ週を再出力する                 | 同じ週の報告を更新し、別の報告を増やさない                           | PM が更新前後の差分を確認する                             |
| 実行中の作業があり起動が見送られた | その回は報告を作らず、次の起動機会に作る                             | PM が報告の有無を確認し、必要なら手動で作成する           |
| 報告の作成が失敗した               | 報告を作らない。失敗の記録は Job Run または routine の失敗記録に残る | PM が失敗の記録を確認し、原因の解消後に同じ週を再実行する |
