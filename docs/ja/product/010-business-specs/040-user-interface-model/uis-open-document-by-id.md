# 画面仕様（VS Code の ID で文書を開く入力）

## 1. 概要

VS Code 拡張のコマンド「SpecDojo: Open Document by ID」で、利用者が文書 ID を入力し、その ID の文書をエディタで開く入力画面である。ファイルの置き場所を知らなくても、wikilink や plan に書かれた ID から文書へ移れるようにする。

- 対象はワークスペースとして開いたリポジトリの 1 つ目のフォルダと、その `.specdojo/doc-index.json`（文書索引）である。索引は拡張の起動時に読み、索引のファイルが作られたとき・変わったときに読み直す。
- 索引の作成は CLI の `specdojo index build` が担い、本画面では扱わない。

## 2. 対象ユーザー/利用目的

| 対象ユーザー                  | 利用場面・目的                                                       |
| ----------------------------- | -------------------------------------------------------------------- |
| 文書の作成者・確認者          | plan・result・個票・grade の指摘に書かれた ID の文書を開いて確かめる |
| orchestrator を操作する利用者 | 登録簿や成果物カタログの ID から対象の成果物を開く                   |

権限による操作の差はない。ワークスペースを開いた VS Code の利用者は誰でも使える。

## 3. 表示項目

| 項目名     | 種別 | 表示内容                                                                                 | 編集可否 | 初期値・表示条件・更新契機                              |
| ---------- | ---- | ---------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------- |
| 案内文     | 状態 | `Enter a SpecDojo document ID`                                                           | 不可     | 入力欄を開いている間                                    |
| 入力例     | 状態 | `e.g. specdojo:prj-overview-rulebook or prj-0001:pm-roles`                               | 不可     | 入力欄が空の間                                          |
| 文書 ID    | 入力 | 開きたい文書の ID                                                                        | 可       | 初期値は空。コマンドを実行するたびに空から始まる        |
| 警告       | 状態 | 索引がないとき、または ID が見つからないときの文言（「エラー表示と利用者の次の手」の表） | 不可     | 確定した入力で文書を開けないとき                        |
| 開いた文書 | 状態 | 索引がその ID に対応づけたファイル                                                       | 可       | 開いた時点のカーソルは索引の行番号の行、なければ 1 行目 |

## 4. 操作

| 操作名         | 対象                                                | 前提条件           | 結果                                                                        |
| -------------- | --------------------------------------------------- | ------------------ | --------------------------------------------------------------------------- |
| コマンドの実行 | コマンドパレットの「SpecDojo: Open Document by ID」 | 拡張が有効         | 文書 ID の入力欄を開く                                                      |
| 入力の確定     | 入力欄で Enter                                      | 文書 ID を入力済み | 索引を確かめ、ID に対応するファイルを開く。開けない場合は警告を出して終わる |
| 取り消し       | 入力欄で Esc、または空のまま Enter                  | 入力欄を開いている | 何も表示せずに入力欄を閉じる                                                |

- 入力の確定では、索引の有無を先に確かめ、次に ID を引く。索引がなければ ID の照合はしない。
- 索引の値が `<path>:<line>` の形の ID は、その行にカーソルを置いて開く。値がパスだけの ID は 1 行目で開く。
- 入力欄は確定の時点で閉じ、警告の後に入力は残らない。入力し直すにはコマンドを実行し直す。

## 5. 遷移

| 遷移名     | 契機                | 遷移元           | 遷移先         | 条件                         | 引き渡し情報・入力の扱い           |
| ---------- | ------------------- | ---------------- | -------------- | ---------------------------- | ---------------------------------- |
| 入力開始   | コマンドの実行      | コマンドパレット | 入力欄         | なし                         | なし。入力欄は空                   |
| 文書を開く | 入力の確定          | 入力欄           | エディタの文書 | 索引があり、ID が索引にある  | 索引のパスと行番号。入力欄は閉じる |
| 警告で終了 | 入力の確定          | 入力欄           | 元の画面と警告 | 索引がない、または ID がない | なし。入力した ID は保持しない     |
| 取り消し   | Esc、空のままの確定 | 入力欄           | 元の画面       | なし                         | なし。入力を破棄する               |

## 6. バリデーション

| 対象                 | 必須性 | 条件                                                                                 | 判定時点   | 違反時の扱い                     |
| -------------------- | ------ | ------------------------------------------------------------------------------------ | ---------- | -------------------------------- |
| 文書 ID の入力       | 必須   | 1 文字以上                                                                           | 入力の確定 | 何も表示せずに閉じる（取り消し） |
| 索引の有無           | 必須   | ワークスペースを開いていて、索引を読めて、項目が 1 件以上ある                        | 入力の確定 | 「索引なし」の警告               |
| 文書 ID と索引の一致 | 必須   | 入力した文字列が索引の ID と完全に一致する。名前空間（`prj-0001:` など）も含めて書く | 入力の確定 | 「ID 未登録」の警告              |

- 書式の検査はしない。前後の空白や大文字小文字の違いも補わず、そのまま照合する。
- wikilink とちがい、名前空間のない ID を所属プロジェクトの ID に読み替えない。プロジェクトの文書は `prj-0001:pm-roles` のように名前空間をつけて入力する。名前空間のない ID（`bds-progress-report` など）は、そのままの ID で索引にある文書だけが開く。

## 7. エラー表示と利用者の次の手

| エラー事象   | 発生条件                                                                                   | 表示要点                                                                        | 状態の扱い                   | 利用者の次の手                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 索引なし     | ワークスペースを開いていない、索引のファイルがない・JSON として読めない、または項目が 0 件 | 警告「SpecDojo index not found. Run: specdojo index build」                     | 入力を破棄し、文書は開かない | リポジトリをワークスペースとして開き、リポジトリのルートで `specdojo index build` を実行してから、コマンドを実行し直す |
| ID 未登録    | 索引はあるが、入力した ID と完全に一致する項目がない                                       | 警告「ID not found: `<id>`」。`<id>` は入力した文字列                           | 入力を破棄し、文書は開かない | ID の綴りと名前空間を確かめて入力し直す。新しく足した文書なら `specdojo index build` で索引を作り直してから開く        |
| ファイルなし | 索引にある ID のファイルが、名前の変更や削除でなくなっている                               | _UNDECIDED_: 拡張は独自の表示を持たず、VS Code のコマンド失敗の表示に任せている | 文書は開かない               | `specdojo index build` で索引を作り直し、ID から開き直す                                                               |

## 8. メモ / 将来課題

- _UNDECIDED_: 索引のファイルを消しても、拡張は読み込み済みの索引を使い続ける（読み直すのは作成と変更のときだけ）。消した後も「索引なし」にならず古い対応で開く点を、仕様として許すか、削除でも読み直すかは決まっていない。
- _UNDECIDED_: 「ファイルなし」のときに、拡張が独自の警告と次の手（索引の作り直し）を出すかは決まっていない。
- 複数フォルダのワークスペースでは 1 つ目のフォルダだけを対象にする。2 つ目以降のフォルダの文書を開く手段は本画面の対象外とする。
