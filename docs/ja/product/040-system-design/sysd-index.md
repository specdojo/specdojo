# SpecDojo システム設計索引（SYSD Index）

本書は、SpecDojo のシステム設計における正本（SSOT: Single Source of Truth）、自動生成物、変更の入口、および関連仕様への導線を 1 箇所に集約するシステム設計索引（SYSD Index）である。設計情報をコード・スキーマ・宣言的定義ファイルへ寄せる運用（Code as Spec）に基づき、各設計要素の詳細は正本へ委ね、本書では正本の所在、非該当理由、更新責任と変更時の確認経路を示し、担当交代時の調査と二重管理を減らす。

## 1. 概要（対象範囲・更新責任）

パスはリポジトリルート基準とし、`schedule/`・`jobs/` 等のプロジェクト内略記は `docs/ja/projects/prj-0001/` 配下を指す。対象範囲は、SpecDojo CLI 本体（`src/`）、JSON Schema 群（`docs/specdojo/schemas/v1/`、`docs/ja/specdojo/schemas/v1/`）、静的ドキュメントサイト生成（`packages/docs-site/`）、VS Code 拡張（`packages/vscode-specdojo/`）、外部 AI エージェント実行基盤、Git / worktree 統合、および反復ジョブ（Job）・定期処理（Routine）・継続品質評価（Grade）である。

### 1.2. 主要略語

- **SSOT（Single Source of Truth）**: 各設計・実装要素について最優先で更新・参照する唯一の正本。
- **SYSD（System Design）**: システム設計（`sysd-index`、`sysd-cross-cutting-policy`、`sysd-critical-flows`、`sysd-*`）。
- **TSD（Technology Stack Definition）**: 技術スタック定義（`tsd-index`、`tsd-*`）。
- **CDFD / CDSD / STSD**: 概念データフロー図（Conceptual Data Flow Diagram）/ 概念データストア定義（Conceptual Data Store Definition）/ 状態遷移仕様（State Transition Specification）。
- **IFX / CLIS**: 外部インターフェース仕様（External Interface Specification）/ CLI 仕様（Command Line Interface Specification）。
- **NFR / OPD / OPR / DEC**: 非機能要件（Non-Functional Requirements）/ 運用方針・設計（Operations Policy and Design）/ 運用手順（Operations Procedure）/ 決定記録（Decision Record）。
- **PJR / CPM**: プロジェクト登録簿（Project Register）/ クリティカルパス法（Critical Path Method）。

## 4. 変更の入口（典型ケース）

設計・実装の変更時は、下表のトリガーに対応する SSOT を最初に更新し、追従する生成物・関連文書を同期したうえで、指定の検証コマンドと対象テストケースが期待結果を満たすことで完了を判定する。コマンドはリポジトリルートで実行し、テストの実行区分は単体・統合の各 script に従う。下記は将来の変更時の手順であり、本書編集時の実行済み証跡ではない。
