# コミュニケーション計画 作成ルール

Communication Plan Documentation Rulebook

関係者が必要な時点で判断・確認・共有できるよう、コミュニケーション機会と証跡を最小構成で定義するルールです。ステークホルダー情報や会議・報告・チャネルを重複管理しません。

## 1. 全体方針

- ステークホルダー登録簿の情報要求から、実際に必要なコミュニケーションだけを抽出します。
- 会議体、報告、通知を別々に網羅せず、「誰に何をいつ伝えるか」の一表へ統合します。
- 定例会議は必須とせず、非同期確認で成立する場合は証跡だけを定めます。
- 関係者の期待・懸念・影響度、Role code の定義、個人連絡先は本書へ複製しません。
- 重要判断、当事者確認、費用・負荷の合意、公開判断が伝達漏れにならないことを優先します。
- AI Agent は草案や整理を支援できますが、合意・承認・公開判断は人間が行います。

## 2. 位置づけと用語定義

| 用語                   | 定義                                                         |
| ---------------------- | ------------------------------------------------------------ |
| コミュニケーション機会 | 判断、確認、共有、相談が必要になるイベントまたは作業節目     |
| 対象                   | 情報を受け取り、確認または判断する関係者・Role code          |
| 証跡                   | 合意、判断、確認結果を後から追跡できる記録                   |
| エスカレーション       | 所定の条件で、一次対応から人間の最終判断者へ判断を上げること |

## 3. ファイル命名・ID規則

- ID は `<project-id>:pm-communication-plan`、ファイル名は `pm-communication-plan.md` とします。
- 関係者はステークホルダー ID、責任主体は採用済み Role code で記述します。

## 6. 記述ガイド

### 6.1. 方針と適用範囲

- 対象プロジェクト、主要な関係者、必要な合意の種類を要約します。
- 常設会議を置くか、作業節目の非同期確認を基本とするかを示します。
- 個人名や連絡先ではなく、ステークホルダー ID または Role code を使います。

### 6.2. コミュニケーション機会

| 対象・機会 | 伝える・確認する内容 | タイミング | 手段 | 責任 | 証跡 |
| ---------- | -------------------- | ---------- | ---- | ---- | ---- |

- ステークホルダー登録簿の情報要求を転記せず、実施する機会へ変換します。
- 会議、報告、通知を同じ表で扱い、同じ内容を複数行へ重複させません。
- 対象者が判断または確認できる内容と、結果の記録先を明記します。

### 6.3. エスカレーション

| 条件 | 一次対応 | 最終判断 | 証跡 |
| ---- | -------- | -------- | ---- |

- 目的・スコープ、当事者価値、費用・負荷、品質・安全、公開・権利など判断者が変わる条件を分けます。
- 緊急度よりも、誰の判断が必要かを基準にします。
- Agent 出力の疑義は人間の成果物責任者または最終判断者へ上げます。

### 6.4. 情報管理と公開

| 情報区分 | 取扱い | 記録先 |
| -------- | ------ | ------ |

- 公開、限定共有、記録禁止など、必要な区分だけを定義します。
- 個人情報、秘密情報、認証情報を公開記録や Agent 入力へ含めません。
- 正本と生成ビューがある場合は、正本側で更新して再生成します。

### 6.5. 見直し条件と未決事項

- ステークホルダー、判断ゲート、公開方針、連絡手段が変わった場合に見直します。
- 未決事項は _UNDECIDED_: とし、決定時期と判断者を添えます。
- 日常的に追跡する課題は本書ではなく登録簿へ移します。

## 7. 禁止事項

| 禁止事項                                           | 理由                                   |
| -------------------------------------------------- | -------------------------------------- |
| ステークホルダー登録簿やRole code一覧を再掲する    | 正本が分散するため                     |
| 会議体、報告、チャネルへ同じ情報を重複記載する     | 更新漏れと過剰な運用を招くため         |
| 目的や証跡のない定例会議を必須にする               | コミュニケーション自体が負荷になるため |
| エスカレーション条件を「必要に応じて」とだけ書く   | 判断時点が不明になるため               |
| Agent に合意、承認、公開判断を委ねる               | 人間の判断責任を代替するため           |
| 個人名、連絡先、秘密・認証情報、実装詳細を記載する | 公開適性と文書責務に反するため         |
