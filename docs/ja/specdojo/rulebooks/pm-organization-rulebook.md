# 組織定義 作成ルール

Organization Definition Documentation Rulebook

プロジェクトの目的に必要な意思決定・実行・確認の分担方針を定義するルールです。Role code やmember一覧を再掲せず、体制の設計根拠と正本だけを示します。

## 1. 全体方針

- プロジェクト規模、関係者、判断の複雑さに合う最小体制を定義します。
- 組織図や役職の網羅ではなく、価値判断、実行、品質確認、公開・運用の責任境界を示します。
- Role code はロール定義、実行主体と兼務はメンバー定義、成果物・プロセス責任は RACI を正本とします。
- 小規模では兼務を認めますが、最終判断と実作業の責任を概念上は分けます。
- AI Agent は実行支援者であり、最終承認、当事者価値、公開可否、説明責任を担いません。
- 参加者や責務が増えた場合に、軽量体制から分担体制へ拡張する条件を示します。

## 2. 位置づけと用語定義

| 用語       | 定義                                                   |
| ---------- | ------------------------------------------------------ |
| 組織モデル | 意思決定、実行、確認をどの責任領域へ分けるかという設計 |
| Role code  | Schedule owner や RACI で使う責任語彙                  |
| 実行主体   | 実際に作業する人、チーム、または支援する Agent         |
| 兼務       | 一つの実行主体が複数の Role code を担うこと            |

## 3. ファイル命名・ID規則

- ID は `<project-id>:pm-organization`、ファイル名は `pm-organization.md` とします。
- Role code、member nickname、Schedule owner の形式は組織関連標準と各YAML正本に従います。

## 6. 記述ガイド

### 6.1. 組織モデル

| 責任領域 | 設計方針 | 最終判断 | 実行・確認 |
| -------- | -------- | -------- | ---------- |

- 目的達成に必要な責任領域だけを示し、全Role codeを列挙しません。
- 当事者・利用者による価値確認と、プロジェクト内部の管理責任を区別します。
- 兼務する場合も、最終判断と実行・確認を読み分けられるようにします。

### 6.2. ロール・owner方針

- Schedule owner と RACI 列には、ロール定義に存在する Role code だけを使います。
- Role code の採用は専任memberの配置を意味しないことを明記します。
- 実行主体、兼務、Agent利用はメンバー定義へ委譲します。

### 6.3. 正本と責任境界

| 情報 | 正本 | 本書で扱うこと |
| ---- | ---- | -------------- |

- ロール語彙、実行主体、責任分担、関係者の正本を分けます。
- 正本の内容を要約・複製せず、組織設計上の使い分けだけを書きます。
- Scheduleや個別成果物の責任割り当ては本書に持ち込みません。

### 6.4. 見直し条件

| トリガー | 確認すること | 更新先 | 判断者 |
| -------- | ------------ | ------ | ------ |

- 目的・スコープ、関係者、参加者、作業滞留、公開・運用責任の変化を扱います。
- 新しいRole codeを増やす前に、既存責任の再配分で対応できるか確認します。
- 体制変更はロール、メンバー、RACI、Scheduleの必要な正本だけへ反映します。

## 7. 禁止事項

| 禁止事項                                             | 理由                             |
| ---------------------------------------------------- | -------------------------------- |
| Role code、member、RACIの一覧を再掲する              | 正本が分散するため               |
| member nickname、人名、agent名をSchedule ownerにする | 責任語彙と実行主体を混同するため |
| 兼務を理由に最終判断者を曖昧にする                   | 説明責任が不明になるため         |
| Agentに最終承認、当事者価値、公開可否を委ねる        | 人間の判断責任を代替するため     |
| 必要性を示さずRole codeや階層を増やす                | 小規模運用の負荷を増やすため     |
| 個人情報、秘密情報、アクセス情報を記載する           | 公開適性に反するため             |
