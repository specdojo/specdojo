# 影響調査（I/F）作成ルール

Impact Analysis (Interface) Rulebook

変更要求による I/F への影響を整理し、変更要否・影響度・対応方針・未解決事項を判断するための記述基準を定めます。

## 1. 全体方針

- I/F 責任者とプロジェクト管理者が合意できる粒度で、影響と判断根拠を記載する。
- 複数の連携方式を扱う場合も影響詳細は I/F 単位とする。データ仕様・テスト仕様・運用手順への波及は概要と判断を示し、詳細は各文書へ委ねる。
- **共通の運用**: 役割は適用先のメンバー定義、`status`・承認・改訂と廃止・未決事項の引き継ぎは [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。文書の整形・lint はリポジトリの検証で扱う。

## 2. 位置づけ

起票済みの要求・課題を含む変更要求を受け、連携先との契約・互換性・障害波及・利用者への影響を判断する。詳細な実装設計は扱わない。

## 3. ファイル命名・ID規則

- 対象ドキュメント ID は `<project-id>:imp-interface` とする（例: `prj-0001:imp-interface`）。
- 推奨配置は `docs/ja/projects/<project-id>/050-impact-analysis/imp-interface.md` とし、適用先の成果物カタログに合わせる。
- 命名の共通規則は [[specdojo:id-and-file-naming-standard|ID・ファイル命名標準]] に従う。
- 関連する追補文書を分割する場合は `<project-id>:imp-interface-<term>` 形式を用いる。

## 4. 推奨 Frontmatter 項目

共通項目・必須性・型制約は [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。`type` は `project`、`rulebook` は `specdojo:imp-interface-rulebook` とする。

## 5. 本文構成（標準テンプレ）

本文は次の6章を標準とする。

| 章  | 見出し         | 必須 | 目的                                          |
| --- | -------------- | ---- | --------------------------------------------- |
| 1   | 目的と適用範囲 | ○    | 対象と判断対象範囲を明確化する                |
| 2   | 変更要求の概要 | ○    | 変更背景と要求内容を要約する                  |
| 3   | 影響分析サマリ | ○    | 影響の全体像と優先順位を俯瞰する              |
| 4   | 影響詳細一覧   | ○    | 影響対象 I/F ごとの変更要否・影響度を記録する |
| 5   | 対応方針       | ○    | 採用方針、実施条件、担当と期限を整理する      |
| 6   | 未解決事項     | ○    | 意思決定待ちや調査不足を明示する              |

## 6. 記述ガイド

### 6.1. 目的と適用範囲

- 対象変更要求の識別子、対象 I/F 範囲、対象期間を明記する。
- 「何を判断する文書か」を 2〜4 行で示す。

### 6.2. 変更要求の概要

- 変更の背景・狙い・成功条件を示す。要求詳細は判断に必要な要点に絞る。

### 6.3. 影響分析サマリ

- 契約互換性、接続先調整、障害・利用者・監査への影響などの評価観点と、高・中・低を分ける尺度を先に定義し、件数と優先対応対象を示す。

### 6.4. 影響詳細一覧

- 影響詳細は表形式で、次の6列を必須とする。

| カラム      | 内容                                                   |
| ----------- | ------------------------------------------------------ |
| 影響対象I/F | 影響を受ける I/F 対象（API、ファイル、メッセージなど） |
| 変更要否    | `要` / `否`                                            |
| 影響度      | `高` / `中` / `低`                                     |
| 対応方針    | 実施・代替・見送りなどの方針                           |
| 判断根拠    | 判定理由の要点                                         |
| 備考        | 制約、前提、関連ドキュメント                           |

### 6.5. 対応方針

- 重要度が高い項目から順に、実施時期、担当、前提条件を記載する。
- 見送りの場合は、再評価条件と時期を必ず記載する。

### 6.6. 未解決事項

- 論点、不足情報、判断・対応への影響と当面の扱いを記載する。未解決事項がなければ「なし」とする。

## 7. 禁止事項

- 実装詳細（SQL 全文、クラス名、API リクエスト構造）を記載しない。
- 「影響あり」「要対応」のみで根拠を記載しない。
- 影響度の尺度を定義せずに高・中・低を混在させない。
