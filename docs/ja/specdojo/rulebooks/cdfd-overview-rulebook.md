# 概念データフロー図（全体概要）作成ルール

Conceptual Data Flow Diagram Overview Documentation Rulebook

業務または運用の全体を、一ノード一領域のプロセス領域と領域間の情報・イベントの流れとして定義するためのルールです。対象境界を合意し、各領域を領域別 CDFD へ重複・欠落なく引き渡せる粒度を定めます。

## 1. 全体方針

- 全体概要は、業務または運用を構成するプロセス領域、領域間の受け渡し、外部主体、人間の判断境界を合意する概念仕様とします。
- 一つのプロセス領域を一覧表の一行と Mermaid 図の一つの代表プロセスノードで表し、領域内の手順、状態遷移、例外経路は領域別 CDFD へ委譲します。
- 一覧表を領域定義と分割境界の正本、Mermaid 図を領域間フローの正本として併用し、領域 ID と用語を一致させます。
- 各領域には固有の業務目的、起点イベント、主要入力、主要出力、データストア、詳細化先を割り当てます。
- 対象者、利用場面、対象範囲、対象外、AS-IS / TO-BE を明示し、人間が担う承認や最終判断をシステムまたは AI Agent に置き換えません。

## 2. 位置づけと用語定義

| 用語           | 定義                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 全体概要       | 複数のプロセス領域と相互の受け渡しを、一ノード一領域で表す最上位の CDFD                    |
| プロセス領域   | 固有の業務目的と成果を持ち、一つの領域別 CDFD へ詳細化できる責務のまとまり                 |
| 領域代表ノード | 全体概要で一つのプロセス領域を代表する角丸長方形の Mermaid ノード                          |
| 起点イベント   | プロセス領域を開始させる、発生した時点を判定できる出来事                                   |
| 領域間フロー   | 外部主体、プロセス領域、データストアの間で受け渡される情報・イベント・必要に応じた現物     |
| データストア   | 領域が参照または更新する、台帳、文書、ファイル、データベースなどの論理的な正本または保管先 |
| 補助操作       | 一覧、検索、状態参照、検証、dry-run など、独立した業務成果を作らず他の領域を支援する操作   |
| 詳細化先       | 全体概要の一領域を引き継ぎ、領域内のプロセス、判断、例外を定義する領域別 CDFD              |

全体概要は領域分割と領域間の受け渡しを定義し、領域別 CDFD は一領域の内部を詳細化します。両者で同じ領域 ID、起点イベント、主要入出力、データストアを引き継ぎます。

## 3. ファイル命名・ID規則

- ファイル名は `cdfd-overview.md`、ドキュメント ID は `<authority>:cdfd-overview` を基本とします。
- 配置は対象プロダクトの業務仕様配下にあるデータフローディレクトリを基本とし、プロジェクト固有の現状分析はプロジェクト文書配下へ配置できます。
- 領域 ID は文書内で一意な `P-01` 形式とし、一覧表、Mermaid 図、領域別 CDFD 対応表で同じ値を使います。
- 領域 ID の採番順に業務上の意味を持たせず、名称変更後も同じ責務を表す限り維持します。
- 詳細化先は `cdfd-<domain>` 形式の ID またはファイル名 stem とし、一領域から一つの領域別 CDFD を識別できる名称にします。

## 6. 記述ガイド

### 6.1. 目的と適用範囲

- 全体概要を使用する対象者と、承認、領域別詳細化、設計入力、網羅性確認などの利用場面を結び付けて記述します。
- 対象業務、開始点、終了点、組織またはシステム境界と、AS-IS / TO-BE の区分を明示します。
- 補助操作、領域内の手順、実装エビデンス、別成果物が責任を持つ事項を対象外として区別します。

### 6.2. プロセス領域一覧

<!-- prettier-ignore -->
| 列 | 記載内容 | 判定基準 |
| --- | --- | --- |
| 領域 ID | `P-01` 形式の安定した識別子 | 一覧、図、対応表で同じ ID を使う |
| プロセス領域 | 業務目的が分かる短い名称 | コマンド名や実装部品名だけにしない |
| 業務目的 | 対象者に生じる成果または維持する状態 | 手順や機能の列挙にしない |
| 主な担当 | 主担当ロールまたは外部主体 | 個人名にしない |
| 起点イベント | 領域の開始を判定できる出来事 | 「必要に応じて」で終わらせない |
| 主要入力 | 判断または処理に必要な概念情報・現物 | 物理項目やオプションを列挙しない |
| 主要出力 | 次の領域または利用者へ渡す成果・状態 | 入力と区別できる名称にする |
| データストア | 参照または更新する論理的な正本・保管先 | 媒体名だけにしない |
| 領域別 CDFD | 領域を詳細化する一意の ID または仮置き名 | 一領域を複数の詳細化先へ重複させない |

独立領域にするのは、固有の起点イベントと業務成果を持ち、他領域と区別できる入力、出力、またはデータストアがある場合です。補助操作は、独立した判断結果や更新成果を持たない限り領域にしません。

### 6.3. 概念データフロー

- 一覧表の全領域を一つずつ領域代表ノードとして配置し、同じ領域 ID と領域名を表示します。
- 各領域の起点イベント、主要データストア、必要な外部主体を配置し、領域間の情報・イベント・現物に内容を表すラベルを付けます。
- 関連領域を `subgraph` で視覚的にまとめる場合も、各領域の代表ノードを省略したり、領域内部の処理を展開したりしません。
- 図で主要入出力を省略した場合は、対象と省略理由を図の直後に記述します。
- 使用したノード形状と線種を凡例で説明し、現物を扱わない場合はその対象外を明示します。

### 6.4. 境界と分割方針

- 対象境界では、独立領域、補助操作、領域別詳細、人間の最終判断、AI Agent やシステムによる支援を区別します。
- 領域別 CDFD への対応では、一領域を一つの詳細化先へ割り当て、全体概要上の責務と、隣接領域へ委譲する事項を同じ行で示します。
- 複数領域を一つの詳細化先へ統合する例外では、統合理由、責務境界、重複・欠落の確認方法を記述します。
- 受入確認では、業務価値と対象境界の承認者、詳細化入力の利用者、重複・欠落の確認者をロールで示し、表と図から判定できる条件にします。

### 6.5. 完成判定

- 一覧表の各領域が図の領域代表ノードと領域別 CDFD 対応表へ一度ずつ登場します。
- 各領域について、起点イベント、主要入力、主要出力、データストア、詳細化先を一行で識別できます。
- 図のエッジから、領域間または外部主体との受け渡し内容と方向を説明できます。
- 補助操作と領域内詳細が全体概要へ独立領域として混入せず、委譲先が明らかです。
- 受入条件を確認者が表と図から判定でき、未決事項は確定情報と区別されています。

## 7. 禁止事項

- 一つの領域を複数の代表ノードへ分割したり、複数領域を理由なく一つの代表ノードへ統合したりしません。
- 全体概要に領域内の操作手順、状態遷移、例外分岐、物理テーブル・カラム、SQL、実装クラス、詳細 API、コマンドオプションを記載しません。
- 一覧、検索、状態参照、検証、dry-run などを、固有の業務成果がないまま独立領域にしません。
- 表、図、領域別 CDFD 対応表で、同じ領域、イベント、入出力、データストアに異なる名称を使いません。
- ラベルのない情報・現物のエッジ、起点または到達先のないエッジ、対応する一覧行のない領域代表ノードを残しません。
- 人間が責任を持つ主要判断、承認、公開可否を AI Agent またはシステムの自動処理として表しません。
- 未決事項を黙って省略したり、_TODO_: / _UNDECIDED_: / _ASSUMPTION_: 以外の独自ラベルで表したりしません。
