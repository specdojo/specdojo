# 運用手順 全体構成 作成ルール

Operations Procedure Runbook Index Documentation Rules

運用者が作業と証跡を再現できる `opr-index` の記述基準を定める。

## 1. 全体方針

- 実行手順と証跡の正本とし、方針・統制は `opd-*` に従う。
- 本文構成と記述ガイドで骨組み・記入基準が定まるため、別の recipe・template は不要とする。
- **共通の運用**: 役割は適用先のメンバー定義、`status`・承認・改訂と廃止・未決事項の引き継ぎは [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。整形・lint はリポジトリの検証で扱う。

## 2. 位置づけと用語定義

`opr-index` は手順群の入口・共通規約、`opr-<term>` は差分（具体手順・個別判断）、`opd-index` は方針を担う。

## 3. ファイル命名・ID規則

- ID は `opr-index` とする。
- ファイル名は `opr-index.md` を推奨する。
- 分冊は `opr-<term>.md`（kebab-case）とする。

## 4. 推奨 Frontmatter 項目

共通項目・必須性・型はドキュメントメタ情報標準に従う。`specdojo.type` は `operations`、必須の `specdojo.rulebook` は `specdojo:opr-index-rulebook` とする。

## 5. 本文構成（標準テンプレ）

全章必須。該当作業がなければ「対象外」と理由を示し、分冊した手順は参照で満たす。

| 章  | 内容                                             | 必須 | 受入条件                                                      |
| --- | ------------------------------------------------ | ---- | ------------------------------------------------------------- |
| 1   | 概要（index）                                    | ○    | 対象運用・目的・利用者                                        |
| 2   | 手順適用範囲・前提                               | ○    | 対象内外・時間帯・権限・環境                                  |
| 3   | 日次/週次/月次点検手順                           | ○    | 頻度別の点検対象・操作・判定                                  |
| 4   | 障害対応手順（P1/P2…、切り分け、一次対応、復旧） | ○    | 優先度別の初動 SLA・段階別操作・連絡条件と先                  |
| 5   | アラート対応手順（確認→暫定対応→恒久対応）       | ○    | 各段階の操作・誤検知の終了条件                                |
| 6   | バックアップ確認・リストア手順（演習含む）       | ○    | 確認・復元操作・演習頻度・復旧目標の達成判定                  |
| 7   | バッチ再実行・失敗時対応                         | ○    | 再実行条件・上限回数・冪等性・上限到達時の対応                |
| 8   | 運用変更作業（設定変更・デプロイ・ロールバック） | ○    | 承認者・実施条件・切戻し条件と操作                            |
| 9   | アカウント付与/剥奪手順                          | ○    | 申請・承認・実施・権限検証・記録                              |
| 10  | 問い合わせ一次対応手順（テンプレ・ナレッジ）     | ○    | 分類・回答例・参照知識・引継ぎ条件と先                        |
| 11  | 証跡（ログ、チケット、チェックリスト、実施記録） | ○    | 保存先・保管期間・参照権限・`ticket_id` / `run_id` 等の識別子 |
| 12  | 関連ドキュメント導線（`opd-index` 参照）         | ○    | 方針と分冊への導線（分冊なしも明示）                          |

## 6. 記述ガイド

- 方針と適用範囲を確認し、手順、証跡、関連導線の順に具体化する。未決の条件は該当章に論点と運用への影響を残す。
- 手順表の標準列は「実施者・入力条件・操作・完了条件・証跡」とする。良い例:「当番・再実行済み・実行 ID で結果照合・成功かつ重複なし・実行ログ」。悪い例:「適宜再実行」。
- 受入確認は各手順を検証環境で実行または模擬し、完了条件と証跡を照合する。異常時の分岐を含め、操作・判断・記録を再現でき、方針と一致すれば合格とする。

## 7. 禁止事項

- 優先度別障害対応を未定義のまま確定しない。
- 証跡要件（保存先・識別子）を省略しない。
- `opd` と矛盾する手順を独自に定義しない。
