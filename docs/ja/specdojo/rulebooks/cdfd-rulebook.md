# 概念データフロー図（プロセスグループ別）作成ルール

Conceptual Data Flow Diagram Process Group Documentation Rulebook

全体概要で定めた一つのプロセスグループを引き継ぎ、グループに属する全領域の内部プロセス、領域間の受け渡し、主要例外、グループ外への委譲を、表と Mermaid 図で合意可能にするためのルールです。状態を変えるプロセスと起動条件は示しますが、状態の定義と遷移は STSD を参照します。

## 1. 全体方針

- 一文書は、全体概要で定めた一つのプロセスグループと、そのグループに属する一つ以上のプロセス領域を詳細化します。各領域はちょうど一つのプロセスグループ別 CDFD に属します。単一領域のグループも、その領域だけを含む一つのプロセスグループ別 CDFD として扱います。
- 「プロセス領域」をプロセスの業務目的・担当・起動条件・完了条件・必須性の表の正本とし、主要入力・主要出力の箇条書きは設けず、受け渡しは概念データフロー図を正本とします。「データストア」を本グループが読み書きする上位一覧の部分集合、「個別プロセス主要入出力」をプロセス単位の入出力の正本とします。
- 一つのプロセスノードは、一つの業務目的と完了条件を持つ処理だけを表します。コマンドや画面の一操作を無条件に一プロセスへ分割せず、複数の判断・更新・生成を一ノードに詰め込みません。
- 同一グループ内の領域間の受け渡しは内部フローとして図に描きます。他グループの内部処理は展開せず、プロセスグループ別 CDFD またはユースケース別 CDFD へ委譲します。
- 状態を変えるプロセスとその起点イベントは記載しますが、状態名・成立条件・遷移元・遷移先・イベント・遷移条件は STSD を正本とし、本書では参照関係だけを示します。
- 正常系だけでなく、業務結果を変える主要例外を、検出条件、扱い、継続・再開条件で定義します。ログや内部エラーの全列挙は行いません。
- 目的は 1〜2 文、適用範囲は対象と対象外を 1 行ずつとし、人間と AI Agent の責任分担などの共通原則は全体概要を参照します。凡例は全体概要の凡例を参照し、本書で再定義しません。

## 2. 位置づけと用語定義

| 用語                   | 定義                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| 全体概要               | プロセス領域、プロセスグループ、データストア、グループ間の受け渡しを定める最上位 CDFD                        |
| プロセスグループ       | 業務の性質が近いプロセス領域をまとめた集合。本 rulebook が扱う一文書の単位                                   |
| プロセス領域           | 全体概要で ID、名称、業務目的、担当、起点イベントが定義され、一つのプロセスグループに属する責務のまとまり    |
| プロセス               | 起動条件と入力を受け、業務上意味のある出力または状態変化を一つ生む処理単位                                   |
| 起点イベント           | 対象領域または内部プロセスを開始させる、発生を判定できる出来事                                               |
| データストア           | 全体概要で名称と区分が定義された、情報の正本または継続的な保管先                                             |
| 主要例外               | 正常系と異なる業務判断、生成結果、引き渡し可否を生じさせ、再開条件の合意が必要な分岐                         |
| グループ外委譲         | 他グループの内部処理を作り込まず、委譲先 CDFD、引き渡す情報、戻す条件によって責任境界を示すこと              |
| 状態遷移の参照         | 状態を変えるプロセスから、状態一覧と状態遷移図を統合した STSD をたどる対応。状態名や遷移表そのものは含めない |
| 個別プロセス主要入出力 | プロセスごとの主要入力・主要出力・データストアを示す章。「プロセス領域」の表と項目を重複させない             |

全体概要は領域とグループの分割、およびグループとデータストアの間の受け渡しを定義します。プロセスグループ別 CDFD は一グループの内部を詳細化し、ユースケース別 CDFD は複数グループを横断する順序と引き渡し条件だけを定義します。

## 3. ファイル命名・ID規則

- 対象プロダクトの業務仕様配下にあるデータフローディレクトリへ配置します。
- ファイル名と成果物 ID は `cdfd-<group>` とし、ファイル名だけ `.md` を付けます。`<group>` は全体概要のプロセスグループ名を表す英小文字・数字・ハイフンのスラッグです。
- product 成果物の ID にプロジェクト ID や authority は付けません。例: ファイル名 `cdfd-sales.md`、ID `cdfd-sales`。
- `cdfd-overview` は全体概要、`cdfd-uc-<topic>` はユースケース別 CDFD の ID であり、本 rulebook の対象外です。
- プロセス ID は、全体概要の領域 ID `P-<nn>` に二桁の枝番を付けた `P-<nn>-<nn>` 形式とします。例: 領域 `P-03` の二番目のプロセスは `P-03-02`。文書内一意の `P-01` 形式は使用しません。
- 主要例外 ID は、対象領域の番号に二桁の枝番を付けた `E-<nn>-<nn>` 形式とします。複数領域にまたがる例外は、最初に検出するプロセスの領域番号を使います。
- プロセス ID と例外 ID は名称変更後も同じ対象を示す限り維持し、一覧、図、入出力表、例外表で同じ値を使います。

## 4. 推奨 Frontmatter 項目

| 項目       | 説明                                                  | 必須 |
| ---------- | ----------------------------------------------------- | ---- |
| id         | `cdfd-<group>`                                        | ○    |
| type       | `flow`                                                | ○    |
| status     | `draft` / `ready` / `deprecated`                      | ○    |
| rulebook   | `specdojo:cdfd-rulebook`                              | ○    |
| based_on   | 全体概要など、依存関係上許可された直接の内容根拠の ID | 任意 |
| supersedes | 置き換える旧 CDFD の ID                               | 任意 |

- product 成果物の `id` はプロジェクト修飾なしとし、`based_on` に全体概要を記載する場合も product 成果物 ID を使用します。
- `based_on` は成果物カタログの `depends_on` の推移閉包に含まれる直接の内容根拠だけを列挙します。
- 文書のタイトルと利用目的は本文 H1 と「目的」で示し、未定義の Frontmatter 項目を追加しません。
- 作成途中の `status` は `draft` とします。`ready` へ昇格できるのは、「完成判定」の全項目を満たし、対象プロジェクトのロール定義または責任分担文書で特定した承認者による業務境界・主要例外・委譲境界の承認記録を、登録簿の決定記録またはレビュー結果から特定できる場合です。

## 6. 記述ガイド

### 6.1. 目的と適用範囲

- 目的は、誰がグループ内部のフロー、領域間の受け渡し、主要例外、グループ外への委譲を合意または設計入力とするかを、1〜2 文で簡潔に記述します。
- 適用範囲は、対象（対象グループ・期間・境界）と対象外（領域内部の詳細化先、他グループの責務、横断ユースケース）をそれぞれ 1 行（1 文）で明記します。
- 人間と AI Agent の責任分担などの共通原則は本文で再定義せず、全体概要（またはプロジェクト方針文書）を参照します。

### 6.2. プロセス領域

- 章の冒頭で、対象グループ名、含む領域数、全体概要との正本関係を簡潔に示します。全体概要の対象グループ名と、そこに属する全領域の ID・名称を引き継ぎ、領域を追加・削除・別グループへ移動しません。
- 領域ごとに節（`3.1.`、`3.2.`、…）を設け、見出しは「領域名（領域 ID）」とします。
- 各節はプロセスの表のみで構成します。主要入力・主要出力・データストアの箇条書きは記載せず、受け渡しは概念データフロー図を正本とします。
- 領域 ID、名称、業務目的、主な担当、起点イベントは全体概要を正本とします。本章では領域 ID と名称を見出しの対応キーとして使い、業務目的・担当・起点イベントを書き写しません。
- 各節の表は一行を一つのプロセスノードへ対応させます。

| 列          | 記載内容                                       | 判定基準                                                    |
| ----------- | ---------------------------------------------- | ----------------------------------------------------------- |
| プロセス ID | 対応領域 ID に枝番を付けた `P-<nn>-<nn>`       | プロセス領域のいずれかへ一意に属し、表と図で同じ ID を使う  |
| プロセス    | 一つの業務目的が分かる短い名称                 | 複数プロセスや操作列を一行へ詰め込まない                    |
| 業務目的    | 対象者に生じる成果または維持する状態           | 手順や状態遷移の列挙にしない                                |
| 主な担当    | 主担当となるロールまたは外部主体               | 個人名にせず、人間の最終判断を明示する                      |
| 起動条件    | 開始を判断できるイベント、前段の完了、承認条件 | 「必要に応じて」で終わらせない                              |
| 完了条件    | 業務目的を達成したと判定できる出力または事実   | yes / no で判定でき、主要出力または正本の確定と対応している |
| 必須性      | 必須、条件付き、選択のいずれか                 | 条件付き・選択では起動条件と非起動時の正常な扱いを示す      |

### 6.3. データストア

- 全体概要の「データストア」と同じ「マスタ・構成データ」「トランザクションデータ」の節に分け、本グループが読み書きする行だけを掲載します。該当する行がない区分は節ごと省略します。
- 表の列は「データストア」「読み書き」「本グループでの利用」とします。「読み書き」は「参照」「更新」「参照・更新」のいずれかとし、物の保管先を扱う場合は利用内容に現物の受け渡しであることを示します。
- 名称と区分は全体概要から変更しません。
- 概念データフローを複数図に分けて同じデータストアを再掲する場合を除き、表の各行と図のデータストアノードを一対一に対応させ、名称を一致させます。

### 6.4. 概念データフロー

- Mermaid のノード、エッジ、形状、線種は Frontmatter の `includes` で指定した記法ルールに従います。
- 全体概要の各領域を一つの代表ノードとして再掲せず、「プロセス領域」の各表の行を一つずつ個別のプロセスノードとして配置します。
- 同一グループ内の領域間の受け渡しは、双方のプロセスを同じ図または対応する分割図に置いて示します。他グループは内部プロセスを描かず、委譲先の代表ノードまたは起点・完了イベントだけを置きます。
- 図は領域ごと、または業務の性質が近いプロセスごとに分けることを基本とします。
- 各図の直後に、全体概要の「凡例（本プロダクト共通）」を参照する旨、および省略事項を 1〜2 文で簡潔に注記します（色・絵文字の割り当ては再掲しません）。
- 状態名をノードとして並べたり、状態間の矢印を描いたりしません。状態を変える業務はプロセスと起点イベントだけを示し、「状態遷移の参照」から STSD へ接続します。

### 6.5. 個別プロセス主要入出力

- 図を領域単位で分けた場合は領域ごと、業務の性質で分けた場合は同じまとまりごとに節を設けます。
- プロセス ID ごとに、主要入力、主要出力、データストアを表で示します。業務目的、担当、起動条件、必須性は「プロセス領域」の表から重複させません。
- データストアの名称と区分は「データストア」および全体概要と一致させます。
- 全プロセスをちょうど一度掲載し、一プロセスだけのまとまりでも同じ表構成を省略しません。

### 6.6. 状態遷移の参照

- 状態を変えるプロセスがある場合、表の列は「対象」「状態を変えるプロセス」「ステータス定義（STSD）」とします。該当プロセスがない場合は、その事実と確認根拠を一文で記載して表を省略します。
- STSD は状態名・意味・成立条件と、遷移元・遷移先・イベント・遷移条件の単一正本として参照します。
- CDFD には状態の一覧、遷移表、状態を頂点とする状態遷移図を複製しません。

### 6.7. 主要例外とグループ外への委譲

- 主要例外は「例外 ID」「対象プロセス」「検出条件」「停止範囲」「本グループでの扱い」「継続・再開条件」の表で示します。
- グループ外委譲は「委譲先」「委譲する事項」「引き渡す情報」「本グループへ戻す条件」の表で示します。
- 主要例外またはグループ外委譲が 0 件の場合も対応する節を残し、確認範囲と該当なしの結論を一文で記載して表を省略します。

### 6.8. 完成判定

本節だけを `ready` 昇格のチェックリストの正本とします。次の全項目を満たす必要があります。

- Frontmatter に必須の `id`、`type`、`status`、`rulebook` があり、`id` とファイル名が命名規則に一致します。
- 「目的」が 1〜2 文で対象者と利用結果を定義し、「適用範囲」に対象と対象外が 1 行ずつ明記され、共通原則として全体概要が参照されています。
- 全体概要で対象グループに属する全領域が「プロセス領域」にちょうど一つの節として登場し、各節がプロセスの表だけで構成されています（箇条書きを含まない）。
- 各プロセスに業務目的、主な担当、起動条件、完了条件、必須性があり、完了条件は主要出力または正本の確定から yes / no で判定できます。
- 全プロセスが領域ごとの表、図、個別プロセス主要入出力へ同じ ID と名称で登場し、ID が所属領域を示します。
- 「データストア」が全体概要の部分集合であり、名称・区分が一致します。
- 同一グループ内の領域間受け渡しを内部フローとしてたどれ、他グループの内部処理を作り込んでいません。
- 図の説明・注記は 1〜2 文で簡潔に記載され、凡例は全体概要の凡例を参照しています。
- 状態を変えるプロセスは STSD を参照し、CDFD 本文に状態の定義、遷移表、状態遷移図を重複記載していません。
- 主要例外の検出、停止範囲、継続・再開条件と、グループ外への引き渡しを確認者が説明できます。

## 7. 禁止事項

- プロセス領域に主要入力・主要出力・データストアの箇条書きを記載する、または図の受け渡しを文章でなぞる長文の注記を書く。
- 詳細 CDFD に独自の凡例を再掲・重複定義する。
- 複数領域を持つグループから一部の領域だけを切り出して別文書にしたり、一つの領域を複数のプロセスグループ別 CDFD に重複配置したりする。
- 全体概要と異なるデータストア名・区分を使用したり、物理テーブル名、物理カラム名、SQL、実装クラス、詳細 API を概念フローへ記載したりする。
- 状態名・意味を CDFD で定義したり、遷移元・遷移先・遷移条件の表や状態遷移図を複製したりする。
- 他グループの内部プロセスを展開したり、同一グループ内の領域間受け渡しをグループ外委譲として扱ったりする。
- 一覧、検索、状態参照、検証、dry-run など、独自の業務成果を持たない補助操作を独立プロセスにする。
- プロセス領域の表と個別プロセス主要入出力、図直後の注記、例外表の間で同じ事実を重複記載する。
