# 影響調査（運用）作成ルール

Impact Analysis (Operations) Rulebook

変更要求による運用への影響を整理し、変更要否・影響度・対応方針を判断する基準を定めます。

## 1. 全体方針

- 運用責任者とプロジェクト管理者が合意できる粒度で、影響と判断根拠を記載する。
- 複数領域を扱う場合も影響詳細は運用対象単位とし、実運用手順の詳細化は扱わない。
- 標準6章・6列と sample で記入形式が定まるため、別の作成手順・雛形は不要とし、`recipe`・`template` は `not-needed` とする。
- **共通の運用**: 役割は適用先のメンバー定義、`status`・承認・改訂と廃止・未決事項の引き継ぎは [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。文書の整形・lint はリポジトリの検証で扱う。

## 2. 位置づけ

波及の概要と判断は本書に残し、詳細はデータ仕様（`bdd-*`）、I/F 仕様（`ifx-*`）、テスト戦略・方針（`tsp-index`）などへ委譲する。「備考」に適用先カタログの対応する成果物 ID を示す。

## 3. ファイル命名・ID規則

- 文書 ID は `<project-id>:imp-operations`、推奨ファイル名は `imp-operations.md` とする。
- 追補は `<project-id>:imp-operations-<term>` とし、共通規則は [[specdojo:id-and-file-naming-standard|ID・ファイル命名標準]] に従う。

## 4. 推奨 Frontmatter 項目

共通項目・必須性・型制約は [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。`type` は `project`、`rulebook` は `specdojo:imp-operations-rulebook` とする。`based_on` は直接の根拠とした変更要求や資料の ID を記載する任意項目とする。

## 5. 本文構成（標準テンプレ）

本文は次の6章を標準とする。

| 章  | 見出し         | 必須 | 目的                 |
| --- | -------------- | ---- | -------------------- |
| 1   | 目的と適用範囲 | ○    | 対象と判断範囲       |
| 2   | 変更要求の概要 | ○    | 背景・要求・成功条件 |
| 3   | 影響分析サマリ | ○    | 尺度・件数・優先対象 |
| 4   | 影響詳細一覧   | ○    | 対象別の判定と根拠   |
| 5   | 対応方針       | ○    | 実施条件・担当・時期 |
| 6   | 未解決事項     | ○    | 論点・不足情報・影響 |

## 6. 記述ガイド

### 6.1. 目的と適用範囲

変更要求の識別子、対象運用領域、対象期間、判断目的を示す。

### 6.2. 変更要求の概要

背景・要求・狙いと成功条件を判断に必要な要点に絞って要約する。

### 6.3. 影響分析サマリ

運用品質・障害対応力・継続運用性・利用者影響の評価観点と高・中・低の尺度を先に示し、件数と優先対象をまとめる。監視体制、障害初動、運用負荷、統制・監査への影響を検討する。

### 6.4. 影響詳細一覧

影響詳細は次の6列を含む表とする。

| カラム       | 内容                                           |
| ------------ | ---------------------------------------------- |
| 影響対象運用 | 監視・アラート・手順・体制・統制・SLA 運用など |
| 変更要否     | `要` / `否`                                    |
| 影響度       | `高` / `中` / `低`                             |
| 対応方針     | 実施・代替・見送りなどの方針                   |
| 判断根拠     | 判定理由の要点                                 |
| 備考         | 制約、前提、関連ドキュメント                   |

### 6.5. 対応方針

- 重要度が高い項目から順に、実施時期、担当、前提条件を記載する。
- 見送りの場合は、再評価条件と時期を必ず記載する。

### 6.6. 未解決事項

論点、不足情報、運用判断への影響と当面の扱いを記載する。

## 7. 禁止事項

- 「影響あり」「要対応」のみで根拠を記載しない。
- 影響度の尺度を定義せずに高・中・低を混在させない。
