# 議事録 作成ルール

Meeting Minutes Documentation Rulebook

会議で決まったことと、誰がいつまでに何をするかを後から追えるように記録する議事録の作り方を定めます。

## 1. 全体方針

- 目的: 決定の経緯とアクションの抜け漏れを防ぎ、進捗報告と登録簿の個票へ確実に引き継ぐ。
- 対象: 決定またはアクションが生じた会議（定例・レビュー・関係者との調整）。決定もアクションもない情報共有だけの会議は対象外とする。
- 記載レベル: 議論の経過より、決定・アクション・保留を優先して残す。
- 共通の運用: Frontmatter の項目（`specdojo.type` は `project`）、`status` の昇格と承認、改訂と廃止は [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従い、本書と成果物で言い直さない。

## 2. 位置づけ

- 会議で何が決まり、どのアクションが未完了かを判断するための記録である。
- 決定を受けて対応が要る課題・リスク・変更要求は、登録簿の個票へ起票し、議事録には個票 ID を書く。議事録の中で対応を追跡しない。
- アクションの進み具合は進捗報告で追い、議事録はアクションの発生元として参照される。
- 決定を訂正するときは、元の議事録を書き換えず、次の会議の議事録に訂正の決定として残す。

## 3. ファイル命名・ID規則

- ファイル名は `mm-<yyyy-mm-dd>-<nn>.md` とする（必須）。日付は会議の開催日を ISO 形式で書き、`<nn>` は同日内の 2 桁ゼロ埋め連番とする。
- 文書 ID は `<project-id>:mm-<yyyy-mm-dd>-<nn>` 形式とし、ファイル名と一致させる（例: `prj-0001:mm-2026-03-01-01`）。
- 形式は Markdown のみとする。
- 作成後にファイル名と ID を変えない。進捗報告や個票から ID で参照されるためである。

## 4. 本文要件

| 番号 | 見出し             | 必須 | 目的                                     | 必要な項目                                                   |
| ---- | ------------------ | ---- | ---------------------------------------- | ------------------------------------------------------------ |
| 1    | 会議情報           | ○    | どの会議の記録かを特定する               | 会議名、日時（開始-終了）、参加者                            |
| 2    | 議題               | ○    | 扱った論点を示す                         | 議題の箇条書き                                               |
| 3    | 決定事項           | ○    | 何が決まったかを示す                     | 表: No.、決定事項、決定者                                    |
| 4    | アクションアイテム | ○    | 誰がいつまでに何をするかを示す           | 表: No.、内容、担当者、期限。任意で完了条件、関連する個票 ID |
| 5    | 保留事項           | 任意 | 結論が出なかった論点と次の確認時期を示す | 表: No.、保留事項、保留の理由、次回確認日                    |

- 決定事項・アクションアイテムが無い場合も章を省かず「なし」と書く。

## 5. 記述ガイド

- 決定事項は、読んだ人が同じ行動を取れる一文で書く。
  - 良い例: 補充判定のしきい値を「在庫3以下」に統一する。
  - 悪い例: しきい値について合意した。
- アクションの内容は、完了したかどうかを判定できる動詞で書く。判定が難しい場合は完了条件を添える。
  - 良い例: 補充判定条件の更新案を作成する（完了条件: 業務担当が確認できる状態で共有）。
  - 悪い例: 補充判定を検討する。
- 担当者・決定者・参加者は、プロジェクト内で通じる役割名（例: 店主、業務担当、開発担当）で書き、文書内で表記をそろえる。
- 期限は `yyyy-mm-dd` で書き、「来週中」のような相対表現を使わない。
- 個人情報（連絡先・私的な事情）や公開できない取引条件は書かず、必要なら管理先の名前だけを書く。
- 共通事項（Frontmatter、記法）は上位の標準を正とし、議事録ごとに言い直さない。

## 6. 禁止事項

- 決定事項・アクションアイテムの章を省略しない。
- 担当者・期限のどちらかが空のアクションを残さない。
- 決定事項に「検討する」「調整する」など結論を含まない表現だけを書かない（結論が出ていなければ保留事項に書く）。
- 課題・リスク・変更要求の対応状況を議事録で更新し続けない（個票で追う）。
- 設計や実装の詳細（コード、設定値の一覧）を本文に転記しない。成果物の ID で参照する。
