# 影響調査（テスト）作成ルール

Impact Analysis (Test) Rulebook

変更要求によるテストへの影響を整理し、変更要否・影響度・対応方針・未解決事項を判断する記述基準を定めます。

## 1. 全体方針

- テスト責任者とプロジェクト管理者が合意できる粒度で影響と根拠を示す。
- 複数のテストレベルを扱う場合も影響詳細はテスト対象単位とする。仕様・I/F・運用への波及は概要と判断を示し、詳細は各仕様へ委ねる。
- **共通の運用**: 役割は適用先のメンバー定義、`status`・承認・改訂と廃止・未決事項の引き継ぎは [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。文書の整形・lint はリポジトリの検証で扱う。

## 2. 位置づけ

起票済みの要求・課題を含む変更要求を受け、テスト観点・条件・ケース・判定基準への影響を判断する。個別テスト手順の詳細設計は扱わない。

## 3. ファイル命名・ID規則

- 文書 ID は `<project-id>:imp-test`、推奨ファイル名は `imp-test.md` とする。
- 命名の共通規則は [[specdojo:id-and-file-naming-standard|ID・ファイル命名標準]] に従う。
- 追補文書は `<project-id>:imp-test-<term>` とする。

## 4. 推奨 Frontmatter 項目

共通項目・必須性・型制約は [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。`type` は `project`、`rulebook` は `specdojo:imp-test-rulebook` とする。

## 5. 本文構成（標準テンプレ）

本文は次の6章を標準とする。

| 章  | 見出し         | 必須 | 目的                                           |
| --- | -------------- | ---- | ---------------------------------------------- |
| 1   | 目的と適用範囲 | ○    | 対象と判断対象範囲を明確化する                 |
| 2   | 変更要求の概要 | ○    | 変更背景と要求内容を要約する                   |
| 3   | 影響分析サマリ | ○    | 影響の全体像と優先順位を俯瞰する               |
| 4   | 影響詳細一覧   | ○    | 影響対象テストごとの変更要否・影響度を記録する |
| 5   | 対応方針       | ○    | 採用方針、実施条件、担当と期限を整理する       |
| 6   | 未解決事項     | ○    | 意思決定待ちや調査不足を明示する               |

## 6. 記述ガイド

### 6.1. 目的と適用範囲

- 対象変更要求の識別子、対象テスト範囲、対象期間を明記する。
- 「何を判断する文書か」を 2〜4 行で示す。

### 6.2. 変更要求の概要

- 背景・狙いと要求の要点を示す。成功条件は指標と閾値、または達成状態に加え、確認対象・判定方法を記載する。

### 6.3. 影響分析サマリ

- 欠陥流出リスク・検証網羅性・実行コスト・納期など、採用する評価観点ごとに高・中・低を分ける条件（数値の境界または状態）を先に定義する。
- 複数観点で判定が分かれる場合の集約規則（例: 最も高い影響度を採用）を定め、同じ規則で件数を集計する。
- 優先対応対象を明記し、同じ影響度で順序を分ける場合は理由を添える。

### 6.4. 影響詳細一覧

- 表形式で次の6列を必須とする。

| カラム         | 内容                                                           |
| -------------- | -------------------------------------------------------------- |
| 影響対象テスト | 影響を受けるテスト対象（レベル、観点、条件、ケース、判定基準） |
| 変更要否       | `要` / `否`                                                    |
| 影響度         | `高` / `中` / `低`                                             |
| 対応方針       | 実施・代替・見送りなどの方針                                   |
| 判断根拠       | 変更要否の理由、評価観点ごとの事実と尺度・集約規則の適用結果   |
| 備考           | 制約、前提、関連ドキュメント                                   |

### 6.5. 対応方針

- 影響度の高い順に、実施時期、担当、前提条件を記載する。
- 見送りの場合は、再評価条件と時期を必ず記載する。
- 受入確認では「変更要求の概要」の成功条件に判定方法を適用し、全条件の達成を合格とする。未達は影響対象と対応方針へ戻す。

### 6.6. 未解決事項

- 論点、不足情報、判断・対応への影響と当面の扱いを記載する。該当がなければ「なし」とする。

## 7. 禁止事項

- 「影響あり」「要対応」のみで根拠を記載しない。
- 影響度の尺度を定義せずに高・中・低を混在させない。
