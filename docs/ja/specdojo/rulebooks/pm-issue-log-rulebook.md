# 課題ログ 作成ルール

Issue Log Documentation Rules

顕在化した課題の優先度・期限・対応・状態を追跡する課題ログの記述基準を定める。

## 1. 全体方針

- 顕在化した課題ごとに、未解決かどうかと次の対応を判定できる形で残す。
- **共通の運用**: 役割の割り当ては適用先のメンバー定義に、`status`・承認・改訂と廃止・未決事項の引き継ぎは [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] に従う。文書の整形・lint はリポジトリの検証で扱う。

## 2. 位置づけ

- プロジェクト登録簿を使うプロジェクトでは、課題 1 件を `item_type: issue` の個票に書き、`controls/generated/pm-issue-log.md` は `register build` が個票から生成する。生成物の Frontmatter は `rulebook: specdojo:pjr-rulebook` とし、直接編集しない（[[specdojo:pjr-rulebook|プロジェクト登録簿 作成ルール]] に従う）。
- 本書の判断基準は、個票と、登録簿を使わない単独の課題ログの両方に適用する。

## 3. ファイル命名・ID規則

- `id` は `<project-id>:pm-issue-log`、ファイル名は `pm-issue-log.md` とする。
- 課題 ID は登録簿では `PJR-XXXX`、単独のログでは `IS-NNN` とし、再利用しない。

## 4. 推奨 Frontmatter 項目

- 許可キーと型は [[specdojo:document-metadata-standard|ドキュメントメタ情報標準]] を正本とし、`type` は `project` とする。

## 5. 本文構成（標準テンプレ）

| 番号 | 見出し           | 必須 |
| ---- | ---------------- | ---- |
| 1    | 概要             | ○    |
| 2    | 課題ログ一覧     | ○    |
| 3    | 優先度と期限     | ○    |
| 4    | 対応計画         | ○    |
| 5    | 進捗レビュー     | ○    |
| 6    | 関連ドキュメント | ○    |

## 6. 記述ガイド

### 6.1. 概要

- 管理対象、レビュー頻度、記録単位を 1〜3 行で示す。

### 6.2. 課題ログ一覧

- 課題 ID、発生日、内容、優先度、対応策、担当、期限、ステータスを一覧にする。
- 優先度とステータスは登録簿の `priority`・`item_status` の値を使い、言い換えない。

### 6.3. 優先度と期限

- 優先度の基準、期限の決め方、期限超過時のエスカレーション先、優先度の変更を決める者を書く。

### 6.4. 対応計画

- 対応策、依存事項、完了条件を書く。完了条件は確認の手段と合格の基準で書く。

### 6.5. 進捗レビュー

- レビュー周期、完了を判定する者と判定の観点、状態を更新する契機を書く。

### 6.6. 関連ドキュメント

- 根拠、影響先、課題から起票したリスク・変更要求を文書 ID で示す。なければ `（本書のみ）` と書く。

## 7. 禁止事項

| 禁止事項                                   | 理由                       |
| ------------------------------------------ | -------------------------- |
| 課題IDなしで記録する                       | 追跡不能になるため         |
| 優先度・期限を未記載にする                 | 対応順序が判断できないため |
| 根拠のない完了判定を記載する               | 品質低下を招くため         |
| 個人情報・認証情報を内容や対応策に書き写す | 公開範囲を超えて広がるため |
| 生成された `pm-issue-log.md` を直す        | 再生成で修正が失われるため |
