# 受入テストカタログ: 店頭の現金販売

## 1. 概要（`cash-sale`）

店主不在の店番で、家族利用者代表が商品Aを登録して会計を確定し、レシートと販売一覧・在庫一覧で結果を確かめるまでを受け入れるかの判断に使う。確定前の取消と確定後の取引の照合もこのカタログ（`atc-cash-sale`）で扱う。店番の交代は `atc-sale-hold` の引継ぎ経路だけで確かめる。ローカル ID は `atc-cash-sale` とし、粒度は [[specdojo:atc-index-sample|受入テストカタログ 概要]] の分割基準（商品の登録→会計確定→レシートの受け渡し）に従う。

ケースは家族利用者代表と店主代表が操作し、BA が所要時間・質問・支援・誤操作を記録、QE が期待値と証跡を照合し、店主代表（PO）が受入可否を判定する。

## 2. 受入の責務（成果/完了条件）

- 店主不在でも、家族利用者代表が説明なしで商品Aの会計を確定できる。SC-01 の測定記録で支援0回・自力で回復できない事象0件になる。
- 確定後にレシートと販売一覧に同じ取引番号と合計額が表示され、どの販売かを特定できる。
- 確定した数量だけ在庫一覧の在庫が減り、販売一覧の数量と在庫差分が一致する。
- 確定前に取り消した購入は販売一覧に残らず、在庫も開始時のまま変わらない。
- 確定後に、店番が取引番号から販売一覧の取引を特定し、商品・数量・金額を説明できる。

完了条件は、本カタログの P0 全件 Pass と、P1 の「合格基準」による判定である（基準は `atc-index` のとおり）。

## 3. 対象外

| 対象外                         | 理由                                                           | 代替                                                                                |
| ------------------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 在庫超過・入力不足の停止と再開 | 「販売を確定しない」合否命題は `atc-sale-hold` が主担当        | `atc-sale-hold`。再開後の会計は `at-cash-sale-sale-complete-010` の期待値を参照する |
| 在庫と同数の購入（在庫0個）    | 境界の正しさは ST で確定済みで、利用者の判断を要しない         | ST の `st-cash-sale-flow-success-020`                                               |
| つけ販売と残高確認             | 金銭の授受がなく、照合の責任を店主代表だけが負う               | `atc-stock-credit-check`                                                            |
| 返品と確定後の訂正             | 業務受入条件で将来の別シナリオとされ、期待結果が決まっていない | なし。店主代表が必要性を決めてから観点を追加する                                    |

## 4. 環境/データ/外部依存

| 項目           | 内容                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 開始           | 店番担当が店舗端末の会計画面で新しい取引を開始し、取引番号が表示された時点                                                                      |
| 完了           | レシートを受け渡し、販売一覧と在庫一覧で同じ取引番号の結果を確かめた時点。確定前の取消は、取消済みの表示を確かめた時点                          |
| データ         | 各ケースの開始時に `kinuya-at` を `kinuya-test-data`（商品A 単価30円・在庫5個）へ戻す                                                           |
| 外部依存       | 店舗プリンタ（実機）。開始前にテスト印字でレシートが出ることを確かめる                                                                          |
| 判定保留条件   | 用紙切れ・紙詰まりでレシートが出ない場合は判定保留とし、印刷の復旧後にデータを戻して再実施する。印刷失敗の経路は ST で扱い、AT の Fail にしない |
| 共通方針との差 | なし                                                                                                                                            |

判定に影響する前提は次のとおり。確定するまで、該当ケースの Pass を受入可の根拠に使わない。

| 前提                                         | 影響するケース                                                         | 当面の扱い                                                             | 判断者と次の手                                                                                                  |
| -------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| _ASSUMPTION_: 確定前の取消の期待結果         | `at-cash-sale-sale-complete-020`                                       | 業務受入条件に取消の条件がないため、`atc-index` の分割判断を根拠に測る | BA が取消の業務受入条件の追加を PM へ PJR 登録候補として渡し、PO が承認する。承認後に QE がトレースを差し替える |
| _ASSUMPTION_: レシートに取引番号が印字される | `at-cash-sale-sale-complete-010`、`at-cash-sale-transaction-check-010` | レシートの取引番号を観測点として測る                                   | DEV が画面・帳票の設計で確認する。印字しない場合は QE が観測点を販売一覧の表示へ改め、PO へ報告する             |

## 6. 受入観点とケース

### 6.1. 観点：会計確定の成立

`perspective_key`: `sale-complete`

#### 6.1.1. 意図

店主不在の店番でも会計を確定でき、レシート・販売一覧・在庫一覧が同じ取引を指すこと、確定前に取り消した購入は何も残さないことを両代表が受け入れられるかを判定する。
