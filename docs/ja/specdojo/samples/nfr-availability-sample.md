# 駄菓子屋きぬや 販売管理システム 可用性要件

## 1. 概要（対象・目的）

店主が不在でも店番担当が販売・在庫・つけの記録を続けられるよう、障害時に許す停止時間と記録の損失を定める。対象業務は店頭タブレット 1 台での販売記録、在庫確認、つけの記録と残高確認とする。

営業時間中にシステムが止まると、次の業務影響が出る。基準値の厳しさは、この影響と、記録を営業日の 90% 以上で続けるというプロジェクトの初期目標（[[specdojo:prj-overview-sample|プロジェクト概要]]）から決める。

- 販売記録が残らず、在庫数が実物とずれて人気商品の欠品に気付けない。
- つけの記録と残高確認ができず、記録漏れや来店客への残高の説明誤りが起きる。
- 店主以外の店番担当は記憶で補えないため、店主不在の日ほど影響が大きい。

障害時は、店番担当が記録できないことに気付いたら紙の販売控えへ切り替える。`OPS` が障害の度合いを判定して復旧を確かめ、データを復元するかは `PO` が決める。

## 2. 適用範囲・除外条件

停止がどの条件で要件の対象になるかを、次の表で定める。

| 区分                   | 条件                                                                                             | 稼働率の計算での扱い                         |
| ---------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| 対象時間帯             | _ASSUMPTION_: 営業日の 10:00〜18:00（運用方針の運用時間帯と同じ）                                | 対象時間に含める                             |
| 対象外の時間帯         | 休業日、閉店後から翌日の開店まで。日次締めは閉店後の店番担当の操作のため対象外とする             | 対象時間に含めない                           |
| 計画停止               | アプリの版の更新と点検は閉店後に限る。営業時間中の変更は障害の復旧に必要なときだけとする         | 閉店後の計画停止は除く。営業時間中は除かない |
| 店頭端末の故障         | タブレット 1 台の故障・紛失・電池切れで記録できない時間                                          | 停止に含める                                 |
| 店舗の通信回線の断     | 店舗の回線が切れて記録できない時間。_ASSUMPTION_: 通信断の頻度と影響は未確認（前提条件 ACD-A02） | 停止に含める                                 |
| ホスティング環境の停止 | 事業者の障害・計画停止で記録できない時間。_UNDECIDED_: 事業者の SLA（「未決事項」参照）          | 停止に含める                                 |

外部依存のうち、ホスティング環境と店舗の回線は SLA または実績が分かるまで自システムの稼働率の基準と整合するか判断できない。整合しない場合のリスクは「未決事項」に置く。

## 3. 可用性要件一覧

次の表は、要件ごとの対象・基準・根拠と、基準を支える仕組みを示す。基準が未確定の要件は `_UNDECIDED_` とし、決まるまでの暫定の判定を併記する。

| 要件ID        | 対象範囲                               | 指標                   | 基準                                                                                    | 根拠・業務影響                                                   | 技術前提                                                                             |
| ------------- | -------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `nfr-avl-001` | システム全体（販売・在庫・つけの記録） | 営業時間内の月間稼働率 | _UNDECIDED_: ○○% 以上。決まるまでは停止の時間を記録するだけとし、達成・未達を判定しない | 停止中は販売・つけが記録されず、在庫と残高が実物とずれる         | 単一構成で冗長化しない（_ASSUMPTION_）。ホスティング環境の死活を営業時間中に監視する |
| `nfr-avl-002` | システム全体                           | RTO                    | _UNDECIDED_: ○○ 分以内。決まるまでは翌営業日の開店までに記録を再開できれば合格とする    | 停止が翌日へ持ち越すと、紙の控えの転記が溜まり記録漏れが増える   | 監視が 5 分続けて応答なしで通知する。復旧の手順は運用手順に置く                      |
| `nfr-avl-003` | 販売・在庫・つけの記録（データベース） | RPO                    | _UNDECIDED_: ○○ 時間以内。決まるまでは前日の閉店時点まで戻ることを許す                  | 失った記録は紙の控えから転記するため、範囲が広いほど手間が増える | バックアップは閉店後に 1 日 1 回自動で取り、復元を月次で演習する                     |
| `nfr-avl-004` | 停止中の店頭販売                       | 停止中の取引の転記漏れ | _ASSUMPTION_: 0 件                                                                      | 停止中も販売は止めないため、紙の控えが唯一の記録になる           | 紙の販売控えを店頭に常備する。復旧後に控えの件数・金額と登録した記録を照合する       |

## 4. 測定・検証方法

要件ごとの測定方法と判定時期を、次の表で定める。基準値は「可用性要件一覧」を参照する。

| 要件ID        | 算出・測定の方法                                                                                                                                                                                       | 測定期間           | 判定時期                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------ | ------------------------------------------ |
| `nfr-avl-001` | 稼働率 =（対象時間 − 停止時間）÷ 対象時間。対象時間は営業日の 10:00〜18:00 の合計とする。停止時間は監視の無応答の時間と、店番担当が障害記録に残した記録できなかった時間を合わせ、重なりは 1 回と数える | 暦月               | 月次の運用レビュー                         |
| `nfr-avl-002` | 起点は監視の通知か店番担当の気付きの早いほうの時刻、終点は本番で販売・在庫・つけを各 1 件記録できた時刻とする。受入前は復旧試験で、運用後は障害ごとに障害記録から測る                                  | 障害ごと・試験ごと | 受入前の復旧試験、運用後は障害記録の確認時 |
| `nfr-avl-003` | 復元したデータの最後の記録の時刻と、障害が起きた時刻の差を測る。月次の復元演習では、前日のバックアップを検証用の環境へ戻し、販売件数が本番と一致するかも確かめる                                       | 演習ごと・障害ごと | 受入前の復元試験、運用後は月次点検         |
| `nfr-avl-004` | 復旧後、紙の控えの取引件数・金額と、転記して登録した記録の件数・金額を突き合わせる                                                                                                                     | 停止ごと           | 復旧後の最初の日次締め                     |

測定結果は、指標が基準を満たせば pass、満たさなければ fail とする。基準が `_UNDECIDED_` の間は暫定の判定で pass / fail を決め、確定後は確定値で判定し直す。

## 6. 未決事項

次の表は、確定していない基準値・外部 SLA・技術前提と、決まるまでの扱いを示す。

| 論点                                        | 当面の扱い                                                                                     | 決まったときに直す要件ID     |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------- |
| _UNDECIDED_: 営業時間内の稼働率の目標       | 停止の時間を記録するだけとし、達成・未達を判定しない                                           | `nfr-avl-001`                |
| _UNDECIDED_: RTO と RPO の値                | 翌営業日の開店までの再開と、前日の閉店時点までの損失を暫定の合格とする                         | `nfr-avl-002`、`nfr-avl-003` |
| _UNDECIDED_: ホスティング環境の SLA         | 自システムの稼働率の目標と整合するか判断できない。SLA が目標を下回る場合は冗長化の要否を見直す | `nfr-avl-001`、`nfr-avl-002` |
| _UNDECIDED_: タブレット故障時の代替端末     | 代替がない間は、故障から復旧まで紙の控えで販売を続ける                                         | `nfr-avl-002`、`nfr-avl-004` |
| _UNDECIDED_: 通信断の頻度と店頭での記録方法 | 通信断も停止として数え、紙の控えで販売を続ける（前提条件 ACD-A02）                             | `nfr-avl-001`、`nfr-avl-004` |
