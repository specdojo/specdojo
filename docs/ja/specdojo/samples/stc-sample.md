# 総合テストカタログ: 店頭の現金販売

## 1. 概要（`cash-sale`）

店番担当が商品Aの明細を登録して請求額を合意し、会計を確定してから、販売記録・在庫減算・レシート印刷の結果がそろうまでの経路を確かめる。確定前の取消と、確定後に印刷だけが失敗する経路もこの term で扱う。ローカル ID は `stc-cash-sale` とし、分割の判断は [[specdojo:stc-index-sample|総合テストカタログ 概要]] の分割基準に従う。

## 2. 目的

- 会計確定で、商品・数量・販売額が一致する販売記録が取引番号つきで1件だけ残り、在庫が同じ数だけ減ることを確かめる。
- 在庫と同数の購入でも在庫が0個になり、販売記録と在庫記録の差分が一致することを確かめる。
- 会計を確定する前に取り消すと、販売記録が作られず在庫が開始時のまま残ることを確かめる。
- 確定後に印刷が失敗・結果不明になっても会計は維持され、画面に取引番号と「未印字」または「印字結果不明」が表示されることを確かめる。
- 同じ取引の会計確定を二度送信しても、販売記録と在庫減算が1回分にとどまることを確かめる。
- 放課後ピーク相当の負荷で、会計確定の応答が仮置き基準（95%が2秒以内）を満たすことを確かめる。
- 同じピーク負荷の試行で送った60取引が、取引番号ごとに販売記録と一致し、欠落・重複がないことを確かめる。

## 3. 対象外

- 対象外: 金額・税額の計算パターンの網羅（理由: 単価30円・数量の組合せは計算の正しさであり業務シナリオの成立とは別、代替: UT）
- 対象外: 応答欠落後に照合待ちとなった取引の識別と記録の復元（理由: 実施者と観測点が運用境界で分かれる、代替: ST の `stc-record-recovery`）
- 対象外: 在庫超過・入力不足で販売を止める経路（理由: 「販売を確定しない」合否命題は別 term が主担当、代替: ST の `stc-sale-hold`）
- 例外: 印刷の障害は `stc-index` の共通の対象外「印刷コマンド・保管サービスの全障害パターン」の例外のうち、用紙切れと印字結果不明（30秒タイムアウト）の2種だけをこの term で再現する。保存失敗は `stc-record-recovery` で扱う。
- 例外: 会計確定の応答は `stc-index` の対象外の例外に従い、この term で1回だけ測る。条件は ST 専用の検証環境・`kinuya-test-data`・プリンタ検証機の構成で、負荷は1時間60取引とする（根拠: TR-05）。

## 4. 境界/環境/依存

| 項目           | 内容                                                                                                                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 開始           | 店番担当が会計画面で新しい取引を開始し、取引番号が表示された時点                                                                                                                                                                                    |
| 完了           | 会計確定の通知が表示され、販売記録・在庫記録・印刷結果の記録が同じ取引番号でそろった時点。確定前の取消は、取消済みの通知が表示された時点                                                                                                            |
| データ         | 性能試行を除き、各ケースの開始時に `kinuya-st` を `kinuya-test-data`（商品A 単価30円・在庫5個）へ戻し、終了時に当該取引の販売記録を削除する。性能試行の記録の保持・後始末は [[specdojo:stc-index-sample\|総合テストカタログ 概要]] の共通方針に従う |
| 外部依存       | プリンタ検証機と保管サービスの検証用領域への実接続は共通方針に従う。この term では、用紙切れを疑似応答スタブ、印字結果不明を30秒のタイムアウトを返すスタブで再現する                                                                                |
| 観測点         | 会計画面の通知と警告、販売記録（件数・数量・販売額）、在庫記録（開始前後の差分）、印刷結果の記録、取引番号つきの記録サービスのログ                                                                                                                  |
| 共通方針との差 | `st-cash-sale-commit-response-010` だけ商品Aの在庫を100個にする。在庫5個では60取引の途中で在庫不足になり、応答を測れないためである。照合と共通方針の記録保持を終えてから `kinuya-test-data` へ戻し、他ケースへの影響を防ぐ                          |

判定に影響する前提は次のとおり。いずれも確定するまで、該当ケースの合格を出口条件の根拠に使わない。

| 前提                                           | 影響するケース                     | 当面の扱い                                       | 次の手                                                                                   |
| ---------------------------------------------- | ---------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| _ASSUMPTION_: 会計確定の応答基準               | `st-cash-sale-commit-response-010` | TSP の仮置き値（60取引/時で95%が2秒以内）で測る  | NFR の確定後に期待値を置き換え、PM へ出口条件の変更を報告する                            |
| _ASSUMPTION_: 二度目の確定は「処理済み」を返す | `st-cash-sale-double-commit-010`   | 記録サービスが取引番号で重複を判定する前提で測る | 記録サービスの設計で確かめる。異なる場合は期待値を改め、`stc-record-recovery` と照合する |

### 6.1. 観点: 販売確定成立

販売記録と在庫減算は会計を確定した取引にだけ、同じ取引番号で1回分残ることを保証する。

### 6.5. 観点: 会計記録保全

`perspective_key`: `commit-records`
