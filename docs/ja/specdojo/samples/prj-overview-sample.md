# プロジェクト概要: 駄菓子屋きぬや 販売管理システム

駄菓子屋きぬや 販売管理システムは、店頭販売、在庫、常連顧客のつけを一元管理し、店主一人でも日々の運用を続けやすくするための小規模店舗向け業務支援システムである。

## 1. 背景

地域の子どもたちに長年親しまれている「駄菓子屋きぬや」では、販売記録や在庫管理をノートと記憶に頼っている。店主の高齢化により、仕入れ判断や在庫確認、つけ残高の確認に時間がかかる場面が増えている。店番は主に店主が行い、店主の不在時は家族が交代で入る。

現在、次の問題が生じている。頻度は店主代表と家族利用者代表への聞き取りによる概算で、記録に基づく値ではない。実測値は運用開始前1か月のベースライン測定で置き換える。

| 問題                                                         | 聞き取りによる頻度・影響（概算）                                         |
| ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 人気商品（うまい棒、ラムネ等）の欠品が増えている             | 来店客に聞かれて欠品に気づくことが週1回程度あり、その場の販売を逃す      |
| 仕入れのタイミングや数量が勘頼りで、在庫のムラが大きい       | 賞味期限切れによる廃棄や値引きが月に数品目出る                           |
| 常連の子どもや近所の大人のつけ管理が曖昧で、記録漏れが起きる | ノートの残高と本人の認識が合わず、確認に時間を取られることが月に数件ある |
| 店主以外が店番をすると、販売・在庫・つけの状況を確認できない | 家族の店番日には、つけの受付や在庫の問い合わせを店主の戻りまで保留する   |

## 2. 必要性

このまま記憶と紙の運用を続けると、欠品や在庫過多による損失が増え、店舗継続リスクが高まる。また、店主以外が店番をする場合に同じ判断ができず、業務が属人化したままになる。

_ASSUMPTION_: 繁忙期は学校の夏休み期間（例年7月下旬から8月末）とする。この期間は子どもの来店と取引が集中し、欠品・在庫・つけの確認負荷が一気に高まる。記憶と紙の運用のままでは繁忙期の負荷に対応しきれず、損失と属人化のリスクが顕在化するため、繁忙期が始まる前に初期公開と記録の定着（運用開始後2週間）を終えておく必要がある。初期公開の日付は _UNDECIDED_: 初期公開の計画で決定する。

中心仮説は、販売・在庫・つけを同じ手順で記録・確認できるようにすれば、日々の操作負担を許容範囲に保ちながら欠品と在庫の無駄を減らし、店主不在時も店舗運営を継続できる、というものである。中心仮説は次の3件の価値仮説に分け、期待効果の各時間軸で確かめる。

1. 店主と家族が、説明なしでも同じ手順で販売・在庫・つけを記録・確認できる（初期公開指標で確かめる）。
2. 記録の操作が店番の負担にならず、毎営業日続けられる（短期指標で確かめる）。
3. 蓄積した記録を仕入れと引き継ぎに使うと、欠品と在庫の無駄が減り、店主不在でも運営できる（中長期指標で確かめる）。

## 3. 基本的な考え方

1. **Record First（まず記録する）**: 高度な分析よりも、販売・在庫・つけの記録が毎日続くことを優先する。記録が欠けると中長期の効果を測れないため、機能を追加するかどうかは記録の継続を妨げないかで判断する。
2. **Simple Operation（迷わず操作できる）**: 店主一人でも使えるように、画面数と入力項目を最小限にする。家族が店番をしても同じ判断ができる状態を、入力項目を増やすことより優先する。
3. **Small Start, Improve Later（小さく始めて改善する）**: 初期公開（店頭で使い始める最初の版の提供）では単一店舗の店頭運用に絞り、記録が安定してから仕入れ支援や分析を拡張する。拡張の要否は短期指標の結果を見て決める。

## 4. 実現したいこと

- 駄菓子の販売、在庫、常連顧客のつけをシンプルな仕組みで一元管理する。
- 店主一人でも無理なく操作できる画面と操作フローを提供する。
- 家族が店番をする場合でも、在庫状況とつけ残高を同じ手順で確認できるようにする。
- 欠品や過剰在庫に気づける販売・在庫の記録基盤を整え、後続の仕入れ支援や分析につなげられるようにする。

詳細な対象範囲と対象外は [[specdojo:prj-scope-sample|プロジェクトスコープ]] で扱う。

## 5. 期待効果

下記の目標値は初期仮説である。受入条件と判定時期を含む確定した成功判定は [[specdojo:prj-success-criteria-and-acceptance-criteria-sample|成功基準と受入条件]] で管理し、本書の値は実測値に基づき同書で見直す。欠品回数と在庫の無駄は、運用開始前1か月の実績をベースラインとする。季節、仕入れ条件、来店数などの影響も記録し、改善を本システムだけの成果とは断定せず寄与として評価する。

### 5.1. 初期公開指標

初期公開前には、実際に店番を行う店主代表と家族利用者代表が主要操作を完遂できるかを、代表シナリオの試行で確認する。機能数ではなく、一連の業務を止まらずに終えられることを判定する。

| 観点       | 指標                                                                               | 目標                             | 測定方法                                                             |
| ---------- | ---------------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------- |
| 作業完遂   | 販売記録、在庫確認、つけ残高確認の必須タスク完了率                                 | 店主代表・家族利用者代表とも100% | 操作説明なしで代表シナリオを実施し、完了、所要時間、支援内容を記録   |
| 使いやすさ | 自力で回復できず必須タスクを継続できない重大な行き詰まりの件数                     | 0件                              | 操作中の迷い、誤操作、質問、回復方法を観察して重大度を判定する       |
| 判断の一致 | 同じ販売・在庫・つけ記録について、店主代表と家族利用者代表の確認結果が一致する割合 | 100%                             | 同じ記録をそれぞれ確認し、販売内容、在庫数、つけ残高の回答を比較する |

### 5.2. 短期指標

運用開始後2週間で、主要操作が日々の店番に定着し、店主の負担を増やさずに利用できるかを判定する。

| 観点     | 指標                                                             | 初期目標              | 測定方法                                                   |
| -------- | ---------------------------------------------------------------- | --------------------- | ---------------------------------------------------------- |
| 運用定着 | 販売・在庫・つけの記録が残っている営業日の割合                   | 営業日の90%以上       | 営業日ごとに3種の記録有無を確認し、営業日数を母数に集計    |
| 操作負担 | 1営業日の販売・在庫・つけの記録・確認にかかる追加操作時間        | 1日あたり合計10分以内 | 初期運用期間に記録・確認の所要時間を日次で計測             |
| 家族利用 | 家族利用者代表が店番を担当し、店主の補助なしで記録を完了した回数 | 3回以上               | 店番日、実施した記録、必要だった支援、未完了事項を記録する |

### 5.3. 中長期指標

蓄積した記録が仕入れ判断、つけ管理、店主以外への引き継ぎに役立ち、店舗運営の継続へ寄与したかを確認する。欠品削減・つけ管理・店舗継続は運用開始後6か月、在庫適正化は季節変動を1巡含める運用開始後12か月で判定する。

| 観点       | 指標                                                             | 初期目標                  | 測定方法                                                                                        |
| ---------- | ---------------------------------------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------- |
| 欠品削減   | 対象の人気商品の月間欠品回数                                     | ベースライン比50%削減     | 対象商品を固定し、運用開始後6か月目の月間欠品回数をベースラインの1か月と比較する                |
| 在庫適正化 | 廃棄・値引き・長期滞留による在庫の無駄（数量と金額）             | 年間換算で20%削減         | 運用開始後12か月の月次集計の合計を、ベースラインの1か月を12倍した年間換算値と比較する           |
| つけ管理   | 記録漏れまたは残高不一致が解消されず翌月へ残った件数             | 月0件                     | 月末に記録と確認結果を照合し、不一致、原因、解消状況を記録する。運用開始後6か月の各月で判定する |
| 店舗継続   | 店主が不在でも家族が販売・在庫・つけ管理を完了できた店番日の割合 | 店主不在の店番日の90%以上 | 運用開始後6か月の店主不在の店番日を母数として、必須記録と引き継ぎの完了を確認する               |

参考指標として、売上、来店数、仕入れ条件、季節要因、店主・家族の負担感を記録し、指標変化の背景とシステムの寄与を確認する。ベースラインの1か月が繁忙期にかかる場合は、季節要因の記録をもとに比較の扱いを成功基準で見直す。

## 6. 前提条件

運営体制と業務の進め方のうち、本プロジェクトで変えない前提は次のとおりとする。

- 対象は単一店舗（きぬや）の店頭販売、店頭在庫、常連顧客のつけ管理に限定する。
- 初期公開では、EC 連携、複数店舗管理、本格会計連携、仕入れ先システム連携は対象外とする。
- 店主と家族が店番を行う現在の運営体制と、店舗の接客手順は変えず、現行運用に近い入力手順を優先する。

本プロジェクトが成り立つために、次の条件に依存する。

- 店内で使うタブレットを1台用意できること。
- 運用開始前1か月のベースラインとして、欠品と廃棄・値引き・長期滞留を手書きの記録で残せること。
- 家族利用者代表が、初期公開前の試行と運用開始後の店番に参加できること。

判断責任、AI Agent の役割、公開方針、取捨選択方針は次のとおりとする。

- 店主が最終的な業務判断を行い、システムは記録と確認を支援する位置づけとする。仕入れ数量やつけの扱いをシステムが自動で決めることはしない。
- AI Agent は、成果物の下書き作成と点検の補助に使ってよい。採否と業務上の判断は人が行い、AI Agent の出力をそのまま確定としない。
- 顧客の氏名、連絡先、つけ残高は店内の記録にのみ置き、本書を含む共有する文書には記載しない。
- 初期公開の範囲に入らない要望は記録だけ残し、短期指標の判定後に、記録の継続を妨げないかを基準に採否を決める。
- オフライン時の運用方針は _UNDECIDED_: 初期公開の計画で決定する。
