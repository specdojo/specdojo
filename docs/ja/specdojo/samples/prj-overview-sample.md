# プロジェクト概要: 駄菓子屋きぬや 販売管理システム

駄菓子屋きぬや 販売管理システムは、店頭販売、在庫、常連顧客のつけを一元管理し、店主一人でも日々の運用を続けやすくするための小規模店舗向け業務支援システムである。

## 1. 背景

地域の子どもたちに長年親しまれている「駄菓子屋きぬや」では、販売記録や在庫管理をノートと記憶に頼っている。店主の高齢化により、仕入れ判断や在庫確認、つけ残高の確認に時間がかかる場面が増えている。

現在、次の問題が生じている。

- 人気商品（うまい棒、ラムネ等）の欠品が増えている
- 仕入れのタイミングや数量が勘頼りで、在庫のムラが大きい
- 常連の子どもや近所の大人のつけ管理が曖昧で、記録漏れや確認コストが発生している
- 店主以外が店番をした際に、販売・在庫・つけの状況をすぐに確認できない

## 2. 必要性

このまま記憶と紙の運用を続けると、欠品や在庫過多による損失が増え、店舗継続リスクが高まる。また、店主以外が店番をする場合に同じ判断ができず、業務が属人化したままになる。

とりわけ繁忙期は来店と取引が集中し、欠品・在庫・つけの確認負荷が一気に高まる。記憶と紙の運用のままでは繁忙期の負荷に対応しきれず、損失と属人化のリスクが顕在化するため、負荷が高まる前のこの時期に着手する必要がある。

## 3. 基本的な考え方

1. **Record First（まず記録する）**: 高度な分析よりも、販売・在庫・つけの記録が毎日続くことを優先する。
2. **Simple Operation（迷わず操作できる）**: 店主一人でも使えるように、画面数と入力項目を最小限にする。
3. **Small Start, Improve Later（小さく始めて改善する）**: 初期リリースでは単一店舗の店頭運用に絞り、記録が安定してから仕入れ支援や分析を拡張する。

## 4. 実現したいこと

- 駄菓子の販売、在庫、常連顧客のつけをシンプルな仕組みで一元管理する。
- 店主一人でも無理なく操作できる画面と操作フローを提供する。
- 家族が店番をする場合でも、在庫状況とつけ残高を同じ手順で確認できるようにする。
- 欠品や過剰在庫に気づける販売・在庫の記録基盤を整え、後続の仕入れ支援や分析につなげられるようにする。

## 5. 期待効果

初期リリース前は、店主代表と家族利用者代表が店頭販売、在庫確認、つけ残高確認を迷わず完了できるかを確認する。リリース後の短期は日々の記録が無理なく定着するか、中長期は記録の活用が欠品、在庫の無駄、属人化の軽減と店舗運営の継続に寄与したかを確認する。

下記の目標値は初期仮説であり、実測値に基づき継続的に見直す。欠品回数と在庫の無駄は、運用開始前1か月の実績をベースラインとする。季節、仕入れ条件、来店数などの影響も記録し、改善を本システムだけの成果とは断定せず寄与として評価する。

### 5.1. 初期公開指標

初期リリース前には、実際に店番を行う利用者が主要操作を完遂できるかを確認する。機能数ではなく、一連の業務を止まらずに終えられることを判定する。

| 観点       | 指標                                                                               | 目標                             | 測定方法                                                             |
| ---------- | ---------------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------- |
| 作業完遂   | 販売記録、在庫確認、つけ残高確認の必須タスク完了率                                 | 店主代表・家族利用者代表とも100% | 操作説明なしで代表シナリオを実施し、完了、所要時間、支援内容を記録   |
| 使いやすさ | 自力で回復できず必須タスクを継続できない重大な行き詰まりの件数                     | 0件                              | 操作中の迷い、誤操作、質問、回復方法を観察して重大度を判定する       |
| 判断の一致 | 同じ販売・在庫・つけ記録について、店主代表と家族利用者代表の確認結果が一致する割合 | 100%                             | 同じ記録をそれぞれ確認し、販売内容、在庫数、つけ残高の回答を比較する |

### 5.2. 短期指標

リリース後2週間は、主要操作が日々の店番に定着し、店主の負担を増やさずに利用できるかを確認する。

| 観点     | 指標                                                             | 初期目標              | 測定方法                                                   |
| -------- | ---------------------------------------------------------------- | --------------------- | ---------------------------------------------------------- |
| 運用定着 | 販売・在庫・つけの記録が残っている営業日の割合                   | 営業日の90%以上       | 営業日ごとに3種の記録有無を確認し、営業日数を母数に集計    |
| 操作負担 | 1営業日の販売・在庫・つけの記録・確認にかかる追加操作時間        | 1日あたり合計10分以内 | 初期運用期間に記録・確認の所要時間を日次で計測             |
| 家族利用 | 家族利用者代表が店番を担当し、店主の補助なしで記録を完了した回数 | 3回以上               | 店番日、実施した記録、必要だった支援、未完了事項を記録する |

### 5.3. 中長期指標

中長期的には、蓄積した記録が仕入れ判断、つけ管理、店主以外への引き継ぎに役立ち、店舗運営の継続へ寄与したかを確認する。

| 観点       | 指標                                                             | 初期目標              | 測定方法                                                       |
| ---------- | ---------------------------------------------------------------- | --------------------- | -------------------------------------------------------------- |
| 欠品削減   | 人気商品の欠品回数                                               | ベースライン比50%削減 | 対象商品を固定し、運用前後の欠品発生を月単位で比較する         |
| 在庫適正化 | 廃棄・値引き・長期滞留による在庫の無駄                           | 年間20%削減           | 廃棄、値引き、長期滞留の数量と金額を月次で集計する             |
| つけ管理   | 記録漏れまたは残高不一致が解消されず翌月へ残った件数             | 月0件                 | 月末に記録と確認結果を照合し、不一致、原因、解消状況を記録する |
| 店舗継続   | 店主が不在でも家族が販売・在庫・つけ管理を完了できた店番日の割合 | 対象日の90%以上       | 店主不在の店番日を母数として、必須記録と引き継ぎ結果を確認する |

参考指標として、売上、来店数、仕入れ条件、季節要因、店主・家族の負担感を記録し、指標変化の背景とシステムの寄与を確認する。

## 6. 前提条件

本プロジェクトの策定および活用にあたっては、以下を前提とする。

- 対象は単一店舗（きぬや）の店頭販売、店頭在庫、常連顧客のつけ管理に限定すること。
- 初期リリースでは、EC 連携、複数店舗管理、本格会計連携、仕入れ先システム連携は対象外とすること。
- 操作端末は店内のタブレット 1 台を想定すること。
- 店舗の接客手順を大きく変えず、現行運用に近い入力手順を優先すること。
- 店主が最終的な業務判断を行い、システムは記録と確認を支援する位置づけとすること。
- オフライン時の運用方針は _UNDECIDED_: 初期リリース計画で決定すること。
