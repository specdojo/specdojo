# 駄菓子屋きぬや 販売管理システム 操作性要件

## 1. 概要（対象・目的）

店主代表と、不定期に店番する家族利用者代表が、店頭のタブレットで現金会計とつけの記録・残高確認を説明書なしで終えられるよう、操作品質の基準を定める。守りたいのは、操作に迷って来店客を待たせること、会計やつけの誤登録、店番の交代ごとに操作を教え直す手間の 3 つである。

基準の厳しさは、店主以外も同じ手順で店番できるようにするという目的と、つけ残高を 1 分以内で確認できるというプロジェクトの初期目標（[[specdojo:prj-overview-sample|プロジェクト概要]]）から決める。

## 2. 適用範囲・利用者前提

基準値は次の業務・画面と利用者・環境の組み合わせで成り立つ。

| 区分   | 業務                             | 画面                                                                                     |
| ------ | -------------------------------- | ---------------------------------------------------------------------------------------- |
| 対象   | 現金会計（明細登録から会計確定） | [[specdojo:uis-sample\|販売登録画面]]（`uis-sales-register`）と販売完了画面              |
| 対象   | つけの記録と残高確認             | `uis-credit-ledger`（未作成の仮置き名）                                                  |
| 対象   | 在庫数の確認                     | `uis-stock-list`（未作成の仮置き名）                                                     |
| 対象外 | 日次締め、商品・価格の登録       | 閉店後に店主代表だけが落ち着いて行う業務のため、本書の基準を当てず受入時の確認だけとする |

被験者は次の利用者属性で選ぶ。

| 利用者区分 | 該当する店番担当 | 業務知識                         | システム経験         | 利用頻度         |
| ---------- | ---------------- | -------------------------------- | -------------------- | ---------------- |
| 熟練利用者 | 店主代表         | 商品・価格・つけ客を把握している | 本システムの研修済み | 営業日のほぼ毎日 |
| 新任利用者 | 家族利用者代表   | 会計の手順と商品はおおむね分かる | 本システムは未経験   | 週 1〜2 回       |

利用環境は、店頭のレジ横に置いたタブレット 1 台を立ったまま指で操作し、来店客と対面しながら入力する状態とする。

- _ASSUMPTION_: 画面は 10 インチ前後のタブレットを横向きで使い、ブラウザで表示する。端末の機種は決まっておらず、変わった場合は「操作性要件一覧」の完了時間を測り直す。
- _ASSUMPTION_: 放課後の混雑時は 1 人の店番担当が続けて会計する。混雑時と閑散時で基準は分けない。
- 店主代表は小さい文字が読みにくいため、熟練利用者の測定も同じ端末・同じ文字サイズの設定で行う。

## 3. 操作性要件一覧

次の表の各行を、指標の測定値が基準を満たすかで合否判定する。被験者の数え方と対象操作は `備考` に書く。

| id            | 内容                                                       | 指標                                                                                      | 基準      | 備考                                                                                   |
| ------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------- | -------------------------------------------------------------------------------------- |
| `nfr-usb-001` | 新任利用者が説明なしで現金会計を終えられる                 | タスク完了率（介助なしで会計確定まで終えた被験者数 ÷ 被験者数）                           | 80% 以上  | 新任利用者。3 品目の明細登録から預かり金入力・会計確定まで                             |
| `nfr-usb-002` | 会計の誤操作を少なく抑える                                 | 誤操作率（確定後に取消理由「誤登録」で取り消した会計数 ÷ 確定した全会計数）               | 2% 以下   | 新任利用者・熟練利用者の両方。営業日の会計すべて                                       |
| `nfr-usb-003` | つけ残高をすぐに確かめられる                               | 完了時間（つけ客の検索開始から残高が表示されるまで）                                      | 60 秒以内 | 新任利用者・熟練利用者の全被験者・全試行。客名の一部を入力して検索する場合             |
| `nfr-usb-004` | 新任利用者が短い習熟で会計の時間を熟練利用者に近づけられる | 習熟時間（初回の操作から、3 品目の会計を 90 秒以内で 3 回続けて終えるまでの累積操作時間） | 30 分以内 | 新任利用者。90 秒は熟練利用者の同じ会計の所要時間の目安とする（_ASSUMPTION_）          |
| `nfr-usb-005` | エラー表示から利用者が次の手を選べる                       | 対処方法含有率（次の操作を示しているエラー表示の数 ÷ 対象画面のエラー表示の総数）         | 100%      | 「適用範囲・利用者前提」の対象画面のエラー表示すべて                                   |
| `nfr-usb-006` | 取り消せない操作を確認なしで実行させない                   | 破壊的操作の確認網羅率（実行前に確認を求める破壊的操作の数 ÷ 破壊的操作の総数）           | 100%      | 取引中止、つけ記録の取消、確定済み会計の取消。明細削除は確定前に直せるため対象外とする |

`nfr-usb-002` は、来店客の購入取りやめなど誤操作以外の理由の取消を分子に含めない。確定前に直した誤登録は記録が正しく残るため数えず、迷いによる待ちは `nfr-usb-001` と `nfr-usb-004` で扱う。

## 4. 測定・検証方法

基準値は「操作性要件一覧」を参照する。

| 要件ID        | 測定方法                                                                                                       | 判定タイミング                           | 判定者         |
| ------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | -------------- |
| `nfr-usb-001` | ユーザビリティテスト。新任利用者の属性に合う 5 名が、検証用の環境で事前説明なしに会計を 1 回ずつ行う           | リリース前の受入試験                     | 利用者代表・QE |
| `nfr-usb-002` | 操作ログ集計。確定した会計数と、取消理由ごとの取消件数を暦月で数える                                           | 受入試験、運用開始後は月次の運用レビュー | QE             |
| `nfr-usb-003` | ユーザビリティテスト。被験者 5 名が登録済みのつけ客 3 名の残高を確かめ、画面録画から開始と表示の時刻を読む     | リリース前の受入試験                     | 利用者代表・QE |
| `nfr-usb-004` | ユーザビリティテスト。新任利用者 3 名が同じ 3 品目の会計を繰り返し、試行ごとの所要時間と累積操作時間を記録する | リリース前の受入試験                     | 利用者代表・QE |
| `nfr-usb-005` | レビュー。画面仕様のエラー表示の一覧と実画面を照合し、表示ごとに次の操作が書かれているかを数える               | 総合テストの終了時                       | QE             |
| `nfr-usb-006` | レビュー。対象画面の操作から破壊的操作を洗い出し、実画面で各操作の実行前に確認が出ることを確かめる             | 総合テストの終了時                       | QE             |

ユーザビリティテストの被験者は、本システムの開発に関わっていない人から選ぶ。測定値が基準を満たせば pass、満たさなければ fail とし、fail の要件は該当画面を直したあと同じ条件で測り直す。
