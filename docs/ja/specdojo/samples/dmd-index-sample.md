# データ移行設計（全体構成）: 駄菓子屋きぬや 販売管理システム

## 1. 概要（index）

商品ノートと常連客ノートの記録を転記用の表へ書き写し、店頭タブレットの販売管理システムへ取り込む移行について、取り込み直しても同じ結果になる手順と、元ノートと一致したことを示す照合の方法を定める。範囲は `mip-index` が移行対象とした商品台帳・現在庫・顧客台帳とつけ残高であり、対象ごとの書き写し方と取り込みの詳細は対象別の `dmd-<term>` に置く。

## 2. 共通方針（抽出/変換/除外/冪等性/ログ）

- 抽出方式: 全対象をフルとする。移行元が紙のノートで変更日時を持たず、増分の基準にできる項目がないためである。最終棚卸から取り込みまでは臨時休業で販売がないため、差分を取り込む必要もない。
- 変換: 転記用の表へ書き写す時点で、金額は税込の円の整数、在庫数は個数の整数にそろえる。ノートの書き方と転記用の表の値が異なる行は、備考欄に元の書き方を残す。
- 除外: ノートで取り消し線を引いた商品（販売をやめた商品）と、取り消し線を引いた顧客は書き写さない。除外した行は、元ノートのページと除外の理由を転記用の表の除外欄に記録する。
- 冪等性: 取り込みのたびに対象の台帳を空にしてから、転記用の表の全行を投入する（洗い替え）。同じ転記用の表からは常に同じ台帳ができ、前回の取り込みの記録は残らない。取り込み直しは切替日の正午の開店前に限り、開店後は台帳を空にしない。
- ログ: 取り込みと照合のたびに、`run_id`、開始・終了の日時、対象、段階（取り込み／照合）、転記用の表の行数、投入した件数、エラーの件数とその行、作業した役割名を記録する。

## 3. `run_id` 規約（命名/採番/記録/参照方法）

`run_id` は取り込み 1 回ごとに採番し、その回のログ・投入データ・照合表を同じ値で結び付ける。

| 項目     | 決まり                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 命名     | `DMD-YYYYMMDD-<term>-NN`。`<term>` は対象の論理名（`item` 商品台帳、`stock` 現在庫、`credit` 顧客台帳とつけ残高）              |
| 採番     | `NN` は 2 桁の 01 始まりで、同じ日・同じ対象の取り込みごとに 1 つ進める（例: 取り込み直した商品台帳は `DMD-20261207-item-02`） |
| 記録先   | 店頭タブレットの移行作業フォルダ `migration/<run_id>/` にログと照合表を置き、紙の移行作業の記録表にも `run_id` を書く          |
| 参照方法 | 取り込んだ各記録の取り込み元欄に `run_id` を付け、照合表のファイル名と紙の照合表の見出しにも同じ `run_id` を書く               |

- 移行リハーサルも同じ規約で採番する。日付の部分でリハーサルと切替日の取り込みを区別する。
- _UNDECIDED_: 移行作業フォルダの控えをタブレットの外へ残すか。顧客の氏名・連絡先を含むため、店主代表が控えの要否と置き場所を決める。

## 4. 検証の共通方針（種別/基準/証跡/保管）

照合は取り込みのたびに次の 3 種別をすべて行い、どれか 1 つでも基準を満たさなければその回の取り込みを不合格とする。

| 種別         | 比べるもの                                                                                         | 合格基準                                                           |
| ------------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 件数照合     | 転記用の表の行数（除外欄を除く）と、取り込み後の商品・顧客の件数                                   | 差分 0 件                                                          |
| サンプル照合 | 元ノートの各ページから 1 行ずつ選んだ記録と、システムの画面に出る同じ記録のすべての項目            | 差分 0。ただし商品名の表記ゆれは許容差として差分に数えない（下記） |
| 重要値照合   | 元ノートのつけ残高（顧客ごとと合計）と取り込み後の残高一覧、最終棚卸の記入表と取り込み後の在庫一覧 | 顧客ごとの残高・合計とも差異 0 円、全商品で在庫数の差異 0 個       |

- 許容差の例: サンプル照合の商品名は、全角と半角、長音記号の違いだけの差を許容する。商品名は店頭の表示に使うだけで、販売・在庫の記録は商品番号で結び付くため、売上と在庫数に影響しない。金額・個数・つけ残高に許容差は設けない。
- 合否の判定: 照合の結果は、`mip-index` の成功条件に定めた判定者が照合表を見て決める。
- 証跡: 照合表は `<run_id>-check-<種別>`（種別は `count`・`sample`・`value`）の名前で `migration/<run_id>/` に保管する。同行レビュー担当が読み合わせた紙の照合表は、店頭台帳保管棚の鍵付きの引き出しに `run_id` 順にしまう。
- _UNDECIDED_: 照合表と旧ノートの保管期間。`mip-index` が本書に委ねた値で、つけ残高の問い合わせに備える期間を店主代表が決める。

## 5. 対象一覧（スコープ/非対象/担当/対応ドキュメント）

対象と非対象は `mip-index` の移行対象一覧の「データ」「非対象」の行を受けたものである。

| 区分   | 対象（論理名）     | 旧→新                                     | 方針（フル/増分） | 担当 | 対応DMD           | `mip-index` との対応・除外の理由                               |
| ------ | ------------------ | ----------------------------------------- | ----------------- | ---- | ----------------- | -------------------------------------------------------------- |
| データ | 商品台帳           | 商品ノート → 商品台帳                     | フル              | DEV  | `dmd-item-data`   | データ「商品台帳」を受ける                                     |
| データ | 現在庫             | 最終棚卸の記入表 → 在庫                   | フル              | DEV  | `dmd-stock-data`  | データ「現在庫」を受ける。入出庫の履歴は移さない               |
| データ | 顧客台帳とつけ残高 | 常連客ノート（顧客欄・つけ欄） → 顧客台帳 | フル              | DEV  | `dmd-credit-data` | データ「顧客台帳とつけ残高」を受ける。顧客ごとの残高だけを移す |
| 非対象 | 過去の販売ノート   | 販売ノート → -                            | -                 | -    | -                 | 紙のまま保管し、問い合わせ時に参照する                         |
| 非対象 | 仕入ノート         | 仕入ノート → -                            | -                 | -    | -                 | 仕入先との連携が初期リリースの対象外で、移行先に記録先がない   |
| 非対象 | つけ販売の明細     | 常連客ノート（つけ欄の明細） → -          | -                 | -    | -                 | 移行後の請求には残高だけを使うため。明細はノートで参照する     |

## 6. 関連ドキュメント（必須）

- `dmd-item-data`: 商品台帳の書き写し方と取り込み
- `dmd-stock-data`: 最終棚卸の記入表から在庫への取り込み
- `dmd-credit-data`: 顧客台帳とつけ残高の書き写し方と取り込み
- `mip-index`: 移行計画（移行対象、成功条件と判定者、業務停止時間）
- `mtp-index`: 移行リハーサル計画（作業時間の測定と照合の合否の確かめ方）
