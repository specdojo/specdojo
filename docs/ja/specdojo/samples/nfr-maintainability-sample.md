# 駄菓子屋きぬや 販売管理システム 非機能要件 / 保守性

## 1. 概要（対象・目的）

店主不在の日も家族が店番を続けられるよう、レジ代わりのタブレットで販売・つけを記録できなくなったときの切り分けと切り戻しを、紙の販売控えへ切り替える前に終える。切り分けや切り戻しが長引くと、その間の販売とつけは紙に書いて後で転記することになり、記録漏れと照合の手間が増える。これは「店主の経験と記憶だけに依存せず店舗運営を継続する」と「営業日の 90% 以上で記録を継続する」という目的に応えるための要件である。

閾値のうち、次の表の値は店主代表の業務判断が要るため未決とする。決まるまでは「決まるまでの扱い」に従い、該当する要件で pass / fail を判定しない。

| 未決事項                                        | 判断者 | 決まるまでの扱い                                         | 影響する要件・文書                    |
| ----------------------------------------------- | ------ | -------------------------------------------------------- | ------------------------------------- |
| _UNDECIDED_: P1 障害の MTTR の上限              | `PO`   | 障害記録から月次の平均を集計して報告だけ行う             | `nfr-mnt-003`、可用性の RTO、受入判定 |
| _UNDECIDED_: 商品マスタ・価格変更のリードタイム | `PO`   | 要求日と反映日を変更記録に残し、月次の最大を報告だけ行う | `nfr-mnt-004`、変更手順               |

## 2. 適用範囲・前提条件

対象は、店頭のタブレット 1 台で使う販売・在庫・つけの記録機能と、その記録を保存するホスティング環境で起きる障害対応と変更である。

| 項目                 | 内容                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 対象システム         | 販売・在庫・つけの記録機能（タブレットの画面とホスティング環境のアプリ・データベース）                                               |
| 対象の保守作業       | 障害の一次切り分け、修正、切り戻し、商品マスタ・価格の変更                                                                           |
| 対象時間帯           | 障害対応は営業時間 10:00〜18:00。変更と切り戻しは閉店後から翌営業日の開店まで                                                        |
| 保守作業を担う役割   | 切り分けの判断は `OPS`、修正と切り戻しは `DEV`、紙の販売控えへの切替の判断は `PO`。店番担当は異常の連絡と記録の再開の確認だけを行う  |
| 測定の前提となる記録 | 障害記録（検知・切り分け完了・再開の時刻と原因の範囲）、変更記録（要求日・反映日・切り戻しの有無）、ホスティング環境の死活監視の通知 |
| 対象外               | 停止許容時間と RTO/RPO（`nfr-availability`）、画面の応答時間（`nfr-performance`）、EC・本格会計・複数店舗                            |

_ASSUMPTION_: 時刻の記録は `OPS` が障害記録・変更記録に手で書く。自動で時刻を集める仕組みは初期リリースでは持たず、記録が欠けた障害は判定できないものとして `nfr-mnt-005` で扱う。

## 3. 保守性要件一覧

次の表は、保守作業ごとの指標と、pass / fail を決める基準を示す。基準には集計方法と集計期間を併記する。

| id            | 内容                                                      | 指標                     | 基準                                                                                | 備考                                                            |
| ------------- | --------------------------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `nfr-mnt-001` | P1 障害で、原因の範囲（アプリ・データ・端末・通信）を絞る | 一次切り分け時間         | 各 P1 障害で最大 30 分以内（障害ごとに判定）                                        | 紙の販売控えへの切替を判断する時刻（P1 検知から 30 分）と揃える |
| `nfr-mnt-002` | 閉店後に適用した変更を、直前の正常な版へ戻す              | ロールバック時間         | 切り戻しを決めた変更のすべてで、翌営業日の 10:00 までに記録を再開（変更ごとに判定） | 直前の正常な版を常に 1 つ保持していることを前提とする           |
| `nfr-mnt-003` | P1 障害から業務を再開する                                 | MTTR                     | _UNDECIDED_（P1 障害の平均、月次集計）                                              | 上限は可用性の RTO を超えない値で決める                         |
| `nfr-mnt-004` | 商品マスタ・価格の変更を反映する                          | 変更リードタイム         | _UNDECIDED_（全件の最大、月次集計）                                                 | 反映は閉店後に限る                                              |
| `nfr-mnt-005` | P1・P2 障害の解析に要る時刻と原因の範囲を残す             | 障害記録の必須項目の充足 | P1・P2 障害の 100% で検知・切り分け完了・再開の時刻と原因の範囲がある（月次集計）   | 1 件でも欠ければ fail とし、`nfr-mnt-001`・`003` の判定から外す |

## 4. 測定・検証方法

次の表は、要件ごとにどの記録で測り、いつ誰が pass / fail を決めるかを示す。agent は障害記録・変更記録からの集計の補助だけを行い、判定はしない。

| 要件ID        | 測定方法                                                                   | 判定タイミング                       | 判定者 |
| ------------- | -------------------------------------------------------------------------- | ------------------------------------ | ------ |
| `nfr-mnt-001` | 障害記録の検知時刻と切り分け完了時刻の差。受入前は通信断を模した訓練で計る | 障害の収束後の事後確認、受入前の訓練 | `OPS`  |
| `nfr-mnt-002` | 変更記録の切り戻し決定時刻と、店番担当が記録の再開を確かめた時刻           | 切り戻しのたび、受入前の切り戻し訓練 | `OPS`  |
| `nfr-mnt-003` | 障害記録の検知時刻と再開時刻の差を、P1 障害について月ごとに平均する        | 月次点検                             | `PO`   |
| `nfr-mnt-004` | 変更記録の要求日と反映日の差を月ごとに集め、最大を取る                     | 月次点検                             | `PO`   |
| `nfr-mnt-005` | 月内の P1・P2 障害記録で、必須の 4 項目がそろう件数の割合                  | 月次点検                             | `OPS`  |

判定で見つかった事柄は次のように残す。

- 閾値が `_UNDECIDED_` の要件は、測った値を月次点検で報告し、未決事項として登録簿へ引き継ぐ。
- 基準未達は、要件 ID・該当する障害または変更・測った値を課題として登録簿の個票に残す。
- 閾値や測定方法を変えたときは判断を登録簿の decision に残し、可用性要件・受入判定・運用手順の該当箇所を同じ時期に直す。

閾値を見直す契機は、`nfr-mnt-001` か `nfr-mnt-002` の未達が 2 か月続いたとき、営業時間が変わったとき、記録の保存先や時刻の記録方法が変わったときとする。
