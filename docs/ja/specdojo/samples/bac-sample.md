# 駄菓子屋きぬや 現金販売の業務受入条件

## 1. 概要

BAC を初めて作成する BA と、承認・設計・受入テストへ引き継ぐ担当者に向けた完成例である。構成と品質判定・検査・確定条件は [[specdojo:bac-rulebook|業務受入条件 作成ルール]] の「本文要件」、rulebook・共通文脈の変更時の追従は [[specdojo:sample-authoring-standard|Sample 記述標準]] の「運用ルール」に従う。

店主代表または家族利用者代表が、現金販売を確定し、販売記録と在庫の変化を照合して店番を引き継げることを確認する。店主の記憶とノートへの転記に頼る負担を減らし、家族が担当しても同じ販売結果を確認できるようにする。

- 価値との対応: 販売と在庫の記録を照合する価値を BAC-01、販売できない購入を誤って確定せず引き継ぐ価値を BAC-02・BAC-03 で確認する。
- 利用場面・対象範囲: 単一店舗・端末1台で、購入する商品と数量をそろえ、請求額への合意と現金受領を経て、販売と在庫の記録を確認するまで。
- 対象外: つけ販売、キャッシュレス決済、返品、確定後の訂正、仕入れ、オフラインでの販売継続。
- 根拠: [[specdojo:prj-overview-sample|プロジェクト概要]] の「まず記録する」方針と家族による店番の継続を、現金販売に限定して具体化する。本例用の業務仕様 `kinuya-bps-cash-sale` は未同梱の架空参照名であり、以下の仮定を完成例の条件とする。受入条件の直接の根拠となる先行成果物への `based_on` は未接続である。

_ASSUMPTION_: 本例では、商品・数量が確定し、在庫が足り、合意した請求額の現金を受領してから販売を確定する。確定時は販売を1件記録し、販売数だけ在庫を減らす。入力不足・在庫不足では確定せず、不足を解消してから同じ購入内容の確認へ戻る。これは学習用の業務仮定であり、実店舗の承認済み仕様ではない。

_ASSUMPTION_: 未確定の購入は、分かっている商品・希望数量、不足情報、次に確認することを引継ぎメモに残す。購入中止が合意された場合は中止を記し、再開対象から外す。販売記録・在庫記録・引継ぎメモは論理的な証跡名であり、保存形式は本例で定めない。

| 役割             | 確認・合意する内容                                                         |
| ---------------- | -------------------------------------------------------------------------- |
| 家族利用者代表   | 店主不在でも、販売記録・在庫・未確定の購入内容を照合して引き継げること     |
| 店主代表         | 販売確定の条件、販売を止める条件、停止後の次の行為を業務として承認すること |
| 同行レビュー担当 | 各シナリオの開始状態と確定後の記録から期待結果を確認できること             |
| 開発担当         | 業務条件を設計と動作確認へ引き継ぎ、入力項目と保存構造の正本を整えること   |

## 2. 受入条件

共通前提として、店番担当は店主代表または家族利用者代表とする。商品Aは販売可能な商品で、単価は最終的な販売価格30円、開始時の在庫は5個とする。各ケースは独立した開始状態で確認し、端末と記録の利用に支障はない。計算方式・税区分・保存構造は本例では定めない。

### 2.1. BAC-01 現金販売を確定して記録を照合する

根拠: 概要に記した販売確定と記録の仮定。

#### 2.1.1. 前提

- 商品Aと購入数量が確定し、在庫数以内である。
- 来店客と請求額を合意し、その金額の現金を受領している。

#### 2.1.2. 操作

- 店番担当が、商品と数量、請求額、受領額を確認して販売を確定する。

#### 2.1.3. 期待結果

| ケース ID | 条件・入力                                                         | 期待結果（観測点）                                                   |
| --------- | ------------------------------------------------------------------ | -------------------------------------------------------------------- |
| C-01      | 家族利用者代表が商品Aを2個、請求額60円・受領額60円で販売する       | 商品A・数量2・販売額60円の販売記録が1件残り、在庫が5個から3個になる  |
| C-02      | 店主代表が商品Aを在庫と同じ5個、請求額150円・受領額150円で販売する | 商品A・数量5・販売額150円の販売記録が1件残り、在庫が5個から0個になる |

- 販売記録と在庫の変化を同じ販売へ対応付けて確認できる。次の店番担当は販売済みと未確定の購入を区別できる。

#### 2.1.4. 判定方法

- 同行レビュー担当が確定後の販売記録と開始前後の在庫記録を照合し、商品・数量・金額・件数と在庫差分を確認する。家族利用者代表は店番交代時に同じ販売記録と引継ぎメモから、販売済みの内容と未確定の購入を区別して説明する。

### 2.2. BAC-02 在庫不足なら販売を確定せず確認へ戻る

根拠: 概要に記した在庫不足時の仮定。

#### 2.2.1. 前提

- 商品Aの購入希望数は6個で、在庫5個を超えている。
- 販売は未確定で、現金をまだ受領していない。

#### 2.2.2. 操作

- 店番担当が、希望数量と在庫を照合して販売を進めようとする。

#### 2.2.3. 期待結果

- 不足1個と対象商品を店番担当が確認でき、販売は確定されない。販売記録は追加されず、在庫は5個のままである。
- 店番担当は不足を来店客へ説明し、数量変更または購入中止を確認できる。店番交代時には、商品A・希望6個・不足1個・来店客への数量変更または中止の確認待ちを引継ぎメモに残し、未確定の内容として次の担当へ渡せる。
- 来店客が2個への変更に合意した場合は、請求額と現金受領を確認してから BAC-01 の C-01 に相当する販売へ進む。希望数6個の販売記録は作られない。
- 購入中止に合意した場合は引継ぎメモを中止へ更新し、販売記録は追加せず在庫5個を維持する。

#### 2.2.4. 判定方法

- 同行レビュー担当が停止直後の不足の表示・販売記録・在庫記録を希望数と開始前の状態に照合する。家族利用者代表は交代時の引継ぎメモから対象・不足数・次の確認行為を説明する。数量変更と購入中止は独立した開始状態で確認し、合意後に同行レビュー担当が引継ぎメモと販売・在庫記録を照合する。変更時は在庫3個・記録1件、中止時は在庫5個・記録追加なしであることを確認する。

### 2.3. BAC-03 必須情報が不足した購入を未確定のまま引き継ぐ

根拠: 概要に記した入力不足時の仮定。

#### 2.3.1. 前提

- 共通前提と異なり、次のケースのいずれかで販売に必要な情報がそろっていない。
- 販売は未確定で、現金受領前である。各ケースは独立して確認する。

#### 2.3.2. 操作

- 店番担当が購入内容を確認し、不足があれば来店客または次の店番担当へ確認事項を伝える。

#### 2.3.3. 期待結果

| ケース ID | 条件・入力                              | 期待結果（観測点）                                               |
| --------- | --------------------------------------- | ---------------------------------------------------------------- |
| C-03      | 数量2は分かるが、対象商品が特定できない | 対象商品の確認が必要と分かり、別の商品を推測して販売を確定しない |
| C-04      | 商品Aは分かるが、数量が不明である       | 数量の確認が必要と分かり、仮の数量で販売を確定しない             |

- 両ケースで販売記録は追加されず、在庫は5個のままである。引継ぎメモに判明済みの情報と商品または数量の確認待ちを記し、確定済みの販売と区別して次の担当へ引き継げる。
- 不足が解消し商品A・数量2となった場合は、請求額と現金受領を確認してから BAC-01 の C-01 に相当する販売へ進める。不足中の内容を別の販売として残さない。

#### 2.3.4. 判定方法

- 同行レビュー担当が停止時の販売記録と在庫記録を開始前と照合する。店番交代時に家族利用者代表が引継ぎメモから判明済みの情報、不足情報、次に確認すること、未確定であることを説明する。補完後は同行レビュー担当が確定時の販売記録と在庫記録を C-01 の期待値に照合し、不足中の販売記録がないことを確認する。
