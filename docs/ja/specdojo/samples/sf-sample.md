# 駄菓子屋きぬや 商品販売機能仕様

## 1. 目的と概要

店主代表と家族利用者代表が、店頭のタブレットから現金販売を記録し、請求額・釣銭と在庫への反映結果を同じ取引で確認できるようにする。ノートへの転記漏れと暗算の誤りを減らし、店番が交代しても記録を続けられるようにする。これは [[specdojo:prj-overview-sample|プロジェクト概要]] の「まず記録する」方針に対応する。

上位のシステム化機能一覧は `sf-index`（未作成）で、対応エントリは機能 ID `SF-POS-01`「店頭商品販売」とする。一覧への登録時に対応を確定する（「未決事項」の `Q-01`）。

| 区分   | 範囲                                                                                                                               |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 対象   | 単一店舗の現金販売。明細の登録・修正、税額・請求額・釣銭の提示、販売記録の確定、在庫反映結果の確認、レシート発行要求、確定前の中止 |
| 対象外 | つけ販売（`P-04`）、補充判断（`P-06`）、キャッシュレス決済、確定後の返品・値引訂正、EC・複数店舗                                   |

店番中の店主代表・家族利用者代表が利用し、設計と受入試験では本書の要件と受入条件を入力にする。

## 2. 業務プロセス・画面との対応

業務境界は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）]] の店頭販売 `P-03` と在庫確認 `P-05` に対応する。詳細 BPS `bps-sales-order-flow` は未作成のため、領域単位で対応付ける（`Q-01`）。

| 根拠領域        | 本機能の責務                                                   | 対応要件・入出力                    |
| --------------- | -------------------------------------------------------------- | ----------------------------------- |
| `P-03` 店頭販売 | 購入商品と数量を受け、明細と請求額を提示する                   | `FR-01`・`FR-02`、購入明細・請求額  |
| `P-03` 店頭販売 | 現金の受領確認を受け、販売を記録して完了可否を返す             | `FR-03`、預かり金・販売記録         |
| `P-05` 在庫確認 | 払出数量を渡し、反映結果を会計結果へ対応付ける。在庫算出は委譲 | `FR-03`、販売確定情報・在庫反映結果 |
| `P-03` 店頭販売 | 確定前の取引中止を受け、未確定の明細を破棄する                 | `FR-04`、取引中止結果               |

| 接点                                   | トリガー・受け渡し                                               | 責務境界                                                 |
| -------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| [[specdojo:uis-sample\|販売登録画面]]  | 商品追加・数量修正・会計確定・中止を受け、明細・金額・結果を返す | 表示・入力形式・遷移は UIS、会計の確定可否は本機能       |
| 在庫確認機能 `sf-inventory`            | 払出数量を渡し、反映済み・未反映・結果不明の区別を受ける         | 在庫更新は連携先。未反映・結果不明を販売完了と通知しない |
| レシート出力 `ifx-cmd-receipt-printer` | 確定した販売の印字内容を渡し、印刷結果を受ける                   | 印刷失敗は販売確定と区別する                             |

利用接点は GUI とし、CLI による会計は対象外とする。

## 3. 入出力と前提条件

### 3.1. 入出力

| 区分 | 論理情報                               | 入手元 / 提供先                         | 必須性・確定条件                       | 正本仕様                                              | 対応要件         |
| ---- | -------------------------------------- | --------------------------------------- | -------------------------------------- | ----------------------------------------------------- | ---------------- |
| 入力 | 商品識別子、販売数量、明細の修正・削除 | 店番担当 / 明細登録                     | 登録・修正時に必須                     | 販売登録画面、[[specdojo:bdd-sample\|業務データ辞書]] | `FR-01`          |
| 入力 | 販売単価、税区分、販売可能な在庫数量   | 商品台帳・在庫確認機能 / 会計確認       | 会計前に確認できること                 | 業務データ辞書、`br-tax-calculation`、`sf-inventory`  | `FR-01`・`FR-02` |
| 入力 | 預かり金額、現金の受領確認             | 店番担当 / 会計確定                     | 確定時に必須                           | 販売登録画面                                          | `FR-02`・`FR-03` |
| 入力 | 在庫反映結果、保存済みの販売と処理結果 | 在庫確認機能・販売記録 / 確定・再開判定 | 確定要求時と結果照合時に必須           | `sf-inventory`、`ifx-api-store-sales`                 | `FR-03`          |
| 出力 | 購入明細、税額、請求額、釣銭           | 本機能 / 店番担当・来店客               | 明細・預かり金の変更に追従する         | 販売登録画面、`br-tax-calculation`                    | `FR-01`・`FR-02` |
| 出力 | 売上記録・売上明細、販売確定情報       | 本機能 / 販売記録・在庫確認機能         | 確定要求ごとに一度だけ記録・反映する   | 業務データ辞書、`sf-inventory`                        | `FR-03`          |
| 出力 | 会計結果、停止理由、中止結果、印字内容 | 本機能 / 店番担当・レシート出力         | 完了・保留・中止と印刷成否を識別できる | 販売登録画面、`ifx-cmd-receipt-printer`               | `FR-03`・`FR-04` |

データ項目・型・コード値は業務データ辞書を正本とし、本書へ転記しない。

### 3.2. 前提条件と事後条件

- 着手条件: 店番担当が販売権限で利用でき、商品台帳と店舗内の記録先へ接続できること。進行中の取引があれば継続し、別の取引を重ねない。
- 事後条件: 正常完了は `FR-03`、中止は `FR-04`、保留・失敗は「例外・回復条件」に従う。印刷成否は会計結果と分けて判定する。

## 4. 処理要件・機能振る舞い

### 4.1. 通常処理

| 要件 ID | 開始条件                               | 処理の責務・確定する結果                                                                                                     | 判断の正本                                            |
| ------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `FR-01` | 商品・数量を受けた                     | 商品と在庫を照合して明細を更新する。未登録商品・販売不可の数量は理由を返し、既存明細を維持する                               | 販売登録画面の入力条件                                |
| `FR-02` | 有効な明細がある                       | 税額・請求額を提示し、預かり金から釣銭を求める。明細が空、または預かり金が不足する間は確定を受け付けない                     | `br-tax-calculation`、販売登録画面の会計条件          |
| `FR-03` | 現金の受領を確認し、会計確定を要求した | 販売時の単価・数量を売上記録へ残し、在庫反映結果を照合してから販売完了を返し、レシート発行を要求する。再送には元の結果を返す | 業務データ辞書、`sf-inventory`、`ifx-api-store-sales` |
| `FR-04` | 確定前に取引中止の確認を受けた         | 未確定の明細を破棄する。確定中・結果不明の取引は照合へ引き渡し、取消済みと扱わない                                           | 販売登録画面、`stsd-sales-transaction`                |

商品の販売済みへの遷移は [[specdojo:stsd-sample|商品 ステータス定義]] を参照する。販売完了の通知は釣銭・商品の手渡しとは別であり、システムは顧客受領を推測しない。

### 4.2. 例外・回復条件

| 条件                                     | 通知と保持する情報                                                         | 回復・再開条件                                                                                                           |
| ---------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 未登録商品、数量不正、在庫不足           | 対象商品と理由を通知する。拒否した変更を明細・記録・在庫に反映しない       | 商品または数量を修正し、`FR-01` で再照合する                                                                             |
| 明細なし、預かり金不足・入力不正         | 確定不可と理由を返し、有効な明細を維持する                                 | 明細追加または預かり金の補正後に `FR-02` から確認する                                                                    |
| 保存・在庫反映の失敗、応答途絶で結果不明 | 完了を通知せず、取引・停止位置・反映状況を保持する。自動で別取引を作らない | OPS が記録と在庫を照合し、確定済みなら結果を再提示、未完了なら未反映部分だけを再開する。照合まで再確定・中止を許可しない |
| 会計完了後の印刷失敗                     | 会計完了と印刷未完了を分けて通知し、販売記録と印字内容を保持する           | プリンタ回復後に同じ販売を再印刷する。売上・在庫を再更新しない                                                           |

## 5. 非機能・技術制約

| 観点               | 制約と適用範囲                                                                                   | 正本・判定方法                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 利用構成・外部依存 | 単一店舗・タブレット1台で店舗内の記録先へ接続して使う。未接続時の新規確定は保証しない            | [[specdojo:sample-authoring-standard\|共通サンプル文脈]]、`V-05` |
| 完全性             | 完了を表示した販売は記録と在庫反映を照合できる。再送でも二重売上・二重払出を起こさない           | `FR-03`、`V-04`・`V-05`                                          |
| 性能・使いやすさ   | 店番中の登録と会計確認を続けられる。応答時間の受入値は実端末の測定後に決める                     | `Q-02`、`V-08`                                                   |
| 権限・秘匿         | 販売権限のない主体は確定できない。顧客情報を必須にせず、認証情報を画面・レシート・証跡へ出さない | `opr-pos-operation`、`V-07`                                      |
| 契約・互換性       | 画面・記録先・在庫連携・印刷先の schema・版・再送契約が一致するまで統合受入を保留する            | `Q-01`。物理構造と公開契約は連携仕様・schema を正本とする        |

## 7. 検証・受入観点

データは架空の商品・取引を使い、証跡には処理前後の記録・在庫・表示を残す。

| 観点 ID | 対象要件         | 対象条件                                                                      | 観測する期待結果                                                                                              | 検証方法・証跡                     | 確認ロール   |
| ------- | ---------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ------------ |
| `V-01`  | `FR-01`・`FR-02` | 追加・数量変更・削除。数量は UIS の許容下限・上限とその外側、在庫と同数・超過 | 許容時だけ明細と金額が更新される。それ以外は理由を返し、既存明細を維持する                                    | 結合試験、入出力比較               | DEV・QE      |
| `V-02`  | `FR-02`・`FR-03` | 請求額108円の明細に、預かり金107円・108円・200円を与える                      | 107円は確定不可、108円は釣銭0円、200円は釣銭92円。完了時は売上記録と在庫反映を確認できる                      | 結合試験、金額表示・記録照合       | QE・BA       |
| `V-03`  | `FR-02`・`FR-04` | 空明細で確定、非数値の預かり金で確定、有効明細を確定前に中止                  | 前二者は理由付きで拒否、後者は明細を破棄する。いずれも売上記録・在庫払出を作らない                            | 結合試験、処理前後の記録           | QE           |
| `V-04`  | `FR-03`          | 確定成功後に同じ要求を再送し、その後商品台帳の単価を変える                    | 売上と払出は各1回分で元の結果を返す。過去の売上明細の単価は変わらない                                         | 結合試験、件数・在庫差分・明細照合 | DEV・QE      |
| `V-05`  | `FR-03`・`FR-04` | 保存前、販売記録後・在庫反映前、在庫反映後・応答前に障害を起こす              | 完了を推測せず停止位置と反映状況が残り、照合前の再確定・中止を拒否する。回復後は売上・払出が各1回分で一致する | 障害注入、保留表示・回復記録       | ARC・QE・OPS |
| `V-06`  | `FR-03`          | 会計完了後に印刷失敗し、回復後に再印刷する                                    | 印刷未完了の通知と控えが残り、再印刷しても売上件数と在庫が変わらない                                          | 外部連携試験、印刷結果・記録比較   | QE・OPS      |
| `V-07`  | 権限・秘匿       | 販売権限なしで確定要求する。顧客情報なしで現金販売する                        | 無権限の確定は拒否される。権限ありは顧客情報なしで完了し、出力に認証情報が含まれない                          | 権限試験、画面・レシート・証跡確認 | QE・OPS      |
| `V-08`  | 性能・使いやすさ | 実店舗と同じ端末で店主代表・家族利用者代表が登録・修正・会計・中止を行う      | プロジェクト概要の作業完遂・行き詰まりの基準を満たす。応答時間は `Q-02` で決めた受入値と比べる                | 利用者受入、観察・計測記録         | UX・QE・PO   |
