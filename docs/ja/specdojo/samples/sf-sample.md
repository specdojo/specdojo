# 商品販売機能 仕様

## 1. 目的と概要

- 目的: レジ端末において、顧客が購入する商品をバーコードまたは商品コードで読み取り、合計金額の計算と販売記録の確定を行う。
- 期待効果: 手計算によるミスを防ぎ、リアルタイムな在庫引き当てと売上記録を実現する。
- スコープ:
  - インスコープ: 商品の読取、小計・消費税・合計の計算、支払方法に応じた決済連携要求、販売確定処理
  - アウトオブスコープ: 在庫の物理的補充作業（`bps-inventory-replenishment` で定義）、現金の精算機への装填・回収（`opr-cash-handling` で定義）
- 主な利用者: レジ担当者、店舗スタッフ

## 2. 業務プロセス・画面との対応

- 業務プロセス（BPS）との対応:

| 業務プロセス ID        | 処理ステップ  | システム化機能の責務                                 |
| ---------------------- | ------------- | ---------------------------------------------------- |
| `bps-sales-order-flow` | S-01 商品読取 | バーコード読取結果から商品情報を取得し画面へ展開する |
| `bps-sales-order-flow` | S-02 合計計算 | 小計および消費税の計算（`br-tax-calculation` 参照）  |
| `bps-sales-order-flow` | S-03 販売確定 | 売上トランザクションの記録と在庫減算イベントの発行   |

- 画面仕様（UIS）との対応:

| 画面 ID              | 操作                  | 連携内容                         |
| -------------------- | --------------------- | -------------------------------- |
| `uis-sales-register` | バーコード入力 / 検索 | 商品情報・単価・初期数量の表示   |
| `uis-sales-register` | 販売確定ボタン押下    | 会計処理の実行とレシート発行要求 |

## 3. 入出力と前提条件

- 入力情報:

| 項目                    | 入手元            | 必須性          | 正本仕様             |
| ----------------------- | ----------------- | --------------- | -------------------- |
| 商品識別子（JANコード） | スキャナ / 手入力 | 必須            | `bdd-product-master` |
| 販売数量                | レジ担当者入力    | 任意（既定: 1） | `bdd-sales-order`    |
| 支払方法                | レジ担当者選択    | 必須            | `cdt-payment-method` |

- 出力情報:

| 成果物・記録         | 提供先           | 確定条件   | 正本仕様              |
| -------------------- | ---------------- | ---------- | --------------------- |
| 販売記録（レシート） | 顧客 / POS端末   | 会計完了時 | `bds-sales-receipt`   |
| 売上確定イベント     | 売上管理サービス | 会計完了時 | `bes-sales-completed` |

- 前提条件:
  - レジ端末が営業開始（開局）状態であること（`stsd-pos-status` 参照）。
  - 商品マスタがローカルキャッシュに同期済みであること。

## 4. 処理要件・機能振る舞い

- 処理フロー要件:
  - 商品スキャン時に即座に商品名・税込単価を表示する。
  - 値引・割引が適用可能な場合は `br-discount-calculation` に基づいて自動計算する。
  - 在庫残数が 0 以下の商品については警告メッセージを表示するが、販売自体は中断しない。
- エラー・例外処理:
  - マスタ未登録商品が読み取られた場合、警告音を鳴らし未登録警告を表示して手動入力を促す。
  - 決済連携タイムアウト時は、自動で再試行を行わず、担当者に現金決済への切替または手動再実行を確認する。

## 5. 非機能・技術制約

- 性能要件: バーコード読取から画面反映までの応答時間は 200ms 以内とする。
- 可用性・耐障害性: 外部ネットワーク切断時でもオフラインモードで販売継続可能とする（最大1,000件の一時保存）。
- セキュリティ: クレジットカード決済時のカード番号情報は本機能内部に保持しない（決済端末側で直接トークン化）。

## 7. 検証・受入観点

| 観点 ID | 対象条件           | 期待する振る舞い                                                 | 検証方法                |
| ------- | ------------------ | ---------------------------------------------------------------- | ----------------------- |
| V-01    | 登録済み商品の読取 | 正しい商品名と金額が表示され、小計が更新されること               | 単体テスト / 結合テスト |
| V-02    | 割引ルールの適用   | 対象商品の購入時に正しく割引額が減算されること                   | 結合テスト              |
| V-03    | オフライン時の販売 | ネットワーク切断状態でも販売が確定し、復旧時に自動同期されること | システム受入テスト      |
