# プロジェクト課題と解決アプローチ: 駄菓子屋きぬや 販売管理システム

本書は、[[specdojo:prj-overview-sample|プロジェクト概要]] が示す記憶とノートに頼る運用の問題を起点に、[[specdojo:prj-scope-sample|プロジェクトスコープ]] の初期対象（店頭販売・在庫・つけ管理）と [[specdojo:prj-assumptions-constraints-dependencies-sample|前提・制約・依存関係]] の成立条件（単一店舗、タブレット1台、店主代表の最終判断）を前提として、初期リリースでどの課題をどの方針で解くかを判断するための文書である。

合意対象は、優先して扱う課題（P-01〜P-03）、採用する解決アプローチ（A-01 と A-03 の併用）、先送りする課題（P-04）、次の判断に要る検討事項である。画面・データ・操作手順の詳細、特定の端末やアプリの採否は合意対象に含めない。

## 1. 課題一覧

頻度は概要の「背景」にある聞き取りの概算で、運用開始前1か月のベースライン測定で置き換える。次の表は、店頭で起きている現象ごとに、放置した場合の影響と初期リリースで扱う優先度を示す。

| 課題ID | 課題                                                                 | 影響                                                                                       | 優先度 | 備考                                       |
| ------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------ | ------------------------------------------ |
| P-01   | 店主代表が不在の日は、販売・在庫・つけの状況を同じ手順で確認できない | 家族の店番日はつけの受付と在庫の問い合わせが店主代表の戻りまで保留になる                   | High   | 概要の店舗継続の価値に直結する             |
| P-02   | つけ残高の確認に時間がかかり、ノートの残高と本人の認識が合わない     | 残高の食い違いの確認が月に数件起き、記録漏れのまま翌月へ残る                               | High   | 期待効果「つけ残高を1分以内で確認」の対象  |
| P-03   | 人気商品の在庫の減りに気づくのが遅れる                               | 来店客に聞かれて欠品に気づくことが週1回程度あり、その場の販売を逃す                        | Medium | 欠品削減の判定は運用開始後6か月            |
| P-04   | 仕入れのタイミングと数量が勘で決まり、在庫が過不足になる             | 賞味期限切れによる廃棄・値引きが月に数品目出る。判断の根拠になる販売・在庫の記録がまだない | Low    | 記録の蓄積後に扱う（スコープ外の自動提案） |

## 2. 原因（仮説でも可）

一つの課題に原因を一つだけ置かず、手順・情報・判断基準の別に分けた。次の表は、課題ごとの原因を事実と仮説に分け、事実の根拠または仮説の確認方法を示す。

| 課題ID | 原因区分 | 内容                                                                       | 根拠 / 補足                                                                                                                          |
| ------ | -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| P-01   | 事実     | 販売・在庫・つけの記録手順が口頭でだけ伝えられ、書いた手順がない           | 家族利用者代表への聞き取りで、店番日ごとに記録の書き方が異なると確認した                                                             |
| P-01   | 事実     | 在庫数とつけ残高の最新値が店主代表のノートと記憶にしかない                 | 家族の店番日に問い合わせを保留している（概要の「背景」）                                                                             |
| P-02   | 事実     | つけを顧客別ではなく日付順にノートへ書いており、残高を探して足し上げている | 月末の残高確認で、顧客ごとにページをさかのぼって合計している                                                                         |
| P-02   | 仮説     | 支払いの記入が受け取りの場で漏れ、残高が実際より多く残っている             | 確認方法: ベースライン期間に支払いを受けた日時を別紙へ控え、月末にノートの記入と照合して漏れの件数を数える                           |
| P-03   | 仮説     | 在庫確認のタイミングが決まっておらず、店番の担当ごとにばらつく             | 品切れ発生時の状況からの推測。確認方法: ベースライン期間に在庫確認の実施日時と欠品の発生日を記録し、確認の間隔と欠品の発生を照合する |
| P-03   | 仮説     | 補充を始める在庫数の目安が商品ごとに決まっていない                         | 確認方法: 欠品した商品について、欠品の前日に残っていた数と補充の判断の有無を店主代表に聞き取る                                       |
| P-04   | 事実     | 仕入れの判断に使える販売数・廃棄数の記録がない                             | 現在の記録はつけのノートだけで、販売数と廃棄数は残していない                                                                         |

## 3. 解決策候補

記録の手段は A-01 と A-02 のどちらかを選ぶ代替の関係、確認の時期と引き継ぎを扱う A-03 は記録の手段と別の原因を扱う補完の関係である。次の表は、各案の概要と効果、対応する課題を示す。

| 案ID | 案                                           | 関係 | 概要                                                                                     | 期待できる効果                                                 | 対応課題         |
| ---- | -------------------------------------------- | ---- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ---------------- |
| A-01 | タブレットで最小機能の記録を行う             | 代替 | 販売・在庫・つけを同じ手順で記録し、在庫一覧とつけ残高を顧客別に引ける最小機能を作る     | 店番が交代しても同じ記録を見られ、残高確認の足し上げがなくなる | P-01、P-02、P-04 |
| A-02 | 紙の記録様式と手順書をそろえる               | 代替 | つけを顧客別のページに分け、販売・在庫の記録欄と手順書を紙でそろえる。システム化はしない | 導入はすぐできるが、残高の合計と在庫の集計は手作業のまま残る   | P-01、P-02       |
| A-03 | 在庫確認の時期と店番交代時の引き継ぎを決める | 補完 | 開店前と閉店後に在庫低下とつけ残高を確認し、店番交代時に未処理の受付を申し送る           | 確認のばらつきと交代時の見落としを減らし、補充の判断を早める   | P-01、P-03       |

P-04 の仕入れ数量の判断は、A-01 で販売数と廃棄数の記録がたまるまで比べる案を立てず、スコープ外の「仕入れ数量の自動提案」と同じく中長期指標の判定後に扱う。

## 4. 採用アプローチと理由

採用アプローチは、記録の手段として A-01 を採用し、確認の時期と引き継ぎを A-03 で補う方針とする。A-01 は記録の手順のばらつきと最新値の所在（P-01・P-02 の事実の原因）を扱うが、いつ在庫を確かめるかという P-03 の仮説の原因は扱わない。A-03 は確認の時期をそろえるが、手作業の集計と残高の足し上げは残す。どちらか一方では P-01〜P-03 を解けないため併用し、A-03 の確認は A-01 の在庫一覧とつけ残高を見て行うので、A-01 の初期リリースと同時に始める。

判断軸は、記録が毎営業日続くこと（記録継続性）、店番の操作負担の小ささ（利用者負荷）、繁忙期前に導入できること（導入のしやすさ）の順に重視する。これは概要の「基本的な考え方」の Record First と Simple Operation の順に合わせたものである。次の表は、案ごとの判定と、どの判断軸で決めたかを示す。

| 採用対象                | 判定   | 理由                                                                                                               |
| ----------------------- | ------ | ------------------------------------------------------------------------------------------------------------------ |
| A-01 タブレット記録     | 採用   | 記録継続性: 店番が交代しても同じ記録が残り、P-04 の判断に使う販売数・廃棄数も同時にたまる                          |
| A-02 紙の様式統一       | 非採用 | 導入のしやすさでは A-01 に勝るが、利用者負荷: 残高の足し上げが残り、つけ残高を1分以内で確認する目標に届かない      |
| A-03 在庫確認・引き継ぎ | 採用   | 利用者負荷: 確認を開店前と閉店後の2回に限ることで、店番の追加操作時間（1日10分以内）に収めたまま確認をそろえられる |

## 5. トレードオフ/リスク

次の表は、採用の代償として先送りするものと、起きうるリスクおよび前提が崩れた場合の軽減策を示す。

| 区分         | 内容                                                                                    | 軽減策                                                                                       |
| ------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| トレードオフ | 初期リリースを最小機能に絞り、会計連携、仕入れ支援、分析を後回しにする                  | 要望は記録だけ残し、短期指標の判定後に記録の継続を妨げないかで採否を決める                   |
| トレードオフ | 導入が早い A-02 を採らないため、初期リリースまでの間は今のノートの運用が続く            | ベースライン測定と並行して、つけの支払いを別紙に控える運用だけを先に始める                   |
| リスク       | 店主代表がタブレット操作に慣れず、記録が止まる                                          | 操作メモを用意し、運用開始後2週間は記録の有無を日次で確認して、止まった操作を特定する        |
| リスク       | タブレットが使えない日や通信断の日に記録が抜ける（ACD-D01・ACD-A02 の前提が崩れた場合） | その日は A-02 と同じ紙の様式に控え、復旧後に入力し直す。オフライン時の記録方法は _UNDECIDED_ |

## 7. 見直しと変更管理

原因の仮説ごとに反証されたときの見直しを決め、前提とスコープの変化も契機に加えた。次の表は、本書の合意を見直す契機ごとに、確認する観点と対応方針を示す。

| 見直しの契機                                           | 確認する観点                                                           | 対応方針                                                                  |
| ------------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| P-03 の在庫確認の仮説が反証された                      | 欠品が確認の時期ではなく補充の目安数の不在から起きていないか           | A-03 の採否と確認時期を見直し、補充の目安数を決める案を補完策として加える |
| P-02 の支払い記入漏れの仮説が反証された                | 残高の食い違いが記入漏れ以外の原因（計算の誤りなど）から起きていないか | つけ残高の移行方法の照合手順を見直し、A-01 の残高確認で足りるかを確かめる |
| つけ残高の移行が完了した                               | P-02 の残高確認の課題が解消したか                                      | 解消した課題を閉じ、残る課題の優先度を見直す                              |
| 記録継続の前提（ACD-A01）が崩れた                      | 現行手順に近い操作のまま記録を続けられない場面はどこか                 | A-01 の最小機能を減らすか、A-03 の確認回数を減らして利用者負荷を下げる    |
| 店番の体制や利用者が変わった                           | P-01 の記録手順の共有への影響                                          | 引き継ぎの申し送り内容と最小機能の範囲を見直す                            |
| 短期指標を判定した、または仕入れ支援がスコープに入った | P-04 を扱う記録がたまったか                                            | P-04 の優先度を見直し、仕入れ数量の判断に使う解決策候補を立てる           |
