# コミュニケーション計画: 駄菓子屋きぬや 販売管理システム

## 1. 方針と適用範囲

[[specdojo:pm-plan-sample|管理計画]] の判断ゲートと [[specdojo:prj-stakeholder-register-sample|ステークホルダー登録簿]] のコミュニケーション要件を、営業を妨げない確認・共有へ具体化する。Issue・Pull Request・チャットの非同期の記録を基本とし、対面は試用の準備と結果の聞き取りに限る。AI Agent は記録の整理と草案を支援し、合意・承認・公開は判断しない。

## 2. コミュニケーション機会

| 対象・機会                                         | 伝える・確認する内容                      | タイミング                                                       | 手段                       | 責任  | 証跡                         |
| -------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------- | -------------------------- | ----- | ---------------------------- |
| `STH-SHOP-OWNER` への判断依頼                      | 範囲・優先機能・UI の変更、費用・時間上限 | 準備着手前、管理計画の判断ゲート「重大変更・再開」に当たる変更時 | Issue（対面の結果も転記）  | `PM`  | Issue、変更要求ログの変更 ID |
| `STH-SHOP-OWNER` への進捗共有                      | 完了、次の作業、ブロック、必要な判断      | 節目、ブロック発生時                                             | Schedule と Issue コメント | `PM`  | `kinuya-schedule`、課題ログ  |
| `STH-DEVELOPER` の実装結果の確認                   | 機能範囲、テスト完了、設計と実装結果      | イテレーション末                                                 | Pull Request、チャット     | `DEV` | Pull Request                 |
| `STH-TECH-MENTOR` との設計相談                     | データフローと画面構造案                  | 週次                                                             | チャット                   | `DEV` | Issue                        |
| `STH-FAMILY-USER` との試用準備                     | 操作方法、確認項目、困り事の伝え方        | 試用前                                                           | 簡易手順書と短時間の実演   | `BA`  | Issue                        |
| `STH-SHOP-OWNER` の受入確認                        | 受入条件、試験結果、未解決事項            | 初期リリース前                                                   | Pull Request のレビュー    | `QE`  | `kinuya-acceptance-record`   |
| `STH-SHOP-OWNER`・`STH-FAMILY-USER` の試用結果確認 | 継続可否、追加負担、改善候補              | 試用終了時                                                       | 対面の聞き取り             | `BA`  | `kinuya-trial-log`           |

## 3. エスカレーション

| 条件                                                                                                 | 一次対応                                                               | 最終判断 | 証跡         |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | -------- | ------------ |
| 利用者価値または受入条件を登録簿・成功条件から判定できない                                           | `BA` が事実と選択肢を整理する                                          | `PO`     | 課題ログ     |
| 現金支出・作業時間が管理計画 M-03・M-04 の上限を超える見込み                                         | `PM` が縮小案と中止案を整理する                                        | `PO`     | 変更要求ログ |
| 受入条件の未達、または検証できない Agent 出力                                                        | `QE` が対象版と不足証跡を整理し、`PM` が是正を Schedule に置く         | `PO`     | 受入記録     |
| 顧客情報・認証情報が公開資料・一般共有チャネル・Agent 入力に出た、または公開物に権利・内部事情の懸念 | 発見者が共有を止め、`QE` が影響範囲を確認し、`PM` が判断材料を整理する | `PO`     | 課題ログ     |
| 範囲・上限・試用日の基準を変える要求                                                                 | `PM` が影響と代替案を整理する                                          | `PO`     | 変更要求ログ |

## 4. 情報管理と公開

| 情報区分                               | 取扱い                                                                  | 記録先                                                                                                                                                  |
| -------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 判断・課題・リスク・変更               | 理由と次の行動を付ける。口頭の決定は `PM` が転記する                    | [[specdojo:pm-issue-log-sample\|課題ログ]]、[[specdojo:pm-risk-register-sample\|リスク登録簿]]、[[specdojo:pm-change-request-log-sample\|変更要求ログ]] |
| 進捗・作業結果                         | プロジェクト関係者で共有する                                            | `kinuya-schedule`、Pull Request                                                                                                                         |
| 顧客の氏名・つけ残高・連絡先、認証情報 | 公開資料・一般共有チャネル・AI Agent の入力に含めない                   | プロジェクトの記録には残さない                                                                                                                          |
| 公開する事例・画面                     | 匿名化し、店舗運営に不要な内部事情を除く。`PO` の公開判断を経て公開する | `kinuya-acceptance-record` の公開可否                                                                                                                   |

## 5. 見直し条件と未決事項

参加者、判断ゲート、公開範囲、主な連絡手段が変わった場合に本計画を見直す。

- _UNDECIDED_: 営業時間外の緊急連絡手段。決まるまで営業時間外の停止連絡の伝達先が定まらない。店頭試用の開始前に `PO` が決定する。
