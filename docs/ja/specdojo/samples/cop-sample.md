# カットオーバー計画: 切替日の取り込みと開店（駄菓子屋きぬや 販売管理システム）

## 1. 概要（cutover-day）

切替日の前日の閉店後から当日の正午の開店までに、最終棚卸・取り込み・照合・動作確認を終え、店頭タブレットでの並行記録を始める手順を定める（`cop-cutover-day`）。並行記録の運用と正本切替（`mip-index` の GO4）は対象外とし、`cop-index` から導く別の対象別計画と `otp-index` に委ねる。

_UNDECIDED_: 臨時休業の開始時刻。本書は遅くとも開店の 180 分前（T-180m）に始める前提で組んでおり、これより遅いと取り込み直しの予備枠がなくなる。店主代表が移行リハーサルの結果を見て決める。

## 2. 当日タイムライン

次の表は、前日の閉店（C）と当日の開店（T、正午）を基準にした作業の順序と、各時点の完了条件・判定点を示す。判定点の条件は「切替判定ポイント（GO/NO-GO）」の表を正とする。

| 時刻（相対）  | イベント                         | 完了条件                                                                      | 判定点 |
| ------------- | -------------------------------- | ----------------------------------------------------------------------------- | ------ |
| 前日 C+0m     | 閉店・販売ノートの締め           | 販売ノートとつけ欄の当日分に締め線を引いた                                    | -      |
| 前日 C+10m    | 最終棚卸の開始                   | 棚卸の記入表に全商品の行がそろっている                                        | -      |
| 前日 C+70m    | 最終棚卸の完了                   | 全商品の数を記入表に書き、店主代表が確認の印を押した                          | GO1    |
| 前日 C+75m    | つけ残高の上書きと読み合わせ     | 転記用の表の残高 25 件を最終行の値で上書きし、読み合わせ済みの印を付けた      | -      |
| 前日 C+100m   | 前日作業の終了                   | 転記用の表と記入表を店頭台帳保管棚の鍵付きの引き出しにしまった                | -      |
| 当日 T-180m   | 作業開始                         | 臨時休業の貼り紙が出ており、店頭タブレットの充電が 80% 以上ある               | -      |
| 当日 T-170m   | 商品台帳・現在庫の取り込み       | 取り込みログに投入件数が表示された                                            | -      |
| 当日 T-160m   | 商品台帳・現在庫の照合           | 件数と在庫数の照合表を記入した                                                | -      |
| 当日 T-120m   | 顧客台帳・つけ残高の取り込み     | 取り込みログに投入件数が表示された                                            | -      |
| 当日 T-110m   | 顧客台帳・つけ残高の照合         | 件数・サンプル・残高の照合表を記入した                                        | -      |
| 当日 T-75m    | 照合結果の判定                   | 照合表のすべての行に判定を書いた                                              | GO2    |
| 当日 T-75m 〜 | 取り込み直しの予備枠（1 回まで） | 差異を直した回の照合表が T-30m までにそろった（差異がない日は使わない）       | -      |
| 当日 T-30m    | 動作確認                         | 現金販売とつけ販売を 1 件ずつ記録し、両方を取り消せた                         | -      |
| 当日 T-10m    | 開店の判定                       | 動作確認の結果を店主代表が見て判定した                                        | GO3    |
| 当日 T-5m     | 開店準備                         | 臨時休業の貼り紙を外し、販売ノートとタブレットをレジ横に並べた                | -      |
| 当日 T+0m     | 開店・並行記録の開始             | 最初の販売をノートとシステムの両方に記録した                                  | -      |
| 当日 T+60m    | 当日作業の完了報告               | 開店後 1 時間の販売がすべて両方に記録されていることを家族利用者代表と確かめた | -      |

## 3. 作業手順チェックリスト

次の表は、タイムラインの各作業を実施者と証跡まで分けたものである。手順の番号順に行い、前の手順の証跡がそろうまで次へ進まない。

| 手順 | 作業内容                                                           | 実施者                     | 証跡                                       | 備考                                                 |
| ---- | ------------------------------------------------------------------ | -------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| 1    | 販売ノートとつけ欄の当日分に締め線を引く                           | 店主代表                   | 締め線を引いたページの写真                 | 以後の販売は受けない                                 |
| 2    | 全商品の現在庫を数え、棚卸の記入表に書く                           | 店主代表、家族利用者代表   | 記入表（店主代表の確認印つき）             | 2 人で棚ごとに分担し、数え直しは店主代表が行う       |
| 3    | 転記用の表のつけ残高を最終行の値で上書きし、読み合わせる           | 開発担当、同行レビュー担当 | 転記用の表の読み合わせ済みの印             | 手順は `dmd-credit-data` の移行手順に従う            |
| 4    | 臨時休業の貼り紙とタブレットの充電を確かめる                       | 家族利用者代表             | 移行作業の記録表の開始時刻欄               | 充電が足りなければ充電しながら作業する               |
| 5    | 商品台帳・現在庫を取り込み、件数と在庫数を照合する                 | 開発担当                   | 取り込みログ、在庫数の照合表               | `run_id` を移行作業の記録表に書く                    |
| 6    | 顧客台帳・つけ残高を取り込み、件数・サンプル・残高を照合する       | 開発担当、同行レビュー担当 | 取り込みログ、件数・サンプル・残高の照合表 | 照合表の読み合わせは同行レビュー担当が行う           |
| 7    | 差異があれば転記用の表を直し、別の `run_id` で取り込み直す         | 開発担当                   | 不合格の回と取り直した回の照合表           | 1 回まで。T-30m に間に合わなければ手順 8 へ進まない  |
| 8    | 現金販売とつけ販売を 1 件ずつ記録し、両方を取り消す                | 店主代表、家族利用者代表   | 動作確認の記録欄（取引番号と取消の結果）   | 取り消した後、つけ残高が元の値に戻ったことも確かめる |
| 9    | 貼り紙を外し、正午に開店して最初の販売をノートとシステムに記録する | 店主代表                   | 最初の販売の取引番号とノートの行           | 並行記録の運用は `otp-index` に従う                  |

## 4. 担当者/連絡系統

次の表は、当日の役割ごとの担当と連絡の手段を示す。判定結果と進捗は店頭で口頭で店主代表へ報告し、店外にいる役割へは家族の連絡用グループチャット「きぬや移行当日」で伝える。

| 役割               | 担当                 | 連絡先                           | 備考                                                                    |
| ------------------ | -------------------- | -------------------------------- | ----------------------------------------------------------------------- |
| 判断者（GO/NO-GO） | 店主代表             | 店頭（対面）                     | 延期とロールバックも決める                                              |
| 作業の進行と記録   | 開発担当             | 店頭（対面）、グループチャット   | 各作業の開始・完了時刻を移行作業の記録表に書き、課題を issue 個票に起票 |
| 照合の確認         | 同行レビュー担当     | 店頭（対面）                     | 照合表の読み合わせ結果を開発担当へ渡す                                  |
| 店頭の準備と店番   | 家族利用者代表       | 店頭（対面）、グループチャット   | 開店後は並行記録の店番に入る                                            |
| エスカレーション先 | 技術メンター         | CoderDojo のメンター連絡チャネル | 取り込みの失敗や端末の不具合を開発担当が 15 分で切り分けられないとき    |
| 運用の相談先       | 店舗運営アドバイザー | グループチャット                 | 開店後の店番の引継ぎで困った点を受ける                                  |

- 判定結果は、判断者 `PO` として decision 個票に、課題と未決事項は対応者の Role code（`DEV`・`QE` など）を付けて issue 個票に記録する。
- 連絡先に個人の電話番号やメールアドレスは書かない。グループチャットの参加者は店主代表が前日までに決める。

## 5. 実施条件（事前完了条件）

次の表は、前日の閉店までにそろっていなければならない条件と、そろわないときの扱いを示す。1 つでも未達なら、店主代表が前日の閉店時に延期か代替手順かを決める。

| 事前完了条件                                                         | 確認方法                                 | 未達時の扱い                                       | 判断者   |
| -------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------- | -------- |
| 移行リハーサルで、取り込みと照合が T-30m までに終わることを確かめた  | `mtp-index` のリハーサル結果の合否       | 延期。リハーサルをやり直してから切替日を決め直す   | 店主代表 |
| 転記用の表（商品・顧客）と元ノートの全件の読み合わせが済んでいる     | 転記用の表の読み合わせ済みの印           | 延期。残りを読み合わせてから切替日を決め直す       | 店主代表 |
| 臨時休業の貼り紙を切替日の 1 週間前から店頭に出している              | 貼り紙の写真と掲示日（移行作業の記録表） | 延期。告知期間が 1 週間に満たない切替日は使わない  | 店主代表 |
| 仕入先の配送が切替日の午前に入らない                                 | 仕入先の注文窓口へ配送日時を確かめた記録 | 代替手順。配送分は開店後に数え、在庫を手入力で足す | 店主代表 |
| 店頭タブレットの画面ロックと、取り込み画面の操作を開発担当が確かめた | 移行作業の記録表の前日確認欄             | 延期。端末の不具合を技術メンターと切り分ける       | 店主代表 |

## 6. 切替判定ポイント（GO/NO-GO）

次の表は、各判定点で照合する対象・閾値・証跡と、満たさないときの扱いを示す。条件を 1 つでも満たさなければ NO-GO とし、表の失敗時の扱いに進む。

| 判定点 | 条件                                                                                                                        | 判断者   | 失敗時の扱い                                                                       |
| ------ | --------------------------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------- |
| GO1    | 前日 C+70m までに、棚卸の記入表で全商品の数が埋まり、空欄が 0 件である                                                      | 店主代表 | 延期。切替日を延ばし、ノートで営業を続ける                                         |
| GO2    | 照合表で、商品・顧客の件数差異が 0 件、全商品の在庫数が記入表と一致、顧客ごとと合計のつけ残高の差異が 0 円である            | 店主代表 | 代替手順。差異を直して取り込み直す（1 回まで）。T-30m までに一致しなければ延期する |
| GO3    | 動作確認の記録欄で、現金販売とつけ販売が 1 件ずつ取引番号つきで記録され、取り消した後のつけ残高が取り消す前の値と同じである | 店主代表 | ロールバック。取り込んだデータを使わず、正午にノートだけで開店する                 |

## 7. ロールバック手順

GO3 で NO-GO となった場合と、開店後に販売の記録が 10 分以上できない場合に発動する。並行記録の期間はノートが正本のため、復旧方針は「システムの利用をやめ、ノートだけで営業を続ける」とし、取り込んだデータは消さずに次の切替日の取り込みで洗い替える。

次の表は、ロールバックの手順と、それぞれを終えたと判断できる条件を示す。

| 手順 | 内容                                                                    | 実施者         | 証跡                                         | 完了条件                                             |
| ---- | ----------------------------------------------------------------------- | -------------- | -------------------------------------------- | ---------------------------------------------------- |
| 1    | 店主代表がロールバックを決め、グループチャットで全員に伝える            | 店主代表       | decision 個票（判定点と事象）                | 全員が受け取ったと返信した                           |
| 2    | 販売画面を閉じ、タブレットをレジ横から下げる                            | 家族利用者代表 | 移行作業の記録表のロールバック欄             | 店番がタブレットに記録しない状態になった             |
| 3    | 開店後にシステムだけに記録した販売があれば、販売ノートへ書き写す        | 開発担当       | 書き写した販売の取引番号とノートの行の対応表 | システムにあってノートにない販売が 0 件になった      |
| 4    | 取り込み用ファイルとログを `migration/<run_id>/` に残したことを確かめる | 開発担当       | フォルダの一覧の写真                         | 次の切替日に同じ不具合を調べられる記録がそろっている |
| 5    | 発生した事象と原因の見込みを issue 個票に起票する                       | 開発担当       | issue 個票                                   | 次の切替日を決めるための論点が個票にそろっている     |

## 8. 障害時判断・エスカレーション

次の表は、当日に起きた事象の重大度と、判断の基準・連絡の経路を示す。復旧の見込みは開発担当が 15 分で切り分けた結果で判断し、見込みが立たなければ 1 段上の重大度として扱う。

| 重大度 | 判断基準                                                                     | 復旧見込みの判断                             | 連絡経路                                              |
| ------ | ---------------------------------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------- |
| 高     | 開店後に販売の記録が 10 分以上できない、またはつけ残高が取り込み後に変わった | 見込みにかかわらずロールバックする           | 開発担当 → 店主代表（対面）→ 技術メンター（チャネル） |
| 中     | 開店前の作業が予定より 15 分以上遅れ、T-30m に動作確認を始められない見込み   | T-30m までに追いつく見込みがなければ延期する | 開発担当 → 店主代表（対面）                           |
| 低     | 操作の分からない点、印字の不具合など、ノートへの記録で販売を続けられる事象   | 閉店後の日次締めまでに直す                   | 店番 → 開発担当（グループチャット）                   |

## 9. 周知（ユーザ通知/停止告知）

次の表は、来店客と関係先への周知の内容と時期を示す。周知には利用者が来店の判断に要る情報だけを書き、作業の手順は書かない。

| 通知対象         | 手段                     | 時期                          | 内容                                                                           | 証跡                             |
| ---------------- | ------------------------ | ----------------------------- | ------------------------------------------------------------------------------ | -------------------------------- |
| 来店客           | 店頭の貼り紙             | 切替日の 1 週間前から当日正午 | 「〇日（切替日）は午前休業、正午から営業します。お問い合わせは店頭まで」       | 貼り紙の写真（移行作業の記録表） |
| つけのある常連客 | 来店時に口頭で伝える     | 切替日の前の週の来店時        | 午前休業と、つけ残高は切替の前後で変わらないこと。問い合わせは店頭で受けること | 常連客ノートの伝達済みの印       |
| 仕入先           | 注文窓口へ配送日時を連絡 | 切替日の 1 週間前             | 切替日の午前は受け取れないため、配送を午後にすること                           | 仕入先への連絡記録               |

- ロールバックした場合も来店客への周知は変えない。正午に開店し、ノートで販売する。

## 10. 関連ドキュメント

- `cop-index`: カットオーバー計画の入口（共通の判断体系と、本書を含む対象別計画への導線）
- `mip-index`: 移行計画（成功条件、GO/NO-GO の最低条件、臨時休業の前提）
- `mtp-index`: 移行リハーサル計画（作業時間の測定と照合の合否）
- `dmd-index`、`dmd-credit-data`: データ移行設計（取り込みの手順、`run_id`、照合の方法と所要時間）
- `otp-index`: 運用切替計画（開店後の並行記録の運用と問い合わせ窓口）
