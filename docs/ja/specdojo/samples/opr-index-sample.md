# 駄菓子屋きぬや 販売管理システム 運用手順（全体構成）

## 1. 概要（index）

駄菓子屋きぬや 販売管理システムの恒常運用で、店番担当・`OPS`・`DEV` が行う作業の手順と、作業ごとに残す証跡の正本である。目的は、店主代表が不在の日も店番担当が同じ手順で販売・在庫・つけを記録し、異常時に同じ判断で連絡・切替できるようにすることとする。判断基準と目標値は [[specdojo:opd-index-sample|運用方針・設計（全体構成）]] に従い、本書は手順だけを書く。

本書を使う場面は次のとおりとする。

- 開店前・閉店後の点検と、月次点検を行うとき。
- 店頭で記録できない、夜間バックアップがないなどの異常に気付いたとき。
- 版の更新・価格の一括変更・アカウントの付与と剥奪を行うとき。
- 店番担当から操作の質問や記録の訂正の依頼を受けたとき。

次の表は、運用方針で未決の値が本書のどの手順に影響し、決まるまでどう扱うかを示す。値が決まった時点で該当する章の手順と判定を差し替える。

| 未決事項                                      | 決まるまでの手順上の扱い                                 | 影響する章                           |
| --------------------------------------------- | -------------------------------------------------------- | ------------------------------------ |
| _UNDECIDED_: オフライン時の記録方法           | 紙の販売控えに書き、復旧後に転記する                     | 障害対応手順                         |
| _UNDECIDED_: RTO/RPO とバックアップの保管期間 | 翌営業日の開店までに前日閉店時点へ復元できれば合格とする | バックアップ確認・リストア手順、証跡 |
| _UNDECIDED_: 営業時間外の緊急連絡手段         | 営業時間外に気付いた異常は翌朝の開店前に連絡する         | 障害対応手順、アラート対応手順       |
| _UNDECIDED_: 証跡の保管期間（監査ログ以外）   | 消さずに残し、保管期間が決まった時点で古いものを整理する | 証跡                                 |

## 2. 手順適用範囲・前提

次の表は、本書の手順が対象とする範囲と、手順を行う前提を示す。

| 項目     | 内容                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 対象内   | 店頭のタブレット 1 台での販売・在庫・つけの記録、閉店後の日次締め、ホスティング環境の夜間バックアップ    |
| 対象外   | 複数店舗、EC、本格会計、仕入れ先連携、キャッシュレス決済。仕入れの発注作業は現行の紙の手順のまま行う     |
| 時間帯   | 営業時間 10:00〜18:00。点検は開店前（9:45 から）と閉店後（18:00 から）、月次点検は毎月の最初の休業日     |
| 権限     | 店番担当は記録の権限、`DEV` は管理者権限、`OPS` は点検に使う閲覧の権限を持つ。共有のアカウントは使わない |
| 環境     | 本番のホスティング環境と、復元の確認・手順の模擬に使う検証用の環境                                       |
| 連絡手段 | 営業時間中は店内の電話、営業時間外は店内の連絡帳。_UNDECIDED_: 営業時間外の緊急連絡手段                  |

手順を新しく書いたときや改訂したときは、検証用の環境で手順を実行または模擬し、完了条件と証跡が表のとおりに得られることを確かめる。異常時の分岐（P1 の切替、再実行の上限到達など）も 1 回ずつ模擬する。

## 3. 日次/週次/月次点検手順

次の表は、頻度ごとの点検の手順と、点検を終えたと判定する条件を示す。週次の点検は置かず、週単位で見る項目は月次点検で扱う。

| 頻度 | 実施者   | 入力条件                           | 操作                                                                     | 完了条件                                                     | 証跡           |
| ---- | -------- | ---------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------ | -------------- |
| 日次 | 店番担当 | 開店前（所要 5 分）                | タブレットでログインし、前日の日次締めと夜間バックアップの成功表示を見る | 両方の成功表示がある。ない場合はアラート対応手順へ進んだ     | 日次点検の記録 |
| 日次 | 店番担当 | 閉店後、現金を数え終えた           | 日次締めを実行し、販売記録の合計と現金の合計を比べる                     | 差が 0 円。差がある場合は原因と金額を日次締め記録に書いた    | 日次締め記録   |
| 日次 | 店番担当 | 閉店後、日次締めを終えた           | 人気商品の在庫数を棚と照らし、欠品した商品を記録する                     | 対象商品すべてで在庫数が一致するか、差を調整して記録した     | 欠品記録       |
| 月次 | `OPS`    | 毎月の最初の休業日（所要 1 時間）  | 日次締め記録・欠品記録・障害記録から KPI と SLO を集計する               | 運用方針の KPI と SLO の全行に当月の値がある                 | 月次点検の記録 |
| 月次 | `OPS`    | KPI と SLO を集計した              | 顧客の検索から残高の表示までを 3 回計る                                  | 3 回の値を記録した。1 分を超えた回があれば課題として登録した | 月次点検の記録 |
| 月次 | `OPS`    | 前日の閉店時点のバックアップがある | バックアップ確認・リストア手順の復元演習を行う                           | 同章の完了条件を満たした                                     | 復元演習の記録 |
| 月次 | `OPS`    | 店番担当の一覧が最新               | アカウント付与/剥奪手順の棚卸しを行う                                    | 同章の完了条件を満たした                                     | 棚卸しの記録   |

月次点検のどれかを当日中に終えられない場合は翌週の休業日に行い、遅れた項目と理由を月次点検の記録に残す。月次点検で目標を下回った指標は、`OPS` が `PO` へ報告し、課題としてプロジェクトの課題管理へ登録する。

## 4. 障害対応手順（P1/P2…、切り分け、一次対応、復旧）

次の表は、優先度ごとの連絡の期限と、切り分けから復旧までの操作を示す。優先度の条件は運用方針の体制・責任分界の表に従う。紙の販売控えへの切替と転記の詳しい手順は `opr-incident` に分冊する。

| 優先度 | 条件                                           | 連絡先と期限                               | 切り分け（`DEV`）                                          | 一次対応（店番担当）                                                                    | 復旧の完了条件                                              |
| ------ | ---------------------------------------------- | ------------------------------------------ | ---------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| P1     | 販売・つけのどちらかを記録できない             | `OPS` へ 15 分以内。応答がなければ `PO` へ | 店舗の通信回線、ホスティング環境、直近の変更の順に確かめる | 30 分で再開できなければ `PO` の判断で紙の販売控えへ切り替える。つけの新規記録は受けない | 販売・在庫・つけを各 1 件記録でき、紙の控えの転記を照合した |
| P2     | 記録はできるが、在庫の確認や日次締めができない | `OPS` へ当日の閉店まで                     | 該当機能の画面とデータの件数を確かめる                     | 記録を続け、できなかった確認を日次締め記録に書く                                        | 該当機能が使え、当日分の確認をやり直した                    |
| P3     | 表示の崩れなど、回避して記録を続けられる       | `OPS` へ次の月次点検で                     | 次の月次点検で再現の条件を確かめる                         | 回避の操作を店内の連絡帳に書き、記録を続ける                                            | 修正を運用変更作業の手順で適用した                          |

店番担当は気付いた時刻・画面の状態・優先度を障害記録に書いてから連絡する。復旧後、`OPS` は原因・影響・再発防止を障害記録に追記し、月次点検で `PO` へ報告する。

## 5. アラート対応手順（確認→暫定対応→恒久対応）

自動の通知はホスティング環境の死活と夜間バックアップの 2 つで、閾値と通知先は運用方針の監視・アラート方針に従う。次の表は、通知を受けてからの段階ごとの操作を示す。

| アラート               | 確認（`OPS`）                                | 暫定対応                                      | 恒久対応（`DEV`）                                  | 誤検知としての終了条件                                   |
| ---------------------- | -------------------------------------------- | --------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------- |
| ホスティング環境の死活 | 店番担当に電話し、記録できているかを確かめる | 記録できなければ P1 として障害対応手順へ進む  | 停止の原因を直し、運用変更作業の手順で適用する     | 店番担当が 1 件記録でき、5 分後の再確認でも応答がある    |
| 夜間バックアップ       | 開店時に当日分の成功記録がないことを確かめる | P2 としてバッチ再実行・失敗時対応の手順へ進む | 失敗の原因を直し、翌日の夜間バックアップで確かめる | 成功記録が遅れて表示され、記録の日時が当日の閉店後である |

誤検知で終えた通知は、障害記録に「誤検知」と原因を書く。同じ誤検知が月 3 回を超えたら、閾値の見直しを課題として登録する。

## 6. バックアップ確認・リストア手順（演習含む）

次の表は、バックアップの確認・復元・演習の手順を示す。取得は夜間バックアップが自動で行う。

| 作業     | 実施者   | 入力条件                                   | 操作                                                                               | 完了条件                                             | 証跡           |
| -------- | -------- | ------------------------------------------ | ---------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------- |
| 確認     | 店番担当 | 開店前                                     | 日次点検で成功表示を見る                                                           | 前日の閉店後の日時で成功表示がある                   | 日次点検の記録 |
| 復元     | `DEV`    | P1 でデータが失われた、`PO` が復元を決めた | 最新の成功したバックアップを本番へ戻し、紙の控えと日次締め記録から当日分を転記する | 前日の販売件数と転記した件数・金額が一致する         | 障害記録       |
| 復元演習 | `OPS`    | 月次点検、検証用の環境が使える             | 前日のバックアップを検証用の環境へ戻し、販売件数を本番と比べる                     | 件数が一致し、作業の開始から終了までの時間を記録した | 復元演習の記録 |

復旧目標の達成は、_UNDECIDED_: RTO/RPO が決まるまで、翌営業日の開店までに前日の閉店時点へ戻せたかで判定する。演習で件数が一致しない場合は P2 として扱う。

## 7. バッチ再実行・失敗時対応

定期のバッチは夜間バックアップだけとする。日次締めは店番担当の操作で、失敗時は日次締めをやり直す。

| 項目         | 手順                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| 再実行の条件 | 開店時に当日分の成功記録がない、または実行ログが失敗で終わっている                      |
| 再実行の操作 | `DEV` が手動で取得を 1 回実行し、実行ログの `run_id` と結果を障害記録に書く             |
| 上限回数     | 1 日あたり 2 回                                                                         |
| 冪等性       | 同じ日付の取得は同じ世代を上書きするため、再実行しても世代は増えない                    |
| 上限到達時   | P2 のまま記録を続け、閉店後の日次締めの後にもう一度取得する。翌朝も失敗なら P1 へ上げる |

## 8. 運用変更作業（設定変更・デプロイ・ロールバック）

変更の承認者・時間帯・戻す条件は運用方針の変更管理に従う。次の表は、変更を適用して戻すまでの手順を示す。

| 段階         | 実施者   | 入力条件                                     | 操作                                                         | 完了条件                                       | 証跡     |
| ------------ | -------- | -------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------- | -------- |
| 事前確認     | `DEV`    | 変更の内容が変更記録にある                   | 検証用の環境で適用し、販売・在庫・つけを各 1 件記録する      | 3 件とも記録でき、変更記録に結果を書いた       | 変更記録 |
| 承認         | `PO`     | 事前確認を終えた                             | 変更記録の内容と事前確認の結果を見て、適用してよいかを決める | 変更記録に承認の日付がある                     | 変更記録 |
| 適用         | `DEV`    | 承認があり、閉店後である                     | 本番へ適用し、事前確認と同じ 3 件の記録を行う                | 3 件とも記録できた                             | 変更記録 |
| 開店前の確認 | 店番担当 | 翌朝の開店前                                 | 変更した画面や価格を 3 商品分見る                            | 変更前と違う点が変更記録のとおりである         | 変更記録 |
| ロールバック | `DEV`    | 適用後または開店前の確認で戻す条件に当たった | 直前の版や変更前の価格へ戻し、同じ 3 件の記録を行う          | 3 件とも記録でき、戻した理由を変更記録に書いた | 変更記録 |

営業時間中の変更は、P1 の復旧に必要な場合だけ `PO` の承認で行い、適用と確認の手順は同じとする。

## 9. アカウント付与/剥奪手順

次の表は、アカウントの申請から記録までの手順を示す。アカウントは店番担当と `DEV` に限る。

| 段階     | 実施者 | 入力条件                               | 操作                                                           | 完了条件                               | 証跡         |
| -------- | ------ | -------------------------------------- | -------------------------------------------------------------- | -------------------------------------- | ------------ |
| 申請     | `OPS`  | 店番を始める、または店番をやめる       | 対象の役割と権限の種類（記録・閲覧・管理者）を権限の記録に書く | 権限の記録に申請の日付がある           | 権限の記録   |
| 承認     | `PO`   | 申請がある                             | 申請の内容を見て付与・剥奪してよいかを決める                   | 権限の記録に承認の日付がある           | 権限の記録   |
| 実施     | `DEV`  | 承認がある。剥奪は店番をやめた日のうち | 記録の権限を付与する、またはアカウントを無効にする             | 付与・剥奪した日時を権限の記録に書いた | 権限の記録   |
| 権限検証 | `OPS`  | 実施を終えた                           | 付与は記録の画面に入れること、剥奪は入れないことを確かめる     | 結果を権限の記録に書いた               | 権限の記録   |
| 棚卸し   | `OPS`  | 月次点検                               | 有効なアカウントの一覧と店番担当の一覧を比べる                 | 差がない。差があれば剥奪の申請を出した | 棚卸しの記録 |

## 10. 問い合わせ一次対応手順（テンプレ・ナレッジ）

窓口は `OPS` の 1 つで、店番担当は口頭または店内の連絡帳で問い合わせる。次の表は、分類ごとの回答例と、`OPS` で終えられない場合の引継ぎ先を示す。

| 分類             | 回答例                                                       | 参照する知識         | 応答の目標         | 引継ぎ条件と引継ぎ先                 |
| ---------------- | ------------------------------------------------------------ | -------------------- | ------------------ | ------------------------------------ |
| 操作の質問       | 「つけの記録は、顧客の画面の取り消しから当日分だけ消せます」 | 店内の操作メモ       | 当日の閉店まで     | 操作メモにない操作は `DEV` へ        |
| 記録の訂正の依頼 | 「前日の数量は訂正の画面で直し、理由を残します」             | 日次締め記録         | 翌営業日の開店まで | 締め済みの金額が変わる訂正は `PO` へ |
| 機能の要望       | 「次の月次点検で採否を決め、結果を連絡帳でお知らせします」   | 課題管理の要望の一覧 | 次の月次点検       | 月次点検で `PO` へ                   |
| 障害にあたるもの | 「障害として記録し、障害対応手順で対応します」               | 障害対応手順         | 優先度の期限に従う | 障害対応手順の連絡先へ               |

回答した問い合わせは、分類・回答・引継ぎの有無を問い合わせ記録に書く。同じ操作の質問が月 2 回を超えたら、店内の操作メモに追記する。

## 11. 証跡（ログ、チケット、チェックリスト、実施記録）

次の表は、各手順の証跡をどこに残し、どの識別子で照合するかを示す。

| 証跡           | 保存先                               | 保管期間                                  | 参照権限              | 最低限残す識別子                 |
| -------------- | ------------------------------------ | ----------------------------------------- | --------------------- | -------------------------------- |
| 日次点検の記録 | 店内の点検ノート（紙）               | _UNDECIDED_                               | 店番担当、`OPS`       | 点検日、点検した役割             |
| 日次締め記録   | 販売管理システムの日次締めの画面     | _UNDECIDED_                               | 店番担当、`OPS`、`PO` | `closing_date`                   |
| 欠品記録       | 販売管理システムの在庫の画面         | _UNDECIDED_                               | 店番担当、`OPS`       | `closing_date`、商品コード       |
| 障害記録       | プロジェクトの課題管理               | _UNDECIDED_                               | `OPS`、`DEV`、`PO`    | `ticket_id`、優先度、発生時刻    |
| 実行ログ       | ホスティング環境のバックアップの記録 | _UNDECIDED_: バックアップの保管期間と同じ | `OPS`、`DEV`          | `run_id`、実行日時               |
| 変更記録       | プロジェクトの課題管理               | _UNDECIDED_                               | `OPS`、`DEV`、`PO`    | `ticket_id`、適用する版          |
| 権限の記録     | プロジェクトの課題管理               | _UNDECIDED_                               | `OPS`、`PO`           | `ticket_id`、権限の種類          |
| 監査ログ       | 販売管理システムの監査ログ           | 1 年                                      | `OPS`、`PO`           | 操作日時、アカウント、操作の種類 |
| 月次点検の記録 | プロジェクトの課題管理               | _UNDECIDED_                               | `OPS`、`PO`           | `ticket_id`、対象月              |
| 問い合わせ記録 | 店内の連絡帳                         | _UNDECIDED_                               | 店番担当、`OPS`       | 受付日、分類                     |

復元演習の記録と棚卸しの記録は、月次点検の記録の同じ `ticket_id` に含める。

## 12. 関連ドキュメント導線（`opd-index` 参照）

次の表は、本書の手順の判断基準と、本書から切り出した分冊の対応を示す。分冊は障害対応だけとし、ほかの作業領域は本書で完結する。

| 種別 | ドキュメントID                                            | 読む場面                                          | 状態   |
