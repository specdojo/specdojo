# 駄菓子屋きぬや 販売管理システム 非機能要件 / 完全性

## 1. 概要（対象・目的）

駄菓子屋きぬや 販売管理システムが扱う業務データのうち、販売記録・在庫数・つけ残高を重要記録とし、その正確性・整合性・改ざんの検知・変更履歴の追跡性を定める。

重要記録を選んだ基準は、欠落や不整合が店主代表の業務判断を直接誤らせるかどうかである。次の表は、重要記録ごとに完全性が損なわれたときの業務影響と、その影響から導いた要件を示す。

| 重要記録   | 完全性が損なわれたときの業務影響                                                       | 対応する要件                 |
| ---------- | -------------------------------------------------------------------------------------- | ---------------------------- |
| 販売記録   | 売上の欠落・重複で日次の売上集計を誤り、人気商品の欠品削減の効果を測れない             | `nfr-int-001`・`nfr-int-003` |
| 在庫数     | 販売と在庫が食い違い、仕入れのタイミングと数量を誤る（在庫の過不足が再発する）         | `nfr-int-002`                |
| つけ残高   | 残高が実際の未払額と一致せず、常連客への請求漏れや過大請求が起きる                     | `nfr-int-004`                |
| 変更の履歴 | 店主以外の店番が訂正した記録を後から確かめられず、誤りと意図的な書き換えを区別できない | `nfr-int-005`・`nfr-int-006` |

販売記録と在庫数の誤りは毎営業日の判断に影響するため、つけ残高の誤りは顧客との信頼関係に影響するため、いずれも違反を 0 件とする基準にする。

## 2. 適用範囲・前提条件

対象は店頭販売・在庫・つけ管理の初期リリースが扱う次のデータとする。

- 販売記録: 会計確定した取引の取引番号・明細・請求額・支払区分（現金またはつけ）。
- 在庫数: 商品ごとの帳簿上の在庫数と、販売・入荷・在庫調整による増減の記録。
- つけ残高: 常連客ごとのつけ販売額と入金額、およびその差である残高。

整合性境界（一致を保つデータの組）は次のとおりとする。

| 整合性境界          | 一致させる内容                                                                 |
| ------------------- | ------------------------------------------------------------------------------ |
| 販売記録 ↔ 在庫数   | 会計確定した明細の数量合計と、同じ取引による在庫の減算数量が商品ごとに一致する |
| 販売記録 ↔ つけ残高 | 支払区分がつけの取引の請求額合計と、つけ販売額の合計が顧客ごとに一致する       |
| つけ残高 ↔ 入金記録 | 残高が「つけ販売額の累計 − 入金額の累計」と顧客ごとに一致する                  |

除外条件は次のとおりとする。

- 実在庫と帳簿在庫の差（破損・紛失・数え間違い）は完全性の違反に含めない。差は在庫調整として記録し、その記録自体は `nfr-int-005` の監査証跡の対象とする。
- 会計確定前に取り消した取引は販売記録に含めない。
- 仕入れ先とのシステム連携・会計ソフトへの転記は初期リリースの対象外のため、本書の整合性境界に含めない。
- 誰が記録を参照・操作できるか、操作者の認証とアクセスの監査は `nfr-security-safety` に定める。本書は記録の変更が漏れなく履歴に残り、履歴を経ない変更を検知できることだけを定める。

監査証跡は、販売記録・在庫調整・つけの入金と訂正のすべての変更について、操作者の nickname・操作日時・対象記録・変更前の値・変更後の値・変更理由を残す。保持期間は記録の発生日から 7 年とする。

_ASSUMPTION_: 保持期間の根拠は、個人事業の帳簿書類の保存期間（青色申告で 7 年）とする。根拠とする規程文書は未作成のため、`based_on` は空にしている。

_UNDECIDED_: 通信や端末の障害で店頭のタブレットが使えない間に紙へ記録した販売を、復旧後にどう入力し、どの時点から整合性境界の対象とするかは未決定である。オフライン時の運用方針と合わせて決める。

## 3. 完全性要件一覧

次の表は、各要件の指標と、pass/fail を判定する基準を示す。割合の指標は分子と分母を備考に定義する。

| id          | 内容                                                         | 指標               | 基準                   | 備考                                                                                             |
| ----------- | ------------------------------------------------------------ | ------------------ | ---------------------- | ------------------------------------------------------------------------------------------------ |
| nfr-int-001 | 会計確定を通知した取引は、必ず販売記録として残る             | 販売記録欠落件数   | 0 件（営業日ごと）     | 会計確定を通知した取引番号のうち、販売記録が存在しない件数                                       |
| nfr-int-002 | 販売記録と在庫数が商品ごとに一致する                         | 整合性違反件数     | 0 件（営業日ごと）     | 「販売記録 ↔ 在庫数」の境界で数量が一致しない商品の件数                                          |
| nfr-int-003 | 同じ取引が二重に販売記録へ残らない                           | 重複記録件数       | 0 件（月次）           | 同一取引番号の販売記録が 2 件以上ある取引の件数                                                  |
| nfr-int-004 | つけ残高が販売記録と入金記録から計算した値と一致する         | 整合性違反件数     | 0 件（営業日ごと）     | 「販売記録 ↔ つけ残高」「つけ残高 ↔ 入金記録」の境界で一致しない顧客の件数                       |
| nfr-int-005 | 重要記録のすべての変更に監査証跡が残る                       | 監査証跡欠落率     | 0%（月次）             | 分子は監査証跡の必須項目が欠けた変更件数、分母は販売記録・在庫調整・つけの入金と訂正の全変更件数 |
| nfr-int-006 | 監査証跡を経ずに書き換えた重要記録を整合性チェックで検知する | 改ざん検知漏れ件数 | 0 件（試験ケースごと） | 試験で監査証跡を経ずに書き換えた記録のうち、整合性チェックが検知しなかった件数                   |

## 4. 測定・検証方法

整合性チェックは、閉店後に当日分の整合性境界と監査証跡を照合し、違反の件数と対象の記録を一覧にする確認とする。次の表は、要件ごとの測定手段・判定のタイミング・合否条件・判定する Role code を示す。

| id          | 測定手段                                                                                    | 判定のタイミング                                     | 合否条件                                           | 判定する Role code |
| ----------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------- | ------------------ |
| nfr-int-001 | 整合性チェック（会計確定の通知記録と販売記録の取引番号を突き合わせる）                      | 営業日の閉店後                                       | 欠落件数が 0 件                                    | OPS                |
| nfr-int-002 | 整合性チェック、受入試験 `sac-integrity`                                                    | 営業日の閉店後、初期リリースの受入試験               | 違反件数が 0 件                                    | OPS・QE            |
| nfr-int-003 | 整合性チェック、試験 `stc-integrity`（会計確定の二重送信を再現する）                        | 月末、初期リリースの受入試験                         | 重複件数が 0 件                                    | OPS・QE            |
| nfr-int-004 | 整合性チェック、受入試験 `sac-integrity`                                                    | 営業日の閉店後、初期リリースの受入試験               | 違反件数が 0 件                                    | OPS・QE            |
| nfr-int-005 | 監査レビュー（月次で変更件数と監査証跡の件数・必須項目を照合する）                          | 月末                                                 | 欠落率が 0%                                        | QE                 |
| nfr-int-006 | 試験 `stc-integrity`（販売記録・在庫数・つけ残高を各 1 件以上、監査証跡を経ずに書き換える） | 初期リリースの受入試験、データ保存の方式を変えたとき | 投入したすべての書き換えを整合性チェックが検知する | QE                 |

基準未達や改ざんの疑いを検知したときは、次のとおり扱う。

- 整合性チェックが違反を検出したら、対象の取引番号・商品・顧客と違反の内容を課題として記録し、翌営業日の開店前に店主代表が現物・ノート・入金の控えと照合して訂正する。訂正も監査証跡に残す。
- 監査証跡を経ない書き換えを検知したら、通常の課題ではなく登録簿の個票に記録し、`nfr-security-safety` のアクセス監査と合わせて原因を調べる。
- 同じ境界の違反が 1 か月に 2 回以上起きたとき、重要記録や整合性境界を追加・変更するとき（例: 仕入れ記録を初期リリース後に扱うとき）は、要件と基準を見直す。

_UNDECIDED_: 整合性チェックを閉店後に自動で実行するか、店番が操作して実行するかは未決定である。店番の操作負担と閉店時刻のばらつきを踏まえて運用方針 `opd-integrity-check` で決める。
