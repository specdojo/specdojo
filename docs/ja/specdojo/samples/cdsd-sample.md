# 概念データストア定義（駄菓子屋きぬやの販売と締め）

## 1. 概要

店主代表と家族の店番担当が、販売の記録漏れと締めの差異を同じ根拠で確認できるよう、販売から日次・月次の確認に使う情報の管理境界を定める。販売明細と締めの判断を同じ欄で上書きすると、差異の発生元と誰が確認したかを追えなくなるため、取引の正本、再生成する集計、人が確定する記録を分ける。

範囲は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）]] の販売・締め領域の5単位とする。顧客台帳・つけ台帳・仕入記録・在庫記録は購入者・未収金・差異確認のために参照だけし、更新責務は各領域へ委ねる。売場棚の現物管理、EC、複数店舗、本格会計、仕入先との通信は対象外とする。

## 2. 概念データストア一覧

| データストア名 | 対応プロセス                   | 主な内容                                                             | 更新タイミング                                     | 粒度                                 | 主な用途                                                           |
| -------------- | ------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------ |
| 商品台帳       | 店頭販売、つけ販売、月次見直し | 商品の識別、表示名、標準販売価格、補充基準                           | 随時（商品登録・承認済みの売価や補充基準の変更時） | 商品種類毎。現物一個毎ではない       | 店番担当が販売対象と現在価格を確認し、店主代表が売価を見直す       |
| 販売記録       | 店頭販売、つけ販売、日次締め   | 確定した売上記録と売上明細、支払方法、購入者の参照                   | イベント（会計確定時・承認済み訂正時）             | 売上ID毎。明細は売上IDと明細番号の組 | 店番担当が記録漏れを確認し、店主代表が現金販売とつけ販売を区別する |
| 日次販売集計   | 日次締め                       | 対象日の販売件数、請求金額合計、支払方法別内訳、集計の基準時点       | 日次（閉店後）、イベント（対象日の販売訂正後）     | 店舗・対象日・基準時点毎             | 店主代表が締めの販売額を確認し、店番担当が集計漏れ・重複を調べる   |
| 日次締め記録   | 日次締め、月次見直し           | 日次販売集計の参照、仕入・在庫・つけ残高の確認結果、判断理由、確認者 | 日次（閉店時の照合後）、イベント（締めの再確認時） | 店舗・対象日・確認版毎               | 店主代表がその日の締めを確定できるか判断する                       |
| 月次報告       | 月次見直し                     | 対象月の売上・欠品・つけ残高の根拠、比較結果、見直しの判断           | 月次（月末の締め確認後）、イベント（根拠の訂正後） | 店舗・対象月・報告版毎               | 店主代表が売価・補充基準・つけ上限の見直しを判断する               |

売上明細は売上記録の内訳であり、明細用ファイルが別でも独立した管理単位にしない。日次販売集計は販売記録から作る参照ビューで、全体概要の「日次締め記録」とは更新責務が異なるため区別する。

## 3. 正本区分と更新責務

### 3.1. 生成元と利用制約

| データストア名 | 正本区分・生成元                                       | 扱いの制約                                                                             | 更新担当                  | 確認担当 |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------- | -------- |
| 商品台帳       | 商品種類と現在の販売条件の正本。PO の承認内容を反映    | 価格変更を過去の販売単価へ遡及させない                                                 | OPS                       | PO、BA   |
| 販売記録       | 確定した会計と明細の正本                               | 入力途中・取消済みの取引を含めない。訂正は元の売上を特定し、PO の承認を得て行う        | OPS                       | PO、QE   |
| 日次販売集計   | 販売記録から再生成する派生情報                         | 対象日と基準時点の販売集合を記録する。集計値を直接訂正しない                           | OPS                       | QE       |
| 日次締め記録   | 日ごとの照合・判断の正本。日次販売集計と隣接台帳が根拠 | 参照した版・基準時点を固定する。以前の判断を黙って上書きしない                         | OPS（案作成）、PO（確定） | BA、QE   |
| 月次報告       | 月ごとの判断記録。日次締め記録と隣接台帳が根拠         | 根拠の対象日と版を識別する。見直し案を台帳へ自動で書き戻さず、承認後に各領域へ依頼する | BA（案作成）、PO（確定）  | QE、OPS  |

### 3.2. 訂正・不整合時の扱い

訂正・再生成の詳細手順は予定文書 `specdojo:cop-sales-reconciliation` が担う。

| 場面                               | 次の行動                                                                                       | 受け付ける担当 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------- | -------------- |
| 販売集計と元記録が合わない         | 対象日・基準時点と販売集合を照合し、元記録の誤りは販売側で訂正してから集計を再生成する         | OPS            |
| 締め確定後に販売を訂正する         | 旧締めの参照と判断を残し、再生成した集計で締めの新しい確認版を判断する。月次報告への影響も見る | OPS・PO・BA    |
| つけ台帳や在庫記録を取得できない   | 未取得を残高0・差異なしと読み替えず、取得できた範囲だけを記録して締めの確定を保留する          | OPS・PO        |
| 月次報告に根拠のない見直し案がある | 対象月・根拠版・判断理由を補ってから PO が判断する                                             | BA・PO         |

## 4. 関連仕様と検証

### 4.1. 管理単位ごとの参照対応

| データストア名 | 根拠・参照先                                                                                        | 照合する内容                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 商品台帳       | [[specdojo:bdd-sample\|販売管理の辞書]] の商品、[[specdojo:ccd-sample\|概念クラス図]]               | 商品の識別、標準販売価格と販売単価の区別                                                                                                                                            |
| 販売記録       | [[specdojo:bdd-sample\|販売管理の辞書]] の売上記録・売上明細、[[specdojo:ccd-sample\|概念クラス図]] | 売上と明細の所属・粒度、商品参照、つけ販売時の購入者。現金販売の確定までの操作は [[specdojo:clis-sample\|販売管理 CLI 仕様]]、つけ販売の確定は未作成の `specdojo:cdfd-sales` で扱う |
| 日次販売集計   | 本書の販売記録、未作成の `specdojo:bdd-sales-summary`                                               | 対象日・基準時点に含めた売上の集合と支払方法別の集計                                                                                                                                |
| 日次締め記録   | [[specdojo:cdfd-overview-sample\|全体概要]] の日次締め、未作成の `specdojo:bdd-closing`             | 販売額の照合、仕入・在庫・つけ台帳の確認結果、PO の判断と参照版                                                                                                                     |
| 月次報告       | [[specdojo:cdfd-overview-sample\|全体概要]] の月次見直し、未作成の `specdojo:bdd-monthly-report`    | 日次締め記録の網羅、売上・欠品・つけ残高の根拠、更新依頼先                                                                                                                          |

項目・値・構造は各辞書が参照する schema・外部 I/F を正本とし、本書で別の制約を作らない。

### 4.2. 照合手順と受入条件

schema が未作成のため、次の手動照合で確かめる。数値は例示データである。

| 対象         | 確認手順                                                                             | 合格条件                                                                               |
| ------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 一覧の網羅   | 「概要」の5単位を一覧・正本区分・参照対応の各表と照合する                            | 欠落・重複が0件                                                                        |
| 商品台帳     | 価格変更の前後で商品IDと、変更前に確定した売上明細を照合する                         | 商品IDが維持され、過去の販売単価・請求額が変わらない                                   |
| 販売記録     | 確定済み・入力途中・取消済みの取引を一つずつ用意し、保存された売上と明細を確認する   | 確定済みだけが残り、明細の売上・商品の参照が存在し、つけ販売には購入者参照がある       |
| 日次販売集計 | 同じ対象日の現金販売108円とつけ販売216円を集計し、元の売上IDの集合と照合する         | 販売2件・請求合計324円、内訳108円・216円。入力途中・取消済みとつけ精算の入金を含めない |
| 日次締め記録 | 上記集計を使った締め案と、つけ残高を取得できない締め案を比べる                       | 基準時点と各台帳の参照を追える。未取得がある案は確定保留となり、確認者と次の行動が残る |
| 月次報告     | 対象月の日次締め記録と報告の根拠一覧を照合し、締め訂正前の版を参照する報告も確かめる | 対象日の欠落・重複が0件。旧版参照の影響が示され、台帳へ無断で反映しない                |

不一致は「訂正・不整合時の扱い」に従って直し、再照合する。

## 5. 確認事項と変更影響

| 論点                                                                                       | 影響と当面の扱い                                                                                                             |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 集計・締め・報告の辞書と、販売・締めの詳細 CDFD が未作成                                   | 管理境界と手動照合の基準までを採用し、保存形式や締めの全項目は確定しない。未整備のまま実装すると基準時点の異なる情報が混ざる |
| `_UNDECIDED_`: システム化後の保存・保持・復旧方式（`specdojo:sll-sales-closing` が未作成） | 現行の販売ノートは明細欄と締め欄を分けて扱う。訂正・再生成の手順が整うまでシステム上で本番実施しない                         |
| 販売の訂正方式や粒度を変える場合                                                           | 販売記録、辞書・概念クラス図、販売プロセス、集計、締め、月次報告と既存記録の再照合へ波及する                                 |
