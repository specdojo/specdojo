# 影響調査（運用）サンプル

## 1. 目的と適用範囲

本書は、変更要求 `cr-2026-004`（バーコード会計とキャンペーン値引きの導入）が駄菓子屋の販売管理システムの運用へ与える影響を判定し、変更要求を運用面で受け入れるか、どの運用をどこまで変えるかを、運用の準備に着手する前に決めるための文書である。業務とデータへの影響は [[specdojo:imp-business-sample|影響調査（業務）サンプル]] と [[specdojo:imp-data-sample|影響調査（データ）サンプル]] の判定を前提とし、本書では再掲しない。

- 対象の運用領域: 監視運用、アラート初動、日次締め運用、問い合わせ一次対応。
- 対象外の運用領域: 店番の交代体制（店番をする人と時間帯が変わらないため）、端末の故障時の運用（タブレット 1 台の構成が変わらないため）。
- 対象期間: 2026-05-01（運用影響の判定開始）〜2026-07-31（切替後の月次運用の振り返りの完了日）。

_ASSUMPTION_: 切替日は影響調査（データ）と同じ 2026-06-01 とする。監視は販売管理アプリがタブレットの画面に警告を出し、警告を端末内の記録に残す仕組みとし、外部の監視サービスや通知先は使わない。

## 2. 変更要求の概要

- 背景: 夕方の混雑時の会計待ちを減らすため、バーコード会計とキャンペーン値引きを導入する。現行の運用には値引きがなく、値引きの適用誤りやバーコードの読み取り失敗に気付く手段も、締めで値引きを確かめる手順もない。
- 要求の要点: 値引きと読み取りの失敗を検知できるようにし、店番が警告を見たときの初動と、日次締めでの値引きの確認を運用に加える。
- 狙い: 店番が店主代表でも家族利用者代表でも、値引きの誤りを締めまでに把握して売上を記録し続けられること。

成功条件は次の 3 つとし、すべて達成した場合に運用面の受入確認を合格とする。

| 成功条件                                                       | 確認対象                   | 判定方法                                                                         |
| -------------------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------- |
| 値引き適用エラーのうち、その日の締めまでに把握されない件数が 0 | 警告の記録と日次締めの記録 | 2026-06-01〜2026-06-14 の全営業日で、締めの差額の原因が警告の記録と 1 件ずつ対応 |
| 値引き適用エラーの検知から初動開始までが上限時間以内           | 警告の記録と初動の記録     | 同じ期間の全件で、警告の表示時刻と初動の記録時刻の差が上限以内                   |
| 日次締めを営業日の 90% 以上で完了                              | 日次締めの記録             | 2026-06-01〜2026-06-30 の営業日のうち、締めを当日に完了した日の割合              |

_UNDECIDED_: 初動開始までの上限時間は店主代表が決める（未解決事項 `PJR-O4Q1`）。

## 3. 影響分析サマリ

影響度は、次の境界値を当てはめてから判定する。

- 許容停止時間: 営業時間中の会計の停止は 0 分とする（影響調査（データ）と同じ）。
- 初動開始の上限: _UNDECIDED_（`PJR-O4Q1`）。決まるまでは「その日の閉店までに把握する」を下限として判定する。
- 店番の対応上限: 店番は 1 人で、会計を止めずに行えるのは警告の確認と記録までとする。原因の調査と訂正は閉店後に店主代表が行う。

運用品質（監視・統制・監査）、障害対応力、運用負荷、利用者影響の 4 観点を、次の条件で判定する。

| 評価観点                     | 高                                                           | 中                                                 | 低                             |
| ---------------------------- | ------------------------------------------------------------ | -------------------------------------------------- | ------------------------------ |
| 運用品質（監視・統制・監査） | 誤りを検知できない、または値引きの記録を締めで確かめられない | 監視の追加や締めの確認項目の変更で検知・確認できる | 現行の監視・締めで足りる       |
| 障害対応力                   | 店番が初動できない、または初動が上限を超える                 | 初動の手順の変更か、店番への周知が必要             | 現行の初動で足りる             |
| 運用負荷                     | 店番の対応上限を超える作業が増える                           | 対応上限の範囲で手順が増える                       | 作業が変わらない               |
| 利用者影響                   | 来店客が会計を受けられない                                   | 来店客への周知や説明が必要                         | 来店客の受ける会計が変わらない |

集約規則: 観点ごとの判定のうち最も高いものを、その行の影響度とする。件数は「影響詳細一覧」の行を同じ規則で集計した。

| 影響度 | 件数 | 主な対象運用           | 優先対応 |
| ------ | ---- | ---------------------- | -------- |
| 高     | 2    | 監視運用、アラート初動 | 要       |
| 中     | 1    | 日次締め運用           | 要       |
| 低     | 1    | 問い合わせ一次対応     | 否       |

運用面の結論は **条件付き受入** とする。条件は、監視の追加とアラート初動の手順が 2026-05-28 までに整い、その前提として初動開始の上限（`PJR-O4Q1`）が 2026-05-15 までに決まることである。

## 5. 対応方針

影響度の高い順に、対応項目ごとの期限・担当・前提条件と、完了を判定する条件を示す。

| 影響度 | 対応項目                               | 期限       | 担当  | 前提条件                                                                          | 完了条件                                                                        |
| ------ | -------------------------------------- | ---------- | ----- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 高     | 監視 3 項目の追加                      | 2026-05-26 | `DEV` | 売上明細への値引き理由の追加が終わっていること（影響調査（データ）で 2026-05-22） | 移行テストで 3 項目の警告がそれぞれ 1 回以上画面に出て、端末内の記録に残る      |
| 高     | アラート初動の手順の改訂と店番への周知 | 2026-05-28 | `OPS` | 初動開始の上限が決まっていること（`PJR-O4Q1`）                                    | 店主代表と家族利用者代表が、模擬の警告から上限以内に初動を始めて記録を残せる    |
| 中     | 日次締めの差分手順書の作成と併用       | 2026-05-28 | `OPS` | 日次締めの確認項目が確定していること（影響調査（業務））                          | 移行テストの締めを差分手順書だけで 1 回完了でき、値引き理由別の合計が記録に残る |
| 低     | 問い合わせ一次対応の見送りの再評価     | 2026-07-31 | `BA`  | 切替日から問い合わせノートに値引きの問い合わせを記録していること                  | 再評価条件の成否と、見送りを続けるかの判断が登録項目に記録されている            |

見送り・代替の再評価条件は次のとおりとする。

- 日次締め運用（代替）: 2026-06-01〜2026-06-14 に、差分手順書を使っても締めの差額の原因が分からない日が 0 日なら、2026-06-14 に手順書を一本化する。1 日でもあれば一本化を延ばし、2026-06-30 に再評価する。併用中に差分手順書で判断できない点は、店番が締めの記録に書き残し、翌日の開店前に店主代表が確かめる。店主代表が判断に迷う点は店舗運営アドバイザーに相談する。
- 問い合わせ一次対応（見送り）: 切替日から 4 週間（2026-06-01〜2026-06-28）のうち、値引きに関する問い合わせがいずれかの週で 5 件を超えたら、問い合わせへの回答の手順の追加を 2026-07-31 までに再評価する。
