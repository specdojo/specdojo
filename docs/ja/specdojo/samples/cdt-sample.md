# 商品区分

駄菓子屋の店主代表と家族利用者代表が、商品の棚割り・仕入れ方針・棚札を同じ基準で選ぶための分類を定義する。

## 1. 概要

- 業務目的: 商品の種類と仕入れ方針を分け、季節商品を定番商品と同じ基準で補充する誤りや、棚札の表記ゆれを防ぐ。
- 対象エンティティ: 商品（`product`）。商品の管理単位と識別は [[specdojo:bdd-sample|業務データ辞書（駄菓子屋の販売管理）]] に合わせる。
- 適用範囲: 店舗の商品台帳と棚札で使う「商品区分」「取扱区分」「棚札タグ」。商品区分と取扱区分はそれぞれ一つを選び、棚札タグは必要な場合だけ複数付けられる。
- 主担当ロール: BA が判断境界を整理し、PO を担う店主代表が区分の意味と各商品の分類を決める。家族利用者代表は仕入れや店番で参照し、QE は境界事例を確認する。
- 責務の境界: これらは実装前の店舗運営上の分類であり、業務データ辞書に未定義の属性を実装済みとは扱わない。税区分・保管温度・賞味期限は商品ごとに確認し、本分類だけから税率や保管方法を決定しない。

## 2. 分類定義

### 2.1. 商品区分

| 定義項目         | 内容                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 対象エンティティ | 商品（`product`）                                                                  |
| 分類定義名       | 商品区分（`product_type`）                                                         |
| 種別             | 業務分類                                                                           |
| 正本参照（SSOT） | なし（スタンドアロン定義）。本書の「商品区分の選定」を正本とする                   |
| 説明             | 店主代表が商品の主な用途で棚割りを決める区分。冷蔵の要否や販売する季節では分けない |

### 2.2. 取扱区分

| 定義項目         | 内容                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| 対象エンティティ | 商品（`product`）                                                                                  |
| 分類定義名       | 取扱区分（`handling_type`）                                                                        |
| 種別             | 業務分類                                                                                           |
| 正本参照（SSOT） | なし（スタンドアロン定義）。本書の「取扱区分の選定」を正本とする                                   |
| 説明             | 店主代表が継続補充・期間限定・試験導入のどの方針で仕入れるかを決める区分。商品の種類とは独立に選ぶ |

### 2.3. 棚札タグ

| 定義項目         | 内容                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 対象エンティティ | 商品（`product`）                                                                                            |
| 分類定義名       | 棚札タグ（`shelf_tags`）                                                                                     |
| 種別             | 動的分類                                                                                                     |
| 正本参照（SSOT） | 店主代表が保管する紙の商品台帳の「棚札タグ管理欄」。追加・変更・廃止は本書の「棚札タグの管理」に従う         |
| 説明             | 売場で注目してほしい特徴を示す任意の分類。店主代表が運用中に増減でき、商品区分や取扱区分の代わりには使わない |

この三つの属性名は商品台帳の分類軸を識別するための呼称であり、データ構造は定義しない。商品区分・取扱区分には実装やスキーマによる許容値の定義がなく、本書が業務上の正本を担う。棚札タグの現行値は商品台帳で管理し、本書には固定の値一覧を置かない。

## 3. 値の業務的意味と使い分け

### 3.1. 商品区分の選定

| 値      | 分類名 | 表示名 | 説明・成立条件                                                                                                     |
| ------- | ------ | ------ | ------------------------------------------------------------------------------------------------------------------ |
| `snack` | お菓子 | お菓子 | 食べることを主な用途とする駄菓子・菓子類。飲む商品は `drink` とし、包装の絵柄や冷蔵の有無では区分を変えない        |
| `toy`   | 玩具   | 玩具   | 遊ぶことを主な用途とする非食品。シール・こま・花火などを含む。食べる商品に景品が付くことだけを理由に玩具とはしない |
| `drink` | 飲料   | 飲料   | 飲むことを主な用途とする清涼飲料・瓶ジュース類。常温で販売する飲料も含み、冷蔵した菓子を含めない                   |

菓子と玩具が一体の商品は、商品説明と売場での案内から主な用途を店主代表が確認する。用途を一つに決められない場合は、家族利用者代表が推測で区分を付けず、店主代表が扱いを決めるまで棚割りを保留する。既存の三分類に当てはまらない商品も、便宜的にいずれかへ入れず、分類の追加要否を確認する。

### 3.2. 取扱区分の選定

| 値             | 分類名   | 表示名   | 説明・成立条件                                                                                                         |
| -------------- | -------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `staple`       | 定番商品 | ★定番    | 店主代表が通年で棚に置き、継続して補充すると決めた商品。発注点を設定する対象。売れ行きが良いだけでは自動で定番にしない |
| `seasonal`     | 季節商品 | 季節限定 | 店主代表が販売期間を定め、その期間内だけ仕入れる商品。期間終了時は追加仕入れを止め、残品の扱いを店主代表が決める       |
| `experimental` | 試験商品 | お試し   | 継続取扱の判断材料を集めるために初回導入する商品。入荷後30日間の売れ行きを確認して、店主代表が継続方針を決める         |

#### 3.2.1. 条件が重なる場合

1. 販売期間を限定している商品は、新規導入でも `seasonal` を優先する。期間を延ばす場合も、通年補充の決定がなければ `staple` にしない。
2. 期間限定ではなく、継続取扱が未決定の新商品は `experimental` とする。入荷後30日を過ぎただけでは `staple` に変えず、判断待ちの間は追加仕入れを保留する。
3. 店主代表が通年補充を決定した時点で `staple` とする。商品の新旧や販売量だけでは選ばない。

#### 3.2.2. 区分を変更する場合

- 店主代表は変更理由と適用日を商品台帳に残し、家族利用者代表に新しい補充方針を伝える。商品IDは変えない。取扱区分の変更適用日までに、店番担当（店主代表または家族利用者代表）は店頭の棚札表示（表示名: `★定番` / `季節限定` / `お試し`）を新しい取扱区分に合わせて貼り替える。
- `experimental` から `staple` に変更する場合は発注点の設定を確認する。未設定をゼロと読み替えて補充判断を進めない。
- 継続取扱をやめる場合は、無理に別区分へ移さず追加仕入れを止める。取扱終了は商品の種類ではなく販売対象の管理として扱い、過去の記録を残す。

### 3.3. 棚札タグの管理

| 管理項目         | 規約                                                                                                                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理元           | 紙の商品台帳の棚札タグ管理欄を正本とし、棚札へ同じ名称を転記する。棚札だけに新しいタグを作らない                                                                             |
| 作成・変更権限   | 店主代表が追加・改名・アーカイブを決める。家族利用者代表は登録済みの有効なタグを商品へ付け外しでき、新設や統合が必要な場合は店主代表へ依頼する                               |
| 命名規約         | 来店客が特徴を理解できる短い日本語名とし、商品名・人物名を使わない。同義のタグは新設せず既存名に揃える。「定番」「季節限定」「お試し」は取扱区分の表示と混同するため使わない |
| 改名・統合       | 同じ意味の改名は既存の参照を引き継ぎ、商品台帳と棚札を揃える。意味を変える場合は別タグを作り、旧タグを同じ意味だったように書き換えない                                       |
| 削除・アーカイブ | 商品や過去の記録から参照されたタグは削除せずアーカイブする。以後の新規付与を止め、既存の参照と当時の意味は確認できるよう残す。未使用の誤登録だけ削除できる                   |

例えば「小分け」は少量ずつ分けて渡せる商品への棚札表現として店主代表が登録できるが、必須のタグではない。タグが付いていなくても商品区分・取扱区分の選定には影響しない。

### 3.4. 判断境界の具体例

| 場面                                         | 選定結果・次の判断       | 境界の根拠                                                       |
| -------------------------------------------- | ------------------------ | ---------------------------------------------------------------- |
| 通年補充する瓶ジュースを常温棚で売る         | `drink` / `staple`       | 飲む用途と通年補充の方針で選ぶ。保管温度は商品ごとに確認する     |
| 夏季だけ販売する花火を初めて仕入れる         | `toy` / `seasonal`       | 非食品で遊ぶ用途。新規導入でも期間限定が優先される               |
| 継続取扱を決めていない新しい駄菓子を導入する | `snack` / `experimental` | 食べる用途。入荷後30日間の確認を経て店主代表が継続方針を判断する |

## 4. 関連仕様との関係

| 関連仕様                                                      | 分類との関係・変更時に確認すること                                                                                                                                                                                 |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [[specdojo:bdd-sample\|業務データ辞書（駄菓子屋の販売管理）]] | 商品（`product`）と発注点（`reorder_point`）を参照する。本書の分類属性やタグの管理構造は同辞書に未定義。システム化する際は辞書へ構造を定義し、許容値を実装・スキーマに持たせる場合は本書の正本参照方式を切り替える |
| [[specdojo:gl-sample\|用語集 在庫・調達]]                     | 「定番商品」と「発注点」の語義を参照する。定番の成立条件を変える場合は、通年で棚に置く方針および発注点の利用対象と矛盾しないか確認する                                                                             |
| [[specdojo:br-sample\|在庫不足判定]]                          | 定番商品で発注点に基づく不足判定を行う際に参照する。計算式と入力不備の扱いは同ルールに委ねる。季節・試験商品の追加仕入れは店主代表が取扱方針に沿って判断する                                                       |
| [[specdojo:uis-sample\|販売登録画面 画面仕様]]                | 販売する商品の識別と会計操作を参照する。本書は商品分類の編集画面や税率の算出を定義しない。分類の変更を会計へ反映する場合は、商品ごとの税区分との関係を別途確認する                                                 |
