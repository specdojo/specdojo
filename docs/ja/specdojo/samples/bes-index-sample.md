# 業務イベント一覧: 駄菓子屋きぬや販売管理

駄菓子屋きぬやの店舗運営で、各プロセス領域を起動する業務上の出来事を一覧で定義する。対象は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）]] の「プロセス領域」に挙げた仕入・販売・在庫・顧客・締めの 10 領域の起点イベントである。領域 ID・領域名・起点イベントの文言は同書を正本とする。値引き・取消・返品は領域内部の出来事として一覧に含めない（業務の対象外ではない）。起点を足すときは先に上位 CDFD を見直す。

本一覧は、販売・入荷・つけを記録する時点を揃える。購入の申し出と会計確定、納品と検品後の入荷記録を区別し、記録漏れや二重計上を防ぐ。業務プロセス仕様（BPS）・UI・テスト仕様は、本一覧の行を出来事の単位とする。受けた後の手順は BPS、金額計算は [[specdojo:br-sample|販売金額計算の業務ルール]]、取引の状態は状態定義、事実データの値・構文・構造はデータモデル・schema に委ねる。

## 3. 未決事項と承認条件

### 3.1. 未決事項

<!-- prettier-ignore -->
| 論点 | 影響と当面の扱い |
| --- | --- |
| _UNDECIDED_: 発注のない納品を `bes-goods-delivered` に含めるか | 現定義では、発注のない納品で `bes-goods-delivered` は発生しない。決まるまで発注外納品の BPS・UI・テストを確定しない。決まったら `bes-goods-delivered` の発生条件を直すか、上位 CDFD と照合して行を足す |
| _UNDECIDED_: つけ上限超過は受付と店主代表の承認のどちらで成立するか | 上限内は一覧の定義で扱う。超過の経路は個別仕様（「個別仕様への詳細化」）で決まるまで確定入力にしない。決まったら `bes-credit-sale-requested` の行と、つけ販売の BPS・業務ルール（BR）・UI・テストの期待結果を直す |
| _ASSUMPTION_: 閉店は店主代表の宣言時点とした。月末の締めと最終営業日の日次締めの関係は未確認 | 日次・月次の起動時点が変わり得る。営業延長日と月末休業日の例で関係を決めたら、上位 CDFD と `bes-store-closed`・`bes-month-end-closed` の行を直す |
| _ASSUMPTION_: 事実データ列は、上位 CDFD の「データストア」の記録のうち発生時点で観測できる情報を概念名で挙げた。販売記録・在庫記録・つけ台帳のデータモデルとは未照合 | 照合まで事実データ列を確定入力にしない。照合で、発生時点に情報がそろわない行や発生後の結果を含む行が見つかったら、その行の事実データを直す |
| _UNDECIDED_: `P-03`・`P-05` の起点イベントの文言（「顧客が売場の商品を持って会計を申し出た」「販売が記録された」）とイベント名の差を、上位 CDFD と行のどちらで直すか | 決まるまで `bes-cash-sale-confirmed`・`bes-stock-movement-recorded` の行を確定入力にしない。決まったら上位 CDFD の起点イベントか該当行のイベント名を直す |

### 3.2. 照合の結果と確定入力として扱う条件

一覧を BPS・UI・テストの確定入力にする前に、次の表の照合を行った。各行の「確定入力としての扱い」で除くとした範囲と「未決事項」の範囲を除き、残りを確定入力として扱う。

<!-- prettier-ignore -->
| 確かめたこと | 結果 | 確定入力としての扱い |
| --- | --- | --- |
| 上位 CDFD の 10 領域・起点イベントと有効行の対応 | 10 領域に有効な 10 行が 1 対 1 で対応し、出典のない行・欠落は 0 件。`P-03`・`P-05` は起点イベントの文言とイベント名が異なる | 文言の差 2 件は「未決事項」のとおり、どちらを直すか決まるまで該当行を確定入力にしない |
| 必須列の空欄 | 全 10 行の 8 列に空欄 0 件 | 確定入力にする |
| イベント ID の形式と重複 | 10 件すべてが `bes-<event>` の形式に適合し、重複 0 件（廃止行なし） | 確定入力にする |
| 各行からの発生・不成立の判定 | 現金受領不足・明細確認中は確定なし、確定後の再表示・再印字は追加の確定なしと判定できる。納品受取と検品後の入荷記録、閉店宣言と閉店時刻到来も区別できる | 確定入力にする。個別の判定例は個別の業務イベント仕様（BES）に委ねる |
| 詳細化の対応と個別 BES からの参照 | `bes-cash-sale-confirmed` は個別 BES から一覧と対応行のイベント ID を参照しており一致。`bes-credit-sale-over-limit` は未作成のため未実施 | つけ上限超過の範囲は個別 BES の作成まで除く |
| 事実データとデータモデルの照合 | 未実施 | 「未決事項」のとおり照合まで事実データ列を確定入力にしない |
