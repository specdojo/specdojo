# 業務イベント一覧: 駄菓子屋きぬや販売管理

駄菓子屋きぬやの店舗運営で、各プロセス領域を起動する業務上の出来事を一覧で定義する。対象は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）]] の「プロセス領域」に挙げた仕入・販売・在庫・顧客・締めの 10 領域の起点イベントであり、領域 ID・領域名・起点イベントの文言は同書を正本とする。

販売・入荷・つけをいつ記録するかを揃え、購入の申し出と会計確定、納品と検品後の入荷記録を区別して記録漏れや二重計上を防ぐ。BPS・UI・テスト仕様は本一覧の行を出来事の単位とする。受けた後の手順は BPS、金額計算は [[specdojo:br-sample|販売金額計算の業務ルール]]、取引の状態は状態定義、事実データの値・構文・構造はデータモデル・schema に委ねる。

_ASSUMPTION_: 事実データは、上位文書の「データストア」の記録から発生時点で観測できる情報を概念名で挙げた。

## 3. 未決事項と承認条件

### 3.1. 未決事項

<!-- prettier-ignore -->
| 論点 | 影響と当面の扱い |
| --- | --- |
| _UNDECIDED_: 発注のない納品を `bes-goods-delivered` に含めるか | 現定義では発生しない。決まるまで発注外納品の BPS・UI・テストを確定しない。決まったら `bes-goods-delivered` の発生条件を直すか、上位 CDFD と照合して行を足す |
| _UNDECIDED_: つけ上限超過は受付と店主代表の承認のどちらで成立するか | 上限内は一覧の定義で扱う。超過の経路は個別仕様（「個別仕様への詳細化」）で決まるまで確定入力にしない。決まったら `bes-credit-sale-requested` の行と、つけ販売の BPS・BR・UI・テストの期待結果を直す |
| _ASSUMPTION_: 閉店は店主代表の宣言時点とした。月末の締めと最終営業日の日次締めの関係は未確認 | 日次・月次の起動時点が変わり得る。営業延長日と月末休業日の例で決まったら、上位 CDFD と `bes-store-closed`・`bes-month-end-closed` の行を直す |
| _ASSUMPTION_: 事実データが販売記録・在庫記録・つけ台帳のデータモデルと未照合 | 照合まで事実データ列を確定入力にしない。発生時点で情報がそろわない、または発生後の結果を含む行は直す |
| 一覧の範囲は 10 領域の起点イベントだけとした | 値引き・取消・返品は領域内部の出来事として含めない（業務の対象外ではない）。起点を足すなら先に上位 CDFD を見直す |

### 3.2. 確定入力として扱う条件

- 上位 CDFD の 10 領域に有効な 10 行が対応し、出典のない行・空欄、イベント ID の形式違反・重複（廃止行を含む）が 0 件である。
- 現金受領不足・明細確認中は現金会計の確定なし、確定後の再表示・再印字では追加の確定なしと判定できる。納品受取と検品後の入荷記録、閉店宣言と閉店時刻到来も区別できる。個別の判定例は個別 BES に委ねる。
- 「個別仕様への詳細化」の対応範囲と個別 BES からの参照が一致する。「未決事項」の範囲は解消まで除く。
