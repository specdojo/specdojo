# 影響調査（I/F）サンプル

## 1. 目的と適用範囲

本書は、変更要求 `cr-2026-004`（バーコード会計とキャンペーン値引きの導入）が駄菓子屋の販売管理システムの外部 I/F へ与える影響を判断し、I/F ごとの変更要否・影響度・対応方針と連携先との調整を、I/F の改修に着手する 2026-05-11 より前に決めるための文書である。業務への影響は [[specdojo:imp-business-sample|影響調査（業務）サンプル]] で判断済みであり、本書はその判断を前提とする。データ・テスト・運用への波及の詳細は [[specdojo:imp-data-sample|影響調査（データ）サンプル]]・[[specdojo:imp-test-sample|影響調査（テスト）サンプル]]・[[specdojo:imp-operations-sample|影響調査（運用）サンプル]] へ委ね、本書は結論だけを「影響詳細一覧」の備考に示す。

- 対象の I/F: 外部システム I/F 一覧（[[specdojo:ifx-index-sample|外部システムI/F一覧サンプル]]）の「本部商品マスタの照会」「本部への売上登録」「確定済みレシートの印字」と、一覧への追加を検討中の「在庫変更イベント」の 4 I/F。
- 対象外の I/F: なし。一覧に掲載された I/F はすべて調べた。仕入先とのシステム連携とキャッシュレス決済は初期リリースの対象外であり、I/F が存在しない。
- 本書では判断しない事項: 各 I/F の送受信項目の定義と応答コードの扱い（各 I/F 仕様で決める）、店舗端末内の取引記録・設定ファイル（CLI 仕様の入出力で扱う）。
- 対象期間: 2026-05-01（I/F 影響の判定開始）〜2026-06-07（切替後 1 週間の連携結果を本部と確かめ終える日）。

_ASSUMPTION_: 新しい I/F で連携を始める日（切替日）を、影響調査（データ）・影響調査（テスト）と同じリリース予定日 2026-06-01 とする。

## 2. 変更要求の概要

- 背景: 夕方の混雑時に会計待ちが長いため、業務影響調査でバーコード読取による会計とキャンペーン値引きの導入が決まった。現行の I/F は商品コードでしか商品を照会できず、本部への売上登録にも値引きの内訳を渡せない。
- 要求の要点: 本部の商品マスタをバーコード値で照会できるようにし、売上登録に値引き額と値引き理由を加え、レシートに値引きを印字する。切替前の店舗端末からの連携は止めない。
- 狙い: 業務影響調査の成功条件（混雑時の 1 会計あたり平均 90 秒以内）を、商品照会の失敗で崩さないこと。あわせて、値引き導入後も本部の売上と店舗の日次締めを突き合わせられる状態を保つこと。

成功条件は次の 4 つとし、すべて達成した場合に連携先の受入確認を合格とする。

| 成功条件                                                      | 確認対象                           | 判定方法                                                                                           |
| ------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| 切替前の店舗端末からの売上登録が、改修なしで受け付けられる    | 本部売上登録の互換試験の結果       | 値引き項目を含まない売上登録を互換試験で送り、全件が受付済みになること                             |
| 売上上位 30 品目をバーコード値で照会できる                    | 本部商品マスタ照会の外部結合テスト | 30 品目すべての照会で、商品名・販売単価・税区分が商品マスタと一致すること                          |
| 本部の値引き合計が店舗の日次締めと一致する                    | 本部の売上集計と店舗の日次締め帳票 | 2026-06-01〜2026-06-07 の全営業日で、値引き合計の差額が 0 円であること                             |
| 切替後 1 週間、新しい項目・照会条件に起因する連携の拒否がない | 本部商品照会・売上登録の拒否の記録 | 2026-06-01〜2026-06-07 の拒否のうち、バーコード値または値引き項目を原因とするものが 0 件であること |

## 3. 影響分析サマリ

影響度は、契約互換性・障害波及・連携先調整の 3 観点を次の条件で判定する。

| 評価観点   | 高                                                             | 中                                                             | 低                         |
| ---------- | -------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------- |
| 契約互換性 | 既存の送受信が壊れ、改修しないと連携を続けられない             | 既存の送受信は保たれ、項目・条件の追加で吸収できる             | 送受信の内容が変わらない   |
| 障害波及   | 連携が止まると会計・日次締めが止まる、または誤った値のまま続く | 連携が止まっても手入力や後日の照合で会計・日次締めを続けられる | 会計・日次締めに影響しない |
| 連携先調整 | 連携先の改修が終わらないと切替日に新しい連携を始められない     | 連携先の設定変更・段階導入・実機確認などの手順追加で済む       | 連携先の作業が要らない     |

集約規則: 観点ごとの判定のうち最も高いものを、その I/F の影響度とする。件数は「影響詳細一覧」の行を同じ規則で集計した。

| 影響度 | 件数 | 主な影響対象I/F                        | 優先対応 |
| ------ | ---- | -------------------------------------- | -------- |
| 高     | 2    | 本部商品マスタの照会、本部への売上登録 | 要       |
| 中     | 1    | 確定済みレシートの印字                 | 要       |
| 低     | 1    | 在庫変更イベント                       | 否       |

影響度「高」の 2 件のうち、本部への売上登録の調整を先に始める。本部が値引き項目を受け付けられる時期が未定（未解決事項 `PJR-I6R1`）であり、本部の改修が切替日に間に合わないと分かった時点で切替日を見直す必要があるためである。

## 5. 対応方針

影響度の高い順に、対応項目ごとの期限・調整先と、達成を判定する完了条件を次に示す。

| 影響度 | 対応項目                                       | 期限       | 担当  | 調整先                            | 前提条件                                                                     | 完了条件                                                                                                   |
| ------ | ---------------------------------------------- | ---------- | ----- | --------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 高     | 本部への売上登録に値引き額・値引き理由を追加   | 2026-05-22 | `DEV` | 本部（売上登録 API の管理元）     | 本部の改修可能時期の回答（`PJR-I6R1`）、値引き理由の区分の確定（`PJR-D4Q1`） | 互換試験で値引き項目なしの登録が全件受付済みになり、値引きありの登録で本部の値引き合計が売上明細と一致する |
| 高     | 本部商品マスタの照会にバーコード値の照会を追加 | 2026-05-20 | `DEV` | 本部（商品マスタ API の管理元）   | 上位 30 品目のバーコード値が商品マスタに登録済み（2026-05-15）               | 外部結合テストで上位 30 品目の照会が全件一致し、未登録のバーコード値では明細が増えない                     |
| 中     | 確定済みレシートに値引き合計を 1 行印字        | 2026-05-26 | `DEV` | 店舗プリンタ（receipt-print CLI） | 実機での印字幅の確認（`PJR-I6Q4`）                                           | 定額・定率の値引き各 1 件の会計で値引き合計が 1 行で印字され、印字失敗時も会計が確定したまま残る           |
| 低     | 在庫変更イベントの見送りの再評価               | 2026-07-31 | `BA`  | 本部（在庫通知の受け手）          | 本部が在庫通知を採用するかの回答                                             | 再評価の要否を判断し、結果を決定記録 `PJR-I6D1` に記録している                                             |

- 見送り・代替の再評価条件: 確定済みレシートの印字は、来店客からレシートと支払額の食い違いの申し出が月 3 件を超えたら、明細ごとの値引きの印字を 2026-07-31 までに再評価する。在庫変更イベントは、本部が在庫通知の採用を決めた時点で、値引き時の通知項目を 2026-07-31 までに再評価する。
