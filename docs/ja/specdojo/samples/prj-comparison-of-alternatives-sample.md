# 代替案比較: 駄菓子屋きぬや 販売管理システム

販売・在庫・つけの記録を店主代表以外の店番でも継続できるよう、解決方式を比較し、試行対象と見直し条件を決める。

## 1. 比較目的と前提条件

| 決定ID | 比較レイヤー           | 決定すること                        | 決定しないこと                     |
| ------ | ---------------------- | ----------------------------------- | ---------------------------------- |
| D-01   | 業務・システム解決方式 | P-01〜P-03 を改善する方式と試行対象 | 個別製品、開発手法、作業管理ツール |

根拠資料:

- [[specdojo:prj-scope-sample|プロジェクトスコープ]]: 初期対象は販売・在庫・つけと簡易一覧。EC・会計・仕入れ先連携・複数店舗は対象外。
- [[specdojo:prj-issues-and-approach-sample|プロジェクト課題と解決アプローチ]]: P-01 記録不統一、P-02 残高確認の負荷、P-03 在庫過不足。
- [[specdojo:prj-assumptions-constraints-dependencies-sample|前提・制約・依存関係]]: タブレット1台、現行手順に近い操作、費用承認、通信断時の方針決定。

_ASSUMPTION_: 期間評価の目安は準備着手の承認から2週間とする（初期リリース日ではない）。支出・作業時間の上限と具体日は [[specdojo:pm-plan-sample|プロジェクト管理計画]] の U-01〜U-03 で決まるまで、未承認の支出・作業を始めない。

| 候補カテゴリ       | 候補に含める基準                                                 |
| ------------------ | ---------------------------------------------------------------- |
| 非システム対応     | 紙の記録と手順だけで P-01〜P-03 を改善できる                     |
| 汎用デジタルツール | 専用システムを構築せず、タブレットで記録・検索・集計できる       |
| 既存製品・サービス | 販売・在庫を既存機能で扱い、つけ管理を含む一式の運用を構成できる |
| 個別構築           | 店舗固有の手順と初期対象に合わせた最小機能を構築できる           |

ALT-02・ALT-03 は [Google スプレッドシート](https://support.google.com/docs/answer/6000292) と [Square](https://squareup.com/help/jp/ja/article/8331-set-up-inventory-tracking) の公式ヘルプ（確認日: 2026-11-13）で編集・書き出しと販売連動の在庫更新を確かめて加えた。市場代表・店舗適合の証明ではない。製品比較は既存サービス案が残った場合に別レイヤーで行う。

## 2. 比較対象案

### 2.1. D-01: 業務・システム解決方式

全案が初期対象の記録と一覧を扱い、日次確認・引き継ぎ（前段の A-03）を含む。ALT-01・ALT-04 は前段の A-02・A-01 に当たる。

| 案ID   | 案                               | カテゴリ           | 課題解決への道筋                                     | 主な構成要素                         |
| ------ | -------------------------------- | ------------------ | ---------------------------------------------------- | ------------------------------------ |
| ALT-01 | 紙帳票と手順の標準化             | 非システム対応     | 帳票と日次確認を統一し、店番交代時のばらつきを減らす | 統一帳票、操作メモ、手計算による確認 |
| ALT-02 | 共有表計算による簡易管理         | 汎用デジタルツール | 共有表への記録と数式集計で残高・在庫を確認する       | 販売・在庫・つけ台帳、入力規則       |
| ALT-03 | 既存 POS・在庫管理サービスの利用 | 既存製品・サービス | 既存の販売・在庫機能とつけの補助手段で一式を構成する | POS、在庫、つけ補助台帳、照合        |
| ALT-04 | 最小販売管理システムの個別構築   | 個別構築           | 店舗の記録項目と操作に合わせて一元化する             | 販売登録、在庫、つけ残高、簡易一覧   |

## 3. 評価軸と評価基準

`High` / `Middle` / `Low` は採択に有利な順。材料がなければ「未判定」とし、中間評価で代用しない。

| 評価軸             | 判定基準（High / Middle / Low）                                                                              | 根拠となる課題・制約          |
| ------------------ | ------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| 効果               | 記録統一・残高検索・在庫低下把握の3能力を同じ記録から提供 / 2能力 / 1能力以下                                | P-01〜P-03                    |
| コスト             | 現金支出・作業時間がともに承認上限の80%以内 / ともに上限内だが一方が80%超 / 一方でも上限超。上限未決は未判定 | ACD-C02、U-01・U-02           |
| 期間               | 試行候補の準備が7日以内 / 8〜14日 / 14日超。上限承認後に見積もる                                             | 2週間の目安、U-03             |
| リスク             | 誤記録・停止・移行漏れの全経路で照合・回復を検証済み / 対策と確認条件があるが未検証 / 対策のない経路がある   | P-01・P-02、ACD-A02・D03      |
| 業務適合           | 両利用者が必須タスクを支援なしで完了 / 支援付きで完了 / 一つでも完了不能（操作性を含む）                     | P-01、現行手順とタブレット1台 |
| 技術実現性         | 端末・移行・外部依存の成立を確認済み / 実現経路はあるが検証待ち / 成立しない依存がある                       | ACD-D01〜D04                  |
| データ移行・可逆性 | 元ノートとの全件照合と取り出し・紙への復元を検証済み / 方法を定義し検証待ち / 残高・履歴を復元する方法がない | P-02、既存ノート              |
| 運用・保守性       | 引き継ぎ・項目変更・回復を後任が単独で完了 / 手順はあるが支援を要する / 担当・手順を用意できない             | P-01、小規模体制              |

重み付け・加重合計は用いない。効果・業務適合が `Low` の案は主方式から外し、残りを効果、業務適合、リスクの順で比べて試行対象を選ぶ。正式採用は全軸が `Middle` 以上、未判定なし、受入・試用条件の合格を要する。総合評価はこのゲートの充足状況で示す。

### 4.2. 技術的実現性と影響

| 案ID   | 技術的実現性・外部依存                    | 正本・移行・停止時の扱い                                                                                                 |
| ------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| ALT-01 | 現行の紙を使える                          | 統一帳票を正本とし、既存残高を照合して転記する（未検証）                                                                 |
| ALT-02 | 端末 OS、共有権限、利用条件は実機確認待ち | 共有表を正本とする。停止時は全記録を書き出して紙へ復元する（未検証）                                                     |
| ALT-03 | つけ補完、端末・接続、契約は未確認        | 正本境界・照合を製品比較で定めるまで採用しない。商品情報の出力だけで撤退可能とみなさない                                 |
| ALT-04 | ACD-D01〜D04 の確認が残る                 | システム記録を正本とし、ノート残高を全件照合して移行する。停止時は出力して紙へ復元する（未検証）。構造・実装は後続設計へ |

### 4.3. 比較試行の完了条件

- 入力と範囲: ALT-04 と ALT-01 に同じ架空の販売10件、入荷・在庫確認、つけ残高5件を用いる。
- 完了条件: 全件一致・欠落重複0件・両利用者の必須タスク完了で机上評価を更新する。期間・上限内に未達を解消できなければ中止または範囲縮小を判断する。通信断・紙への切り戻しは ACD-D03 の方針が決まるまで実運用しない。
- 正式採用と記録先: [[specdojo:prj-success-criteria-and-acceptance-criteria-sample|成功基準と受入条件]] の初期受入と2週間の試用継続条件を満たすこと。案 ID・条件 ID・対象版・結果を試行記録 `kinuya-trial-log`（未同梱の架空記録）に残す。

## 6. 決定と見直し

D-01 は ALT-04 を優先試行対象とし、ALT-01 の統一帳票を切り戻し候補として一部採択する（理由は「比較結果と採択理由」）。方式の選択と実運用の承認は分け、最終判断は `PO` が行う。

| 見直し契機                                    | 再評価                                                   |
| --------------------------------------------- | -------------------------------------------------------- |
| 試行・受入の不合格、2週間の試用継続条件の未達 | 縮小・延期・停止を判断する                               |
| 移行漏れ、端末・通信障害、保守担当不在の兆候  | 対象案のリスク評価と軽減策を見直す                       |
| 承認上限、範囲、利用者・端末、外部依存の変更  | 該当カテゴリの全案を再比較する。特定製品を自動採用しない |

判断理由・影響範囲・移行と撤退の方法は決定記録に残す。
