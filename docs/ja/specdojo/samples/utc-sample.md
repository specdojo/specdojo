# 単体テストカタログ: 会計確定（駄菓子屋きぬや 販売管理システム）

## 1. 概要（sales-checkout）

会計確定サービス。店番担当が確認した購入内容（商品・数量）と受領額から請求額を計算し、在庫を引き当てて販売を1件確定する。在庫不足や受領額不足のときは確定せず、在庫を変えない。

本書の `utc-<term>` は `utc-sales-checkout` であり、[[specdojo:utc-index-sample|単体テストカタログ: 概要]] の括り方に従う。

## 2. 責務

- 購入内容の単価と数量から請求額を計算する（商品A 30円×2 → 60円）。
- 会計確定時に、販売数だけ在庫を減らす（在庫5個・数量2 → 3個）。
- 販売数が在庫を超える明細があれば在庫不足エラー（種別 `out-of-stock`）を返し、販売を確定せず在庫を変えない。
- 受領額が請求額に満たなければ受領額不足エラー（種別 `insufficient-payment`）を返し、販売を確定しない。
- 確定した販売に採番器の取引番号を付け、確定1件につき印刷要求を1回だけ送る。

## 3. 対象外

- 対象外: 商品・数量の入力検証と、入力不足時の保留判定（理由: 依存境界が異なる別 term の責務、代替: `utc-sale-input`）。
- 対象外: 印刷失敗時に会計を維持すること（理由: `receipt-print` の実際の応答が必要、代替: 外部結合テスト `PATH-05`）。
- 対象外: 確定した販売記録と在庫が業務記録 DB に保存されること（理由: 実接続が必要、代替: 内部結合テスト `PATH-01`）。

## 4. 境界/依存

- 入口: 会計確定の操作（入力は購入明細と受領額）。出口: 確定結果（取引番号・請求額）またはエラー種別。
- 依存の扱いは [[specdojo:utc-index-sample|単体テストカタログ: 概要]] の「単体テスト共通の境界/依存の扱い」に従い（外れる扱いはない）、本 term では次を使う。

| 依存            | 制御方法                                              |
| --------------- | ----------------------------------------------------- |
| 商品リポジトリ  | Fake（`kinuya-test-data` の商品A: 単価30円）          |
| 在庫リポジトリ  | Fake（各ケース開始時に在庫5個へ戻し、前後を比較する） |
| 取引番号の採番  | 固定の連番 `T-0001` を返す採番器を注入する            |
| `receipt-print` | Mock（送信回数と送信内容を検証する）                  |
