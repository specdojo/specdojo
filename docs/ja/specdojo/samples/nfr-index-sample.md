# 駄菓子屋きぬや 販売管理システム 非機能要件インデックス

## 1. 概要（対象範囲・管理方針）

駄菓子屋きぬや 販売管理システムの非機能要件（NFR）を 8 カテゴリの分冊に分け、その入口として各分冊と検証・運用・判断記録への導線をまとめる。対象は初期リリースの店頭販売・在庫・つけ管理で、店頭のタブレット 1 台と記録を保存するホスティング環境を前提とする。複数店舗、EC、本格会計、仕入れ先連携は対象外とする。

要求・合否基準・検証方法の正本は各 `nfr-<category>` 分冊であり、本書は要求本文や目標値を再掲しない。分冊に分けるのは、店番担当の困りごと（会計の待ち、つけ残高の誤り、記録の欠落）から該当カテゴリだけを探せるようにし、1 カテゴリの改定が他カテゴリのレビューを巻き込まないようにするためである。

NFR の根拠は、プロジェクト概要の期待効果（記録の継続、つけ残高の 1 分以内の確認）、販売処理の横断ルール、運用方針・設計（全体構成）とする（Frontmatter の `based_on`）。

## 2. カテゴリ一覧（8カテゴリ）

次の表は、8 カテゴリそれぞれが何を守るかと、分冊で合否を判定する代表指標の対応を示す。

| カテゴリ       | 本システムで守ること                                   | 代表指標                                                     |
| -------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| 信頼性         | 誤った金額・数量の販売記録を作らない                   | 販売記録の誤り件数（月次）、入力検証で止めた誤入力の割合     |
| 可用性         | 営業時間 10:00〜18:00 に販売・つけを記録し続けられる   | 営業時間内の稼働率、RTO、RPO                                 |
| 保守性         | 障害や価格改定に短い時間で対応できる                   | 平均修復時間（MTTR）、変更の依頼から適用までの日数           |
| 完全性         | 販売・在庫・つけの記録が欠けず、二重に作られない       | 日次締めの現金と販売記録の差額、同一取引番号の重複記録件数   |
| 機密性・安全性 | 店番担当以外がつけ残高や価格を見たり変えたりできない   | 権限のない操作の成功件数、剥奪までの日数、監査ログの保管期間 |
| 性能           | 放課後の混雑時も会計で来店客を待たせない               | 会計確定の応答時間（P95）、つけ残高の表示までの時間          |
| 運用           | 店主不在でも店番担当が同じ手順で異常に気付き連絡できる | 異常の一次連絡までの時間、夜間バックアップの成功率           |
| 操作性         | 家族利用者代表が説明なしで会計とつけの記録を終えられる | 説明なしでのタスク完了率、誤操作による取消の件数             |

## 3. 分冊ドキュメント一覧（ID/参照先）

次の表は、カテゴリごとの分冊 ID と参照先を示す。参照先は `docs/ja/product/060-non-functional-requirements/` からの相対パスで、1 分冊 = 1 カテゴリとする。

| カテゴリ       | 分冊 ID               | 参照先                   | 備考                                                                            |
| -------------- | --------------------- | ------------------------ | ------------------------------------------------------------------------------- |
| 信頼性         | `nfr-reliability`     | `nfr-reliability.md`     | -                                                                               |
| 可用性         | `nfr-availability`    | `nfr-availability.md`    | _UNDECIDED_: 稼働率・RTO・RPO の目標値。運用方針と同時に決める                  |
| 保守性         | `nfr-maintainability` | `nfr-maintainability.md` | -                                                                               |
| 完全性         | `nfr-integrity`       | `nfr-integrity.md`       | -                                                                               |
| 機密性・安全性 | `nfr-security-safety` | `nfr-security-safety.md` | 監査ログの保管期間 1 年は運用方針と揃える                                       |
| 性能           | `nfr-performance`     | `nfr-performance.md`     | _UNDECIDED_: 会計確定の応答時間の目標値。決まるまで総合テストは仮置き基準で測る |
| 運用           | `nfr-operations`      | `nfr-operations.md`      | _UNDECIDED_: 営業時間外の緊急連絡手段                                           |
| 操作性         | `nfr-usability`       | `nfr-usability.md`       | -                                                                               |

各分冊は `part_of` に `nfr-index` を持つ。目標値が `_UNDECIDED_` の分冊は、その指標で合否を判定せず、発生の記録だけを残す。

## 4. 変更の入口（追加・統廃合・改定）

分冊を変えるときは本書を最初に更新する。次の表は、変更の種類ごとに更新する文書と、変更を終えたと判定する条件を示す。

| 変更の種類 | 例                                             | 更新する文書                                                            | 完了条件                                                                  |
| ---------- | ---------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 追加       | オフライン時の記録を独立したカテゴリとして扱う | 本書のカテゴリ一覧・分冊一覧・導線、新分冊、検証する `sac-*`・`stc-*`   | 新分冊が `part_of` で本書に属し、導線表の検証列が `（なし）` でない       |
| 削除       | 対象外とした機能だけを扱う分冊が残っている     | 本書のカテゴリ一覧・分冊一覧・導線、削除する分冊を指す `sac-*`・`stc-*` | 削除した分冊 ID を指す文書がない                                          |
| 統合       | 信頼性と完全性で同じ二重記録の要求を持っている | 本書の分冊一覧・導線、統合先の分冊、旧分冊を指す `sac-*`・`stc-*`       | 旧分冊の要求が統合先へ重複なく移り、検証導線が統合先を指す                |
| 分割       | 性能の分冊から店頭の会計と夜間処理を分ける     | 本書の分冊一覧・導線、分割後の各分冊、`sac-*`・`stc-*`                  | 旧分冊の要求が分割後のどれか 1 つだけに移り、検証導線が分割後の分冊を指す |
| 改定       | 会計確定の応答時間の目標値を決める             | 該当分冊、変更した要求を検証する `sac-*`・`stc-*`                       | 分冊と検証の `sac-*`・`stc-*` が同じ基準値を指す                          |

改定で分冊 ID と参照先が変わらない場合、本書のカテゴリ一覧・分冊一覧は更新しない。

## 5. 関連ドキュメント導線（SAC/STC/OPD/OPR/DEC）

次の表は、カテゴリごとに合否を確かめる検証、守るための運用、例外の判断記録をどの文書で辿るかを示す。導線がないものは `（なし）` とする。

| カテゴリ       | 検証（SAC/STC）                                           | 運用（OPD/OPR）                                                              | 判断記録（DEC）         |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------- |
| 信頼性         | `sac-store-sales`、`stc-cash-sale`、`stc-sale-hold`       | （なし）                                                                     | （なし）                |
| 可用性         | `sac-store-sales`、`stc-record-recovery`                  | `opd-index`、`opr-backup-restore`、`opr-incident`                            | `dec-offline-recording` |
| 保守性         | （なし）                                                  | `opd-index`、`opr-change`                                                    | （なし）                |
| 完全性         | `sac-store-sales`、`stc-cash-sale`、`stc-record-recovery` | `opr-index`                                                                  | （なし）                |
| 機密性・安全性 | `sac-store-sales`                                         | `opd-access-control`、`opr-access-control`                                   | （なし）                |
| 性能           | `stc-cash-sale`                                           | `opd-monitoring`                                                             | （なし）                |
| 運用           | （なし）                                                  | `opd-monitoring`、`opd-incident-management`、`opr-monitoring`、`opr-support` | （なし）                |
| 操作性         | `sac-store-sales`                                         | （なし）                                                                     | （なし）                |

保守性と運用の検証は、総合テストで条件を作れないため `（なし）` とし、月次点検の記録で確かめる。`dec-offline-recording` は紙の販売控えへの切替を判断する記録で、オフライン時の記録方法が決まるまで決定待ちとする。
