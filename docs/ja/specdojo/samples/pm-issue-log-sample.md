# 課題ログ サンプル

## 1. 概要

駄菓子屋きぬや 販売管理システム構築で、初期リリースの準備から2週間の店頭試用終了までに顕在化した課題を管理する。記録単位は課題 1 件 1 行（`IS-NNN`）とし、週 2 回（月曜・木曜）の進捗レビューで全行を見直す。記載は 2026-04-07 時点である。

本書は登録簿を使わない単独の課題ログの完成例である。登録簿を使うプロジェクトでは課題を `item_type: issue` の個票に書き、`pm-issue-log.md` は個票から生成する（[[specdojo:pjr-rulebook|プロジェクト登録簿 作成ルール]]）。

| 課題ID | 発生日     | 内容                                                                           | 優先度   | 対応策                                                   | 担当 | 期限       | ステータス    |
| ------ | ---------- | ------------------------------------------------------------------------------ | -------- | -------------------------------------------------------- | ---- | ---------- | ------------- |
| IS-001 | 2026-04-02 | 代表シナリオの受入確認に使う商品・顧客・販売記録のテストデータが足りない       | `high`   | 架空の商品・顧客・販売記録を作るデータ生成手順を用意する | `QE` | 2026-04-08 | `in-progress` |

## 3. 優先度と期限

優先度は、課題が初期受入と店頭試用の判断にどう影響するかで次のとおり割り当てる。

| 優先度   | 割り当てる条件                                                                                                             |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `high`   | 初期受入の必須条件（SC-01・AC-01〜AC-04）の確認作業を止める。または未解決のまま初期リリース候補日を迎える                  |
| `medium` | 必須条件の確認は進められるが、確認結果の一部（印字・表示など）が確定しない。または試用継続の条件（SC-02・SC-03）に影響する |
| `low`    | 上記に当たらず、店頭試用の終了後に対応しても受入と試用の判断を変えない                                                     |

- 期限は、課題が止める確認作業の予定日の前営業日とする。依存先の判断が要る場合は、その判断の期日を対応計画の依存事項に書く。
- 期限の前営業日までに完了条件を満たす見込みがない場合と、期限を超過した場合は、担当 Role がその日のうちに `PM` へ報告する。`PM` は翌営業日までに、受入日程への影響と対応案を `PO` へ判断依頼する。
- 優先度の変更は `PM` が決める。変更によって初期リリース候補日が動く場合は `PO` が決める。

_UNDECIDED_: 初期リリース候補日（[[specdojo:pm-plan-sample|プロジェクト管理計画]] の U-03）が未決のため、`high` の判定に使う候補日は U-03 の決定後に確定する。

## 5. 進捗レビュー

月曜・木曜の進捗レビューで、各課題の期限・依存事項・完了条件の確認結果を見直す。完了は、担当 Role が示した確認結果を `QE` が完了条件の確認の手段と合格の基準に照らして判定する。判定の観点は、完了条件に書いた手段で確認したか、合格の基準を満たしたか、確認に使ったデータと対象版が記録されているか、の 3 点とする。

次の表は、ステータスを変える契機と、変更を記録する Role を示す。

| 変更後のステータス | 変える契機                                           | 記録する Role |
| ------------------ | ---------------------------------------------------- | ------------- |
| `in-progress`      | 担当 Role が対応に着手した、または依存事項が解消した | 担当 Role     |
| `waiting`          | 依存事項が満たされるまで対応を進められなくなった     | 担当 Role     |
| `done`             | `QE` が完了条件を満たしたと判定した                  | `QE`          |
| `deferred`         | `PO` が店頭試用の終了後への延期を決めた              | `PM`          |

対応方針の採否は決定記録へ起票し、本書には決定記録の ID だけを書く。IS-003 で表示倍率 125% を採用した判断は `kinuya-decision-log` の DR-001 である。
