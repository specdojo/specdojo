# 駄菓子屋きぬや 販売管理 GUI デザインシステム

## 1. 目的・適用範囲

店員・店主が、商品登録と金額確認の際に操作の重要度や入力不備を見分けられるよう、店舗の販売管理 GUI に共通する表現を定める。読みやすい金額、一定の操作位置、色に頼らない状態表示を採用し、会計中の読み違いと操作の迷いを減らす。

| 項目           | 適用範囲                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 対象           | 販売登録、商品検索、取引確認・完了に共通する GUI。販売登録の業務仕様は [[specdojo:uis-sample\|販売登録画面の完成例]] を参照                |
| 利用環境       | 店舗内の明るい場所、ライトテーマ、ブラウザの CSS viewport 幅 360px 以上。主端末は幅 1280px のレジ端末                                      |
| 入力・確認環境 | キーボード、マウス、タッチ、キーボード入力型バーコードスキャナ。読み上げ確認は Windows の NVDA と Firefox の組合せで行い、検証時の版を記録 |
| 対象外         | レシート、CLI、画面ごとの項目・操作・遷移・業務バリデーション、API のエラー契約・再送条件                                                  |

## 2. 正本と適用方法

この完成例ではデザインツール、実装トークン、部品カタログをまだ導入していないため、表現の正本は本書とする。外部の正本へ移す際は対象の定義を参照に置き換え、移行先の版とキーを記録する。

| 領域                   | 正本の所在・参照キー                                 | 版                | 更新責任                   |
| ---------------------- | ---------------------------------------------------- | ----------------- | -------------------------- |
| トークン               | 本書「デザイントークン」の名前                       | 本書の Git commit | GUI 設計担当               |
| 部品・状態・レイアウト | 本書の `dss-comp-*` / `dss-state-*` / `dss-layout-*` | 本書の Git commit | GUI 設計担当               |
| アクセシビリティ       | 本書の `dss-a11y-*`                                  | 本書の Git commit | GUI 設計担当・品質保証担当 |

UIS と本書を入力として agent が試作を作り、プロダクトリポジトリの `prototypes/store-gui/` に置く。試作は文書のワイヤーフレームとして保守しない。確認した差分は業務仕様なら UIS、共通表現なら本書へ反映してから実装に適用する。検証記録には入力文書と試作・実装の commit を残す。

## 3. デザイントークン

値は CSS px を基準とし、文字サイズと余白は 16px を 1rem とする相対値へ変換して使う。画面内で独自の色や余白を追加せず、用途が合わない場合は GUI 設計担当がトークンを追加する。

### 3.1. 色

| 名前                     | 値        | 用途・制約                                             |
| ------------------------ | --------- | ------------------------------------------------------ |
| `color-surface`          | `#FFFFFF` | 入力・表・ダイアログの面                               |
| `color-canvas`           | `#F3F4F6` | 画面背景。上に置く通常文字は `color-text`              |
| `color-text`             | `#111827` | 本文、金額、ラベル                                     |
| `color-muted`            | `#4B5563` | 補足文。背景は surface または canvas                   |
| `color-primary`          | `#1D4ED8` | 主操作の面、リンク、フォーカス枠                       |
| `color-on-action`        | `#FFFFFF` | primary または danger の面に載せる文字                 |
| `color-danger`           | `#B91C1C` | エラー文字・枠、破壊的操作の面。エラーには文言も添える |
| `color-success`          | `#166534` | 完了通知の文字。背景は surface                         |
| `color-border`           | `#6B7280` | 入力枠、補助ボタン枠、表の区切り                       |
| `color-disabled-surface` | `#E5E7EB` | 無効な部品の面。文字は muted とし、透明度で薄めない    |

primary・danger の文字リンクと枠は surface 上で用いる。ホバーは下線または内側の枠で示し、未定義の色を作らない。

### 3.2. 文字・寸法

| 名前                              | 値                         | 用途・制約                                                       |
| --------------------------------- | -------------------------- | ---------------------------------------------------------------- |
| `font-body`                       | `system-ui, sans-serif`    | 日本語は OS の代替フォントを使い、特定フォントの字幅に依存しない |
| `text-body`                       | 16px / 行高 1.5 / 太さ 400 | 本文、入力、ボタン                                               |
| `text-caption`                    | 14px / 行高 1.5 / 太さ 400 | 補足文。金額・エラー・操作名には使わない                         |
| `text-heading`                    | 24px / 行高 1.5 / 太さ 700 | 画面見出し                                                       |
| `text-amount`                     | 32px / 行高 1.5 / 太さ 700 | 合計等の主要金額。数字は等幅の字形を使う                         |
| `space-1` / `space-2`             | 4px / 8px                  | ラベルと補足文 / 部品内の間隔                                    |
| `space-3` / `space-4`             | 16px / 24px                | 入力群 / セクション間の間隔                                      |
| `radius-control` / `radius-panel` | 4px / 8px                  | 入力・ボタン / パネル・ダイアログ                                |
| `size-target`                     | 最小 44px × 44px           | ボタン、入力、行内操作の操作領域。拡大時は内容に合わせて伸長     |
| `stroke-control` / `stroke-focus` | 1px / 3px                  | 通常の枠 / フォーカス枠。フォーカス枠は外側に 2px 離す           |

## 4. 部品の使い方

状態表現は「状態の見せ方」、操作と支援技術への配慮は「アクセシビリティ」に従う。

| 規則 ID・部品            | 選択条件・使い方                                                                                               | 禁止・制約                                                                                    |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `dss-comp-01` ボタン     | 主操作は primary の塗り、補助操作は surface と border、破壊的操作は danger の塗り。ラベルは UIS の操作名を使う | 一つの操作群に主操作は一つ。アイコンだけの会計・取消操作、無条件の Enter による会計確定を禁止 |
| `dss-comp-02` 入力       | 常設ラベル、必須の文字表示、単位、説明文を対応付ける。金額は右寄せし「円」を隣接表示                           | プレースホルダーだけのラベル、入力中の値の消去、業務条件の部品側での再定義を禁止              |
| `dss-comp-03` 表         | 見出し付きの表を使い、名称は左寄せ、数量・金額は右寄せ。行内操作には操作名と対象の読み上げ名を付ける           | 行全体のクリックだけに操作を隠さない。長い商品名は折り返し、金額は省略しない                  |
| `dss-comp-04` ダイアログ | UIS が確認や検索を求める場合に使う。見出しと説明を持ち、確定・中止を動詞で区別する                             | 多重表示と「はい」「いいえ」だけのボタンを禁止。破壊的操作は中止側を初期フォーカスにする      |
| `dss-comp-05` 通知       | 入力不備は入力欄の直後、処理全体の失敗は見出し直下の通知領域、完了は同じ通知領域を使う                         | 重要な結果・エラーを自動で消さない。通知のためだけのダイアログを開かない                      |

## 5. レイアウトの型

画面別の部品配置は試作で確認する。共通の情報順序は「見出し・通知 → 主情報と入力 → 集計・確認 → 操作」とし、視覚上の順序と読み上げ・Tab 順序を揃える。

| 規則 ID・型                    | 適用条件                         | 配置と幅変化の決まり                                                                                                                   |
| ------------------------------ | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `dss-layout-01` 入力と集計     | 入力と金額等の確認を並行する場面 | 960px 以上は主領域 2 : 確認領域 1 の二列、間隔は space-4。960px 未満は共通の情報順序による一列。外側余白は space-3                     |
| `dss-layout-02` 一覧と条件入力 | 検索・一覧確認の場面             | 条件入力、件数、表の順。表の文字を縮めず、狭い幅では表の領域だけ横スクロールを許す。領域には名前とキーボードでのスクロール手段を付ける |
| `dss-layout-03` 確認・完了     | 処理結果や確認事項を示す場面     | 内容は一列、最大幅 640px。主要金額に text-amount を使う。操作群は折り返し、DOM の順序を維持する                                        |

拡大時も幅の条件で型を切り替える。本文や操作を固定の高さに閉じ込めず、ダイアログは viewport 内に収めて本文を縦スクロール可能にする。追従する操作バーは使わず、フォーカスや金額の隠れを防ぐ。

## 6. 状態の見せ方

状態の発生条件と回復操作は UIS に従う。以下は利用者へ伝える共通表現を定める。

| 規則 ID・状態             | 視覚表現                                              | 通知・フォーカスと注意                                                                                           |
| ------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `dss-state-01` 通常       | 色・文字・寸法のトークンを使い、ラベルを常設          | フォーカスは操作で移し、自動で奪わない                                                                           |
| `dss-state-02` エラー     | danger の枠と「エラー」の文字、UIS の原因・対処を表示 | 送信時は最初の不正入力へフォーカス。入力と説明を関連付け、入力値を保持。全体の失敗は通知領域で一度だけ読み上げる |
| `dss-state-03` 無効       | disabled-surface と muted、近くに無効理由を表示       | native の無効状態を支援技術へ伝え、理由は Tab で止まらなくても読める位置に置く                                   |
| `dss-state-04` 読み込み中 | 操作ラベルを「処理中」にし、寸法を保持                | 処理領域を busy として通知し、同じ操作の重複入力を止める。フォーカスを失わせない。再送条件は横断ルールに委ねる   |
| `dss-state-05` 空         | 見出し付きの「該当なし」と UIS にある次の操作を表示   | 通信中・失敗を空データとして表示しない                                                                           |
| `dss-state-06` 完了       | success と「完了」の文字、UIS が定める結果を表示      | 状態通知として読み上げる。遷移を伴う場合は遷移先の見出しへフォーカス                                             |

## 7. アクセシビリティ

次の数値はこの GUI で採用する設計条件であり、規格全体への適合宣言ではない。利用結果の目標と評価条件は操作性要件で管理する。

| 規則 ID       | 必須の決まり                                                                                     | 確認条件                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `dss-a11y-01` | 全操作をキーボードで実行でき、フォーカスは primary の stroke-focus と surface の間隔で識別できる | Tab / Shift+Tab / Enter / Space で実行。フォーカス切れ、隠れ、意図しない確定がないこと                   |
| `dss-a11y-02` | ダイアログを開くと内部へ移動し、Tab は内部を循環。Escape は中止として閉じ、閉じたら起点へ戻す    | 起点がなくなった場合は次の操作群の先頭へ移す。背景を操作・読み上げの対象から外す                         |
| `dss-a11y-03` | 通常文字と背景は 4.5 : 1 以上、操作部品の識別枠と隣接面は 3 : 1 以上のコントラストを保つ         | トークンの許可された色の組合せとフォーカスを測定。状態は文字・枠等でも区別                               |
| `dss-a11y-04` | 入力はラベル・説明・エラーとの関連、表は列見出し、通知は役割と名前を持つ                         | 読み上げで操作名・値・エラー・処理結果が分かること。スキャンごとの金額通知は連続させず直近結果にまとめる |
| `dss-a11y-05` | 200% の文字拡大と幅 360px で操作・金額・エラーを欠落させない                                     | 表以外の横スクロール、文字の重なり、操作領域の縮小がないこと                                             |
| `dss-a11y-06` | 必須情報を点滅や動きだけで示さず、動きの抑制設定では読み込み中も静止文字で伝える                 | OS の動きを減らす設定の有無で通知内容と操作可否が変わらないこと                                          |

## 8. 検証・変更管理と関連文書

### 8.1. 検証

本例の `nfr-usability`、`sac-usability`、`stc-store-gui`、`sysd-index`、`sysd-cross-cutting-policy` は、利用先で作る文書の想定 ID であり、同梱の型や完成例を指さない。

| 対象                                              | 対応する要求・仕様                                 | 確認方法                                                                                                             | 担当                       |
| ------------------------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 色・文字トークン、`dss-a11y-03` / `05`            | `nfr-usability` の読み違い防止、視認性             | 許可された組合せのコントラスト測定、長い商品名・最大桁の金額を使った幅と拡大の表示確認                               | GUI 設計担当・品質保証担当 |
| `dss-comp-*`、`dss-layout-*`                      | UIS の項目・操作と情報の優先順位                   | 正常・最小・大量データの部品表示と試作確認。UIS の全操作が型に収まるか突合                                           | GUI 設計担当・店主         |
| `dss-state-*`、`dss-a11y-01` / `02` / `04` / `06` | UIS のエラー回復、`nfr-usability` のキーボード操作 | 入力不備・通信失敗・無効・空・処理中・完了を切り替え、キーボードと読み上げで確認                                     | 品質保証担当               |
| 全体の利用結果                                    | `nfr-usability` の完了率・誤操作率・操作時間       | 店員による商品登録から会計までの利用者評価。目標・条件は要件を参照し、`sac-usability` / `stc-store-gui` へ結果を記録 | 店主・品質保証担当         |

### 8.2. 変更・例外と導線

- GUI 設計担当は変更した規則・トークンと、それを使う部品・画面・検証の対応を確認する。見た目だけの変更では UIS を変更せず、操作の意味や回復操作が変わる場合は UIS も変更する。
- 現在の例外はなし。例外の提案は対象規則、理由、適用画面、影響、期限、承認を担う店主を明記して判断記録へ渡し、採用前に検証する。
- `sysd-index` から本書と実装の正本へ案内する。通信・認可・再送等の共通実装は `sysd-cross-cutting-policy`、画面固有の仕様は [[specdojo:uis-sample|販売登録画面の完成例]] の責務とする。
