# 駄菓子屋きぬや 在庫不足判定

在庫確認の対象商品について、予約分を差し引いた販売可能数が発注点を下回るかを判定する。

## 1. 概要

- 業務価値: 店主代表以外が店番しても、同じ在庫から同じ判定を得て人気商品の欠品に気付けるようにする。
- 利用者・適用場面: 店主代表または家族利用者代表が在庫を確認するとき、商品ごとの在庫数・予約数・発注点がそろった時点で使う。
- 適用範囲: 単一店舗の商品 1 種類について、同じ確認時点の個数を比べる。値は学習用である。
- 対象外: 発注点の決め方、発注量、仕入れ先、発注承認、在庫の更新、販売の可否。

## 2. 入力

次の表は、判定に使う入力と、欠けたときの扱いを示す。

| 入力     | 概念データ・項目 | 利用目的                         | 適用条件・欠損時の扱い                     |
| -------- | ---------------- | -------------------------------- | ------------------------------------------ |
| 対象商品 | 商品識別         | 入力と結果を同じ商品へ対応付ける | 必須                                       |
| 在庫     | 在庫数（個）     | 販売可能数の起点                 | 必須。予約分を含む総数                     |
| 予約     | 予約数（個）     | 予約済みの個数を除く             | 必須。予約なしは 0 を明示する              |
| 商品     | 発注点（個）     | 不足とみなす境界                 | 必須。0 も有効な値で、未設定の代用にしない |

## 3. ルール（判定/計算）

### 3.1. 判定規則

#### 3.1.1. R-01 入力の確認

「例外 / 異常系」に示す順で入力を確認し、不備があれば以後の計算を行わない。

#### 3.1.2. R-02 販売可能数の算出

販売可能数を「在庫数 − 予約数」で算出する。予約数が在庫数を超えても負の値を 0 に丸めず、入力不備とも扱わずに判定へ使う。予約の調整は対象外である。

#### 3.1.3. R-03 不足判定

販売可能数が発注点より小さければ「不足」、等しいか大きければ「不足なし」とする。

### 3.2. 判定例

次の表は、入力の組ごとに適用する規則と期待結果を示す。商品識別は `ITEM-A` とし、期待結果が `E-` で始まる例は判定値を返さない。

| 例  | 入力・前提（在庫数 / 予約数 / 発注点、単位: 個） | 適用規則       | 期待結果                                   |
| --- | ------------------------------------------------ | -------------- | ------------------------------------------ |
| 1   | 12 / 3 / 10                                      | `R-02`、`R-03` | 販売可能数 9、不足                         |
| 2   | 13 / 3 / 10                                      | `R-02`、`R-03` | 販売可能数 10、不足なし（境界一致）        |
| 3   | 0 / 0 / 0                                        | `R-02`、`R-03` | 販売可能数 0、不足なし                     |
| 4   | 2 / 4 / 0                                        | `R-02`、`R-03` | 販売可能数 −2、不足（予約超過）            |
| 5   | 8 / 未設定 / 10                                  | `R-01`         | `E-01`                                     |
| 6   | 8 / 0.5 / 10                                     | `R-01`         | `E-02`                                     |
| 7   | −1 / 0 / 10                                      | `R-01`         | `E-03`                                     |
| 8   | −1 / 未設定 / 10                                 | `R-01`         | `E-01` が先。`E-03` は修正後の再判定で示す |
| 9   | 商品識別が未設定、8 / 0 / 10                     | `R-01`         | `E-01`。結果を商品へ関連付けられない       |

## 4. 出力

次の表は、本ルールが返す項目と利用先を示す。

| 出力       | 意味・単位または区分                    | 利用先                     |
| ---------- | --------------------------------------- | -------------------------- |
| 対象商品   | 入力の商品識別                          | 在庫を確認した人による照合 |
| 販売可能数 | 予約分を除いた個数。負数もあり得る      | 不足理由の確認             |
| 不足判定   | 「不足 / 不足なし」。発注の確定ではない | 店主代表による補充検討     |
| 入力不備   | 例外 ID と該当する項目名                | 入力した担当者による修正   |

入力不備のときは例外 ID と項目名だけを返し、判定不能を「不足なし」と扱わない。

## 5. 例外 / 異常系

次の表は、入力不備の種類ごとの扱いと利用者の次の手を示す。

| ID     | 状況                       | 扱い                             | 利用者の次の手                       |
| ------ | -------------------------- | -------------------------------- | ------------------------------------ |
| `E-01` | 必須項目のいずれかが未設定 | 未設定の項目名を返す             | 入力する。発注点は店主代表へ確認する |
| `E-02` | 個数のいずれかが整数でない | 項目名を返す。換算や丸めはしない | 個数で入力し直す                     |
| `E-03` | 個数のいずれかが負数       | 負数の項目名を返す               | 記録を確かめて直す                   |

いずれの例外でも判定せず、入力した担当者が直して再判定する。不備が複数の種類にわたる場合は `E-01` → `E-02` → `E-03` の順で最初の種類を返し、その種類の項目はすべて示す。呼出元は、入力を取得できない場合に値を推測で補って本ルールを呼び出すことはしない。

## 6. メモ / 将来課題

未決事項はない。本ルールの承認の条件は、判定例 1〜9 の期待結果が `R-01`〜`R-03` と `E-01`〜`E-03` の順序から一意に導けることである。
