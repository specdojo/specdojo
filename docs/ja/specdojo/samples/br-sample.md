# 駄菓子屋きぬや 在庫不足判定

在庫確認の対象商品について、予約分を差し引いた販売可能数が発注点を下回るかを判定する。

## 1. 概要

- 業務価値: 店主代表以外の人が店番するときも、同じ在庫から同じ不足判定を得て、人気商品の欠品に気付けるようにする。
- 利用者・適用場面: 店主代表または家族利用者代表が在庫を確認するとき、商品ごとの現在の在庫数・予約数・発注点がそろった時点で使う。
- 適用範囲: 単一店舗の商品 1 種類に対する、同一の確認時点の個数の比較。在庫数は店舗が保有する総数で、予約分を含む。予約分は店頭で自由に販売できる数量から除く。
- 本完成例では、個数を 0 以上の整数とし、比較時点と商品が一致する入力を前提とする。値は学習用であり、実店舗の設定値ではない。
- 対象外: 発注点の決め方、発注量、仕入れ先、発注承認、在庫の更新、販売の可否。判定結果から自動的に発注を確定しない。

## 2. 入力

| 入力     | 概念データ・項目 | 利用目的                             | 適用条件・欠損時の扱い                                              |
| -------- | ---------------- | ------------------------------------ | ------------------------------------------------------------------- |
| 対象商品 | 商品識別         | 入力と判定結果を同じ商品へ対応付ける | 必須。未設定は `E-01`                                               |
| 在庫     | 在庫数（個）     | 販売可能数の計算の起点               | 必須。同じ確認時点の予約分を含む総数。未設定は `E-01`               |
| 予約     | 予約数（個）     | 販売可能数から予約済みの個数を除く   | 必須。予約なしは 0 を明示する。未設定は `E-01`                      |
| 商品     | 発注点（個）     | 不足とみなす境界                     | 必須。0 も有効な値であり、未設定の代用には使わない。未設定は `E-01` |

## 3. ルール（判定/計算）

### 3.1. 判定規則

#### 3.1.1. R-01 入力の確認

最初に必須項目の有無を確認し、次に個数が整数であること、最後に負数でないことを確認する。不備があれば「例外 / 異常系」に従い、以後の計算を行わない。0 は未設定とは区別する。

#### 3.1.2. R-02 販売可能数の算出

販売可能数を「在庫数 − 予約数」で算出する。

予約数が在庫数を超える場合は、予約を満たす在庫も足りていないため、負の販売可能数をそのまま不足判定に使う。0 に丸めず、入力不備とも扱わない。予約の調整自体は本ルールの対象外である。

#### 3.1.3. R-03 不足判定

- 販売可能数が発注点より小さい場合は「不足」とする。
- 販売可能数が発注点と等しい、または大きい場合は「不足なし」とする。

### 3.2. 判定例

商品識別を `ITEM-A` とし、各行で同じ確認時点の入力を使う。「未設定」は値が与えられていないことを表す。

| 例  | 入力・前提（在庫数 / 予約数 / 発注点、単位: 個） | 適用規則       | 期待結果                                        |
| --- | ------------------------------------------------ | -------------- | ----------------------------------------------- |
| 1   | 12 / 3 / 10                                      | `R-02`、`R-03` | 販売可能数 9、不足                              |
| 2   | 13 / 3 / 10                                      | `R-02`、`R-03` | 販売可能数 10、不足なし（境界一致）             |
| 3   | 14 / 3 / 10                                      | `R-02`、`R-03` | 販売可能数 11、不足なし                         |
| 4   | 0 / 0 / 1                                        | `R-02`、`R-03` | 販売可能数 0、不足                              |
| 5   | 0 / 0 / 0                                        | `R-02`、`R-03` | 販売可能数 0、不足なし                          |
| 6   | 2 / 4 / 0                                        | `R-02`、`R-03` | 販売可能数 −2、不足（予約超過）                 |
| 7   | 8 / 未設定 / 10                                  | `R-01`         | `E-01`。販売可能数・不足判定とも返さない        |
| 8   | 8 / 0.5 / 10                                     | `R-01`         | `E-02`。販売可能数・不足判定とも返さない        |
| 9   | −1 / 0 / 10                                      | `R-01`         | `E-03`。販売可能数・不足判定とも返さない        |
| 10  | −1 / 未設定 / 10                                 | `R-01`         | `E-01` が先。修正後の再判定で `E-03` を確認する |
| 11  | 商品識別が未設定、8 / 0 / 10                     | `R-01`         | `E-01`。商品へ結果を関連付けられない            |

## 4. 出力

| 出力       | 意味・単位または区分                           | 利用先                                         |
| ---------- | ---------------------------------------------- | ---------------------------------------------- |
| 対象商品   | 入力の商品識別。商品識別自体が不備なら返せない | 在庫確認結果を照合する店主代表・家族利用者代表 |
| 販売可能数 | 予約分を除いた個数。負数もあり得る             | 不足理由の確認                                 |
| 不足判定   | 「不足 / 不足なし」。発注の確定を意味しない    | 店主代表による補充検討                         |
| 入力不備   | 例外 ID と該当する項目名。正常時には返さない   | 入力した担当者による修正                       |

正常時は対象商品・販売可能数・不足判定を返す。入力不備のときは例外 ID と不備項目を返し、販売可能数・不足判定を返さない。判定不能を「不足なし」と扱わない。

## 5. 例外 / 異常系

| ID     | 状況                                                             | 扱い                                                         | 利用者の次の手                                                               |
| ------ | ---------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `E-01` | 必須項目のいずれかが未設定                                       | 判定を行わず、未設定の項目名を返す                           | 在庫確認担当が不足項目を確認・入力して再判定する。発注点は店主代表へ確認する |
| `E-02` | 在庫数・予約数・発注点のいずれかが整数でない（文字列や小数など） | 判定を行わず、該当項目を返す。単位の換算や端数の丸めはしない | 在庫確認担当が個数として入力し直して再判定する                               |
| `E-03` | 在庫数・予約数・発注点のいずれかが負数                           | 判定を行わず、負数の項目名を返す                             | 在庫確認担当が記録を確認・修正して再判定する                                 |

複数の種類の不備がある場合は `E-01` → `E-02` → `E-03` の順で最初の種類を返す。同じ種類に該当する項目はすべて示す。修正後は全入力を再確認する。

外部参照の取得処理は本ルールに含めない。呼出元が必要項目を取得できなければ、値を推測して本ルールを呼び出さない。

## 6. メモ / 将来課題

本完成例の判定範囲に未決事項はない。店主代表への業務承認依頼では、予約分の控除、発注点との等号の扱い、予約超過、入力不備時の判定不能を確認する。

季節別の発注点の設定方法は将来の別ルールで扱う。本ルールは与えられた発注点との比較だけを担うため、その設定方法を先取りしない。
