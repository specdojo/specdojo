# 駄菓子屋きぬや 販売管理システム 運用方針・設計（障害対応）

## 1. 概要（incident-management）

本書は、[[specdojo:opd-index-sample|運用方針・設計（全体構成）]] の「障害対応方針（優先度・停止判断・周知）」を具体化する分冊である。店頭のタブレット 1 台で販売・在庫・つけを記録するため、障害が起きると店番担当はその場で、どの業務を紙へ切り替え、どの業務を止め、誰に何を伝えるかを決めなければならない。本書は、優先度の判定条件をきぬやの業務への影響と対応付け、停止・切替の対象と判断者、周知の対象・手段・時機を定める。一次連絡の期限とエスカレーションの連絡先は `opd-index` の SLO とエスカレーション表を正とし、本書では再掲しない。前提とする目的と制約は [[specdojo:prj-overview-sample|プロジェクト概要]] に従う。

次の未決事項は `PO` が決める。決まるまでは、該当する行の扱いで運用する。

| 未決事項                                                        | 判断者 | 決まるまでの扱い                                                                       | 影響する節             |
| --------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------- | ---------------------- |
| _UNDECIDED_: 優先度ごとの復旧の期限                             | `PO`   | 復旧の期限で達成・未達を判定せず、障害記録に発生から復旧までの時間を残す               | 優先度の判定           |
| _UNDECIDED_: オフライン時の記録方法（`opd-index` の未決事項）   | `PO`   | `opd-index` の扱いのとおり紙の販売控えに書き、復旧後に転記する                         | 停止・切替の判断       |
| _UNDECIDED_: 営業時間外の緊急連絡手段（`opd-index` の未決事項） | `PO`   | 営業時間外に気付いた障害は、翌朝の開店前に店主代表と次の店番担当へ連絡帳と口頭で伝える | 周知の対象・手段・時機 |

## 2. 障害対応方針（優先度・停止判断・周知）

### 2.1. 優先度の判定

`opd-index` は優先度ごとの条件を 1 行で定めるだけで、きぬやのどの業務が止まるとどの優先度になるかを定めていない。次の表は、守る業務ごとに、障害の例と回避策の有無から優先度を決める対応を示す（具体化）。

| 守る業務               | 障害の例                                             | システムを使わない回避策                         | 優先度 |
| ---------------------- | ---------------------------------------------------- | ------------------------------------------------ | ------ |
| 店頭販売の記録         | 会計の画面が開かない、販売を保存できない             | 紙の販売控えに書く                               | P1     |
| つけの記録と残高の確認 | つけ残高が表示されない、つけを保存できない           | なし（残高を確かめられないため、つけを受けない） | P1     |
| すべての記録           | 店頭のタブレットが起動しない、店舗の通信回線が切れる | 紙の販売控えに書き、つけは受けない               | P1     |
| 在庫の確認と調整       | 在庫数が表示されない、入荷の数量を保存できない       | 棚を目で確かめ、入荷の数量を連絡帳に控える       | P2     |
| 日次締め               | 閉店後に締めの集計が出ない                           | 翌朝の開店前に締める                             | P2     |
| 表示                   | 文字の崩れ、商品の並び順の誤り（記録の操作はできる） | 回避して記録を続ける                             | P3     |

- 1 つの障害が複数の行に当たる場合は、高い方の優先度とする。
- 回避策が使えなくなった時点で、優先度を 1 つ上げる。例えば、P3 の表示の崩れで商品を選べなくなり販売を記録できなくなったら P1 とする。
- _ASSUMPTION_: 予備のタブレットは置かない。タブレットの故障は、交換できるまで紙の販売控えで営業を続ける P1 として扱う。

### 2.2. 停止・切替の判断

次の表は、`opd-index` の切替方針（営業は止めない、つけ残高を確認できない間はつけの新規記録を受けない）を、優先度ごとの止める・切り替える対象と判断者へ具体化する。

| 優先度 | 止める・切り替える対象                                                             | 止めないもの                       | 判断者   | 判断の時機                                                      |
| ------ | ---------------------------------------------------------------------------------- | ---------------------------------- | -------- | --------------------------------------------------------------- |
| P1     | 販売の記録を紙の販売控えへ切り替える                                               | 営業、現金での販売                 | `PO`     | `opd-index` の切替の期限を過ぎても `OPS` が再開を確かめられない |
| P1     | つけの新規記録を受けない。つけの返済は紙の販売控えに受取額を書き、残高に反映しない | 現金での販売                       | 店番担当 | つけ残高を確かめられないと気付いた時点                          |
| P2     | 在庫の調整の入力を保留し、入荷の数量を連絡帳に控える                               | 販売とつけの記録                   | `OPS`    | 障害の連絡を受けた時点                                          |
| P2     | 日次締めを翌朝の開店前に持ち越す                                                   | 販売とつけの記録、夜間バックアップ | `PO`     | 閉店後に締めの集計が出ないと分かった時点                        |
| P3     | なし                                                                               | すべての業務                       | `OPS`    | 障害の連絡を受けた時点で、回避して続けられることを確かめる      |

紙の販売控えからシステムの記録へ戻すのは、`OPS` が販売とつけを 1 件ずつ記録できることを確かめた後に `PO` が決める。戻した後の転記と照合は `opd-index` の障害対応方針に従う。つけの返済を残高へ反映するのは照合の後とし、二重の反映を防ぐ（補足）。

P1 の復旧で記録の訂正が要る場合は、[[specdojo:opd-access-control-sample|運用方針・設計（権限・アカウント）]] の緊急権限に従う。

### 2.3. 周知の対象・手段・時機

`opd-index` は来店客への口頭の周知だけを定める。次の表は、優先度ごとに、誰に、何を、どの手段で、いつ伝えるかを示す（具体化）。外部の利用者・取引先への周知は、SLA が対象外のため行わない。

| 優先度 | 周知の対象                           | 伝える内容                                                       | 手段                                   | 時機                                           |
| ------ | ------------------------------------ | ---------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------- |
| P1     | 来店客                               | 会計に時間がかかること、つけの新規記録を受けていないこと         | 店頭で口頭、レジ横の掲示               | 紙の販売控えへ切り替えた時点                   |
| P1     | 店主代表（`PO`）                     | 障害の内容、切替の判断の依頼、再開の見込み                       | `opd-index` のエスカレーション表の連絡 | `opd-index` の一次連絡の期限まで               |
| P1     | 次の店番担当（家族利用者代表を含む） | 紙の販売控えの件数、つけの受付を止めた時刻、転記が済んでいない件 | 店内の連絡帳と口頭                     | 店番の交代時と、システムの記録へ戻した時点     |
| P2     | 次の店番担当（家族利用者代表を含む） | 保留した在庫の調整、日次締めの持ち越し                           | 店内の連絡帳                           | 当日の閉店まで                                 |
| P2     | 店主代表（`PO`）                     | 日次締めを持ち越したこと                                         | 店内の連絡帳と口頭                     | 翌朝の開店前                                   |
| P3     | 店番担当（家族利用者代表を含む）     | 回避の方法                                                       | 店内の連絡帳                           | `OPS` が回避の方法を確かめた次の営業日の開店前 |

P2・P3 は会計に影響しないため、来店客へは周知しない。

### 2.4. 障害記録

本節は、`opd-index` の障害記録に、本書の判断を後から確かめるための記録項目を加える（補足）。

- 発生と復旧の時刻、判定した優先度、影響した業務（優先度の判定の表の「守る業務」）を残す。
- P1 では、紙の販売控えへ切り替えた時刻とシステムの記録へ戻した時刻、紙の控えの件数、転記後の照合の結果を残す。
- 月次点検で、回避策が使えなくなり優先度を上げた件を数え、優先度の判定の表を見直すかを `PO` へ報告する。
