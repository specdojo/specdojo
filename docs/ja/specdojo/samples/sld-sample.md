# 保管場所一覧（駄菓子屋きぬやの販売・在庫・記録管理）

## 1. 概要

店主代表と店番担当が、現物・紙台帳・タブレット内のファイルをどこに置き、いつ消してよいかを同じ根拠で判断できるようにする。検品前の入荷品と販売可能な商品の混在や、販売記録の控え・入力途中のセッションファイルの誤削除を防ぐ。

対象範囲は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）: 駄菓子屋きぬや販売管理]] の仕入・販売・在庫・締め領域の物理保管場所と、店舗タブレットのローカル保存領域とする。仕入記録は現行の仕入ノートを含める。在庫記録は今は店主の記憶で保管場所がないため、「確認事項と変更影響」で追跡する。

## 3. 削除・退避・復旧の判断基準

### 3.1. 区分ごとの扱い

- `削除不可` / `処分不可`: 清掃や容量整理で消さず、一覧に書いた移し先へ移す。電子記録は保持期間が決まるまで整理しない。
- `条件付き削除可` / `条件付き処分可`: 「保管場所一覧」の条件をすべて満たした場合だけ消す。満たせなければ残して持ち越す。
- `削除可`: 使用中の作業がなければ消す。

### 3.2. 場面別の対処と復旧手順

| 場面                                                       | 確認と対処                                                                                                                                                                                                                  | 担当・連絡先                                                           |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 会計要求前に再起動し、取引が残っている                     | `sales total` で明細を確かめ、続けるか `sales cancel` で取り消す                                                                                                                                                            | 店番担当。解消しなければ DEV                                           |
| 会計要求後に再起動・応答欠落し、本部の受付結果が分からない | 取消・ファイル削除・再登録をしない。PO が本部受付と `data/sales/` を照合し、受付済みなら同じ取引を回復し、未受付と確かめた場合だけ送信を再開する。照合・回復手順が整うまで、確かめられない取引は保留する                    | OPS が会計を止めて PO・DEV へ連絡。PO が判断                           |
| `data/summary/` を誤って削除した                           | 再生成手順が整うまでは、受付済みの `data/sales/` の現金販売（結果不明を除く）と販売ノートのつけ販売を手で集計し、日次締め記録の参照値と照合する。照合者・照合日・結果は本部の受付結果と別に日次締め記録へ書く               | OPS（店主代表）が再集計、QE が一致を確認。不一致なら PO が締めを再判断 |
| `config/store-config.yaml` が消失・破損した                | 会計を止める。DEV が外部退避媒体の最新世代を復元する。退避がなければ、構造の正本 `kinuya-store-config-schema`（CLIS の未同梱の参照名）がある場合に限り作り直し、なければ PO へ報告する。PO が条件を確かめるまで再開しない   | OPS → DEV（復元）・PO（条件確認）                                      |
| `data/sales/` が消失・破損した                             | 新規会計を止める。DEV が最新世代を復元し、退避後の取引を PO が販売ノート・レシート控え・本部受付と照合し、QE が取引番号の連続と日次締め記録の件数を照合する。退避がなければ推測で作り直さず、照合できない日の締めを保留する | OPS → DEV（復元）・PO（照合と締め）・QE（一致確認）                    |
| 売場で期限切れ・破損品を見つけた                           | 売場で捨てず撤去品保留箱へ移す                                                                                                                                                                                              | 店番担当（移動）→ PO（廃棄確定）                                       |
| タブレットの空き容量が不足した                             | `tmp/` と条件を満たした `receipts/` だけを消す                                                                                                                                                                              | OPS（削除）、DEV・PO（保持期間が決まるまでの容量確保）                 |

## 4. 関連仕様・実装配置との対応と検証

### 4.1. 隣接仕様との分担と対応

| 隣接仕様                                                                     | 定義するものと対応する保管場所                                                                                                                                                                             |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [[specdojo:cdsd-sample\|概念データストア定義（駄菓子屋きぬやの販売と締め）]] | 管理単位と正本区分・更新責務。商品台帳・販売記録・日次締め記録・月次報告は店頭台帳保管棚と母屋書庫、販売記録は `data/sales/`（結果不明の取引は照合待ち）、日次販売集計（保存形式未確定）は `data/summary/` |
| [[specdojo:cdfd-overview-sample\|概念データフロー図（全体概要）]]            | 仕入ノートと顧客・つけ台帳は店頭台帳保管棚と母屋書庫                                                                                                                                                       |
| [[specdojo:stsd-sample\|商品のステータス定義]]                               | 商品の状態と遷移。入荷済み（`received`）・検品済み（`inspected`）は検品場所、販売可能（`sellable`）は売場棚、返品待ち（`return-pending`）は返品保管箱。撤去品保留箱に当たる状態はない                      |

### 4.2. 検証手順と受入条件

| 観点                   | 手順                                                                                                                                                                        | 合格条件                                                                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI 仕様との一致       | タブレット内の各パスと役割を [[specdojo:clis-sample\|駄菓子屋きぬや 販売管理 CLI 仕様]] と照合する                                                                          | CLIS にないパスに `_ASSUMPTION_` が付き、取引セッションと販売記録の控えが別ファイルである                                                          |
| 日次集計の再集計       | CDSD の照合例の現金販売108円を受付済みの `data/sales/` に、つけ販売216円を販売ノートに用意し、結果不明の現金取引1件を加える。`data/summary/` を消して場面別の対処で作り直す | 販売2件・請求合計324円で元の売上IDの集合と一致し、結果不明の取引を含まない                                                                         |
| 記録・状態の網羅       | CDSD の5管理単位、全体概要の仕入記録・在庫記録、STSD の全状態を一覧と照合する                                                                                               | 保管場所のない記録・状態が「確認事項と変更影響」にある。紙の正本が年度で二か所に分かれても欠落せず、受入不可品・撤去品が売場や返品待ちと混ざらない |
| 削除・復旧判断の実効性 | 店番担当が本書だけを見て、空き容量の不足と `data/sales/` の破損を模擬して対処を答える                                                                                       | 容量不足では `tmp/` と条件を満たした `receipts/` だけを消すと答え、破損では新規会計を止めて DEV へ連絡すると答える                                 |

## 5. 確認事項と変更影響

| 論点                                                                       | 影響と当面の扱い                                                                                         |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `_UNDECIDED_`: 外部退避媒体の種類・保管先・保持世代数                      | 決まるまで全世代を保持する                                                                               |
| `_UNDECIDED_`: 販売記録の正本保存先と電子・紙記録の保持期間（CDSD で未決） | 決まるまで `data/sales/` と母屋書庫の記録を処分しない                                                    |
| 日次集計の再生成手順（`specdojo:cop-sales-reconciliation`）が未整備        | 整うまで `data/summary/` を削除できない                                                                  |
| 本部との受付照会・重複排除・回復の契約が未整備                             | 誤った取消・再登録で二重登録や照合根拠の消失が起こる。回復と日次集計の自動再生成に依存する運用は始めない |
| `_UNDECIDED_`: 仕入記録・在庫記録のシステム化後の保管先                    | 在庫記録は今は保管場所がない。決まったら「保管場所一覧」へ行を足す                                       |
| 撤去品保留箱に当たる商品状態が STSD にない                                 | 撤去品保留箱は仮置きで運用する。STSD に状態が足されたら対応を見直す                                      |
| 紙の台帳・締め記録をタブレットへ完全移行する場合                           | 正本区分、`data/` の構成、外部退避の対象、日次集計の再集計元、本部照合に使う記録、検証項目が変わる       |
