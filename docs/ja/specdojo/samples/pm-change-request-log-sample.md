# 変更要求ログ サンプル

## 1. 概要

駄菓子屋きぬや 販売管理システム構築で、初期リリースのスコープ・スケジュール・品質基準に対する変更要求を、準備着手から2週間の店頭試用終了まで管理する。記録単位は変更要求 1 件 1 行（`CR-NNN`）とし、本書は登録簿を使わない単独のログとして、申請・評価・決定・進捗が変わった時点で該当行を更新する。記載は 2026-04-09 時点である。

## 2. 変更要求一覧

次の表は、受け付けた変更要求ごとに、何をどう変えるかと、応える業務課題・期待価値を示す。

| 変更ID | 要求内容                                                                         | 変更理由（業務課題・期待価値）                                                                 | 申請者 | 申請日     | 状態   |
| ------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------ | ---------- | ------ |
| CR-001 | 在庫一覧に商品分類（くじ・ガム・スナック・飲料）の絞り込みを追加する             | 家族利用者代表が店番中に在庫を探すのに時間がかかる。分類から探せれば在庫確認を迷わず終えられる | `UX`   | 2026-04-01 | 実施中 |
| CR-002 | 日次売上一覧の末尾に支払方法別（現金・つけ）の小計行を追加し、既存の列は変えない | 店主代表が閉店後の現金照合のたびに、つけ分を手で差し引いている。照合の手間と計算違いを減らす   | `PO`   | 2026-04-03 | 完了   |
| CR-003 | つけ残高一覧に顧客ごとの支払期限を表示し、期限を過ぎた残高に印を付ける           | つけの支払いが遅れても気づけない。期限超過を一覧で見つけられれば残高確認の漏れを防げる         | `PO`   | 2026-04-06 | 保留   |
| CR-004 | 在庫低下一覧に載った商品について、仕入れ先へ発注メールを自動送信する             | 人気商品の発注忘れで欠品が起きている。発注を自動化して欠品を減らす                             | `DEV`  | 2026-04-07 | 却下   |

## 3. 影響評価

影響度は、次の基準で `小`・`中`・`大` の 3 段階で判定する。

- `小`: 工数 2 人日以下で、納期・品質への影響がない。
- `中`: 準備期間の予備（2 営業日）内の納期影響、または承認済みの受入条件の再確認を伴う。
- `大`: 初期リリース候補日の変更、またはスコープ外の業務・外部連携に及ぶ。

次の表は、変更要求ごとに、スコープ・工数・品質・納期への影響の有無と量、その根拠を示す。

| 変更ID | 観点     | 影響の有無と量                                         | 根拠                                                                        |
| ------ | -------- | ------------------------------------------------------ | --------------------------------------------------------------------------- |
| CR-001 | スコープ | なし（在庫一覧の表示条件の追加）                       | スコープの「在庫管理」に在庫一覧が含まれる                                  |
| CR-001 | 工数     | 1.5 人日                                               | 絞り込み条件 1 つの追加 1 人日、操作メモ 1 項目の更新 0.5 人日              |
| CR-001 | 品質     | あり。AC-02 の再確認が必要                             | 在庫数の表示画面が変わるため、受入済みの確認結果をそのまま使えない          |
| CR-001 | 納期     | なし                                                   | 工数を準備期間の予備の範囲で吸収できる                                      |
| CR-002 | スコープ | なし（簡易レポートの集計行の追加）                     | スコープの「簡易レポート」に日次売上一覧が含まれ、会計処理には踏み込まない  |
| CR-002 | 工数     | 2 人日                                                 | 小計行の追加 1 人日、受入確認用データの準備 0.5 人日、操作メモ更新 0.5 人日 |
| CR-002 | 品質     | あり。既存列の並びと合計値が変わらないことの確認が必要 | 印刷して保管している既存の日次売上一覧と比べられる状態を保つため            |
| CR-002 | 納期     | 準備期間 +1 営業日                                     | 受入確認データの準備が IS-001 のデータ生成完了を待つため                    |
| CR-003 | スコープ | あり。顧客情報に支払期限の項目が増える                 | スコープの「顧客・つけ管理」は最小情報だけを扱う                            |
| CR-003 | 工数     | 3 人日                                                 | 顧客情報への項目追加 1.5 人日、一覧の表示 1 人日、操作メモ更新 0.5 人日     |
| CR-003 | 品質     | あり。SC-03 の追加操作時間が増えるおそれ               | 顧客ごとに支払期限を入力する手順が増える                                    |
| CR-003 | 納期     | 準備期間 +2 営業日                                     | 工数 3 人日のうち予備で吸収できない分                                       |
| CR-004 | スコープ | あり。仕入れ先とのシステム連携に当たる                 | スコープ外の「仕入れ先システム連携」に該当する                              |
| CR-004 | 工数     | 5 人日                                                 | 送信処理 2 人日、仕入れ先ごとの宛先管理 2 人日、送信失敗時の手順 1 人日     |
| CR-004 | 品質     | あり。誤発注を防ぐ受入条件が新たに必要                 | 承認済みの AC-01〜AC-04 は発注を扱わない                                    |
| CR-004 | 納期     | 初期リリース候補日の変更が必要                         | 工数 5 人日が準備期間の予備を超える                                         |

_UNDECIDED_: 参加者別の作業時間上限（[[specdojo:pm-plan-sample|プロジェクト管理計画]] の U-02）が未決のため、上表の工数が上限内かは U-02 の決定後に確かめる。

次の表は、採否の判断材料として、見送ったときの影響と期待効果、総合の影響度を示す。

| 変更ID | 見送ったときの影響                                               | 期待効果                                                    | 影響度 | 評価者 |
| ------ | ---------------------------------------------------------------- | ----------------------------------------------------------- | ------ | ------ |
| CR-001 | 店番中の在庫確認で探す時間が残り、SC-01 の所要時間が延びる       | 家族利用者代表が説明なしで分類から在庫を確認できる（SC-01） | `中`   | `DEV`  |
| CR-002 | 閉店後の手計算が営業日ごとに残り、SC-03 の追加操作時間を圧迫する | 現金照合の手計算をなくし、照合の計算違いを防ぐ（SC-03）     | `中`   | `DEV`  |
| CR-003 | 期限超過は従来どおり店主代表がノートで確認する                   | つけ残高確認の漏れを減らす。効果の大きさは試用前で測れない  | `大`   | `DEV`  |
| CR-004 | 発注は従来どおり在庫低下一覧を見て店主代表が行う                 | 欠品削減（SC-04）に寄与しうるが、運用前の基準値がまだない   | `大`   | `DEV`  |

| 変更ID | 審査結果     | 決定者 | 決定日     | 実施条件・再審査条件                                                                                | 計画のスコープ・優先順位との対応                                                             |

| CR-001 | 承認         | `PO`   | 2026-04-04 | AC-02 を変更後の在庫一覧で再確認する                                                                | M-01 の範囲内。境界の判断基準 1（店番が日々使う業務）に当たり、BV-01 を優先する              |
| CR-002 | 条件付き承認 | `PO`   | 2026-04-05 | 既存列の並びを変えない。変更した操作メモを試用開始の 3 営業日前までに家族利用者代表へ渡す           | M-01 の範囲内で BV-02 に寄与する。納期が延びるため、M-02 に従い `PO` が判断する              |
| CR-003 | 保留         | `PO`   | 2026-04-08 | 店頭試用 1 週目の終了時に再審査する。判断材料として、SC-03 の所要時間と期限超過の件数を追加で集める | M-01 の「最小情報」の境界に掛かり、境界の判断基準 3（店頭手順を増やさない）と衝突しうる      |
| CR-004 | 却下         | `PO`   | 2026-04-08 | 次フェーズの改善候補として、SC-04 の基準値がそろった後に起票し直す                                  | スコープ外の仕入れ先システム連携に当たり、境界の判断基準 4（外部連携は次フェーズ）で除外する |
