# 駄菓子屋きぬや 販売管理システム 機密性・安全性要件

## 1. 概要（対象・目的）

常連顧客の氏名とつけ残高、販売・在庫の記録、価格・商品マスタを、権限のない人の参照・変更と、店外への漏えいから守る。店主代表と家族利用者代表が 1 台のタブレットを交代で使うため、誰がいつつけ残高や価格を変えたかを後から確かめられなければ、記録漏れと不正な訂正を区別できず、つけ管理の記録を信頼して使い続けるというプロジェクトの目的（[[specdojo:prj-overview-sample|プロジェクト概要]]）を満たせない。

## 2. 適用範囲・脅威前提

次の表は、本書が想定する脅威と、要件を適用する範囲・規制・対象外を示す。

| 項目     | 内容                                                                                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 想定脅威 | 店番交代時のログアウト忘れによる別人名義の記録、店番の権限で行うつけ残高・価格の訂正、タブレットの紛失・盗難、本部連携の認証値の漏えい、公開済みの脆弱性の悪用、障害報告や公開資料からの顧客情報の漏えい |
| 対象境界 | 店頭のタブレット 1 台、販売管理システム、記録を保存するホスティング環境、本部連携の認証設定                                                                                                              |
| 適用規制 | 個人情報保護法（常連顧客の氏名とつけ残高を個人データとして扱う）。公開資料の扱いは前提・制約の ACD-C03 に従う                                                                                            |
| 対象外   | 店舗の防犯と現金の盗難、タブレットの OS と端末そのものの管理、カード決済（初期リリースは現金とつけのみ）、複数店舗・EC                                                                                   |

次の表は、アクセス主体ごとに許可する操作と許可しない操作を示す。「機密性・安全性要件一覧」の権限外の操作は、この表の「許可しない操作」を指す。

| 主体                             | 許可する操作                                             | 許可しない操作                                                         |
| -------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------- |
| 店番（店主代表、家族利用者代表） | 販売の記録、在庫の確認、つけの記録と残高の確認、日次締め | 価格・商品マスタの変更、つけ残高の訂正、アカウント管理、顧客情報の出力 |
| 管理（店主代表）                 | 店番の操作、価格・商品マスタの変更、つけ残高の訂正       | 監査ログの削除                                                         |
| 運用（`OPS`）                    | アカウントの作成・停止・区分の変更、監査ログの閲覧       | 販売・つけの記録と訂正、監査ログの削除                                 |
| 保守（`DEV`）                    | 障害の調査に要る記録の閲覧、バックアップの確認           | 記録の変更（緊急権限の間を除く）、監査ログの削除                       |
| 本部連携（外部システム）         | 認証値を使った販売集計の送信                             | 顧客の氏名・つけ残高の受け渡し                                         |

_ASSUMPTION_: 販売管理システムは利用者ごとのログイン、権限区分ごとの操作の制限、無操作時の自動ログアウトを備える。

## 3. 機密性・安全性要件一覧

次の表は、認証・認可・情報保護・監査の要件ごとに、pass / fail を判定する指標と基準を示す。基準が `_UNDECIDED_` の要件は、決まるまでの暫定の判定を `備考` に書く。

| id            | 内容                                                                                         | 指標                                         | 基準                   | 備考                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------- |
| `nfr-sec-001` | 記録の操作は、操作する本人のアカウントでログインした状態でだけ行える                         | ログインなし・共有アカウントで成功した操作数 | 0 件                   | 認証。共有のアカウントは作らない                                                         |
| `nfr-sec-002` | 操作のないまま放置された画面は自動でログアウトする                                           | 最後の操作から自動ログアウトまでの時間       | 10 分以内              | 認証。会計の途中で離れても別の人の名義で記録が残らないようにする                         |
| `nfr-sec-003` | 主体の表の「許可しない操作」は、どの主体でも成功しない                                       | 権限外の操作の成功件数                       | 0 件                   | 認可。母数は主体の表の「許可しない操作」すべて                                           |
| `nfr-sec-004` | 店番をやめた人のアカウントを停止する                                                         | 店番をやめた日から停止までの日数             | 当日中（0 日）が 100%  | 認可。母数は月次点検の対象月に店番をやめた人                                             |
| `nfr-sec-005` | タブレットの紛失やパスワードの漏えいの疑いがあるとき、該当するアカウントを停止する           | 気付いてから停止までの時間                   | 15 分以内              | 認可。営業時間外に気付いた場合も同じ基準とする                                           |
| `nfr-sec-006` | タブレットとホスティング環境の間の通信を暗号化する                                           | 暗号化されずに送られた通信の件数             | 0 件                   | 情報保護。_ASSUMPTION_: TLS 1.2 以上を使う                                               |
| `nfr-sec-007` | 本部連携の認証値を、画面・ログ・販売控え・店舗設定へ出さない                                 | 認証値が現れた出力先の数                     | 0 件                   | 情報保護。横断ルール `scp-SEC-001` と同じ制約                                            |
| `nfr-sec-008` | 顧客の氏名を、障害調査用の診断ログと公開資料に残さない                                       | 診断ログ・公開資料に現れた顧客の氏名の件数   | 0 件                   | 情報保護。前提・制約の ACD-C03                                                           |
| `nfr-sec-009` | ログイン、つけ残高の訂正、価格の変更、アカウントの変更、緊急権限の開始・終了を監査ログに残す | 監査ログに記録がない対象操作の件数           | 0 件                   | 監査。母数は月次点検の対象月の権限変更記録と、つけ残高・価格の変更履歴                   |
| `nfr-sec-010` | 監査ログを 1 年保管し、どの主体からも削除できない                                            | 保管期間・削除できた件数                     | 1 年以上・0 件         | 監査。保管期間は運用方針と揃える                                                         |
| `nfr-sec-011` | 緊急権限は付与から 24 時間、または復旧の確認の早い方で失効する                               | 失効の期限を過ぎて残った緊急権限の件数       | 0 件                   | 認可。延長は運用方針・設計の緊急権限に従う                                               |
| `nfr-sec-012` | 本番のホスティング環境と利用ライブラリの、CVSS 7.0 以上の脆弱性を期限内に修正する            | 公表から修正までの日数                       | _UNDECIDED_: ○○ 日以内 | 情報保護。決まるまでは月次点検で件数と経過日数を記録するだけとし、達成・未達を判定しない |

## 4. 測定・検証方法

次の表は、要件ごとの測定方法、判定時期、判定結果を記録する検証先を示す。

| id            | 測定方法                                                                                                 | 判定時期                     | 検証先                                    |
| ------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------- |
| `nfr-sec-001` | ログインせずに記録の画面を開く操作を試す。運用後は監査ログで、アカウントのない操作が 0 件かを数える      | 受入前、月次点検             | `sac-store-sales`、棚卸し記録             |
| `nfr-sec-002` | 会計の途中で 10 分操作せずに置き、ログアウトしたことと記録が残っていないことを確かめる                   | 受入前                       | `sac-store-sales`                         |
| `nfr-sec-003` | 店番・運用・保守のアカウントで、主体の表の「許可しない操作」をすべて試す                                 | 受入前、権限区分を変えたとき | `sac-store-sales`                         |
| `nfr-sec-004` | 有効なアカウントの一覧を店番の予定表・権限変更記録と照合する                                             | 月次点検                     | 棚卸し記録（`opr-access-control` の手順） |
| `nfr-sec-005` | 停止の依頼の時刻と、監査ログの停止の時刻の差を測る                                                       | 発生ごと                     | 障害記録                                  |
| `nfr-sec-006` | 暗号化しない接続で送ろうとし、接続が拒否されることを確かめる                                             | 受入前                       | `sac-store-sales`                         |
| `nfr-sec-007` | 模擬の認証値を設定して販売と印刷を行い、画面・ログ・控え・設定ファイルに値が現れないことを確かめる       | 受入前、版の更新ごと         | `sac-store-sales`                         |
| `nfr-sec-008` | 架空の顧客の氏名で障害を起こし、診断ログに氏名が現れないことを確かめる。公開資料は公開前に氏名を検索する | 受入前、公開前               | `sac-store-sales`、公開前の点検記録       |
| `nfr-sec-009` | つけ残高の訂正と価格の変更の履歴件数を、監査ログの件数と突き合わせる                                     | 月次点検                     | 棚卸し記録                                |
| `nfr-sec-010` | 最も古い監査ログの日付を確かめ、管理・運用のアカウントで削除を試して拒否されることを確かめる             | 受入前、月次点検             | `sac-store-sales`、棚卸し記録             |
| `nfr-sec-011` | 緊急権限の付与と戻しの時刻を、監査ログで比べる                                                           | 緊急権限の使用ごと           | 権限変更記録                              |
| `nfr-sec-012` | 依存ライブラリとホスティング環境の脆弱性の公表を確かめ、該当する脆弱性ごとに公表日と修正日を記録する     | 月次点検                     | 棚卸し記録                                |

測定結果が基準を満たせば pass、満たさなければ fail とする。fail は運用方針・設計の権限・アカウント運用に従って報告し、原因と対策を課題として登録する。

| 例外ID           | 対象要件      | 理由                                                                                | 代替統制                                                                                                 | 期限                   | 承認者           |
| ---------------- | ------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------- |
| `nfr-sec-ex-001` | `nfr-sec-002` | 初期リリース直後は会計の操作に慣れず、10 分で自動ログアウトすると会計が途中で止まる | 自動ログアウトを 20 分にし、店番の交代時は手でログアウトする。交代時のログアウト忘れを日次締めで確かめる | 初期リリースの 30 日後 | 店主代表（`PO`） |
