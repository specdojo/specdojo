# 業務イベント: 店頭の現金会計の確定

駄菓子屋きぬやで、入力途中の取引や金額の確認を販売実績と混同しないため、一取引の現金会計が確定した事実を定義する。利用できる基準は、「発生条件」の場面から発生有無と回数を決められ、「事実データ」から同じ取引の明細と金額を対応付けられることである。

_ASSUMPTION_: 単一店舗・一台のタブレットでの店頭現金販売を扱う。つけ販売、返品、取消、日次締めは別の出来事とする。

本書は [[specdojo:bes-index-sample|業務イベント一覧]] の `bes-cash-sale-confirmed`（「顧客が商品を購入した」、起点領域 `P-03`）の購入の成立を、現金会計の確定として詳細化する。

## 1. 何が起きたか

一つの取引について、店番担当が購入明細・請求金額・現金の受領を確認し、会計を確定した。

- 一取引の確定につき一回発生する。明細ごとには発生しない。
- 商品の追加、数量の修正、合計金額の表示だけでは発生しない。
- 控えの印字や在庫への反映は、この出来事の後の業務である。

## 2. いつ

販売管理システムが対象取引の会計確定を記録した時点を発生時点とする。顧客が現金を渡した時刻、画面の参照や控えの再印字の時刻、日次締めの確定時刻では置き換えない。

## 3. 誰が／何が

| 起点区分       | 確定を要求する主体 | 確定を記録する主体 | 主体ごとの責務                                           |
| -------------- | ------------------ | ------------------ | -------------------------------------------------------- |
| 店主による店番 | 店主代表           | 販売管理システム   | 明細・請求金額・現金の受領・釣銭を確認して確定を要求する |
| 家族による店番 | 家族利用者代表     | 販売管理システム   | 店主代表と同じ確認を行い、確定を要求する                 |

- 二つの役割を本書では「店番担当」と呼ぶ。誰が店番しても発生境界は同じである。
- 顧客は現金を渡す主体であり、システムへ会計確定を要求する主体ではない。

## 4. 発生条件

次の条件がすべて成立したときに発生する。

1. 店頭の現金取引で、会計がまだ確定していない（取引状態 `payment_status` が `unconfirmed`。仮置き ID `cdsd-order-status`）。
2. 一件以上の商品明細があり、店番担当が購入内容と請求金額を確認している。
3. 受領金額が請求金額以上で、店番担当が受領と釣銭を確認している。
4. 店番担当の確定要求により、会計確定が記録された。

金額計算と端数処理は [[specdojo:br-sample|販売金額計算の業務ルールサンプル]]、確定後の控え・在庫反映と事実の照合・復旧は販売プロセス（仮置き ID `bps-sales-order-flow`）へ委ねる。

| 場面                                     | 発生有無・回数         | 判断根拠                         |
| ---------------------------------------- | ---------------------- | -------------------------------- |
| 複数の商品明細を一つの取引として確定     | 一回                   | 単位は取引の確定である           |
| 受領金額が請求金額未満                   | 発生しない             | 条件 3 を満たさない              |
| 現金の受領後、確定前に入力を見直し中     | 発生しない             | 確定の記録がない                 |
| 確定の記録が成立したか分からないまま停止 | 発生しない             | 受領だけから発生済みと推定しない |
| 確定済み取引の控えを再印字               | 新たには発生しない     | 同じ取引の参照である             |
| 確定後に控えの印字が失敗                 | 確定時の一回のまま     | 印字は確定後の処理である         |
| つけでの購入を受け付ける                 | 本イベントは発生しない | 現金取引の範囲外である           |

_UNDECIDED_: 仮置き ID の文書は未作成で、状態値と項目名を正本と照合できていない。当面は本書の条件と場面の表で判定し、正本が定まったら条件 1 と「事実データ」の項目を見直す。

## 5. 事実データ

型・形式・構造は販売記録のデータモデル（仮置き ID `bdd-sales-record`）へ委ねる。

| 項目         | 業務上の意味                               | 必要になる条件               |
| ------------ | ------------------------------------------ | ---------------------------- |
| 取引番号     | 確定した一つの販売取引を識別する           | 常に必要                     |
| 会計確定時点 | 「いつ」で定義した成立時点                 | 常に必要                     |
| 確定担当     | 確定を要求した実際の店番担当               | 常に必要                     |
| 商品明細     | 商品・数量と、会計確定時点の販売金額の内訳 | 常に必要                     |
| 請求金額     | 顧客に請求した金額                         | 常に必要                     |
| 受領金額     | 店番担当が受領を確認した現金の額           | 常に必要                     |
| 釣銭金額     | 当該会計で確認した釣銭の額                 | 常に必要。釣銭なしも識別する |
| 支払区分     | 現金会計であることを示す情報               | 常に必要                     |

### 5.1. 取引との対応の確認例

取引番号で会計確定と明細・金額を対応付ける。一括・並列の要求は扱わないため、要求を束ねる識別子は持たない。

| 確認対象                           | 確認する事実                                                     |
| ---------------------------------- | ---------------------------------------------------------------- |
| 取引 `TX-A` に二つの商品明細がある | 一回の確定に両明細が含まれ、どちらも `TX-A` の請求金額へたどれる |
| 続けて別の取引 `TX-B` を確定する   | 明細・受領金額・釣銭金額が混ざらず、確定はそれぞれ一回となる     |
| `TX-A` の控えを再印字する          | 同じ取引番号を参照し、新しい会計確定として数えない               |
