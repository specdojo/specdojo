# 移行計画: 概要（駄菓子屋きぬや 販売管理システム）

## 1. 移行の背景/目的

駄菓子屋きぬやでは、販売・在庫・つけの記録をノートと店主の記憶に頼っており、記録漏れとつけ残高の確認の手間が生じている。本計画は、ノートの記録を店頭タブレットの販売管理システムへ移し、店主代表と家族利用者代表が同じ手順で販売・在庫・つけを記録できる状態にするまでの方針と判断点を定める。

移行の成果は、つけ残高と現在庫を取りこぼさずにシステムへ移し、1 週間の並行記録の後にシステムの記録を正本として店舗運営を続けられることである。

## 2. 前提・制約

- 単一店舗・タブレット 1 台で運用する。移行作業もこの端末で行う。
- _ASSUMPTION_: 平日の午前は来店が少ないため、切替日は午前を臨時休業にして取り込みと動作確認を行い、正午に開店して本番で利用する。業務を止めてよいのはこの午前だけとし、閉店時間は変えない。休業は前の週から店頭の貼り紙で知らせる。
- 顧客の氏名・連絡先とつけ残高を書いた転記用の表は、店頭台帳保管棚の鍵付きの引き出しにしまい、店外へ持ち出さない。正本切替の後に裁断して廃棄する。タブレットは画面ロックをかけ、解除の暗証番号は店主代表と家族利用者代表だけが知る。
- 移行元は商品ノート、常連客ノート（顧客欄・つけ欄）、販売ノートの紙媒体である。電子データの移行元はない。
- 対象外の範囲は「移行対象一覧（スコープ/非対象）」に示す。
- _UNDECIDED_: 切替日。店主代表が移行リハーサルの結果を見て決める。

## 3. 移行方式と期間（方式/フェーズ/タイムライン）

並行移行とする。切替日から 1 週間はノートとシステムの両方に販売を記録し、ノートを正本として日次締めで突き合わせる。並行記録の差異が収まった時点で、システムの記録を正本に切り替える。

| フェーズ   | 期間                     | 目的                                                         | 成果物/完了条件                                                                                      |
| ---------- | ------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 準備       | 切替日の 2 週間前から    | 転記用の表に商品・顧客・つけ残高を書き写し、取り込みを試す   | 転記用の表と元ノートの全件照合が済み、移行リハーサルで取り込みと照合が通っている                     |
| 最終棚卸   | 切替日の前日（閉店後）   | 現在庫を数え直し、移行する在庫数を確定する                   | 全商品の現在庫を数えた結果を転記用の表へ記入し、店主代表が確認している                               |
| 移行・検証 | 切替日の午前（臨時休業） | 転記用の表を取り込み、件数と残高を元ノートと照合する         | 商品・顧客の件数と、つけ残高の合計・顧客ごとの残高が元ノートと一致している                           |
| 並行記録   | 切替日の正午から 1 週間  | 販売をノートとシステムの両方に記録し、日次締めで突き合わせる | 各営業日の日次締めで、売上額とつけ残高合計の差異が 0 円であるか、差異の理由が記録されている          |
| 正本切替   | 並行記録の最終日の閉店後 | システムの記録を正本にし、ノートへの記録をやめる             | 店主代表が正本切替を承認し、以後の販売・つけの記録先をシステムだけにしたことを家族利用者代表へ伝えた |

## 4. 移行対象一覧（スコープ/非対象）

| 区分   | 対象                                                 | 補足                                                                                    |
| ------ | ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 業務   | 店頭販売、つけ販売、つけ精算、在庫確認、日次締め     | 並行記録の期間は、ノートとシステムの両方で行う                                          |
| 機能   | 販売画面、在庫画面、つけ画面、日次締め画面           | 切替日の午前の動作確認で、現金販売・つけ販売の記録と取り消しを確かめる                  |
| I/F    | なし                                                 | 仕入先との連携は対象外であり、移行先に外部とのやり取りはない                            |
| データ | 商品台帳（商品名、売価、補充基準、仕入先、発注単位） | 商品ノートから転記用の表へ書き写して取り込む                                            |
| データ | 現在庫                                               | 切替日の前日に数えた最終棚卸の結果を移行する。入出庫の履歴は移さない                    |
| データ | 顧客台帳（常連客の氏名、連絡先、つけ上限）とつけ残高 | 常連客ノートから書き写す。つけ残高は顧客ごとの残高だけを移し、つけ販売の明細は移さない  |
| 非対象 | 過去の販売ノート、仕入ノート、つけ販売の明細         | 紙のまま保管し、問い合わせ時に参照する。詳細の移行手順と照合方法は `dmd-index` で定める |
| 非対象 | 仕入先との連携、売上の会計処理                       | 初期リリースの対象外であり、移行しない                                                  |

## 5. 成功条件・受入基準

| 項目           | 基準                              | 測定対象（対象データ/期間/業務）                                  | 測定/証跡                                                | 判定者   | 失敗時の扱い（ロールバック/延期/代替手順）                               |
| -------------- | --------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------- | -------- | ------------------------------------------------------------------------ |
| 業務停止時間   | 切替日の午前の臨時休業だけ        | 切替日の正午の開店（店頭販売・つけ販売の受付）                    | 移行作業の記録表に書いた、正午に販売を受け付けたかの記録 | 店主代表 | 正午の開店までに終わらなければ延期し、ノートだけで営業する               |
| つけ残高の一致 | 顧客ごとの残高と合計の差異が 0 円 | 常連客ノートの全顧客（移行時点の残高）                            | 取り込み後に出力した残高一覧と元ノートの照合表           | 店主代表 | 差異のある顧客を直して取り込み直す。午前中に直らなければ延期する         |
| 件数の一致     | 商品・顧客の件数差異が 0 件       | 商品台帳・顧客台帳（移行時点の全件）                              | 取り込み結果の件数と転記用の表の行数の照合表             | 開発担当 | 不足分を転記用の表へ追加して取り込み直す                                 |
| 在庫数の一致   | 全商品で最終棚卸の数と一致        | 現在庫（切替日の前日に数えた数）                                  | 取り込み後の在庫一覧と最終棚卸の記入表の照合表           | 店主代表 | 不一致の商品を直して取り込み直す                                         |
| 並行記録の一致 | 売上額とつけ残高合計の差異が 0 円 | 並行記録の 1 週間の各営業日の日次締め（店頭販売・つけ販売・精算） | 日次締め記録の差異欄と、差異の理由のメモ                 | 店主代表 | 理由が分からない差異が残る日があれば並行記録を延ばし、正本切替を延期する |

GO/NO-GO（最低条件）:

- 正午の開店前に、つけ残高・件数・在庫数の照合がすべて一致している。
- 店主代表と家族利用者代表が、移行後の端末で現金販売とつけ販売を 1 件ずつ記録できた。
- 正本切替は、並行記録の最終日の日次締めまで理由の分からない差異が残っていない。

## 6. 体制・役割（GO判断含む）

| 役割              | 担当                 | 責務                                                                           | 連絡/判断                                                                        |
| ----------------- | -------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| GO 判断・正本切替 | 店主代表             | 照合結果を見て本番利用と正本切替を決める。最終棚卸の数を確認する               | 延期と並行記録の延長も店主代表が決める                                           |
| 移行実行          | 開発担当             | 転記用の表の取り込み、件数・残高・在庫数の照合表の作成                         | 照合で差異が出たら店主代表へ伝え、直し方を相談する                               |
| 照合の確認        | 同行レビュー担当     | 照合表と元ノートを第三者の立場で読み合わせる                                   | 読み合わせの結果を照合表に記入する                                               |
| 並行記録の店番    | 家族利用者代表       | 並行記録の期間にノートとシステムの両方へ販売を記録する                         | 記録の食い違いに気付いたら、その場でメモを残し、日次締めで店主代表へ渡す         |
| 技術支援          | 技術メンター         | 取り込みの失敗や端末の不具合を切り分け、直し方を助言する                       | 午前中に直せない不具合は、延期を店主代表へ提案する                               |
| 移行後の運用支援  | 店舗運営アドバイザー | ハイパーケアの期間に、店番の引継ぎで困った点を聞き取り、運用の直し方を助言する | 聞き取った困りごとは週末に店主代表へ伝え、店番の手順を変えるかは店主代表が決める |

## 7. 移行リスクと対策

| リスク                               | 影響                                     | 対策                                                         | 検知/判断                                                                  |
| ------------------------------------ | ---------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| つけ残高の書き写し漏れ・誤記         | 常連客への請求の誤りと信用の低下         | 転記用の表と元ノートを同行レビュー担当が全件読み合わせる     | 残高の照合表で差異がある顧客。店主代表が直し方と延期の要否を決める         |
| 最終棚卸から切替までの販売の数え漏れ | 移行後の在庫数がずれ、補充の判断を誤る   | 最終棚卸は前日の閉店後に行い、切替日の午前は臨時休業にする   | 在庫数の照合表。並行記録の日次締めで在庫差異が続く商品があれば数え直す     |
| 並行記録の二重記録の負担             | 店番中の記録漏れと、差異の理由が残らない | 並行記録は 1 週間に限り、記録漏れはその場でメモを残す        | 日次締めで理由の分からない差異が出たら、店主代表が並行記録の延長を判断する |
| 切替日の午前に作業が終わらない       | 正午の開店で記録先が定まらない           | 移行リハーサルで作業時間を測り、午前中に収まることを確かめる | 開店前に照合が終わっていなければ、店主代表が延期を決める                   |

## 8. カットオーバー概要（当日タイムライン/判定点/ロールバック方針）

| 時刻（相対）           | イベント                   | 完了条件                                        | 判定点 | 失敗時の扱い（ロールバック/延期/代替手順）                                   |
| ---------------------- | -------------------------- | ----------------------------------------------- | ------ | ---------------------------------------------------------------------------- |
| T-1 日（閉店後）       | 最終棚卸                   | 全商品の現在庫を数えた結果を店主代表が確認した  | GO1    | 延期（切替中止）：数え終わらなければ切替日を延ばし、ノートで営業を続ける     |
| T 当日（午前・休業中） | 転記用の表の取り込みと照合 | 件数・つけ残高・在庫数の照合がすべて一致した    | GO2    | 代替手順：差異を直して取り込み直す（午前中に 1 回まで）。直らなければ延期    |
| T 当日（午前・休業中） | 動作確認                   | 現金販売とつけ販売を 1 件ずつ記録し、取り消せた | GO3    | ロールバック：取り込んだデータを使わず、ノートだけで営業する                 |
| T 当日（正午・開店）   | 本番利用と並行記録の開始   | 最初の販売をノートとシステムの両方に記録した    | -      | 代替手順：システムに記録できない販売はノートだけに記録し、日次締めで補記する |
| T+7 日（閉店後）       | 正本切替                   | 並行記録の最終日の日次締めで差異が残っていない  | GO4    | 延期：並行記録を延ばし、ノートを正本のまま続ける                             |

ロールバック方針:

- 各判定点の失敗時の扱いは上の表のとおりとし、延期した場合は店主代表が切替日を決め直す。
- 並行記録の期間中はノートが正本のため、システムを止めても記録は失われない。
- 当日の作業手順の詳細は `cop-index` に置く。

## 9. 移行後ハイパーケア方針

| 項目     | 方針                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 期間     | 正本切替から 2 週間                                                                                   |
| 体制     | 開発担当が閉店後の日次締めに立ち会い、店舗運営アドバイザーが店番の引継ぎで困った点を聞き取る          |
| 対応範囲 | 記録の誤りの訂正、操作の分からない点の説明、端末の不具合の一次切り分け                                |
| 窓口/SLA | 店番中の困りごとは店主代表が受け、その日の閉店後までに開発担当が対応する                              |
| 旧ノート | 正本切替の後も、つけ残高の問い合わせに備えて店頭台帳保管棚に保管する。保管期間は `dmd-index` で定める |

関連ドキュメント:

- `dmd-index`：データ移行設計（転記用の表、取り込み、照合の方法）
- `mtp-index`：移行リハーサル計画（作業時間の測定と照合の合否基準）
- `cop-index`：カットオーバー計画（切替日の作業手順と判定点）
- `otp-index`：運用切替計画（並行記録の運用と正本切替後の問い合わせ窓口）
