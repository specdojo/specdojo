# 成功基準と受入条件: 駄菓子屋きぬや 販売管理システム

## 1. 判定対象と適用範囲

本書は、店頭販売、在庫、つけ管理の最小運用について、初期リリースの受入、運用開始後の短期的な定着、中長期の店舗運営への効果を判定する完成例である。EC、複数店舗管理、本格会計連携は対象外とする。

初期リリースの受入可否は SC-01 と AC-01〜AC-04 のすべてを必須条件として判断する。SC-02〜SC-06 はリリース後に評価し、初期受入の合否には含めない。

本例では、費用低減を業務価値や成功条件に含めない。SC-03 の操作負担は人の追加作業時間として判定し、導入費用や現金支出とは混同しない。

| 業務価値 ID | 業務価値                                                                               | 主な判定段階       |
| ----------- | -------------------------------------------------------------------------------------- | ------------------ |
| BV-01       | 店主代表と家族利用者代表が、迷わず同じ手順で販売・在庫・つけ残高を記録・確認できる     | 初期リリース       |
| BV-02       | 店主代表と家族利用者代表が、日々の記録を負担なく継続できる                             | 運用開始後の短期   |
| BV-03       | 販売・在庫・つけの記録を仕入れ判断と引き継ぎに活用し、店主不在時も店舗運営を継続できる | 運用開始後の中長期 |

| ----- | ---------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------ | ------------------------ |
| SC-01 | BV-01            | 主要操作を迷わず完了できる         | 店主代表と家族利用者代表が、販売記録、在庫確認、つけ残高確認の必須タスクをすべて完了し、重大な行き詰まりがない | 操作説明なしで代表シナリオを実施し、完了、所要時間、質問、支援、誤操作を記録する | 初期リリース受入時 | 店主代表、家族利用者代表 |
| SC-02 | BV-02            | 日々の記録を継続できる             | 初期運用の営業日の90%以上で、販売・在庫・つけの記録が残っている                                                | 営業日ごとに3種の記録有無を確認し、営業日数を母数として集計する                  | 運用開始後2週間    | 店主代表                 |
| SC-03 | BV-02            | 記録・確認の負担を許容範囲に保てる | 1営業日の販売・在庫・つけの記録・確認にかかる追加操作時間が合計10分以内である                                  | 初期運用期間に記録・確認の所要時間を営業日ごとに測定する                         | 運用開始後2週間    | 店主代表                 |

## 3. 受入条件

| ID    | 対応する業務価値 | 種別       | 条件                             | 合格基準                                                                                          | 証跡                                     | 確認者                   | 承認者   |
| ----- | ---------------- | ---------- | -------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------ | -------- |
| AC-01 | BV-01            | 利用者視点 | 販売を記録できる                 | 商品、数量、支払方法を入力して販売を確定すると、販売記録が1件作成される                           | 販売記録、確認日、確認者、操作結果       | 店主代表、家族利用者代表 | 店主代表 |
| AC-02 | BV-01            | 利用者視点 | 在庫とつけ残高を確認できる       | 商品を指定して在庫数を確認でき、常連顧客を指定してつけ残高を確認できる                            | 在庫一覧、つけ残高確認結果               | 店主代表、家族利用者代表 | 店主代表 |
| AC-03 | BV-01            | 利用者視点 | 主要操作で重大な行き詰まりがない | SC-01 の代表シナリオで、利用者が自力で回復できず必須タスクを継続できない事象が0件である           | タスク一覧、所要時間、質問、支援、誤操作 | 店主代表、家族利用者代表 | 店主代表 |
| AC-04 | BV-01〜BV-03     | 技術的受入 | 受入対象と確認結果を追跡できる   | スコープ、成功基準、受入条件、操作メモが矛盾せず、各確認結果に条件 ID、確認日、確認者を記録できる | 文書照合記録、受入確認記録               | 開発担当                 | 店主代表 |

## 4. 判定手順と証跡

1. 店主代表と家族利用者代表が SC-01 と AC-01〜AC-03 の代表シナリオを実施し、条件 ID、確認日、操作結果、必要な支援を記録する。
2. 開発担当が AC-04 の文書整合と証跡を確認する。
3. 未達の条件がある場合は、利用者への影響、是正内容、担当、再確認する条件 ID、再確認日を受入確認記録へ追記する。
4. 店主代表が SC-01 と AC-01〜AC-04 の結果を確認し、初期リリースの受入可否を判断する。
5. 運用開始後は、店主代表が SC-02〜SC-06 を所定の時期に判定し、未達の場合は運用または改善方針を見直す。
