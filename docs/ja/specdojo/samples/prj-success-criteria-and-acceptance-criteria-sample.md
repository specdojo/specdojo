# 成功基準と受入条件: 駄菓子屋きぬや 販売管理システム

## 1. 判定対象と適用範囲

[[specdojo:prj-scope-sample|プロジェクトスコープ]] の対象業務（店頭販売、在庫、つけ管理）を判定対象とし、同書のスコープ外は判定しない。初期リリースの受入は SC-01・SC-07・SC-09 と AC-01〜AC-05 のすべてを必須とする。運用開始後に判定する SC-02〜SC-06・SC-08・SC-10 は、初期受入の合否に含めない。確認者の「両代表」は店主代表と家族利用者代表を指し、承認者の店主代表は Role code の `PO` にあたる。

次の表は、[[specdojo:prj-overview-sample|プロジェクト概要]] の価値仮説と期待効果から定めた業務価値と、その価値を主に確かめる段階を示す。

| 業務価値 ID | 業務価値                                                         | 主な判定段階         |
| ----------- | ---------------------------------------------------------------- | -------------------- |
| BV-01       | 店主と家族が同じ手順で販売・在庫・つけを記録・確認できる         | 初期リリース         |
| BV-02       | 日々の記録を負担なく継続でき、家族も店主の補助なしで記録できる   | 短期                 |
| BV-03       | 記録を仕入れと引き継ぎに使い、店主不在でも運営できる             | 中長期               |
| BV-04       | 常連顧客のつけ残高をその場で確かめ、記録漏れや食い違いを残さない | 初期リリース・中長期 |

## 3. 受入条件

初期リリースで価値提供を始められるかを、確認者が次の条件の合格基準と証跡で確かめる。すべて合格したら、承認者が受け入れを判断する。

| ID    | 対応する業務価値 | 種別       | 条件                             | 合格基準                                                                                                                | 証跡                         | 確認者   | 承認者           |
| ----- | ---------------- | ---------- | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------- | -------- | ---------------- |
| AC-01 | BV-01            | 利用者視点 | 販売を記録できる                 | 商品・数量・支払方法を確定すると販売記録が1件できる                                                                     | 販売記録、操作結果           | 両代表   | 店主代表（`PO`） |
| AC-02 | BV-01、BV-04     | 利用者視点 | 在庫とつけ残高を確認できる       | 商品の在庫数と常連顧客のつけ残高を表示できる                                                                            | 在庫一覧、つけ残高画面       | 両代表   | 店主代表（`PO`） |
| AC-03 | BV-01            | 利用者視点 | 主要操作で重大な行き詰まりがない | SC-01 の代表シナリオで自力で回復できない事象が0件                                                                       | SC-01 の測定記録             | 両代表   | 店主代表（`PO`） |
| AC-04 | BV-01〜BV-04     | 技術的受入 | 確認結果を追跡できる             | スコープ・本書・操作メモが矛盾せず、結果ごとに条件 ID・確認日・確認者が残る                                             | 文書照合記録、受入確認記録   | 開発担当 | 店主代表（`PO`） |
| AC-05 | BV-01、BV-04     | 利用者視点 | 在庫とつけを記録・更新できる     | 入荷・棚卸・廃棄を登録すると在庫数が、つけでの購入と入金を登録するとつけ残高が、登録どおりに増減して AC-02 の画面に出る | 在庫記録、つけ記録、操作結果 | 両代表   | 店主代表（`PO`） |

AC-04 の操作メモは、スコープの運用補助にあたる文書で、両代表が参照する販売・在庫・つけの操作手順と、誤登録の訂正手順を記す。開発担当（`DEV`）が初期リリース受入の前までに作る。

## 4. 判定手順と証跡

証跡は非公開の店舗共有フォルダに置く。受入確認記録はそのフォルダの表で、条件 ID ごとに確認日、確認者、結果、証跡の保存先を1行に記録する。操作結果（所要時間の記録、画面写し）と文書照合記録はファイル名に条件 ID を含めて同じフォルダに置き、受入確認記録の行から参照する。顧客名やつけ残高を含む画面写しは公開文書へ転記せず、公開文書には保存先と確認結果だけを書く。

初期受入と運用開始後の判定は、次の順で行う。

1. SC-04・SC-05 のベースラインとして、店主代表（`PO`）が運用開始の1か月前から、対象商品の欠品、廃棄・値引き・長期滞留の数量と金額、来店数、仕入れ条件、季節要因を手書きで日次に記録する。店主代表（`PO`）は、ベースライン記録の開始前に `例外条件と未解決事項` の対象商品と長期滞留の定義を決める。ベースラインが1か月そろわない場合は、店主代表（`PO`）が SC-04・SC-05 を判定不能として記録し、比較の扱いを決め直す。
2. 初期リリース受入時に、両代表が SC-01・SC-07・SC-09・AC-01〜AC-03・AC-05 の代表シナリオを行い、開発担当（`DEV`）が AC-04 の文書照合を行う。確認者は結果を受入確認記録へ残す。
3. 未達の条件があれば、確認者が受入確認記録に影響、是正内容、是正担当と再確認担当の Role code、再確認する条件 ID と再確認日を追記する。是正担当は記録をもとに作業を引き継ぎ、再確認担当が同じ条件 ID で確かめ直す。
4. 店主代表（`PO`）が必須条件の結果を受入確認記録と照合し、受入可否を判断して記録する。
5. 運用開始後は、各成功基準を判定時期に確認者が判定し、判定記録を同じフォルダに残す。未達なら、確認者が要因（外部要因を含む）、改善案と担当の Role code、再測定時期を判定記録へ書く。店主代表（`PO`）は改善案を承認し、次回の判定へ引き継ぐ。
6. 業務価値、閾値、判定時期、必須条件を変えるときは、変更理由と影響する条件 ID を [[specdojo:pm-change-request-log-sample|変更要求ログ]] に起票し、店主代表（`PO`）の判断を [[specdojo:dec-sample|決定記録]] に残す。変更した条件 ID を引き継ぐ業務受入条件と関連テスト、その条件 ID の取得済みの証跡は、それぞれの担当が再照合する。

## 5. 例外条件と未解決事項

決めきれていない論点ごとに、影響を受ける条件 ID、初期受入を進められるか、決めるまでの扱いを次に示す。

| 論点                       | 判定への影響                                                                                            | 当面の扱い                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 人気商品の対象範囲         | SC-04。初期受入は進められる                                                                             | _UNDECIDED_: 業務分析（`BA`）が販売記録と聞き取りから SC-04 の対象商品と除外条件の候補を整理し、店主代表（`PO`）がベースライン記録の開始前に決める。決まるまで SC-04 の判定を保留する      |
| 長期滞留の定義             | SC-05。初期受入は進められる                                                                             | _UNDECIDED_: 何日売れない在庫を長期滞留とするかを、店主代表（`PO`）がベースライン記録の開始前に決める。決まるまで SC-05 の判定を保留する                                                   |
| 繁忙期にかかるベースライン | SC-04・SC-05。初期受入は進められる                                                                      | _UNDECIDED_: ベースラインの1か月が夏休み期間にかかる場合の比較の扱いを、店主代表（`PO`）がベースライン記録の終了時に季節要因の記録をもとに決める。決まるまで SC-04・SC-05 の判定を保留する |
| オフライン時の記録方法     | 追加する受入条件（ID は起票時に採番）。初期受入は進められ、追加した条件の合格を運用開始の必須条件とする | _UNDECIDED_: 店主代表（`PO`）が運用開始前に運用方針を決め、変更要求ログへ受入条件の追加を起票し、決定記録に残す。追加した受入条件は初期受入後に単独で判定する                              |
