# 帳票仕様（週次販売・欠品報告）

## 1. 概要

週次販売・欠品報告は、駄菓子屋きぬやの 1 週間分の販売記録と在庫記録から、商品別の販売数・欠品の発生・翌週の補充候補をまとめた報告である。店主代表はこの報告で人気商品の欠品の傾向を確かめ、翌週の仕入れ数量を判断する。勘に頼った仕入れを記録に基づく判断へ置き換える最初の手段として、欠品回数の削減の測定にも使う。

## 2. 読み手と利用目的

| 読み手               | 利用目的                                       | 帳票から判断すること                               |
| -------------------- | ---------------------------------------------- | -------------------------------------------------- |
| 店主代表             | 翌週の仕入れ前に、売れ筋と欠品を確かめる       | 仕入れ数量を増やす商品、仕入れを見送る商品         |
| 家族利用者代表       | 店番のときに品切れしやすい商品を知る           | 店番中に在庫を確かめる商品、店主代表へ知らせる事項 |
| 店舗運営アドバイザー | 欠品と記録漏れの傾向から運用の改善点を見つける | 記録の付け方や補充のタイミングの見直しが要る点     |

- 作成は開発担当が設定した定期処理が行い、店主代表が内容を確認する。仕入れ数量の決定は店主代表が行い、報告は候補を示すだけとする。
- つけ残高の確認と会計の締めには使わない。それぞれ `bds-tab-balance-list`・`bds-daily-sales-summary` へ引き渡す。

## 3. 出力の時期と契機

- 契機: 毎週日曜の閉店処理の完了後に、自動で作る。店主代表は必要なときに手動でも作れる。
- 対象期間: 月曜 0 時から日曜の閉店処理完了まで（日本時間）の 1 週間とする。
- 取りこぼし: 端末を起動しなかった週は、次に起動したときに過ぎた週の分を 1 週ずつ作る。
- 再出力: 同じ週を再出力した場合は、その週の報告を作り直し、別の報告を増やさない。

_ASSUMPTION_: 閉店処理は日曜に必ず行う前提とする。日曜が休業日の週は、直前の営業日の閉店処理完了を期間の終点とする。

## 4. 出力形式と提供方法

- 形式: タブレットの画面表示と、印刷用の PDF。
- 単位: 1 週につき 1 件。
- 提供方法: 店主代表がタブレットの報告一覧から開く。印刷した PDF は仕入れノートに綴じる。
- 保存期間: 欠品回数の年間比較のため、1 年分を残す。

## 5. 対象範囲と元にする記録

対象は単一店舗の店頭販売とする。つけ販売は販売数に含め、取り消した販売は含めない。

| 記録       | 用途                         | 正本                     | 欠けるときの扱い                                                   |
| ---------- | ---------------------------- | ------------------------ | ------------------------------------------------------------------ |
| 販売記録   | 商品別の販売数を数える       | `bes-sale-checkout`      | 記録がない営業日は「記録なし」と注記し、販売数 0 と区別する        |
| 欠品の記録 | 欠品の発生日と商品を特定する | `bes-stock-out-recorded` | 欠品の記録がない週は欠品 0 件とし、注記で記録の有無を示す          |
| 商品マスタ | 商品名と商品区分を表示する   | `cdsd-product`           | 商品マスタにない商品は商品コードのまま表示し、店主代表へ確認を促す |
| 前週の報告 | 前週からの販売数の増減を示す | 前週の本報告             | 初回は増減を「前週なし」と表示する                                 |

## 6. 表示項目

| No  | 区分   | 項目名         | 意味・定義                                        | 元にする記録         | 記録からの確かめ方                                                   |
| --- | ------ | -------------- | ------------------------------------------------- | -------------------- | -------------------------------------------------------------------- |
| 1   | 見出し | 対象週         | 対象期間の開始日と終了日（例: 2026-04-13〜04-19） | 販売記録             | 期間内の最初と最後の営業日が範囲に含まれることを照合する             |
| 2   | 見出し | 記録日数       | 期間内で販売記録がある営業日の数                  | 販売記録             | 販売記録がある日付の数と一致することを照合する                       |
| 3   | 明細   | 商品名         | 販売または欠品があった商品の名前                  | 商品マスタ           | 商品コードから商品マスタの名前を引いた結果と一致する                 |
| 4   | 明細   | 販売数         | 期間内に販売した個数（単位: 個）                  | 販売記録             | 期間内の取消を除いた販売明細の数量の合計と一致する                   |
| 5   | 明細   | 前週比         | 販売数の前週との差（単位: 個、増加は `+`）        | 前週の報告           | 今週の販売数から前週の報告の販売数を引いた値と一致する               |
| 6   | 明細   | 欠品回数       | 期間内に欠品を記録した日数                        | 欠品の記録           | 欠品の記録がある日付の数と一致する                                   |
| 7   | 明細   | 補充候補       | 欠品回数が 1 以上の商品に付ける印                 | 欠品の記録           | 欠品回数が 1 以上の商品にだけ印があることを照合する                  |
| 8   | 集計   | 欠品回数の合計 | 全商品の欠品回数の合計                            | 欠品の記録           | 明細の欠品回数の合計と一致する                                       |
| 9   | 注記   | 記録の注意     | 記録なしの営業日、商品マスタにない商品            | 販売記録、商品マスタ | 「対象範囲と元にする記録」の欠けるときの扱いに該当する事項だけが載る |

並び順は販売数の多い順とし、同数の場合は商品名の五十音順とする。

## 7. 集計・算出ルール

- 期間への割り当て: 販売記録の会計確定日時を日本時間で判定し、対象期間に含まれるものを数える。
- 販売数: 販売明細の数量を商品ごとに合計する。取り消した販売の明細は除く。
- 欠品回数: 同じ日に同じ商品の欠品を複数回記録しても 1 回と数える。
- 前週比: 前週の報告に載っていない商品は前週の販売数を 0 として計算する。
- 補充候補: 欠品回数が 1 以上の商品に印を付ける。仕入れ数量は算出しない。

_UNDECIDED_: 欠品回数が 1 回でも補充候補とするか、2 回以上に絞るかは、店主代表が初回の報告を見てから決める。

## 8. 例外と注意事項

| 状況                           | 報告の扱い                                             | 対応する役割と次の手                                                 |
| ------------------------------ | ------------------------------------------------------ | -------------------------------------------------------------------- |
| 期間内に販売記録が 1 件もない  | 報告を作り、明細なし・記録日数 0 と表示する            | 店主代表が休業か記録漏れかを確かめ、記録漏れなら開発担当へ知らせる   |
| 営業日に販売記録がない日がある | 報告を作り、記録の注意にその日付を載せる               | 店主代表がノートの控えと照合し、販売数を 0 とみなさない              |
| 閉店処理の前に手動で出力した   | 出力時点までの記録で作り、見出しに「閉店前」と表示する | 店主代表は閉店処理の後に再出力し、仕入れ判断には再出力した報告を使う |
| 自動での作成が失敗した         | 報告を作らない                                         | 開発担当が原因を確かめ、解消後に同じ週を再出力する                   |

## 9. メモ / 将来課題

| 項目               | 未整備事項と影響                                                                                  | 担当・解消条件                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 根拠の業務イベント | `bes-sale-checkout`・`bes-stock-out-recorded` は未同梱の参照名であり、`based_on` を接続していない | BA が業務イベントを作成した時点で `based_on` に接続する                |
| 補充候補の基準     | 補充候補の欠品回数の基準が未決であり、候補が多すぎる場合がある                                    | 店主代表が初回の報告で基準を決め、同行レビュー担当が判定の例を確かめる |
| 欠品削減の測定     | 月間の欠品回数の集計は本報告に含めていない                                                        | 店主代表が月次報告の要否を判断し、必要なら BA が別の帳票として整理する |
