# 駄菓子屋きぬや 販売管理システム 運用手順（問い合わせ一次対応）

## 1. 概要

駄菓子屋きぬや 販売管理システムの店番担当（店主代表・家族利用者代表）から `OPS` に届く問い合わせを、受け付けてから回答または引き継ぐまでの手順である。本書は [[specdojo:opr-sample|運用手順]]（`opr-index`）の差分・具体化であり、証跡・優先度・承認の規約は `opr-index` に従う。店主代表が不在の日も、家族の店番担当が操作に迷ったときに当日中に答えを得て記録を続けられ、同じ質問を店内の操作メモに蓄えて「営業日の 90% 以上で記録を継続」の KPI を支えることを目的とする。窓口・分類・応答の目標は [[specdojo:opd-index-sample|運用方針・設計（全体構成）]] の問い合わせ運用方針に従い、本書は手順だけを書く。

次の表は、運用方針で未決の値が本書のどの手順に影響し、決まるまでどう扱うかを示す。値が決まった時点で該当する章の完了条件を差し替える。

| 未決事項                                  | 決まるまでの手順上の扱い                                                          | 影響する章                                 |
| ----------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------ |
| _UNDECIDED_: 権限・設定の依頼の応答の目標 | 受け付けた依頼はアカウント付与・剥奪手順または運用変更作業の申請へ移して終える    | 問い合わせ一次対応手順                     |
| _UNDECIDED_: 営業時間外の緊急連絡手段     | 営業時間外に受けた問い合わせは翌営業日の開店前（9:45 から）に受け付けたものとする | 手順適用範囲・前提、問い合わせ一次対応手順 |
| _UNDECIDED_: 問い合わせ記録の保管期間     | 店内の連絡帳を処分せず、すべて残す                                                | 証跡                                       |

## 2. 手順適用範囲・前提

次の表は、本書の手順が対象とする問い合わせの範囲と、手順を行う前提を示す。

| 項目         | 内容                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 対象         | 店番担当から `OPS` への、販売・在庫・つけの記録と日次締めに関する問い合わせ                                      |
| 対象外       | 来店客からの商品・価格の質問（店番担当がその場で答える）、仕入れの発注、システムの対象外の業務（EC・会計など）   |
| 問い合わせ者 | 店番担当（店主代表または家族利用者代表）                                                                         |
| 一次対応者   | `OPS`。引き継ぎ先は操作と不具合が `DEV`、締め済みの金額と要望の採否が `PO`                                       |
| 時間帯       | 営業時間 10:00〜18:00 に受け付ける。時間外の扱いは概要の未決事項の表に従う                                       |
| 必要権限     | `OPS` は閲覧の権限で日次締め記録と画面を確かめる。記録の訂正は店番担当が記録の権限で行う                         |
| 使用手段     | 店内の電話、店内の連絡帳（問い合わせ記録）、店内の操作メモ（ナレッジ）、プロジェクトの課題管理（要望・引き継ぎ） |

手順を新しく書いたときや改訂したときは、`OPS` が次の 4 件を検証用の環境で模擬し、各件が問い合わせ一次対応手順の完了条件を満たすことを確かめる。結果は `opr-index` の月次点検の記録に残す。

- 操作メモにある操作の質問（つけの当日分の取り消し）に、操作メモの記載どおりに答えられる。
- 操作メモにない操作の質問が `DEV` への引き継ぎになり、課題管理に登録される。
- 締め済みの金額が変わる訂正の依頼が `PO` への引き継ぎになる。
- 「つけを記録できない」という問い合わせが P1 と判定され、障害対応手順の連絡へ移る。

## 3. 日次・週次・月次点検手順

`opr-index` 参照。問い合わせに固有の定期点検は置かず、操作メモへの追記の要否は問い合わせ一次対応手順の月次の見直しで扱う。

## 4. 障害対応手順

`opr-index` 参照。障害にあたる問い合わせを受けた後は、`opr-index` の障害対応手順の優先度・初動目標・連絡先で扱う。判定の条件は問い合わせ一次対応手順の分類の表に示す。

## 5. アラート対応手順

本書の範囲外。問い合わせは自動の通知を経由しないため、`opr-index` のアラート対応手順に従う。

## 6. バックアップ確認・リストア手順

本書の範囲外。データの復元を求める問い合わせは障害にあたるものとして扱い、復元の判断は `opr-index` に従う。

## 7. バッチ再実行・失敗時対応

本書の範囲外。夜間バックアップの失敗は監視で検知し、問い合わせとしては受けない。

## 8. 運用変更作業

`opr-index` 参照。設定の変更の依頼は、問い合わせ一次対応手順で受け付けた後、`opr-index` の運用変更作業の承認と適用の手順へ移す。

## 9. アカウント付与・剥奪手順

`opr-index` 参照。権限の依頼は、問い合わせ一次対応手順で受け付けた後、`opr-index` のアカウント付与・剥奪手順の申請へ移す。

## 10. 問い合わせ一次対応手順

### 10.1. 分類と応答の目標

`OPS` は受け付けた問い合わせを次の条件で 1 つの分類に決め、応答の目標までに回答または引き継ぎを終える。複数に当たる場合は表の上の行を優先する。

| 分類             | 判定の条件                                                                                                               | 例                                 | 応答の目標                                                    | 引き継ぎ先と条件                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| 障害にあたるもの | 販売・つけのどちらかを記録できない（P1）、在庫の確認や日次締めができない（P2）、回避して記録を続けられる表示の崩れ（P3） | 「つけの画面が開かない」           | P1 は 15 分以内、P2 は当日の閉店まで、P3 は次の月次点検に連絡 | 運用（`OPS`）の障害対応手順へ。P1 で `OPS` が応答しなければ `PO` |
| 記録の訂正の依頼 | 記録はできたが内容が誤っている                                                                                           | 「前日の販売の数量を間違えた」     | 翌営業日の開店まで                                            | 締め済みの金額が変わる訂正は業務（`PO`）へ                       |
| 権限・設定の依頼 | アカウントの追加・停止、商品マスタ・価格の変更を求める                                                                   | 「土曜だけ店番する人を追加したい」 | _UNDECIDED_（概要参照）                                       | アカウント付与・剥奪手順、運用変更作業の申請へ                   |
| 操作の質問       | 記録できるが操作の方法が分からない                                                                                       | 「つけの記録の消し方が分からない」 | 当日の閉店まで                                                | 操作メモにない操作、画面が説明と違う動きは開発（`DEV`）へ        |
| 機能の要望       | 今の機能にない操作や表示を求める                                                                                         | 「欠品の多い商品を一覧で見たい」   | 次の月次点検で採否を決める                                    | 業務（`PO`）が採否を決める                                       |

### 10.2. 一次対応の流れ

`OPS` は受け付けた問い合わせごとに次の順で進め、各段の内容を問い合わせ記録に書く。

1. 受付: 受付日時、問い合わせた役割（店主代表・家族利用者代表）、問い合わせの文言を書く。
2. 再現条件: 操作した画面、操作の順、表示された内容を店番担当に聞き、`OPS` の閲覧の権限で同じ画面を確かめる。
3. 影響: 記録を続けられるか、つけ残高・締め済みの金額に関わるかを聞き、分類と応答の目標の表で分類を決める。
4. 暫定回避: 障害にあたるものは障害対応手順の一次対応を伝える。操作の質問は操作メモの該当する行を読み上げる。
5. 引き継ぎ要否: 分類と応答の目標の表の引き継ぎ条件に当たれば、課題管理に登録して `ticket_id` を問い合わせ記録に書く。当たらなければ回答した内容を書いて終える。

回答の文例は次のとおりとする。

```text
受付: 11/24 15:10 家族利用者代表 「つけを間違えて記録した。消し方が分からない」
分類: 操作の質問（記録は続けられる。当日分のみ）
回答: 顧客の画面の「取り消し」から当日分だけ消せます（操作メモ「つけの取り消し」）
引き継ぎ: なし
```

### 10.3. 完了条件と月次の見直し

問い合わせは、次のどちらかを満たしたら完了とする。

- 回答した: 店番担当が回答どおりに操作して記録を続けられたことを電話または連絡帳で確かめ、分類・回答・引き継ぎなしを問い合わせ記録に書いた。
- 引き継いだ: 引き継ぎ先が課題管理の登録を受け取り、`ticket_id` を問い合わせ記録に書いた。引き継ぎ先の対応の完了は課題管理で追う。

`OPS` は `opr-index` の月次点検で問い合わせ記録を分類ごとに数え、同じ操作の質問が月 2 回を超えたものを店内の操作メモに追記する。応答の目標を過ぎた件数は月次点検の記録に書き、`PO` へ報告する。

## 11. 証跡

次の表は、本書の手順の証跡をどこに残し、どの識別子で照合するかを示す。保存先と参照権限は `opr-index` の証跡の表と同じとする。

| 証跡種別       | 保存先                 | 保管期間                 | 参照権限           | 最低限残す識別子                         |
| -------------- | ---------------------- | ------------------------ | ------------------ | ---------------------------------------- |
| 問い合わせ記録 | 店内の連絡帳           | _UNDECIDED_（概要参照）  | 店番担当、`OPS`    | 受付日時、分類、引き継ぎ時は `ticket_id` |
| 引き継ぎの記録 | プロジェクトの課題管理 | _UNDECIDED_              | `OPS`、`DEV`、`PO` | `ticket_id`、分類、引き継ぎ先            |
| 操作メモ       | 店内の操作メモ（紙）   | 最新版を残す             | 店番担当、`OPS`    | 項目名、追記した日                       |
| 月次の見直し   | 月次点検の記録         | `opr-index` の証跡に従う | `OPS`、`PO`        | `ticket_id`、対象月                      |

手順の模擬の結果は、月次の見直しと同じ月次点検の記録に確認日・確認した環境・合否を残す。
