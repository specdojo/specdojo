# 駄菓子屋きぬや システム化機能一覧（全体構成）

本書は、駄菓子屋きぬや販売管理システムが店頭のタブレットで実現する機能の全体構成と一覧を定義する。各機能を業務プロセス領域と画面へ対応付け、機能分割・テスト対象の洗い出しと、個別機能仕様への入口として使う。

## 1. 目的と対象範囲

販売・在庫・つけ・締めの業務ごとにシステムが担う記録と確認の範囲を確定し、店主代表がスコープを承認でき、業務からの漏れと機能の重なりを一覧で判断できるようにする。これは [[specdojo:prj-overview-sample|プロジェクト概要]] の「まず記録する」方針と、店番が交代しても同じ手順で記録を続ける目標に対応する。

| 区分   | 範囲                                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象   | 単一店舗の店頭タブレットで行う販売・つけ・在庫・締めの記録と確認。業務プロセス領域 `P-02`〜`P-10` のうち、システムが記録・算出・提示する部分 |
| 対象外 | 仕入先への発注（`P-01`）、補充・つけ上限・売価の最終判断、キャッシュレス決済、本格会計、EC、複数店舗、個別機能の入出力・振る舞いの詳細       |

- 読者: 機能分割と画面・データ設計を行う ARC、実装範囲を確認する DEV、テスト対象を洗い出す QE、業務との対応を確認する BA。
- 承認: 人間の PO（店主代表）がシステム化のスコープを承認する。

## 2. 機能構成

業務プロセス領域の区分は [[specdojo:cdfd-overview-sample|概念データフロー図（全体概要）]] に従う。入荷の記録（`P-02`）は在庫数量を更新する処理のため、仕入ではなく在庫の領域に含める。

| 機能領域 | 略号  | 業務プロセス領域       | システムの責務                                                       | 人間に残す判断                       |
| -------- | ----- | ---------------------- | -------------------------------------------------------------------- | ------------------------------------ |
| 販売     | `POS` | `P-03`                 | 現金販売の明細・請求額・釣銭を提示し、販売を記録して在庫へ渡す       | 取引の中止                           |
| つけ     | `CRD` | `P-04`・`P-07`・`P-08` | 常連客とつけ上限を登録し、つけ販売と精算を記録して残高を提示する     | つけ上限の設定、上限超過時の販売可否 |
| 在庫     | `INV` | `P-02`・`P-05`・`P-06` | 入荷と販売を在庫へ反映し、補充基準を下回った商品と依頼数量を提示する | 補充依頼の承認                       |
| 締め     | `CLS` | `P-09`・`P-10`         | 当日の販売・入荷・在庫・つけを突き合わせ、差異と月次の集計を提示する | 締めの確定、売価・補充基準の見直し   |

仕入計画（`P-01`）はシステム化しない。仕入先とのシステム連携を初期リリースの対象外としたため、店主代表が補充依頼を基に発注する。

## 3. システム化機能一覧

| 機能 ID     | 機能名       | 概要                                                                                   | 業務プロセス仕様                      | 画面                                  | 個別仕様                                 |
| ----------- | ------------ | -------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------------- | ---------------------------------------- |
| `SF-POS-01` | 店頭商品販売 | 商品と数量から請求額・釣銭を提示し、現金の受領確認を受けて販売を記録する               | `bps-sales-order-flow`                | [[specdojo:uis-sample\|販売登録画面]] | [[specdojo:sf-sample\|商品販売機能仕様]] |
| `SF-CRD-01` | つけ販売     | つけ上限と残高を確認して、つけでの販売を記録し、更新後の残高を提示する                 | `bps-credit-sale`                     | `uis-credit-sale`                     | 一覧行で要約                             |
| `SF-CRD-02` | 常連客登録   | 常連客の識別情報とつけ上限を登録・変更し、つけ販売の可否判定に使えるようにする         | `bps-customer-registration`           | `uis-customer`                        | 一覧行で要約                             |
| `SF-CRD-03` | つけ精算     | 支払額を受け付けてつけ残高を減らし、精算後の残高を提示する                             | `bps-credit-settlement`               | `uis-credit-sale`                     | 一覧行で要約                             |
| `SF-INV-01` | 在庫確認     | 販売と入荷を在庫数量へ反映し、商品ごとの現在庫を提示する                               | `bps-inventory-check`                 | `uis-inventory`                       | `sf-inventory`                           |
| `SF-INV-02` | 入荷記録     | 検品済みの商品と数量を入荷として記録し、在庫確認へ渡す                                 | `bps-receiving`                       | `uis-inventory`                       | 一覧行で要約                             |
| `SF-INV-03` | 補充依頼支援 | 補充基準を下回った商品と、発注単位に合わせた依頼数量を提示し、承認された依頼を記録する | [[specdojo:bps-sample\|補充依頼確定]] | `uis-inventory`                       | 一覧行で要約                             |
| `SF-CLS-01` | 日次締め照合 | 当日の販売・入荷・在庫・つけの記録を突き合わせ、差異を提示して締めの確定を記録する     | `bps-daily-closing`                   | `uis-closing`                         | 一覧行で要約                             |
| `SF-CLS-02` | 月次集計報告 | 月次の売上・欠品回数・つけ残高を集計し、見直しの判断材料として提示する                 | `bps-monthly-review`                  | `uis-closing`                         | 一覧行で要約                             |

- `uis-credit-sale` はつけ販売とつけ精算（`SF-CRD-01`・`SF-CRD-03`）にまたがる。`uis-inventory` は在庫の 3 機能にまたがる。
- `SF-POS-01` は販売の払出数量を `SF-INV-01` へ渡す。在庫数量の算出と在庫の未反映時の扱いは `SF-INV-01` が担う。
- 個別仕様は店頭商品販売と在庫確認を先に作成する。その他の機能は一覧行の要約を正とし、詳細化が必要になった時点で成果物カタログへ追加する。
