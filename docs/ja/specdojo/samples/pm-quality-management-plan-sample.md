# 品質管理計画: 駄菓子屋きぬや 販売管理システム

## 1. 品質方針と適用範囲

店主代表と家族利用者代表が販売・在庫・つけの記録を同じ手順で続けられ、追加負担を許容できることを価値品質とする。文書・実装・公開物の整合、再現性、安全性は、その価値を支える成果物品質として確認する。

本計画は、初期リリースの準備着手から、2週間の店頭試用終了時の継続判断と後続観測への引き継ぎ完了まで適用する。対象は単一店舗・タブレット1台の販売・在庫・つけ管理で、範囲と具体日は [[specdojo:pm-plan-sample|管理計画]] に従う。中長期の効果測定は後続計画で扱う。

判定条件は [[specdojo:prj-success-criteria-and-acceptance-criteria-sample|成功基準と受入条件]]（以下「成功条件」）の条件 ID で参照し、閾値・算出方法を本書で再定義しない。現金支出、準備・開発の作業時間、保守・引き継ぎ負荷は、管理計画の M-03・M-04・M-06 で別々に確認する。これらは、日常操作の負担を測る SC-03 に含めない。

## 2. 品質ゲート

`kinuya-` で始まる参照名と `execution/` 配下のパスは、未同梱の架空記録である。次の表は、ゲートごとに確かめる品質観点と、通過に要る合格条件・証跡・時期・判断者を示す。

| ゲート     | 品質観点                                       | 合格条件                                                                                                     | 方法・証跡                                                                                 | 時期                                   | 確認者 / 承認者                |
| ---------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------- | ------------------------------ |
| 技術・公開 | 対象版を再現し、安全に店頭利用・公開できる     | AC-04 と `kinuya-verification-plan` の適用条件が合格し、「公開する画面・文書・記録」の出口条件を満たす       | `DEV` の検証結果と公開対象の差分を照合する。証跡は `execution/reviews/release-1/result.md` | 主要変更後、初期受入前、公開対象変更時 | `DEV`、`QE` / 人間の `PO`      |
| 初期受入   | 店主代表と家族利用者代表が主要業務を完了できる | SC-01・SC-07・SC-09・AC-01〜AC-05 がすべて合格し、技術・公開ゲートと管理計画の初期リリース前提が成立している | 利用者のシナリオ実施結果を条件別に照合する。証跡は `kinuya-acceptance-record`              | 初期リリース・店頭試用開始前、是正後   | `BA`、`QE` / 人間の `PO`       |
| 短期利用   | 日々の記録を負担なく継続できる                 | SC-02・SC-03・SC-08 が合格し、M-06 の保守・引き継ぎ担当と負荷を確認できる                                    | 営業日別の記録・追加操作時間を母数・欠測とともに照合する。証跡は `kinuya-trial-log`        | 運用開始後2週間の試用終了時            | `BA`、`QE`、`PM` / 人間の `PO` |

各条件は合格・未達・保留を区別する。未達と、証跡不足・未決条件による保留は、いずれもゲートを通過させない。SC-04〜SC-06・SC-10 は初期受入の合否に含めず、観測時期の前に合格扱いにしない。

## 3. レビューと証跡

次の表は、レビュー対象ごとの観点と実施責任、レビューを終える出口条件と証跡の記録先を示す。

| 対象                             | 主な観点                                         | 実施責任                              | 出口条件                                                                                                          | 証跡                                                 | 記録先                                         |
| -------------------------------- | ------------------------------------------------ | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| 初期受入の操作と試用中の利用記録 | 操作の理解、業務との一致、追加負担               | `BA`（利用者代表が参加）、照合は `QE` | 対象段階の必須条件（初期受入は SC-01・SC-07・SC-09・AC-01〜AC-03・AC-05、試用終了時は SC-02・SC-03・SC-08）が合格 | 条件別の操作結果、質問・誤操作、営業日別の記録・時間 | `kinuya-acceptance-record`、`kinuya-trial-log` |
| 対象版の文書・実装・生成レポート | 目的・範囲・条件・操作メモとの整合、検証の再現性 | `QE`（`DEV` が検証結果を提示）        | AC-04 と検証計画の適用条件が合格し、参照矛盾と未解決の重大指摘がない                                              | 文書照合、差分、条件別検証結果、是正・再判定結果     | `execution/reviews/release-1/result.md`        |
| 公開する画面・文書・記録         | 個人情報・秘密情報、権利、公開範囲               | `QE`（`PM` が公開対象を提示）         | 全差分を確認済みで、個人情報・秘密情報の混入、権利未確認、未解消の重大指摘がない                                  | 公開対象一覧、確認結果、除外・匿名化・許諾の記録     | `execution/reviews/release-1/result.md`        |

証跡には対象版、実施日、条件 ID、結果、未達条件・指摘、是正内容、再判定結果を残す。公開用の証跡には実在顧客の氏名・つけ残高を載せず、業務確認用の原記録と公開用の匿名化記録を分ける。

## 4. 不適合と是正

重大な不適合は下表の「利用価値」「技術」「公開・安全」とする。軽微は、必須条件・検証結果・公開安全性に影響しない誤字・補足不足に限る。条件に影響する説明不足は、該当する重大区分へ分類する。重大な不適合は、是正と再判定が済むまで該当ゲートを通過させず、影響する作業・利用・公開を止める。次の表は、区分ごとの対応と、ゲートを再び通すための再判定条件・責任・記録先を示す。

| 区分                                               | 対応                                                             | 再判定条件                                                                       | 再判定責任                                | 記録先                                                                        |
| -------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------- |
| 軽微（誤字、補足不足）                             | 該当文書の担当が正本を修正する                                   | 修正版で指摘箇所と関連参照に同じ不整合が残っていない                             | `QE`                                      | `execution/reviews/release-1/result.md` の指摘 ID                             |
| 利用価値（操作不能、負担超過）                     | 原因を調べ、操作・手順を簡素化する。範囲・条件変更は先に変更要求 | 未達の SC・AC を同じ測定方法で再確認し、該当ゲートを満たす。観測期間を省略しない | `QE` が照合、人間の `PO` が価値・継続判断 | [[specdojo:pm-issue-log-sample\|課題ログ]] の課題 ID から受入・試用記録へ接続 |
| 技術（検証失敗、データ不整合）                     | 生成元・実装の正本を修正し、生成レポートは再生成する             | 再生成後、未達の AC-04 または検証条件と影響範囲の検証が成功する                  | `QE`                                      | 課題ログの課題 ID、`execution/reviews/release-1/result.md` の再検証結果       |
| 公開・安全（個人情報・秘密情報の混入、権利未確認） | 該当公開を止め、除外・匿名化・許諾確認を行う                     | 是正済みの公開候補版で「公開する画面・文書・記録」の全対象が出口条件を満たす     | `QE` が再確認、人間の `PO` が公開判断     | 課題ログの課題 ID、`execution/reviews/release-1/result.md`                    |

本例は管理計画に合わせ、必須条件を免除する期限付き例外を設けない。基準を変える場合は変更要求を先に判断し、旧条件の未達結果を残して新条件で再判定する。

## 5. 見直し条件と未決事項

### 5.1. 見直しと後続作業

成功条件、対象業務、利用者、端末・検証方法、公開範囲、体制、重大不適合の傾向が変わったら見直す。見直しでは、影響する条件 ID・証跡・再確認範囲を特定する。そのうえで、管理計画、RACI、`kinuya-schedule`、証跡参照を、影響する作業の開始前に追従させる。新条件は改訂の確定前に合格扱いにしない。

試用終了時は、成功条件 SC-04〜SC-06・SC-10 の測定方法・判定時期と採取済みの基準値を後続観測へ引き継ぐ。継続方針と引き継ぎ先の判断を `kinuya-trial-log` に残した時点で、本計画の適用を終える。SC-04・SC-05 の基準値の準備は管理計画の「運用前の準備」に従う。

### 5.2. 未決事項と保留

未決の論点ごとに、判断材料の担当、決定時期と判断者、未決中に保留する判定と決定後に直す条件・証跡を次に示す。

| 論点                         | 正本と判断材料の担当                                                                                     | 決定時期・判断者                                                                           | 未決中に保留する判定・作業                                                                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 準備着手の上限と試用日       | _UNDECIDED_: 管理計画 U-01〜U-03 が正本。`PM` が支出見込み・参加者別見積もり・候補日を提示する           | U-01・U-02 は準備着手前、U-03 は準備着手前に候補を合意し初期リリース前に確定 / 人間の `PO` | 未承認の支出・時間割り当てと、具体日を前提とする初期リリース判定を保留する。決定後は品質ゲートの時期と `kinuya-schedule` を更新する                |
| オフライン時の運用・受入範囲 | _UNDECIDED_: 成功条件の未解決事項が正本。`BA` が運用案と追加する受入条件の案を整理する                   | 運用開始前 / 人間の `PO`                                                                   | 当該経路の実運用と、その未決を残した店頭試用開始を保留する。決定後は追加された条件 ID を初期受入の合格条件と `kinuya-acceptance-record` に反映する |
| 人気商品の対象範囲・除外条件 | _UNDECIDED_: 成功条件の未解決事項が正本。`BA` が販売記録と聞き取りから対象商品と除外条件の候補を整理する | ベースライン記録の開始前 / 人間の `PO`                                                     | SC-04 の基準値採取と、それを前提とする試用開始を保留する。決定後は基準値の採取対象と `kinuya-trial-log` の引き継ぎ項目を更新する                   |
