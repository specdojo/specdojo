# 駄菓子屋きぬや 販売業務コマンド群 画面仕様

## 1. 概要

駄菓子屋きぬやの店舗端末において、店員・店主が来店客の購入する駄菓子のバーコード読み取りまたは商品コード入力により販売を登録し、小計・消費税・合計金額の確認、会計完了、および釣銭の提示を行うための CLI 操作群である。

## 2. 対象ユーザー/利用目的

- 対象ユーザー: 駄菓子屋きぬやの店員、店主
- 利用目的:
  - 来店客がレジへ持参した駄菓子を迅速に読み取り、購入明細を登録する。
  - 合計請求額を算出して来店客に提示し、受領した代金から釣銭を計算して手渡す。
  - 販売実績を安全に確定し、店舗の販売記録および在庫引落に反映する。

## 3. 操作の流れ

来店客への対面販売における標準的なコマンド実行の流れは以下のとおりである。

1. **販売セッション開始**: `sales start` コマンドを実行し、新規の取引番号（セッション）を発行する。
2. **購入明細追加**: `sales add` コマンドで商品コードと数量を指定し、明細を追加する（商品点数分繰り返す）。
3. **合計確認**: `sales total` コマンドを実行し、小計・消費税・合計金額を確認して来店客へ提示する。
4. **会計完了**: `sales complete` コマンドで来店客から受領した預かり金額を入力し、会計を確定して釣銭金額を出力する。
5. **例外（取引中断）**: 誤登録や購入キャンセルの場合は `sales cancel` コマンドで取引を破棄し、初期状態へ戻る。

## 4. 表示項目

### 4.1. 明細追加時の標準出力要点（`sales add`）

| 項目名     | 種別 | 表示内容要点                               | 備考                         |
| ---------- | ---- | ------------------------------------------ | ---------------------------- |
| 商品名     | 出力 | 追加した商品の正式名称                     | 例: 「きぬや特製 きなこ棒」  |
| 単価       | 出力 | 1個あたりの税込販売価格                    | 10円単位                     |
| 数量       | 出力 | 今回登録した購入数量                       | 1以上の整数                  |
| 明細小計   | 出力 | 今回追加した商品の小計金額（単価 × 数量）  | 税込金額                     |
| 現在合計額 | 出力 | 現在の取引セッションに含まれる全明細の合計 | 店舗端末画面の小計表示に相当 |

### 4.2. 会計完了時の標準出力要点（`sales complete`）

| 項目名   | 種別 | 表示内容要点                     | 備考                   |
| -------- | ---- | -------------------------------- | ---------------------- |
| 取引番号 | 出力 | 取引を一意に識別する連番         | 例: `TX-20261108-0012` |
| 合計金額 | 出力 | 最終請求金額（税込）             | -                      |
| 預かり金 | 出力 | 来店客から受領した金銭           | -                      |
| 釣銭金額 | 出力 | 預かり金 - 合計金額              | 0以上の整数            |
| 取引状態 | 出力 | 会計が正常に完了したことを示す値 | `COMPLETED`            |

## 5. 操作

CLI 操作単位としての各コマンドの利用目的および結果を定義する。引数・オプション・フラグの詳細な仕様は各コマンドの正本リファレンスを参照する。

| 操作名   | 対象コマンド     | 利用目的・操作の意味                           | 正本リファレンス（コマンドリファレンス） |
| -------- | ---------------- | ---------------------------------------------- | ---------------------------------------- |
| 販売開始 | `sales start`    | 新規の販売取引セッションを開始する             | `kinuya-cli-reference#sales-start`       |
| 明細追加 | `sales add`      | 取引に商品コードと数量を追加する               | `kinuya-cli-reference#sales-add`         |
| 合計確認 | `sales total`    | 現在の明細一覧と合計・税額を確認・提示する     | `kinuya-cli-reference#sales-total`       |
| 会計完了 | `sales complete` | 預かり金を登録し、釣銭計算と販売記録を確定する | `kinuya-cli-reference#sales-complete`    |
| 取引取消 | `sales cancel`   | 進行中の販売取引を破棄し、初期状態に戻す       | `kinuya-cli-reference#sales-cancel`      |

## 6. 遷移

| 遷移名       | 契機（実行コマンド） | 遷移元状態 | 遷移先状態 | 条件                     | 引き渡しデータ   | 備考                           |
| ------------ | -------------------- | ---------- | ---------- | ------------------------ | ---------------- | ------------------------------ |
| 取引開始     | `sales start`        | 待機中     | 明細登録中 | 前の取引が完了またはなし | 取引ID           | 新規セッションを発行する       |
| 明細追加継続 | `sales add`          | 明細登録中 | 明細登録中 | 有効な商品コード         | 取引ID、商品ID   | 明細を追加し累計額を更新する   |
| 会計確定へ   | `sales complete`     | 明細登録中 | 待機中     | 預かり金 ≥ 合計金額      | 取引ID、預かり金 | 釣銭を出力し取引セッション終了 |
| 取引破棄     | `sales cancel`       | 明細登録中 | 待機中     | 取消確認に同意           | 取引ID           | 登録明細を破棄して待機へ戻る   |

## 7. バリデーション

- 商品コード: 駄菓子商品台帳に登録済みの有効なコードであること（未登録コードは受け付けない）。
- 販売数量: 1 以上 999 以下の整数であること。また、現在の店舗在庫数を超えないこと。
- 預かり金: 請求合計金額以上の数値であること（不足時は会計を完了できない）。

## 8. エラー表示と利用者の次の手

| エラー事象       | 表示要点                                   | 利用者の次の手（回復アクション）                               |
| ---------------- | ------------------------------------------ | -------------------------------------------------------------- |
| 商品コード未登録 | 「商品コード [XXXX] は登録されていません」 | コードの打ち間違いを確認するか、商品一覧コマンドで商品名を探す |
| 在庫数不足       | 「在庫数が不足しています（現在庫: N個）」  | 数量を現在庫以下に減らして再入力するか、バックヤード在庫を確認 |
| 預かり金額不足   | 「預かり金が不足しています（不足: N円）」  | 来店客から不足分の代金を追加で受領し、再度預かり金を入力する   |
| 取引未開始       | 「販売取引が開始されていません」           | 先に `sales start` コマンドを実行して取引セッションを開始する  |
| 端末通信エラー   | 「店舗ローカルサーバーに接続できません」   | 端末のネットワーク接続を確認し、数秒後に再実行する             |

## 9. メモ / 将来課題

- 将来課題: バーコードスキャナ連携による、コマンド直接入力なしの連続自動スキャンへの対応。
- 将来課題: 電子マネー・QR決済対応時の外部決済端末連動サブコマンドの追加。
