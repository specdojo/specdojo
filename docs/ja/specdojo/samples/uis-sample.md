# 駄菓子屋きぬや 販売登録画面 画面仕様

## 1. 概要

駄菓子屋きぬやの店員・店主が、来店客の購入商品と預かり金を登録し、販売を確定して釣銭を確認する GUI 画面である。販売の記録漏れと金額の計算誤りを減らし、店番を交代しても同じ手順で現金販売を完了できるようにする。

### 1.1. 利用環境と対象範囲

- 単一店舗のタブレット 1 台で、認証済みの担当者が 1 件ずつ取引する。新規販売は店舗待機画面から開始し、確定後は販売完了画面へ進む。
- 商品コードは手入力するか、入力欄を選択した状態でバーコードスキャナから読み取る。スキャナは商品コードの入力と商品追加の確定を行う。
- 本画面は現金販売を扱う。つけ販売・返品・確定後の取消は別業務とし、登録中の取引は本画面で中止できる。
- _ASSUMPTION_: 店舗サービスに接続して商品情報の取得と会計確定を行う。接続できない間は入力済みの明細を保持して復旧を待つ。営業中に復旧できない場合は店主が取引番号と状況を控えて開発担当へ連絡し、紙の販売記録による継続を判断する。

## 2. 対象ユーザー/利用目的

| 対象ユーザー | 利用場面・目的                                             | 許可される操作                                                     |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| 店員         | 接客中に商品を登録し、請求額と預かり金を照合して釣銭を渡す | 商品追加、数量変更、明細削除、商品検索、会計確定、登録中の取引中止 |
| 店主         | 自ら店番し、誤入力や通信失敗時にも取引の確定状況を確認する | 店員と同じ操作、および同じ回復操作                                 |

来店客には担当者が合計請求金額と釣銭を伝える。画面を直接操作するのは店員・店主とする。販売登録権限を持たない利用者は本画面を利用できない。

## 3. 表示項目

### 3.1. 入力・明細・集計

| 項目名                   | 種別 | 表示内容                                         | 編集可否 | 初期値・表示条件・更新契機                                     |
| ------------------------ | ---- | ------------------------------------------------ | -------- | -------------------------------------------------------------- |
| 取引番号                 | 識別 | 開始時に発行された取引の一意な番号               | 不可     | 例 `TX-20261108-0012`。回復操作でも同じ番号を使用              |
| 取引開始日時             | 識別 | 店舗時刻の年月日・時分                           | 不可     | 新規販売開始時に設定し、再試行で変更しない                     |
| 担当者                   | 識別 | 現在の担当者の表示名                             | 不可     | 例「店主」。認証済みの担当者を表示                             |
| 商品コード               | 入力 | 登録する商品の 8 桁数字コード                    | 可       | 初期値は空。追加成功時に空へ戻す。失敗時は入力を保持           |
| 明細の商品コード・商品名 | 一覧 | 追加済みの商品の識別と名称                       | 不可     | 商品台帳から取得。明細なしは「商品を追加してください」         |
| 明細の単価               | 一覧 | 1 個あたりの税込販売価格、円単位                 | 不可     | 商品追加時に取得。確定時に価格変更があれば再確認               |
| 明細の数量               | 入力 | 当該商品の購入数量、個単位                       | 可       | 初回追加は 1。同じ商品の追加で 1 増加                          |
| 明細小計                 | 一覧 | 税込単価 × 数量、円単位                          | 不可     | 追加・数量変更の成功時に更新                                   |
| 現在庫数                 | 一覧 | 各商品の販売可能な数量、個単位                   | 不可     | 商品追加・数量変更・会計確定時に再確認                         |
| 品目数・総数量           | 集計 | 異なる商品の件数と数量の合計                     | 不可     | 初期値は 0 品目 0 点。明細更新時に再計算                       |
| 税抜小計                 | 集計 | 合計請求金額から内税額を差し引いた金額           | 不可     | 初期値は 0 円。明細更新時に再計算                              |
| 内税額                   | 集計 | 税率別の内税額とその合計、円単位                 | 不可     | 初期値は各 0 円。明細更新時に再計算                            |
| 合計請求金額             | 集計 | 全明細小計の合計、円単位                         | 不可     | 初期値は 0 円。明細更新時に再計算                              |
| 預かり金額               | 入力 | 来店客から受領した金額、円単位                   | 可       | 初期値は空。明細更新後も入力値を保持して再判定                 |
| 釣銭金額                 | 集計 | 預かり金額 − 合計請求金額、円単位                | 不可     | 未入力・形式不正・金額不足時は「未計算」。有効な入力後は再計算 |
| 取引状態                 | 状態 | 「登録中」「会計処理中」「結果確認待ち」         | 不可     | 状態別の操作可否は「操作」に従う                               |
| 処理・エラー通知         | 状態 | 実行中の操作、失敗理由、修正対象、次に行える操作 | 不可     | エラー事象に対応する表示を行い、解消時に消去                   |

商品台帳は税込単価と税率区分（8% または 10%）を持つ。金額計算は税率別に税込明細小計を合算し、それぞれの合算額 × 税率 ÷（100 ＋ 税率）の 1 円未満を切り捨てて内税額とする。請求額に内税額を加算しない。

### 3.2. 表示値の確認例

| 商品             | 単価   | 税率区分 | 数量 | 明細小計 |
| ---------------- | ------ | -------- | ---- | -------- |
| きなこ棒（袋）   | 108 円 | 8%       | 2 個 | 216 円   |
| おもちゃ入り菓子 | 110 円 | 10%      | 1 個 | 110 円   |

この明細では 2 品目 3 点、合計請求金額 326 円、内税額は 8% 分 16 円と 10% 分 10 円の計 26 円、税抜小計 300 円となる。預かり金額 500 円で釣銭は 174 円、326 円で釣銭は 0 円、325 円で釣銭は「未計算」となる。

## 4. 操作

### 4.1. 状態と操作可否

| 状態         | 可能な操作                                                       | 状態を抜ける条件                                                                                                               |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 登録中       | 入力・商品追加・数量変更・明細削除・商品検索・取引中止・会計確定 | 会計確定の受付で「会計処理中」。中止確認に同意した場合は店舗待機画面へ                                                         |
| 会計処理中   | 状態表示の確認                                                   | 成功時は販売完了画面へ。確定されていないことが確認できる失敗は「登録中」。通信切断・30 秒の応答待ち超過は「結果確認待ち」      |
| 結果確認待ち | 「結果確認」、認証失効・権限不足時の「再ログイン」               | 確定済みは販売完了画面へ。元の確定処理が終了して未確定であることが確認できれば「登録中」。処理継続中・照会失敗はこの状態を保持 |

「会計処理中」「結果確認待ち」では入力、商品検索、明細変更、取引中止、会計確定を無効化する。登録中の取得・変更操作も 1 件ずつ処理し、その処理中は他の登録操作を無効化する。認証失効・権限不足時は「再ログイン」だけを許可する。

### 4.2. 操作ごとの前提と結果

| 操作名       | 対象                                         | 前提条件                                                                                        | 結果（更新/遷移）                                                                                                                    |
| ------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 商品追加     | 商品コード入力欄と「商品追加」、スキャナ入力 | 登録中。商品コードを入力済み                                                                    | 制約確認後、未追加の商品は数量 1 の行を追加。同じ商品は既存行の数量を 1 増やし、集計・釣銭を再計算。失敗時は明細を保持               |
| 数量変更     | 明細の数量                                   | 登録中。対象明細が存在                                                                          | 制約確認後に数量と集計・釣銭を更新。失敗時は前の有効数量を保持し、修正用の入力値とエラーを表示                                       |
| 明細削除     | 明細の「削除」                               | 登録中。対象明細が存在                                                                          | 対象行を削除し、集計・釣銭を再計算。最終行の削除後は空の明細表示へ戻る                                                               |
| 預かり金入力 | 預かり金額                                   | 登録中                                                                                          | 入力値を保持。形式・金額を判定し、有効なら釣銭を再計算                                                                               |
| 商品検索     | 「商品検索」                                 | 登録中                                                                                          | 商品検索ダイアログを開く。選択した商品コードを商品追加と同じ条件で反映。選択取消時は元の入力・明細を保持                             |
| 取引中止     | 「取引中止」                                 | 登録中                                                                                          | 中止確認を開く。同意時に明細・預かり金を破棄して店舗待機画面へ。戻る場合は登録を継続                                                 |
| 会計確定     | 「会計確定」                                 | 登録中。明細が 1 件以上あり、明細の数量に未修正の入力エラーがなく、預かり金額の形式・範囲が有効 | 「バリデーション」の確定条件を判定。成功時は販売記録と在庫引落をまとめて確定し、完了画面へ。条件違反時は登録中のまま対応エラーを表示 |
| 読み直し     | 「読み直し」                                 | 登録中。商品取得・在庫確認が通信失敗                                                            | 同じ商品コード・数量で情報を再取得し、成功時に元の追加・変更を 1 回反映。失敗時は入力と有効な明細を保持                              |
| 結果確認     | 「結果確認」                                 | 結果確認待ち。認証と販売登録権限が有効                                                          | 同じ取引番号の状態を照会し、「状態と操作可否」に従って復帰。新たな会計確定要求は発行しない                                           |
| 再ログイン   | 「再ログイン」                               | 認証失効または権限不足を検出                                                                    | 取引番号・状態・入力を保持してログイン画面へ。同じ担当者が再認証し権限確認できた場合に復帰                                           |

会計確定は販売記録と在庫引落の両方が成功した時点を完了とする。片方だけの成功を利用者へ完了として表示しない。同じ取引番号で確定操作を再実行しても、販売記録と在庫引落は各 1 回とする。会計処理中の連打は追加の確定として受け付けない。

「読み直し」は直前に失敗した商品取得・在庫確認を対象とする。入力の修正や別の明細操作を行った場合は、その失敗要求を取り消して「読み直し」を解除する。追加・変更の成功後も解除する。

## 5. 遷移

本画面の業務上の識別子は `uis-sales-register` とする。周辺画面は未作成のため、画面名と識別子で示す。

| 遷移名           | 契機（操作）                                 | 遷移元                           | 遷移先                                     | 条件                                 | 引き渡し情報・入力の扱い                                               |
| ---------------- | -------------------------------------------- | -------------------------------- | ------------------------------------------ | ------------------------------------ | ---------------------------------------------------------------------- |
| 新規取引開始     | 「新規販売」                                 | `店舗待機画面（uis-store-home）` | 販売登録画面                               | 販売登録権限があり、未完了取引がない | 新規取引番号、担当者識別子。空の明細と未入力の預かり金で開始           |
| 商品検索表示     | 「商品検索」                                 | 販売登録画面                     | `商品検索ダイアログ（uis-product-search）` | 登録中                               | なし。販売登録の明細・入力は保持                                       |
| 商品選択反映     | 検索で「選択」                               | `商品検索ダイアログ`             | 販売登録画面                               | 商品を 1 件選択済み                  | 選択商品コード。追加に失敗した場合も元の明細と入力を保持してエラー表示 |
| 商品検索取消     | 検索で「戻る」                               | `商品検索ダイアログ`             | 販売登録画面                               | 選択せず戻る                         | なし。保持した明細・入力へ復帰                                         |
| 中止確認表示     | 「取引中止」                                 | 販売登録画面                     | 中止確認ダイアログ                         | 登録中                               | 現在の取引番号。入力は保持                                             |
| 中止確定         | 確認で「中止する」                           | 中止確認ダイアログ               | `店舗待機画面`                             | 中止への同意                         | 中止した取引番号。販売・在庫は更新せず、入力を破棄                     |
| 中止確認から復帰 | 確認で「戻る」                               | 中止確認ダイアログ               | 販売登録画面                               | 中止せず戻る                         | なし。保持した明細・入力へ復帰                                         |
| 会計完了         | 会計確定成功、または結果確認で確定済みを確認 | 販売登録画面                     | `販売完了画面（uis-sales-complete）`       | 同じ取引の販売・在庫更新が確定済み   | 取引番号、確定明細、合計請求金額、預かり金額、釣銭。以後は編集不可     |
| 再認証へ         | 「再ログイン」                               | 販売登録画面                     | `ログイン画面（uis-login）`                | 認証失効または権限不足               | 復帰先と取引番号。入力と直前の取引状態を保持                           |
| 再認証から復帰   | ログイン成功                                 | `ログイン画面`                   | 販売登録画面                               | 同じ担当者に販売登録権限がある       | 保持した取引へ復帰。会計結果が不明なら結果確認待ちで復帰               |

販売完了画面は釣銭の手渡し確認とレシート発行を担う。印刷失敗時の再発行も同画面で扱い、販売登録へ戻して再会計しない。権限が回復しない場合はログイン画面に留まり、店主が担当者の権限を確認する。

## 6. バリデーション

| 対象                   | 必須性           | 条件                                                                            | 判定時点                               | 違反時の扱い・対応エラー                                                                   |
| ---------------------- | ---------------- | ------------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------ |
| 商品コード             | 商品追加時に必須 | 半角数字 8 桁。先頭の 0 を保持し、前後空白や記号を許容しない                    | 商品追加時、スキャン確定時             | 入力値を保持し、明細は変更しない。「商品コード形式不正」                                   |
| 商品の存在・販売可否   | 商品追加時に必須 | 商品台帳に存在し、販売中である                                                  | 商品追加時と会計確定時                 | 未登録は「商品コード未登録」。販売停止は「販売対象外」。確定時の失敗は販売・在庫とも未更新 |
| 数量                   | 各明細で必須     | 半角数字による 1〜999 の整数。空欄・符号・小数・文字を許容しない                | 商品追加時、数量変更時、会計確定時     | 前の有効数量を保持し、修正入力を残す。「数量形式・範囲不正」                               |
| 在庫との相関           | 各明細で必須     | 同一商品をまとめた数量が最新の現在庫数以下                                      | 商品追加時、数量変更時、会計確定時     | 「在庫不足」。入力と明細を保持し、確定時の失敗でも在庫引落なし                             |
| 販売価格               | 確定時に必須     | 追加時の税込単価と最新の単価が一致                                              | 会計確定時                             | 確定せず、最新単価・集計・釣銭へ更新。「販売価格変更」で再確認を求める                     |
| 明細の有無             | 確定時に必須     | 明細 1 件以上                                                                   | 会計確定前                             | 0 件では「会計確定」を無効化                                                               |
| 預かり金額の形式・範囲 | 確定時に必須     | 半角数字による 0〜999999 の整数、円単位。空欄・符号・小数・桁区切りを許容しない | 入力変更時と会計確定前                 | 空欄・形式不正時は「会計確定」を無効化。「預かり金形式・範囲不正」を表示                   |
| 預かり金額との相関     | 確定時に必須     | 預かり金額が合計請求金額以上                                                    | 預かり金入力時、明細更新時、会計確定時 | 不足額を表示。確定操作でも拒否して「預かり金額不足」。釣銭は未計算                         |

会計確定時の条件違反では販売記録を確定しない。数量の境界は 1・999 を許容し、0・1000・1.5 を拒否する。在庫数 3 の商品は数量 3 を許容し、4 を拒否する。金額相関の境界は「表示値の確認例」に従う。

## 7. エラー表示と利用者の次の手

| エラー事象                   | 発生条件                                             | 表示要点                                                                 | 状態の扱い                                                                 | 利用者の次の手（回復アクション）                                                                           |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 商品コード形式不正           | 商品追加時に空欄または 8 桁数字以外                  | 「商品コードを 8 桁の数字で入力してください」                            | 入力を保持。明細・集計は変更しない                                         | コードを修正して「商品追加」。コードが不明なら「商品検索」                                                 |
| 商品コード未登録             | 入力コードが商品台帳にない                           | 「商品コードが登録されていません」と入力コード                           | 入力を保持。明細は追加しない                                               | 入力を確認するか、「商品検索」で登録済みの商品を選択                                                       |
| 販売対象外                   | 追加時または確定時に販売停止を検出                   | 「現在販売できない商品です」と商品名                                     | 確定せず登録中を保持                                                       | 未追加なら別の商品を選択。明細内の商品なら「明細削除」で除いて再確認                                       |
| 数量形式・範囲不正           | 数量が空欄、整数以外、1〜999 の範囲外                | 「数量は 1〜999 の整数で入力してください」と対象商品                     | 前の有効明細と集計を保持し、修正入力を残す                                 | 対象数量を修正。購入しない場合は「明細削除」                                                               |
| 在庫不足                     | 指定数量が現在庫数を超過                             | 「在庫が不足しています」と商品名、現在庫数                               | 販売・在庫は未更新。入力・明細を保持                                       | 数量を現在庫数以下へ修正。現在庫数が 0 なら「明細削除」                                                    |
| 預かり金形式・範囲不正       | 入力が半角数字による 0〜999999 の整数でない          | 「預かり金額を 0〜999999 円の整数で入力してください」                    | 入力を保持。釣銭は未計算                                                   | 受領額を確認し、桁区切り等を除いて預かり金額を修正                                                         |
| 預かり金額不足               | 預かり金額が合計請求金額未満                         | 「預かり金が不足しています」と不足額                                     | 登録中を保持。釣銭は未計算                                                 | 不足分を受領して預かり金額を修正し、再度「会計確定」                                                       |
| 販売価格変更                 | 確定時に単価の変更を検出                             | 「価格が変わりました。金額を確認してください」と変更商品、旧単価・新単価 | 販売・在庫は未更新。最新価格で再計算し、預かり金は保持                     | 新しい請求額を来店客へ伝え、預かり金を確認・修正して再度「会計確定」                                       |
| 商品取得・在庫確認の通信失敗 | 登録中の取得要求で接続切断または 30 秒の応答待ち超過 | 「商品情報を取得できません」と「読み直し」                               | 入力と有効な明細を保持。追加・変更は未反映                                 | 接続を確認して「読み直し」。編集を続ける場合は入力を修正して元の操作を実行すると、失敗した要求を置き換える |
| 会計確定失敗                 | 店舗サービスから、会計が未確定であるとの失敗応答     | 「会計を確定できませんでした」と取引番号                                 | 登録中へ戻る。販売・在庫は未更新、入力を保持                               | 接続の復旧後、明細と預かり金を確認して「会計確定」。再発時は店主へ取引番号を連絡                           |
| 会計結果不明                 | 会計要求後の接続切断または 30 秒の応答待ち超過       | 「会計結果を確認してください」と取引番号、「結果確認」                   | 結果確認待ちへ移り、編集・中止・確定を無効化                               | 接続の復旧後に「結果確認」。未確定が確認できた場合のみ登録を再開                                           |
| 会計結果の照会未完了         | 結果確認で処理継続中、または照会に失敗               | 「会計結果をまだ確認できません」と取引番号                               | 結果確認待ちを保持                                                         | 接続と処理状況を確認して再度「結果確認」。復旧しない場合は店主へ取引番号を連絡                             |
| 認証失効                     | 登録中または結果確認時に認証失効を検出               | 「再ログインしてください」                                               | 入力と直前の状態を保持。会計要求後に検出した場合は結果確認待ち             | 「再ログイン」で同じ担当者が認証。復帰後、結果確認待ちなら「結果確認」                                     |
| 権限不足                     | 画面への進入時または操作時に販売登録権限がない       | 「販売登録の権限がありません」                                           | 進入を拒否。操作中なら入力を保持して変更を停止。会計要求後なら結果確認待ち | 「再ログイン」へ進み、店主に担当者の権限確認を依頼。権限確認後に同じ取引へ復帰                             |

## 8. メモ / 将来課題

- 電子マネー・QR 決済を導入する際は、店主が決済方法と取消手順を確認し、預かり金・会計確定・結果確認の仕様を見直す。
- 入力欄の選択を要しない連続スキャンは将来の拡張候補とし、導入検討時に店員と開発担当が誤読・重複追加時の修正手順を確認する。
