# 駄菓子屋きぬや 販売登録画面 画面仕様

## 1. 概要

駄菓子屋きぬやの店舗レジ端末において、店員・店主が来店客の購入する駄菓子のバーコード読み取りまたは商品コード入力により販売明細を登録し、小計・消費税・合計金額の確認、会計完了、および釣銭の提示を行うための GUI 画面である。

## 2. 対象ユーザー/利用目的

- 対象ユーザー: 駄菓子屋きぬやの店員、店主
- 利用目的:
  - 来店客がレジへ持参した駄菓子を迅速に登録し、購入明細を作成する。
  - 合計請求額を算出して来店客に提示し、受領した預かり金から釣銭を計算して手渡す。
  - 販売実績を安全に確定し、店舗の販売記録および在庫引落に反映する。

## 3. 表示項目

画面に表示する情報の要点を以下に定義する。

| 項目名           | 種別     | 表示内容要点                               | 編集可否 | 備考                        |
| ---------------- | -------- | ------------------------------------------ | -------- | --------------------------- |
| 取引番号         | ヘッダー | 当該取引を一意に識別する連番               | 不可     | 例: `TX-20261108-0012`      |
| 取引日時         | ヘッダー | 取引開始日時（YYYY-MM-DD HH:mm）           | 不可     | システム現在時刻            |
| 担当者名         | ヘッダー | 現在ログイン中の店員・店主の氏名           | 不可     | 例: 「木村 きぬ」           |
| 商品コード入力欄 | 入力     | バーコードスキャナ読取または手入力のコード | 可       | 8桁数字                     |
| 明細一覧: 商品名 | 一覧     | 追加された駄菓子の正式名称                 | 不可     | 例: 「きぬや特製 きなこ棒」 |
| 明細一覧: 単価   | 一覧     | 1個あたりの税込販売価格                    | 不可     | 10円単位                    |
| 明細一覧: 数量   | 一覧     | 当該商品の購入数量                         | 可       | 初期値 1、数量変更可能      |
| 明細一覧: 小計   | 一覧     | 単価 × 数量の計算額                        | 不可     | 税込金額                    |
| 明細件数         | サマリー | 登録された明細の総品目数と総数量           | 不可     | 例: 「3品目 5点」           |
| 小計金額         | サマリー | 税抜合計金額                               | 不可     | -                           |
| 消費税額         | サマリー | 適用税率に基づく消費税合計額               | 不可     | 軽減税率（8%）対象          |
| 合計請求金額     | サマリー | 来店客へ請求する税込最終合計額             | 不可     | 強調表示                    |
| 預かり金額       | 入力     | 来店客から受領した金銭                     | 可       | 会計確定時に必須            |
| 釣銭金額         | サマリー | 預かり金額 - 合計請求金額                  | 不可     | 預かり金入力後に自動算出    |
| 取引状態         | フッター | 現在の取引状態（登録中 / 会計完了 / 中断） | 不可     | 状態インジケータ            |

## 4. 操作

画面上で業務ユーザーが実行可能な操作を定義する。

| 操作名       | 対象                            | 前提条件                                                 | 結果（更新/遷移）                                                      | 備考                       |
| ------------ | ------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------- |
| 商品追加     | 商品コード入力欄 / スキャナ     | 有効な商品コードが入力またはスキャンされたこと           | 明細一覧に商品を追加（既存商品は数量+1）し、合計金額を再計算する       | スキャナ連携時は自動確定   |
| 数量変更     | 明細行の数量変更ボタン / 入力欄 | 数量を変更する明細行が存在すること                       | 指定明細の数量を更新し、明細小計および合計金額を再計算する             | 1〜999の整数               |
| 明細削除     | 明細行の「削除」ボタン          | 削除対象の明細行が存在すること                           | 指定明細を一覧から削除し、合計金額を再計算する                         | -                          |
| 取引中止     | 「取引中止」ボタン              | 取引状態が「登録中」であること                           | 確認ダイアログを表示し、同意時に全明細を破棄して待機画面へ遷移する     | -                          |
| 商品検索呼出 | 「商品検索」ボタン              | なし                                                     | 商品検索ダイアログを前面に表示する                                     | コード不明時に使用         |
| 会計確定     | 「会計確定」ボタン              | 明細が1件以上存在し、預かり金額 ≥ 合計請求金額であること | 販売実績データを確定・保存し、釣銭金額を表示して販売完了画面へ遷移する | レシート印刷処理をトリガー |

## 5. 遷移

画面間の移動および引き渡しデータを定義する。

| 遷移名       | 契機（操作）                     | 遷移元画面         | 遷移先画面         | 条件                       | 引き渡しデータ                     | 備考                     |
| ------------ | -------------------------------- | ------------------ | ------------------ | -------------------------- | ---------------------------------- | ------------------------ |
| 新規取引開始 | 「新規販売」ボタン押下           | 店舗待機画面       | 販売登録画面       | 前の取引が完了していること | 新規取引ID、担当者ID               | 画面初期化               |
| 商品検索表示 | 「商品検索」ボタン押下           | 販売登録画面       | 商品検索ダイアログ | なし                       | なし                               | モーダル表示             |
| 商品選択反映 | 商品検索での「選択」ボタン押下   | 商品検索ダイアログ | 販売登録画面       | 検索結果から商品を選択     | 選択商品コード                     | 検索画面を閉じ明細に追加 |
| 取引中止復帰 | 中止確認ダイアログの「はい」押下 | 販売登録画面       | 店舗待機画面       | 中止確認に同意             | 取引ID                             | 明細破棄                 |
| 会計完了遷移 | 「会計確定」ボタン押下           | 販売登録画面       | 販売完了画面       | 預かり金 ≥ 合計請求金額    | 取引ID、合計金額、預かり金、釣銭額 | 釣銭表示とレシート発行   |

## 6. バリデーション

画面の入力欄における業務妥当性チェック条件を定義する。

- 商品コード: 駄菓子商品台帳に登録済みの有効なコードであること（未登録コードはエラー）。
- 販売数量: 1 以上 999 以下の整数であること。また、現在の店舗在庫数を超えないこと。
- 預かり金額: 数値（半角数字）であり、合計請求金額以上の金額であること（不足時は会計確定ボタン非活性またはエラー）。

## 7. エラー表示と利用者の次の手

異常や制約違反が発生した際に画面に表示するメッセージ要点と、利用者が状況を回復するために次に取るべき具体的なアクション（次の手）を定義する。

| エラー事象             | 表示要点                                   | 原因                                                     | 利用者の次の手（回復アクション）                                                   |
| ---------------------- | ------------------------------------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 商品コード未登録       | 「商品コード [XXXX] は登録されていません」 | 存在しない商品コードを入力またはスキャンした             | コードの打ち間違いを確認するか、「商品検索」ボタンから正式な商品を検索して選択する |
| 在庫数不足             | 「在庫数が不足しています（現在庫: N個）」  | 入力した数量が現在の店舗在庫数を超えている               | 数量を現在庫数以下に変更して再入力するか、バックヤード在庫を確認して補充する       |
| 預かり金額不足         | 「預かり金が不足しています（不足: N円）」  | 入力した預かり金額が請求合計金額を下回っている           | 来店客から不足分の代金を追加で受け取り、正しい預かり金額を再入力する               |
| 未登録での会計確定     | 「販売明細が登録されていません」           | 明細が0件の状態で会計確定を押下した                      | 商品コードを入力またはスキャンして明細を1件以上追加してから会計を行う              |
| 店舗サーバー通信エラー | 「店舗ローカルサーバーに接続できません」   | 端末と店舗サーバー間のネットワーク切断またはサーバー停止 | 端末のLAN接続を確認し、画面上の「再接続」ボタンを押す                              |

## 8. メモ / 将来課題

- 将来課題: バーコードスキャナ連携による、商品コード入力欄へのフォーカス不要な連続自動スキャン対応。
- 将来課題: 電子マネー・QR決済対応時の外部決済端末との連動および決済種別選択機能の追加。
