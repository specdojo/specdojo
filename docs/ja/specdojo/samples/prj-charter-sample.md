# プロジェクト憲章: 駄菓子屋きぬや 販売管理システム

本書は、駄菓子屋きぬや 販売管理システム構築の立ち上げを認可し、開発担当に要件整理、詳細計画、初期準備の権限を委譲する。承認責任者は店主代表（`PO`）であり、本格実行開始と外部公開は本書では承認しない。

## 1. 認可対象

| 項目            | 内容                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ |
| プロジェクト名  | 駄菓子屋きぬや 販売管理システム構築                                                                                      |
| プロジェクト ID | `prj-0001`                                                                                                               |
| 認可対象        | 立ち上げ、詳細計画策定、初期準備                                                                                         |
| 認可しない範囲  | 本格実行開始、外部公開、追加支出、主要スコープ変更                                                                       |
| 直接根拠        | [[specdojo:prj-overview-sample\|プロジェクト概要]]、[[specdojo:prj-stakeholder-register-sample\|ステークホルダー登録簿]] |
| 承認責任        | 店主代表（`PO`）                                                                                                         |
| 認可条件        | 「承認」の表に承認日と証跡リンクが記録されるまで、立ち上げ認可は未承認として扱う                                         |

## 2. プロジェクトの目的

目的は、店主代表が無理なく使える仕組みで販売、在庫、つけ残高を記録し、家族利用者が店番するときも同じ手順で確認できる状態を作ることである。背景、数値目標、測定方法は [[specdojo:prj-overview-sample|プロジェクト概要]] を正とする。

| 観点     | 認可判断で確認する期待効果                 |
| -------- | ------------------------------------------ |
| 記録共有 | 販売、在庫、つけの記録を同じ基準で残せる   |
| 業務継続 | 店主代表が不在でも店番を続けやすい         |
| 残高確認 | つけ残高を短時間で確認できる               |
| 手順統一 | 店主代表と家族利用者が同じ操作手順で使える |

成功判定の観点と受入条件は [[specdojo:prj-success-criteria-and-acceptance-criteria-sample|成功基準と受入条件]] を正とする。

## 5. 権限委譲

| 項目         | 決裁者           | 実行責任者        | 協議先     | 証跡                 |
| ------------ | ---------------- | ----------------- | ---------- | -------------------- |
| 立ち上げ認可 | 店主代表（`PO`） | 開発担当（`DEV`） | 家族利用者 | 「承認」の表         |
| 詳細計画策定 | 店主代表（`PO`） | 開発担当（`DEV`） | 家族利用者 | 計画の承認記録       |
| 本格実行開始 | 店主代表（`PO`） | 開発担当（`DEV`） | 家族利用者 | GO / Not GO 決定記録 |

店主代表に留保する判断は、初期対象範囲の変更、費用上限の確定・増額と外部サービス・機材への支出、公開可否と公開対象、ライセンス方針の確定、本格実行開始とする。

## 7. 本格実行開始の GO / Not GO 判断

合格条件を満たさない観点が残る間は、本格実行開始と外部公開を保留する。

| 判断観点 | 確認内容                                           | 合格条件                                                                                             | 記録先                                                                                                |
| -------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 目的整合 | 優先機能と公開対象                                 | すべてが概要の目的に対応し、店主代表が確認済み                                                       | [[specdojo:pm-plan-sample\|管理計画]]、決定記録                                                       |
| 公開適性 | 公開する画面・文書・記録                           | 公開禁止の情報を含まず、公開範囲が承認済み                                                           | 決定記録、Pull Request                                                                                |
| 予算枠   | 支出と運用負担                                     | 費用上限が承認済みで、計画の支出が上限内                                                             | 決定記録                                                                                              |
| 体制     | 責任の割り当て                                     | 各作業の責任者が 1 人に決まり、承認の決裁者が店主代表                                                | [[specdojo:pm-raci-sample\|RACI]]                                                                     |
| 品質     | 販売管理システムの実装・操作手順・受入結果・公開物 | 品質管理計画の「技術・公開」「初期受入」ゲートが合格し、是正・再判定が済んでいない重大な不適合がない | [[specdojo:pm-quality-management-plan-sample\|品質管理計画]]、`execution/reviews/release-1/result.md` |

## 9. 未決事項

| 論点               | 影響                           | 当面の扱い                                           |
| ------------------ | ------------------------------ | ---------------------------------------------------- |
| 費用上限           | 詳細計画と予算枠を判定できない | 詳細計画の承認前に確定する                           |
| リリース目標日     | マイルストーンを置けない       | 見積もりの後、GO / Not GO の前に店主代表と合意する   |
| オフライン時の扱い | 対象範囲と見積もりが変わる     | 詳細計画の承認前に、スコープで対象か対象外かを決める |
