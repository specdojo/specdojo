# コミュニケーション計画 作成レシピ

Communication Plan Writing Recipe

関係者の判断・確認の必要を、機会と記録先へ変える作り方を示す。

## 1. このレシピの使い方

- 登録簿の情報要求（Why）を、誰がいつ何を判断・確認するか（What）に変え、手段と責任（How）を決め、記録先とステークホルダー ID でたどれるようにする（Trace）。

## 2. 作成前に集める情報

| 項目         | 集める情報                         | 取り出し元             |
| ------------ | ---------------------------------- | ---------------------- |
| 情報要求     | 誰が何を判断・確認する必要があるか | ステークホルダー登録簿 |
| 契機         | 判断ゲート、試行の節目、上限超過   | 管理計画               |
| 判断経路     | 条件ごとに最終判断する人           | PO への確認            |
| 責任主体     | 採用済みの Role code               | ロール定義             |
| 扱えない情報 | 公開記録や AI Agent へ出せない情報 | 当事者・協働組織       |

## 3. 全体の作成手順

1. 機会を最初に書く。機会が決まらないと、エスカレーションの条件と扱う情報が決まらない。
2. エスカレーション、情報管理と公開、見直し条件と未決事項の順に書く。
3. 最後に方針と適用範囲を書く。機会がそろうと、会議を持つかを根拠付きで言える。

## 4. 各章の書き方

### 4.1. 方針と適用範囲

問い:

- 会議でしか決まらない判断はあるか。
- 非同期の記録で足りないのはどんな場合か。
- AI Agent に任せる整理・草案と、人が担う合意・承認・公開の境目はどこか。

コツ: 関係者の一覧は登録簿から写さず、参照に置き換える。

### 4.2. コミュニケーション機会

問い:

- この機会がなければ、誰の判断が止まるか。
- 相手は何を見て判断するか。
- 結果を記録先へ残す責任はどの Role code が持つか。

コツ: 伝える内容から書くと報告の一覧になる。記録先を答えられない機会は目的が決まっていない。

### 4.3. エスカレーション

問い:

- どの条件で判断者が変わるか。
- 一次対応の人は何を持っていくか。

コツ: 緊急度で分けず、誰が決めるかで分ける。AI Agent の出力の疑義は漏れやすい。

### 4.4. 情報管理と公開

問い:

- 公開記録と AI Agent に出せない情報は何か。
- 当事者の発言や試行データは、どの範囲で使う同意があるか。
- 口頭で決まったことは、どの Role code がどの管理記録へ転記するか。

コツ: 生成ビューではなく生成元を直すと書く。

### 4.5. 見直し条件と未決事項

問い:

- どの変化で機会の表が合わなくなるか。
- 連絡時期・判断経路・手段を変えたとき、どの計画・タスク・設定を誰が追従させ、反映をどこに残すか。
- 未決の論点は、どの機会の相手・時期・手段を変えるか。

コツ: 決める人と時期を聞いて書く。

## 5. 深掘り手順

1. 機会の各行が、どの情報要求に応えるかを確かめ、対応のない行を外す。
2. 記録先のない会議や報告を外す。
3. エスカレーションの各条件が、どの機会で見つかるかを確かめる。

## 6. 良い例 / 悪い例

| 観点             | 良い例                                            | 悪い例                       |
| ---------------- | ------------------------------------------------- | ---------------------------- |
| 機会             | 代表試行の後に、利用者が価値と負荷を確かめる      | 利用者会議を定期開催する     |
| 証跡             | 評価結果と採否を試行記録へ残す                    | 議論したことだけを書く       |
| エスカレーション | 費用超過の見込みは、PM が縮小案を作り PO が決める | 重大な問題は速やかに報告する |

## 7. レビュー観点

| 観点       | 確認内容                                           |
| ---------- | -------------------------------------------------- |
| 漏れ       | どの機会にも対応しない情報要求がない               |
| 重複       | 同じ相手・内容・時期の確認が複数行に分かれていない |
| 会議の要否 | 会議ごとに、非同期では決まらない理由を言える       |

## 8. 仕上げチェック

- 機会の各行が、情報要求と記録先の両方につながる。
- AI Agent に合意・承認・公開を任せていない。
- 口頭の決定に、転記する Role code と記録先がある。
- 公開記録の情報が、どの情報区分に当たるかを言える。
