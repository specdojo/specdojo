# ビジネスルール 作成レシピ

Business Rule Writing Recipe

業務担当者の判断を、誰が適用しても同じ結果になる条件に具体化する作り方を示す。

## 1. このレシピの使い方

- 業務プロセスから判断が要る理由（Why）を引き継ぎ、入力と結果の対応（What）、適用順と例外時の扱い（How）を決める。条件・判定例・未決事項は ID で結ぶ（Trace）。

## 2. 作成前に集める情報

| 項目       | 集める情報                             | 取り出し元               |
| ---------- | -------------------------------------- | ------------------------ |
| 利用場面   | 誰がどの業務で判断し、誤ると何が困るか | 業務プロセス、業務担当者 |
| 判断材料   | 使う項目、単位、比較時点               | 概念データ、業務担当者   |
| 代表例     | 実際の判断事例と、その結果になった理由 | 業務担当者への聞き取り   |
| 未決の論点 | 決まらない判断と、止まる作業           | 聞き取りのメモ           |

## 3. 全体の作成手順

1. 代表例の入力と結果を対にして書く。条件から書くと根拠のない条件が混ざる。
2. その結果になる理由を条件にし、等号・同順位・未設定の例へ広げて適用順を決める。
3. 条件が使う項目を入力に、受け取る相手の次の行動を出力に書く。
4. 入力不備と参照失敗で業務が続くかを決め、決めきれない判断はメモ / 将来課題へ送る。
5. 概要は最後に書く。規則が決まると対象外を切りやすい。

## 4. 各章の書き方

| 章                  | 書き手が答える問い                           | コツ                                         |
| ------------------- | -------------------------------------------- | -------------------------------------------- |
| 概要                | 誤ると誰が困るか。前後の業務と重ならないか   | 上位の目的は写さず参照に置き換える           |
| 入力                | 一つ欠けても判断できるか。いつの値か         | 項目を一つずつ隠して聞き、仮のゼロを見つける |
| ルール（判定/計算） | なぜその結果か。同時に成り立てばどちらが先か | 境界の直前・一致・直後を並べて聞く           |
| 出力                | 受け取った人は次に何を選ぶか                 | 利用先が使わない途中の値は外す               |
| 例外 / 異常系       | 誤った値で続けると何が起きるか               | 止める・代替値で続けるの両案を示して選ばせる |
| メモ / 将来課題     | 誰の判断か、どの証拠があれば確定するか       | 範囲を変える論点と確認作業の不足を分ける     |

## 5. 深掘り手順

次の順で対応のない主張を探す。

1. 各条件が概要のどの困りごとに応えるかを確かめ、対応のない条件を外す。
2. 判定例の期待値を導く条件を確かめる。文字列の順位は、大小文字や数字を含む例で決着が変わらないかを問う。
3. 一項目だけ欠ける場合と全件で計算できない場合を分け、同じ代替規則にする根拠を聞く。
4. 決められない期待値は、選択肢ごとに変わる下流の作業を添えて未決へ戻す。

## 6. 良い例 / 悪い例

| 観点         | 良い例                                               | 悪い例                   |
| ------------ | ---------------------------------------------------- | ------------------------ |
| 入力の不足   | 「予約数がないと販売可能数を出せないため判定しない」 | 「空欄はたぶんゼロ」     |
| 部分的な欠損 | 「最早開始日だけ欠けるタスクの順位は未決とする」     | 「欠けたら末尾に置く」   |
| 利用先       | 「不足判定を在庫確認担当へ返し、発注は担当が決める」 | 「不足なら自動発注する」 |

## 7. レビュー観点

| 観点   | 確認する問い                                     |
| ------ | ------------------------------------------------ |
| 用語   | 業務担当者がふだんの言葉で条件を読めるか         |
| 再現性 | 二人が同じ代表例に別の期待値を付ける余地はないか |
| 引継ぎ | 結果と例外から、受け取った人が次の業務を選べるか |

## 8. 仕上げチェック

- 入力の各項目を、条件か例外のどれかが使っている。
- 出力の各結果が、条件か例外のどれかから生じる。
- 未決事項ごとに、影響する条件か判定例を ID で指せる。
