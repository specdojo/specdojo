# ビジネスルール 作成レシピ

Business Rule Writing Recipe

業務担当者の判断を、実装と検証へ引き継げる条件・結果に具体化するための作成手順です。特に境界、欠損、競合する条件と未決事項を掘り下げます。

## 1. このレシピの使い方

- 上位の業務目的から、この判断が誤った場合に誰が何に困るかを確認する。
- 入力と期待する結果を対にして書き、判断の仕方を業務用語で説明する。画面操作や保存方式は、それを定める後続成果物へ渡す。
- 根拠文書・規則・判定例を結び、判断が変わったときに影響箇所を追えるようにする。不足する根拠は業務担当者への問いに戻す。

## 2. 作成前に集める情報

| 項目     | 集める情報・問い                                           |
| -------- | ---------------------------------------------------------- |
| 利用場面 | 誰がどの業務の途中で判断し、誤判定で何が起きるか           |
| 境界     | 直前までに何が確定し、直後にどの業務へ結果を渡すか         |
| 判断材料 | 必要な概念項目、単位、比較時点、入力の出所                 |
| 結果     | 正常な結果、対象なし、判定できない場合をどう見分けるか     |
| 根拠     | 決定済みの条件、参照文書とその作成状況、承認が要る変更     |
| 未決事項 | 誰へ何を判断してもらい、いつまでに決まらないと何が止まるか |

## 3. 全体の作成手順

1. 概要で「どの場面で何を判断するか」を一文にし、守る価値と対象外を添える。
2. 入力で、最初の具体例に必要な項目を書き出す。単位と比較時点をそろえる。
3. ルール（判定/計算）で、その例の結果になる理由を条件に変換する。等号・同順位・未設定の例へ広げ、適用順を決める。
4. 出力で、結果を受け取る相手が次の業務を選べる意味を添える。
5. 例外 / 異常系で、入力不備と参照失敗を通したときに、業務が続くかを確かめる。
6. メモ / 将来課題へ根拠不足と未決の判断を集め、依頼先、判断時点、下流の制約を残す。

## 4. 各章の書き方

| 章                  | 書き手が答える問い                                               | 具体化のコツ                                                       |
| ------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| 概要                | この判断は誰のどの困りごとを減らすか。前後の手順と重複しないか   | 実際の利用場面を一つ選び、開始条件と対象外を切り分ける             |
| 入力                | その材料が一つ欠けても判断できるか。どの時点の数値を使うか       | 項目を一つずつ隠して、仮のゼロで代用していないか調べる             |
| ルール（判定/計算） | なぜその結果になるか。条件が同時成立したらどちらを優先するか     | 境界の直前・一致・直後を並べ、期待値の異なる理由を説明する         |
| 出力                | 結果を受け取る人は何を判断できるか。対象なしと失敗を区別できるか | 結果の意味を言葉にし、利用先に不要な内部計算値を除く               |
| 例外 / 異常系       | 間違った値を使い続けた場合の業務影響は何か                       | 停止・代替・対象外のそれぞれで、結果の有効性と回復の行動を確認する |
| メモ / 将来課題     | どの証拠または誰の判断があれば確定できるか                       | 現行範囲を変える論点と、確認作業だけの不足を分けて依頼する         |

## 5. 深掘り手順

1. 代表例を業務担当者へ説明し、根拠のない条件や、業務価値へつながらない計算を見つける。
2. 境界値、欠損、競合する条件で結果が変わる箇所を探す。文字列比較なら大小文字や数字を含む例で同順位の決着が変わらないかを問う。
3. 順位規則なら一つの項目だけが欠ける場合と、全件で計算できない場合を分ける。両者を同じ代替規則にしてよい根拠を確かめる。
4. 決められない期待値を作らず、選択肢によって変わる下流の作業とともに判断依頼へ戻す。

## 6. 良い例 / 悪い例

| 観点       | 良い例                                                                             | 悪い例                   | 良し悪しを分ける点                 |
| ---------- | ---------------------------------------------------------------------------------- | ------------------------ | ---------------------------------- |
| 境界       | 「発注点と等しければ不足なし」                                                     | 「少なければ不足」       | 等号で結果を確定できるか           |
| 入力の不足 | 「予約数がないと販売可能数を算出できない」                                         | 「空欄はたぶんゼロ」     | 業務根拠のある扱いか               |
| 利用先     | 「不足判定を在庫確認担当へ返す。発注確定は担当者が行う」                           | 「不足なら自動発注する」 | 判断から別の責務へ飛躍していないか |
| 未決事項   | 「閾値変更は店主代表に導入承認前の判断を依頼する。未決なら新閾値の実装を保留する」 | 「閾値は後で考える」     | 次の判断と影響が追えるか           |

## 7. レビュー観点

| 観点         | 確認する問い                                                       |
| ------------ | ------------------------------------------------------------------ |
| 業務的な理由 | 主要な条件がどの課題・価値・決定に由来するか説明できるか           |
| 再現性       | 二人が同じ具体例に別の期待値を付ける余地はないか                   |
| 引継ぎ       | 正常結果と例外から、利用者が次に行う業務を選べるか                 |
| 責務境界     | 手順、構文、保存構造を、それを定める成果物へ委譲できているか       |
| 判断待ち     | 未決事項の影響する規則・例と、判断を依頼する相手を結び付けられるか |

## 8. 仕上げチェック

- 概要から入力、判定、出力、例外、残る判断へ読み進めて、参照していない材料や使われない結果がない。
- 判定例は本文で説明した条件から導け、未決の期待値を確定済みの値として示していない。
- 同じ条件を表・文章・擬似コードで繰り返さず、変更する箇所を一つに絞れている。
- 上位の目的の再掲と実装の詳細を整理し、必要な根拠の参照と未決事項の引継ぎが残っている。
