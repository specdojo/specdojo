# メンバー定義 作成レシピ

Project Human Member Roster Writing Recipe

人間の実行主体と担える Role code を、履歴で変わらない nickname で名簿にする作り方を示す。

## 1. このレシピの使い方

- 名簿は、組織定義の最終判断の集約先（Why）を引き継ぎ、誰がどの Role を担えるか（What）を決め、`--by` と実行ログが nickname で人を指す（Trace）。agent の定義は名簿に持たない。

## 2. 作成前に集める情報

| 項目         | 集める情報                                       | 取り出し元           |
| ------------ | ------------------------------------------------ | -------------------- |
| 最終判断     | 承認・受入・公開可否を誰に集めるか、兼務の方針   | 組織定義             |
| Role code    | 名簿で使える Role code の一覧                    | ロール定義           |
| 使用中の名前 | 実行ログに記録済みの nickname、agent の nickname | 実行ログ・agent 定義 |
| 公開の可否   | 表示名と連絡先を公開してよいか                   | 本人への確認         |

## 3. 全体の作成手順

1. 最終判断を担う人を先に決める。ここが決まると兼務の範囲が決まる。
2. 使用中の nickname を集めてから名前を決める。後から変えると履歴の参照先が切れる。
3. 各人の Role code を割り当て、最後に `rules` へ project 固有の制約だけを書く。

## 4. 各章の書き方

### 4.1. members

問い:

- 承認・受入・公開可否を最後に決めるのは誰か。
- その人が交代しても、nickname の意味は変わらないか。
- 公開文書に載せてよい `display_name` は何か。

コツ:

- 個人名が要らなければ nickname も `display_name` も `po`・「店主代表」のような役割の名前にする。本人に公開の可否を聞き、答えがなければ連絡先を空にする。
- 最終判断の範囲は `note` に 1 文で書き、組織定義を写さない。

### 4.2. rules

問い:

- この project だけの公開制約や交代時の扱いは何か。

コツ:

- 共通の標準や agent の起動設定を書き足したくなったら、正本への参照に置き換える。

## 5. 深掘り手順

1. 各 member の Role code から、組織定義の最終判断へたどれるかを確かめる。
2. `rules` の各行が、この project 固有の制約かを確かめ、共通の内容を外す。

## 6. 良い例 / 悪い例

| 観点     | 良い例                                 | 悪い例                         |
| -------- | -------------------------------------- | ------------------------------ |
| nickname | 交代時は新しい member を足す           | 記録済みの nickname を改名する |
| 連絡先   | 公開の確認がなければ `email: null`     | 推測した私用アドレスを書く     |
| `rules`  | 「公開文書に個人名を書かない」だけ書く | agent の起動設定を写す         |

## 7. レビュー観点

| 観点       | 確認内容                                         |
| ---------- | ------------------------------------------------ |
| 責任の所在 | 最終判断を担う人間が名簿から読み取れるか         |
| 一意性     | agent 定義と合わせても nickname が重ならないか   |
| 公開適性   | 個人名・私用連絡先・非公開の組織情報を含まないか |

## 8. 仕上げチェック

- 各 member の Role code が、組織定義の最終判断の範囲と食い違っていない。
- `rules` に共通の標準や agent の設定の再掲がない。
