# 品質管理計画 作成レシピ

Quality Management Plan Writing Recipe

利用者価値と成果物品質を、少数の品質ゲートと是正手順へまとめる作り方です。

## 1. このレシピの使い方

- 成功基準から価値品質、rulebook・検証から成果物品質を抽出します。
- 品質目標・メトリクス・検査基準を品質ゲートへ統合します。
- レビュー、証跡、是正、再判定を接続します。
- 利用者価値と品質リスク（Why）、合格状態とゲート（What）、検査・是正・再判定（How）を整理し、成功基準・受入条件 ID と検証証跡で追跡します（Trace）。成功基準や個別検証手順は再掲しません。

## 2. 作成前に集める情報

| 項目       | 集める情報                               |
| ---------- | ---------------------------------------- |
| 価値品質   | 利用者評価、費用・負荷、継承、運用成果   |
| 成果物品質 | 構造、参照整合、検証、公開適性           |
| 判定条件   | 成功基準ID、受入条件ID、検証結果         |
| 証跡       | 試行記録、レビュー、費用・作業記録、ログ |
| 責任       | 確認者、承認者、是正担当                 |
| 例外       | 未達時の対応、再判定、変更判断           |

## 3. 全体の作成手順

1. 品質方針を価値品質と成果物品質に分けます。
2. 必要な判定時点だけを品質ゲートにします。
3. 各ゲートへ合格条件、方法・証跡、時期、責任を置きます。
4. レビュー対象ごとの主要観点と出口条件を定めます。
5. 不適合区分、是正、再判定、記録先を定義します。
6. 成功基準や検証手順の再掲を削除します。

## 4. 各章の書き方

### 4.1. 品質方針と適用範囲

- 利用者に生じる価値を品質の中心にします。
- 技術検証は価値提供を支える条件として区別します。
- 人間とAI Agentの確認・判断境界を示します。

### 4.2. 品質ゲート

- 成功基準ID、受入条件ID、検証結果を参照します。
- 代表試行、主要変更、公開前など必要な時点だけを置きます。
- 費用・負荷は現金支出、作業時間、継続運用負荷を分けます。

### 4.3. レビューと証跡

- 対象、観点、実施責任、出口条件を一行にします。
- 指摘と是正結果を追跡できる証跡へ残します。
- 生成物は正本から再生成します。

### 4.4. 不適合と是正

- 軽微、価値不適合、技術不適合、公開不適合など対応差がある区分だけを置きます。
- 未達条件を特定して再判定します。
- 目的・スコープ変更は変更要求へ接続します。

## 5. 深掘り手順

1. 各ゲートがどの価値または受入条件を守るか確認します。
2. 同じ条件を持つ目標・メトリクス・検査を統合します。
3. 技術検証だけで終わるゲートに利用者価値との関係を付けます。
4. 使用されない指標を削除します。

## 6. 良い例 / 悪い例

| 観点       | 良い例                             | 悪い例                 |
| ---------- | ---------------------------------- | ---------------------- |
| 価値品質   | 利用者が主要操作を完遂できる       | lintが成功する         |
| 費用・負荷 | 支出と追加操作時間を別々に判定     | 無償なので低コスト     |
| 是正       | 未達IDを修正して同じゲートを再判定 | 問題ないことを確認する |

## 7. レビュー観点

- 利用者価値と成果物品質を区別できるか。
- 条件が成功基準・受入条件・検証へ接続しているか。
- 同じ条件を複数表へ重複させていないか。
- 是正後の再判定が明確か。

## 8. 仕上げチェック

- 品質ゲート、レビュー、是正がそろっている。
- 費用と人の負荷を必要に応じて分けている。
- 生成物の直接編集を認めていない。
- Agentに価値・例外・公開判断を委ねていない。
- 各品質ゲートが、守る価値または品質リスク、合格条件、検査・是正方法、証跡に対応している。
