# 品質管理計画 作成レシピ

Quality Management Plan Writing Recipe

利用者価値と成果物品質を、少数の品質ゲートと是正の流れへまとめる作り方を示す。

## 1. このレシピの使い方

- 成功基準の利用者価値（Why）を引き継ぎ、ゲートの合格状態（What）を定め、レビュー・是正・再判定（How）で守る。各ゲートは条件 ID と証跡の記録先でたどる（Trace）。

## 2. 作成前に集める情報

| 項目     | 集める情報                                       | 取り出し元    |
| -------- | ------------------------------------------------ | ------------- |
| 守る価値 | どの条件 ID が誰のどの変化を判定するか           | 成功基準      |
| 節目     | どの判断の前に確かめるか、適用の開始と終了       | 管理計画      |
| 公開対象 | 何を公開し、個人情報・非公開情報がどこに混ざるか | `PO` への確認 |
| 証跡     | 試行・検査・費用と作業時間の記録をどこに残すか   | `QE` への確認 |
| 責任     | 誰が照合し、誰が判断し、誰が是正するか           | RACI          |

## 3. 全体の作成手順

1. 品質方針と適用範囲を先に書く。守る価値が決まらないと、ゲートの数が決まらない。
2. 判断の前に要る時点だけを品質ゲートにする。
3. 各ゲートの前に終えるレビューと証跡を書く。
4. 不適合と是正を書く。
5. 最後に見直し条件と未決事項を書く。途中で決めきれなかった点がここに集まる。

## 4. 各章の書き方

### 4.1. 品質方針と適用範囲

- 問い: 利用者のどの変化を価値品質とするか。人間が最終判断する価値・例外・公開は何か。
- コツ: 成功基準の閾値は写さず参照に置き換える。終了日が決まらなければ終了のイベントを聞く。

### 4.2. 品質ゲート

- 問い: そのゲートがないと、どの判断を誤るか。証跡不足のときどう扱うか。
- コツ: 費用は「無償」で済ませず、現金支出と作業時間を別々に聞く。

### 4.3. レビューと証跡

- 問い: どの対象版を誰が確認するか。公開対象を全件確かめたことを何で示すか。
- コツ: 保存先が未定なら仮のパスを書かず未決事項へ回す。

### 4.4. 不適合と是正

- 問い: どの不適合で作業や公開を止めるか。是正後に何を確かめ直すか。
- コツ: 区分は止めるゲートが異なるものに絞る。

### 4.5. 見直し条件と未決事項

- 問い: 何が変わると合格条件を直すか。未決の間どの判定を保留するか。
- コツ: 未決事項に、決まったとき直す条件を添える。

## 5. 深掘り手順

1. 各ゲートが守る条件 ID を確かめ、対応のないゲートを外す。
2. 技術検証だけで閉じるゲートに利用者価値を付ける。
3. どの判定にも使わない指標を外す。

## 6. 良い例 / 悪い例

| 観点     | 良い例                               | 悪い例                 |
| -------- | ------------------------------------ | ---------------------- |
| 価値品質 | 利用者が主要操作を完遂できる         | lint が成功する        |
| 費用     | 支出と追加の作業時間を別々に判定する | 無償なので低コスト     |
| 是正     | 未達 ID を直し同じゲートで再判定する | 問題ないことを確認する |

## 7. レビュー観点

| 観点     | 確認内容                                          |
| -------- | ------------------------------------------------- |
| 判断責任 | AI Agent に価値・例外・公開の判断を委ねていないか |
| 公開適性 | 公開対象に個人情報・非公開情報が残っていないか    |

## 8. 仕上げチェック

- 各ゲートから、守る価値・合格条件・証跡の記録先までたどれる。
