# 品質管理計画 作成レシピ

Quality Management Plan Writing Recipe

利用者価値と成果物品質を、少数の品質ゲートと是正手順へまとめる作り方です。

## 1. このレシピの使い方

- 成功基準から価値品質、rulebook・検証から成果物品質を抽出します。
- 品質目標・メトリクス・検査基準を品質ゲートへ統合します。
- レビュー、証跡、是正、再判定を接続します。
- 利用者価値と品質リスク（Why）、合格状態とゲート（What）、検査・是正・再判定（How）を整理し、成功基準・受入条件 ID と検証証跡で追跡します（Trace）。成功基準や個別検証手順は再掲しません。

## 2. 作成前に集める情報

| 項目       | 集める情報                                               |
| ---------- | -------------------------------------------------------- |
| 価値品質   | 利用者評価、費用・負荷、継承、運用成果                   |
| 成果物品質 | 構造、参照整合、検証、公開適性                           |
| 判定条件   | 成功基準ID、受入条件ID、検証結果                         |
| 証跡       | 試行記録、レビュー、費用・作業記録、ログ                 |
| 責任       | 確認者、承認者、是正担当                                 |
| 例外       | 未達時の対応、再判定、変更判断                           |
| 対象期間   | 適用開始・終了のイベント、初期受入・試用・後続観測の境界 |

## 3. 全体の作成手順

1. 品質方針を価値品質と成果物品質に分け、適用開始・終了と人間・AI Agent の境界を示します。
2. 必要な判定時点だけを品質ゲートにします。
3. 各ゲートへ合格条件、方法・証跡、時期、責任を置きます。
4. レビュー対象ごとの主要観点、実施責任、出口条件、証跡、記録先を結びます。
5. 不適合区分と重大性の境界を定め、是正後の再判定条件・責任・記録先へ接続します。
6. 見直しと後続作業、未決事項と保留を整理し、成功基準や検証手順の再掲を削除します。

## 4. 各章の書き方

### 4.1. 品質方針と適用範囲

- 利用者のどの変化を価値品質とし、どの成果物・技術条件がそれを支えますか。
- いつからいつまで適用し、初期受入・公開後の試用・後続観測をどこで区切りますか。
- AI Agent が支援する確認と、人間が担う価値・例外・公開の最終判断は何ですか。

### 4.2. 品質ゲート

- 各ゲートはどの条件 ID と正本を参照し、どの時点で確認しますか。運用前に必要な比較基準値は採取できますか。
- 誰がどの方法・証跡で確認し、誰が承認しますか。未達・証跡不足・未決条件をどう保留しますか。
- 費用・負荷を扱うとき、現金支出、作業時間、継続運用負荷を別々の基準・記録で判断できますか。

### 4.3. レビューと証跡

- どの対象版を誰が、どの観点で確認しますか。
- 出口条件はどの状態で合否が分かれ、それを裏付ける証跡はどの記録先に残りますか。三つを別々の欄に記入します。
- 指摘から是正・再判定結果を辿れますか。生成物は生成元を直し、再生成結果を証跡にします。

### 4.4. 不適合と是正

- 対応が異なる区分と重大性の境界は何ですか。重大な不適合ではどのゲートを止め、誰へ報告しますか。
- 是正後のどの契機に何を再確認し、誰が再判定しますか。再判定条件と責任を別欄にします。
- 発生済みの支障、将来の品質リスク、目的・スコープ・条件の変更を、誰がどの課題・リスク・変更記録へつなぎますか。

### 4.5. 見直し条件と未決事項

- 成功基準、公開範囲、構造、検証方法、体制、重大不適合の傾向の何が変わると見直しますか。
- 管理計画、RACI、Schedule、証跡参照の更新先・担当・期限・確認者を誰が整理しますか。後続観測への引き継ぎ条件は何ですか。
- 未決論点の正本、判断材料の担当、決定時期・人間の判断者、未決中の保留対象を特定できますか。

## 5. 深掘り手順

1. 各ゲートがどの価値または受入条件を守るか確認します。
2. 同じ条件を持つ目標・メトリクス・検査を統合します。
3. 技術検証だけで終わるゲートに利用者価値との関係を付けます。
4. 使用されない指標を削除します。

## 6. 良い例 / 悪い例

| 観点       | 良い例                             | 悪い例                 |
| ---------- | ---------------------------------- | ---------------------- |
| 価値品質   | 利用者が主要操作を完遂できる       | lintが成功する         |
| 費用・負荷 | 支出と追加操作時間を別々に判定     | 無償なので低コスト     |
| 是正       | 未達IDを修正して同じゲートを再判定 | 問題ないことを確認する |

## 7. レビュー観点

| 観点     | 確認内容                                                                          |
| -------- | --------------------------------------------------------------------------------- |
| 範囲     | 価値品質・成果物品質、適用期間、人間と AI Agent の境界が明確か                    |
| 判定     | 条件 ID、時期、確認・承認責任、方法・証跡が接続し、未達と材料不足を通過させないか |
| レビュー | 出口条件・証跡・記録先を個別に確認できるか                                        |
| 是正     | 重大性の境界、再判定条件・責任、報告・登録先が明確か                              |
| 維持     | 見直し・未決・後続作業が担当と期限へ接続し、正本を重複させていないか              |

## 8. 仕上げチェック

- 品質ゲート、レビュー、是正がそろっている。
- 費用と人の負荷を必要に応じて分けている。
- 生成物の直接編集を認めていない。
- Agentに価値・例外・公開判断を委ねていない。
- 各品質ゲートが、守る価値または品質リスク、合格条件、検査・是正方法、証跡に対応している。
