# プロジェクト管理計画 作成レシピ

Project Management Plan Writing Recipe

価値検証に要る管理・判断・証跡だけを、軽量な管理計画へまとめる作り方を示す。

## 1. このレシピの使い方

- 成功基準の価値と逸脱リスク（Why）から、管理基準・上限・判断ゲート（What）と確認契機・逸脱時対応・責任（How）を決め、各管理行を条件 ID と正本の記録でたどる（Trace）。

## 2. 作成前に集める情報

| 項目       | 集める情報                             | 取り出し元           |
| ---------- | -------------------------------------- | -------------------- |
| 価値と判定 | 成功基準 ID、受入条件 ID、判定時期     | 成功基準             |
| 境界       | スコープ内外、管理を厚くする条件       | スコープ             |
| 費用・負荷 | 現金支出、作業時間、継続運用負荷の上限 | 成功基準、承認責任者 |
| 判断者     | 公開・例外・変更・停止の最終判断者     | 組織定義、RACI       |
| 記録先     | 課題・リスク・変更・品質・費用の記録先 | 登録簿、Schedule     |

## 3. 全体の作成手順

1. 管理目的を価値と期間で 1 文にする。これがないと網羅目的の行が増える。
2. 統合管理表は、一般的な PM 項目ではなく条件 ID ごとの行から書く。
3. 判断ゲートは、逸脱時対応のうち人間の判断が要るものから作る。
4. 未決事項は、決めきれない上限や判断者を最後に集める。

## 4. 各章の書き方

### 4.1. 管理目的と適用方針

問い:

- どの価値を、いつからいつまで検証するのか。
- 契約・監査・組織規模の何が変わると管理を厚くするか。

コツ:

- 比較基準値の収集は前提作業に置く。

### 4.2. 統合管理方針

問い:

- この行は、どの条件 ID の何を守るのか。
- 誰が、いつ逸脱に気づき、次に何をするのか。

コツ:

- 費用を聞くと現金支出だけが返る。準備時間と日々の操作時間を別に聞く。
- 数値や測定手順は成功基準から写さず、条件 ID で参照する。

### 4.3. 判断ゲートとエスカレーション

問い:

- 未達や材料不足なら何を保留し、誰が再判定を起案するのか。
- 初期受入と後続の観測を同じゲートで判定してよいか。

コツ:

- 材料を整理する Role と最終判断する Role を別に聞く。

### 4.4. 正本・報告・見直し

問い:

- 判断・逸脱・作業節目のどれを報告の契機にするのか。
- 目的や体制が変わったら、どの文書をどの順で直すのか。

コツ:

- Schedule の作業担当を承認者と取り違えやすい。承認者は別に聞く。

### 4.5. 未決事項

問い:

- 決まるまで、何の着手や判定を止めるのか。
- 決まったら、どの管理行・ゲートが変わるのか。

コツ:

- 別の正本で追う論点は写さず参照に置き換える。

## 5. 深掘り手順

内容が浅いときは、次の順で対応のない主張を探す。

1. 管理行ごとに応える条件 ID を確かめ、対応のない行を外す。
2. 判断ゲートの各条件が材料を受ける管理行を確かめる。
3. 個別計画・RACI・Schedule・登録簿と重なる説明を参照に戻す。

## 6. 良い例 / 悪い例

| 観点     | 良い例                             | 悪い例                       |
| -------- | ---------------------------------- | ---------------------------- |
| 管理目的 | SC-01〜SC-03 の代表試行を管理する  | 一般的な PM 項目を管理する   |
| コスト   | 現金支出と作業時間を別の上限で確認 | 金額予算はないので管理しない |

## 7. レビュー観点

| 観点   | 確認内容                                   |
| ------ | ------------------------------------------ |
| 判断者 | 継続・保留・停止の判断に使う記録が分かるか |
| 作業者 | 自分の確認契機と逸脱時の行動が分かるか     |

## 8. 仕上げチェック

- 各管理行から、条件 ID、逸脱時の行動、記録先までたどれる。
- AI Agent に最終判断を委ねていない。
